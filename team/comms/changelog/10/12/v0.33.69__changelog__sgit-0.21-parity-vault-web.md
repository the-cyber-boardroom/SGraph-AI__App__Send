# Changelog: vault web ↔ sgit-ai 0.21.0 parity — signed commits, format gate, shared index, rewinds, deterministic trees

**version** v0.33.69 · **date** 2026-10-12 · **from** Dev (Explorer) · **surface** `sgraph_ai_app_send__ui__vault/v0/v0.2/v0.2.3` (library + shells + SGit view), kernel bundle · **API** unchanged

## What changed

The browser vault library now writes exactly what the sgit-ai CLI (0.19.0 → 0.21.0) writes and reads, and enforces the same rules. Verified against the real `sgit-ai 0.21.0` on this repo's in-memory server (`tests/integration/vault_ui/cli/test__sgit_cli_parity.py`): `sgit check verify` reports every web commit **verified**; the gate, tags and CLI clone entries survive web pushes; a CLI folder re-encrypted by the web gets the identical tree id.

| Area | Before | After |
|---|---|---|
| Commits | `commit_v2`, 7 members, unsigned | `commit_v1`, the CLI's ten members, signed per device (ECDSA P-256 over RFC 8785 bytes, `author_key_id`, `branch_id: branch-clone-<16 hex>`); unsigned sessions write the same shape with `signature: null` |
| Signing key | none | per device per vault, non-extractable in IndexedDB; public half at `bare/keys/key-rnd-imm-<id>` (read-key-encrypted `{"type":"public","pem"}`) published before the first push |
| Verification | none (raw signature string shown) | `verifyCommit` / `verifyChain` with the CLI's statuses; chips in the SGit history + object views; gate, signing key and tags in the Refs tab |
| Branch index | one-entry overwrite on create and every push | read → merge (CLI rules) → `write-if-match` → retry; our clone entry upserted; gate / tags / other entries / unknown members preserved; never staged in the commit batch |
| Format gate | ignored | read on open and before every sync; 32-hex ids on format 2; unknown format refuses (`EFORMAT`) |
| Named-ref publish | blind `writeRef` in the shells | `push()` is compare-and-swap with one reconcile; `push({force:true})` is the explicit blind write; `pushIfMatch()` unchanged |
| Rewinds | undetected | last accepted head per device; `EREWOUND` on pull/merge unless accepted; shell banner + "Accept rewind" |
| `signatures-required` | n/a | unsigned/unverifiable local commit refused before publish (`ESIGNATURE`); unverifiable incoming commit refused on pull/merge |
| Trees | random IVs, 5-member entries, `JSON.stringify` | HMAC-derived IV, 7-member entries in CLI order with `content_type` (Python `mimetypes` table) + `large`, Python separators, code-point sorting; unchanged file reuses its blob |
| Clone ref | one shared `web-ui` ref for every browser | per device (`web-ui:<branch id>`) when signed; unpublished work on the legacy ref adopted once |
| Pages / bundle | — | every page loads `lib/sg-vault/sg-vault-interop.js` after `sg-vault-crypto.js`; `kernel-shell-bundle.js` regenerated |

New file: `_common/js/lib/sg-vault/sg-vault-interop.js` (`SGVaultPyJson`, `SGVaultJcs`, `SGVaultPyMimetypes`, `SGVaultSigning`, `SGVaultSigner`, `SGVaultBranchIndex`).

## Behaviour notes for QA

- A vault opened in a browser without IndexedDB (private mode, sandboxed kernel) commits unsigned, as before; under `signatures-required` it cannot publish and says so.
- `push()` on a diverged vault now merges then publishes instead of overwriting; the shell dialog text changed accordingly.
- Entry names, sizes and content types in trees are now deterministically encrypted (same plaintext → same ciphertext), which is what the CLI already did; the host can see equality of names across trees (CLI threat model TM-R08, accepted).
- One CLI finding to pass on: a branch-index entry whose `name` is not `[A-Za-z0-9_-]` makes the CLI's parse of the whole index fail closed, and its next push overwrites the index. We now write `name: 'web-ui'`.
