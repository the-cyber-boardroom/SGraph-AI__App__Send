# Changelog — B1: the vault's AI Chat gets opt-in tools (session + files.read)

**Date:** 2026-08-06 · **Area:** Vault UI — `sg-llm.js`, new `sg-llm-tools.js`, `vault-llm-chat.js`
**Plan:** `team/roles/architect/reviews/08/06/v0.33.56__architect-review__vault-chat-tools-convergence.md`
**Source:** Dinis — the pic2 interactive-chat workflow, with "disable all by default" and grants stored in `.vault/`

## What changed

The chat panel can now *act on the vault* — but only after the user commits a grant. Two
groups ship in B1, both READ-tier:

| Group | Tools |
|---|---|
| `session` | `get_costs`, `get_exchanges` — the `VaultLlmLog` ledger, queryable by the model |
| `files.read` | `list_folder`, `read_file`, `stat`, `exists` |

**The default is today's behaviour, verbatim.** No `tools.json` → every group off →
`tools[]` is not sent at all — zero tokens, zero new attack surface, and the model still
sees only attached files and pasted screenshots.

## The pieces

**1. `tool_calls` through `SGLlm`** — the transport gap the review verified. Streamed
fragments reassemble by index (names and JSON arguments arrive split across frames), the
JSON path is read too, malformed arguments become `args: null` + `argsRaw` (the caller
replies with an error tool-result instead of crashing), and ids are synthesised when a
route omits them. `redactMessages` now truncates tool results and caps tool-call arguments
so a fenced file body cannot flood the provenance log.

**2. `SGLlmTools`** — grants, scope, dispatch. Grants live in **`/.vault/llm/tools.json`**
(separate from `config.json`, which carries the sealed key and should not churn). Every
toggle is a commit: `sgit log` of that one path is the privilege audit log. Security shape,
each property tested:

- **The floor beats every grant.** `.vault/**` is refused `EPROTECTED` at dispatch — in
  traversal spellings, backslash spellings, and for **the grants file itself**: the model
  cannot read, relax, or widen its own privileges. `.vault` never appears in listings.
- **Scope globs** per group (`allow: ["docs/**"], deny: ["finance/**"]`): deny wins, `*`
  does not span segments, empty allow = everything minus the floor. Enforced at dispatch
  *and stated in the tool description*, so the model does not burn paid calls discovering
  the boundary. The root stays listable under an allow-scope so navigation works.
- **Fencing.** `read_file` content returns inside the same `UNTRUSTED DATA` fence the
  vault-chat pack uses, truncation stated *inside* the fence; the system prompt gains the
  fence rule only when tools are on.
- **Fail closed.** A corrupt grants file parses to everything-off. A tool failure is a
  RESULT the model can read (`ENOENT`, `ESCOPE`, `EARGS`…), never a throw in the panel.

**3. The loop in the panel** — send → dispatch → resend until prose. Every round is its
own `VaultLlmLog` entry (a tool-using turn is fully visible in the requests pane), each
call renders as a transcript chip while it runs (`🔧 read_file docs/plan.md ✓`), and only
the final prose joins the conversation history — fenced file bodies are per-turn plumbing;
resending them every later turn would balloon both context and bill. Termination: 8 rounds,
then one final **tool-less** round so the model must land an answer from what it gathered,
with the cap stated to the user.

**4. The `🔧` bar** — beside `⚙`. Groups with tier + *measured* token weight (computed from
the JSON actually sent, not hand-maintained), the commit-as-audit-log stated in the bar. A
failed save **reverts the toggle** — the UI never claims authority the vault refused. A
read-only vault shows the granted posture locked, with the reason.

## Test impact

**SHOULD break (good failures) if reverted:**
- `test__sg_llm.js` (53 → **69**) — fragment reassembly, JSON path, malformed args,
  synthesised ids, `toolCalls === null` on plain replies, tool-traffic redaction.
- `test__sg_llm_tools.js` (**new**, 51) — default-nothing, the floor (incl. the grants file
  itself and traversal spellings), glob semantics, scope-in-description, dispatch against a
  fake vault, fenced + truncated reads, persistence + `EREADONLY`.
- `test__vault_llm_chat.js` (122 → **149**) — the bar (off by default, save-commit,
  revert-on-failure, read-only lock), the loop end-to-end (tools[] sent, fence rule in the
  system prompt, tool-result correlation, chips, per-round ledger, history hygiene), and
  termination at the cap with a tool-less final round.

**Should NOT break (bad failures — investigate if they do):**
- Full vault unit suite + `test:vault-chat-unit` + `pytest tests/unit/vault_ui` green at
  commit time.
- A vault with no `tools.json` behaves byte-for-byte as before — no tools[], no fence
  lecture in the system prompt, single-call `_send`.
- Voice, images, params, and the requests pane are untouched.

## Not in B1 (per the review)

`ui` + `history` groups, the Settings → AI Tools page (scope editor with live match
counts, the audit view), and `files.write` (working set + one-commit flush + CONFIRM).
The dev-pack doc 09 AppSec sign-offs remain the promotion gate.

## Not verified

Not opened in a browser; no live model has driven the loop. The scripted-client tests pin
the message shapes OpenRouter documents, but the first real tool-calling model run —
model choice matters here, tool-use quality varies — is the verification only a browser
session can do.
