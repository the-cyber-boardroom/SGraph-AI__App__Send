# Changelog — `sg.llm.*` hardening (P0–P3 of the 08/13 review)

**Date:** 2026-08-13 · **Area:** App Mode kernel (`app-shell.js`, `app-permissions.js`,
`app-hud.js`) + `lib/sg-llm/` (`vault-llm-log.js`, `sg-llm-tools.js`)
**Implements:** `team/roles/architect/reviews/08/13/v0.33.47__architect-review__sg-llm-as-built-and-next-steps.md`
(findings F1–F5). Kernel bundle regenerated.

## P0 — consent can no longer be weakened by the app (F2)

`app.json` is authored by the app: under the two-tier model it *declares intent*, it does not
*grant capability*. It could nonetheless set `"consent": {"llm.chat": "auto"}` and switch off
the gate on a capability that **spends the vault owner's money**; and `llm.listen` — a
**microphone** — defaulted to `'once'`, cached in `localStorage` indefinitely, directly
contradicting its own code comment ("consent EVERY time … not a capability to grant once and
forget").

- New `AppShell.CONSENT_FLOOR` = `{ 'llm.chat': 'once', 'llm.listen': 'always' }` — the
  *minimum* strength for a verb.
- New `AppShell.strictestConsent(a, b)` (order: `auto` < `once` < `always`). `_consent` clamps
  the manifest value up to the floor, so a manifest may only ever make consent **stricter**.
- Verbs with no floor keep their existing behaviour, `'auto'` included.

## P1 — frame egress is contained by default (F1, F4)

The plan's central coupling was half-delivered: key custody shipped, egress lockdown did not —
leaving precisely the configuration the coupling existed to prevent. Worse,
`app-permissions.js` **asserted the CSP as fact** while no CSP existed anywhere in shipped code.

- `_buildVfsBridgeScript` now prefixes
  `<meta http-equiv="Content-Security-Policy" content="connect-src blob: data:">`.
  It is injected as the first child of `<head>` by `AppFrameBootstrap._injectHead`, so it
  governs the whole document. Done at the **builder**, not the call sites: there are five, and
  forgetting one would silently lose containment.
- **`connect-src blob: data:` — deliberately not `'none'`.** The print RPC fetches `blob:` URLs
  to inline images and stylesheets; `'none'` would break printing silently. Neither scheme can
  reach the network. `img.src` and dynamic `import()` are governed by `img-src`/`script-src`, so
  vault images and CDN component imports are unaffected.
- **`permissions.network` is now real** — it omits the meta, and is the only way to re-open
  direct egress. The false comment is corrected to describe what the code does.
- HUD: `setPrivileges` now lists `use AI models (costs money)`, `use the microphone` (danger),
  and `direct network access (uncontained egress)` (danger) as standing grants — not a
  transient toast.

## P2 — spend is attributed per app (F3)

Per-app caps in `.vault/llm/config.json` were resolved per app but compared against a
**session-global** ledger that the host's own chat also writes to. The owner's chat spend could
trip an app's `EBUDGET`, and two apps cannibalised each other.

- `VaultLlmLog` entries carry `app` (`null` = the host's own chat; a string = the calling app).
- `VaultLlmLog.totals(app)` scopes the tally; called with **no argument** it is unchanged, so
  the displayed session figure ("one bill per session") is unaffected.
- `_llmTotals(app)`, the budget check, and `sg.llm.usage` are all scoped to the caller.

## P3 — tool scope must be explicit (F5)

For `files.read`, an empty `allow` meant **the entire vault minus the floor**. Ticking one
checkbox is not a considered grant over everything.

- Path-scoped groups now require an explicit allow-list; absent scope returns the new
  `ENOSCOPE` with a reason telling the admin what to set.
- The root-listing exemption (so a *scoped* model can navigate) is narrowed to `ESCOPE` only —
  an unscoped group can no longer list the root either.
- `compileTools` tells the model plainly when a group has no usable scope, so it does not burn
  paid calls discovering that every path is refused.
- The floor still wins over any allow-list, including `**` and traversal spellings.

## Test impact

**New:** `test__llm_hardening.js` (42 assertions) — consent-floor algebra, CSP present/absent
and never `'none'`, per-app ledger isolation (incl. "an app is not blocked by the owner's own
spend"), and empty-allow-grants-nothing.

**SHOULD break (good failures) if reverted** — plus these **intentional contract changes**,
whose existing assertions were updated rather than deleted:

- `test__sg_llm_tools.js` — `empty allow = everything (minus floor)` → **`empty allow grants
  NOTHING`**; added that an explicit `**` still grants everything, and that an unscoped group
  cannot list the root. Shared `grantsOn()` fixture now carries `allow: ['**']`.
- `test__app_shell_llm_bridge.js` — the `budget … across surfaces` suite asserted that the
  owner's chat spend counts against an app. That **was** the bug; it now asserts an app is
  capped by its own spend, and a new suite asserts one spender cannot exhaust another's budget.
- `test__app_shell_bridge_build.js` — the bridge-parses guard took the body from `^<script>`;
  it now takes it from the first `<script>` **and additionally asserts the CSP meta precedes
  it**, so the guard is stronger, not weaker.
- `test__vault_llm_chat.js` — the tool-loop fixture gained `allow: ['**']` (it exercises the
  loop, not scoping).

**Should NOT break:** everything else. Full suite green (0 failures), bundle freshness passes
after regeneration.
