## 1. Key prefixes brought up to sgit-ai 0.16.0 (BUG FIX)

A vault key **copied verbatim from current CLI output** failed to open with
`"Vault not found: HEAD ref missing"`: our prefix list still had only the 08/14 generation
(`sgit_vk1_`/`sgit_rk1_`), so PBKDF2 ran over the prefix and derived a different vault.
sgit renamed the prefixes on 08/17.

| File | Change |
|---|---|
| `lib/sg-vault/sg-vault-crypto.js` | `KEY_PREFIXES` = `sgit_private_vault_`, `sgit_private_read_`, `sgit_public_read_`, `sgit_vk1_`, `sgit_rk1_`; `stripKeyPrefix` iterates it (whole-prefix match — the two `sgit_private_*` prefixes share a stem, and partial stripping derives a *different vault*). New `classifyKey()` mirroring sgit's `classify_key` (intent by declaration, never by shape). |
| `vault-loader/vault-loader-format.js` | dep-free twin of the same list, same order (drift-guarded by test) |
| `components/app-shell/app-shell.js` | comment now points at `SGVaultCrypto.KEY_PREFIXES` as the authority |
| `kernel-shell-bundle.js` | regenerated (crypto lib is a bundle source) |

Every key-input path already routed through `stripKeyPrefix` (loader `detectFormat`,
app-shell `_initWithKey`, `parseReadOnlyCredential`), so the one-line list change fixes all
surfaces — vault UI, App UI, read-key/format-6 opens and the `<sg-vault-embed>` element.

**Verified end-to-end**, not just unit-tested: `sgit-ai 0.16.0` `init → commit → push` against
this repo's `Send__User_Lambda__Http_Server`, then opened with this repo's browser stack —
fails before the fix with the reported error, succeeds after, decrypting CLI-written files.

## 2. Recent-vaults list: "Untitled Vault" → the app's title

Extends the 08/15 title fallback (`SGVault.hasCustomName`) to the home page vault list.
The recent entry is written at open time (before `app.json` is read), so `_applyAppJson`
now re-`add()`s the entry with the app title when the vault has no custom name — `add()` is
keyed by vaultKey and updates the row in place (already covered by `test__recent_list.js`
"re-add updates name and moves entry to front"). Skipped in embed mode (non-persisting by
design).

**Known limitation (accepted):** only the **vault UI** path updates the row — `app-shell`
loads no vault-loader scripts and does not write the recent list at all today. A vault
opened *only* through `/en-gb/app/` keeps whatever name the landing page stored.
