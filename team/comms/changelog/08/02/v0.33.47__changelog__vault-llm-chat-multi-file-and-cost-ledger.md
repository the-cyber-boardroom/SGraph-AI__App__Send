# Changelog — vault LLM chat: sg-layout panel, multi-file context, cost ledger

**Date:** 2026-08-02 · **Area:** Vault UI (`/en-gb/vault/`, `/en-gb/browse/`)
**Follows:** `team/comms/changelog/08/02/v0.33.43__changelog__native-vault-llm-chat.md`
**Reported by:** Dinis (5 items — 2 bugs, 3 features)

## What changed

### 1. The chat is a real `sg-layout` panel (was: a fixed drawer)

`vault-shell.js` no longer shows a hard-coded 380px `.vs-llm-sidebar`. It mounts
`<vault-llm-chat>` into **send-browse's `sg-layout`** via `layout.addPanel({el, title})`, so
the chat drags, resizes, re-docks and closes exactly like the tree and file panes.

The panel no longer owns its own visibility — the layout does. `close()` now dispatches
`vault-llm-close` and the shell calls `layout.removePanel(id)`.

- `addPanel` only assigns `el.slot`; the element must already be a light-DOM child of the
  layout, so the shell appends it first.
- Closing via sg-layout's own tab `×` is caught (`events.on('panel:closed')`, bound **once
  per layout** — re-binding per open leaked a listener per cycle) so the next open works.
- **Fallback preserved:** if no layout exists yet (Settings view, custom element still
  upgrading, `_sgLayoutReady()` times out after ~1s) the old fixed sidebar is used instead of
  refusing to open.
- A browse remount (`_mountBrowse`) wipes `filesView` and with it the layout. The AI elements
  are **parked** in the sidebar first and re-mounted after, so the transcript and attached
  files survive a branch switch or refresh.

### 2. BUG FIX — choosing a second file no longer breaks the chat

**Reported:** *"once I have one file selected, I can't choose another (i.e. then 'Ask AI'
doesn't work)."*

**Root cause:** context came from a global `vault-file-viewing` event fired inside
`_renderFileContent`. But `send-browse._openFileTab` **returns early when the file's tab is
already open** — it just clicks the existing tab (`sb.js:509-516`). Re-opening a file, and
switching tabs at all, therefore re-announced nothing, and the chat silently kept the first
file it ever saw.

**Fix (structural, not a patch to the announcement):** the file's bytes are decoded **once per
render**, and the action-bar button closes over that result. The event it emits cannot
describe a different file no matter what has been rendered since. `vault-file-viewing` still
fires, but is now only a hint for the chat's empty state — it never sets context.

### 3. "Ask AI" → "➕ Add to chat" + a top-level way in

- The file action-bar button is now **`➕ Add to chat`** — additive, because the chat holds
  many files. It attaches the file *and* opens the panel (you should see what you attached).
- **`✨ AI Chat`** added to `vault-header` (emits `vault-header-llm`) so the chat can be opened
  with no file selected at all.

### 4. Multi-file context: add, remove, and no-file chat

`<vault-llm-chat>` context is now an **explicit set**, not "whatever is on screen":

| Capability | Detail |
|---|---|
| `addContextFile({path,text,type})` | de-duplicated by path; re-adding a path **replaces** its text (so re-adding after an edit refreshes what the model sees) |
| `removeContextFile(path)` | also the `×` on every chip |
| `clearContextFiles()` | "clear all" control |
| No files | a first-class state — plain chat, with a distinct system prompt telling the model no vault files are attached |
| Cap | 20 files; hitting it is announced, and replacing an already-attached file still works at the cap |
| Binaries | attached by name, never sent as bytes, flagged amber |

**Budget honesty:** all attached files **share one 24 000-char budget** (`_contextMessages()`
splits it evenly, floor 1 500/file) rather than each taking it. Attaching a second file used to
be able to silently double the prompt and the bill. Each slice is still labelled `TRUNCATED`
inside the text the model sees.

### 5. NEW — request & cost ledger

- **`VaultLlmLog`** (`_common/js/lib/sg-llm/vault-llm-log.js`) — a pure, DOM-free session
  ledger. Every call is recorded **when sent**, so in-flight and failed calls are visible too.
  Holds the upstream **generation id** — the join key against an OpenRouter statement.
- **`<vault-llm-requests>`** — a second sg-layout panel (`AI Requests`): per-call table
  (seq, time, model, copyable generation id, tokens, cost, latency, files), running totals, and
  CSV/JSON export for external reconciliation.

**The rule this enforces:** *an estimate is never rendered as a bill.* `totals()` keeps
`billedCost` (upstream told us) and `estimatedCost` (tokens × list price) in **separate
buckets**; reconciliation *moves* a call between buckets rather than double-counting; and
finished calls nobody priced are surfaced as "N with no price yet" instead of silently
counting as $0.

The ledger is a store, not component state — closing the chat does not lose the bill.

## Test impact

**SHOULD break (good failures) if reverted:**
- `test__vault_browse_edit__add_to_chat.js` (**new**, 13) — the reported bug, pinned: render A,
  render B, click A's button, assert A comes out (and re-clicking A still yields A).
- `test__vault_llm_log.js` (**new**, 35) — cost honesty: an estimate must not land in the
  billed bucket; reconciliation must *move* money, not add it; unpriced finished calls are
  flagged; ring cap drops the oldest.
- `test__vault_llm_requests.js` (**new**, 29) — the UI's money claims: `~` on estimates,
  dropped after reconciliation; generation id displayed and copyable; failures shown.
- `test__vault_llm_chat.js` (**rewritten**, 19 → 56) — the contract changed on purpose:
  - *removed:* "starts hidden", "close() hides it", `toggle()` — the layout owns visibility now;
  - *removed:* `setContextFile()` sets the context — it is a hint only;
  - *added:* add/replace/remove/clear, empty-state chat, binaries, the 20-file cap, HTML
    escaping, and the shared-budget assertion (3 big files ≉ 3× the budget).

**Should NOT break (bad failures — investigate if they do):**
- Every other loader test — full suite green at commit time (`run-all.sh`).
- File rendering: the decode is wrapped in try/catch, so a context failure can never break
  `_renderFileContent`.
- `send-browse` itself is **unmodified** — the early-return in `_openFileTab` is left exactly as
  it is; the fix does not depend on changing CDN-served code.
- Read-only sessions: unchanged: `SGLlmVault` still refuses to unseal an owner-tier key
  (`EREADONLY`), and the panel explains why rather than failing silently.

## Follow-ups (not done)

- Per-file token counts (chars are a proxy; real tokenisation needs the model's tokeniser).
- Persisting the ledger across reloads — deliberately session-only for now (it would be vault
  state, which needs an owner-tier decision).
- Cost caps are still enforced per session in the chat, not across panels.
