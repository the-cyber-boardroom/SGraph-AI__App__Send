# Changelog — Vault Settings: AI (OpenRouter) config + read-only share block

**Date:** 2026-08-02 · **Area:** Vault UI (`/en-gb/vault/`, `/en-gb/browse/`) — `vault-settings.js`,
new `_common/js/lib/sg-llm/sg-llm-config.js`
**Plan:** `team/roles/architect/reviews/08/02/v0.33.43__architect-review__sg-llm-kernel-capability-plan.md`

## What changed

1. **New pure module `SGLlmConfig`** (`_common/js/lib/sg-llm/sg-llm-config.js`) — parses and
   serialises `.vault/llm/config.json`: provider/endpoint, key tier, model allow-list
   (`*`, `vendor/*`, exact), default model, per-session limits, per-app limit overrides, key
   shape check and redaction. Safe-by-default — junk or absent config collapses to
   `keyTier:'owner'`, allow-`*`, default caps; the two key tiers are mutually exclusive on parse.
2. **Vault Settings → "AI models (OpenRouter)"** — key entry (password field, cleared from the
   DOM after save), *Test* (validates against `GET /models` from the real origin), *Save*,
   *Clear*, plus an advanced block for key tier, default model, allow-list and spend caps.
3. **Key tiers.** `owner` (default) seals the key with
   `SGVaultOwnerSecrets.deriveKey(vault.writeKeyHex)` — an ro-token session has no write key, so
   it can neither use nor extract the credential. `shared` (opt-in, warned in the UI) stores the
   key in clear in the same file: usable *and extractable* by anyone who can open the vault.
4. **Vault Settings → "Read-only access (share these together)"** — vault id, the combined
   `readkey:vaultid` value (the single form `sgit clone` accepts), and a ready-to-paste
   `sgit clone "…"` command, each with its own copy button.
5. `sg-vault-owner-secrets.js` and `sg-llm/sg-llm-config.js` added to the script sets of
   `v0.2.3/index.html` and `en-gb/browse/index.html`.

**Not shipped:** the `sg.llm.*` bridge verbs, kernel transport, `permissions.llm`, consent,
budget enforcement and the CSP coupling all remain PROPOSED — this is the admin surface only.

  safe-default assertions (`keyTier` defaults to `owner`, junk collapses to defaults) and the

- Existing Vault Settings behaviour — name/key/URL/read-key/access-key sections are unchanged;
  the read-key input keeps its selector and copy button. The `refresh()` path now also
  populates three new read-only inputs and calls `_refreshLlm()`, which no-ops when the section
  is absent.
- App-mode bridge tests — untouched; no bridge, permission or kernel-bundle change in this
  commit (`app-permissions.js` not modified → bundle freshness unaffected).

## Notes for other teams

- `.vault/llm/config.json` is **inside the permission floor** — no vault app can read it via the
  bridge under any grant. That is the point: the credential is invisible to app code by
  construction, not by deny-list.
- Writing it requires a **writable** vault (access key + vault passphrase). Owner-tier sealing
  additionally requires the write key, so it cannot be done from an ro-token session.
- `.vault` is a lazy sub-tree; `_ensureVaultSubtree()` expands it before listing/reading — the
  same trap that once made embedded access tokens look absent.
