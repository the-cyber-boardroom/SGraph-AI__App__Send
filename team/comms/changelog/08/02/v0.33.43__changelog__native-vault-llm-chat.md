# Changelog — native LLM chat in the Vault UI ("Ask about this file")

**Date:** 2026-08-02 · **Area:** Vault UI (`/en-gb/vault/`, `/en-gb/browse/`)
**Plan:** `team/roles/architect/reviews/08/02/v0.33.43__architect-review__sg-llm-kernel-capability-plan.md`
(this is Phase 5 of that plan, pulled forward — see "Why this order changed")

## What changed

1. **`SGLlm` transport** (`_common/js/lib/sg-llm/sg-llm.js`) — OpenRouter chat with SSE
   streaming, abort handling (partial reply kept *and* costed), `models()`, and
   `reconcileCost()` for the authoritative `/generation` figure. Pure statics for framing,
   cost, context-building and redaction.
2. **`SGLlmVault`** (`_common/js/lib/sg-llm/sg-llm-vault.js`) — turns a vault into a
   configured `SGLlm` by reading `.vault/llm/config.json` and unsealing the owner tier.
3. **`<vault-llm-chat>`** — drawer panel in the vault shell: streaming transcript,
   Send/Stop, cost + call pills, a context chip for the file on screen, and explicit
   states when AI is unavailable.
4. **Wiring** — `vault-browse-edit.js` now dispatches `vault-file-viewing` on every file
   render and adds an **✨ Ask AI** button to the file action bar; `vault-shell.js` mounts
   the drawer, listens for both events, and calls `setVault` alongside `vault-settings`.

### Why this order changed

The plan had host-native chat as Phase 5. It is shipping first because the Vault UI is the
**real origin**: it needs no bridge, no postMessage streaming and no CSP work, so it exercises
the transport, key-resolution and policy paths end-to-end at a fraction of the risk. `sg.llm.*`
Phase 1 is now "expose this engine over postMessage + consent + CSP" rather than "build an
engine and a bridge at once".

### Deliberately not built

No tools, no vault writes, no autonomous loop. This is a reader, not an agent — tool-using
agents stay app-side (the SG/Vault Workbench is the reference implementation). Keeping the
kernel-adjacent surface non-agentic is what lets it be always-on with no consent prompt.

## Test impact

**SHOULD break (good failures) if reverted:**
- `test__sg_llm.js` (new, 40 assertions) — notably the two regression pins: SSE framing must
  return the unterminated tail (a lost final `usage` frame is how `cost:null` happens), and a
  mid-stream `data:{"error":…}` must surface rather than yield an empty reply. Also the
  estimate-vs-authoritative rule (`effectiveCost().estimated`).
- `test__vault_llm_chat.js` (new, 19 assertions) — jsdom mount smoke: connectedCallback must
  not throw, context chip rendering, HTML-escaping of the path, and that unavailability is
  *explained* (ENOKEY → points at Settings) rather than silent.

**Should NOT break (bad failures — investigate if they do):**
- All other loader tests (full suite green at commit time).
- Existing file rendering — the `vault-file-viewing` dispatch is wrapped in try/catch
  specifically so a context failure can never break `_renderFileContent`.
- App-mode bridge / kernel bundle — untouched (`app-permissions.js` not modified; no bridge
  change), so bundle freshness is unaffected.

## Notes

- **Cost display**: estimates render with a `~` prefix and are replaced in place when
  `/generation` returns the authoritative figure. Never show an estimate as a bill.
- **Context honesty**: capped at 24 000 chars, with the truncation stated *inside* the text the
  model receives, so it cannot silently summarise a partial file.
- **Availability is a state, not a missing button.** The ✨ Ask AI button always renders; the
  panel explains `ENOKEY` (no key configured → Settings) or `EREADONLY` (owner-sealed key in a
  read-only session). A vanishing control is worse UX than an explained one.
