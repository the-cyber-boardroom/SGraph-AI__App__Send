# Changelog — `sg.llm.*` P4: surfacing (A1–A4) + the six re-review defects (B1–B6)

**Date:** 2026-08-16 · **Implements:** the same-day brief
`team/comms/briefs/08/16/v0.33.47__brief__sg-llm-P4-surfacing-and-review-findings.md`
**Area:** `vault-llm-chat.js`, `app-hud.js`, `sg-llm-tools.js`, `en-gb/app/index.html`.
Kernel bundle regenerated.

## Surfacing (A)

- **A1/A3 — standing session cost pill** in the app HUD (`.hud-llm-cost`), driven by
  `VaultLlmLog.subscribe` so it updates on every ledger write *including* reconciliation
  (the `~` estimate upgrades to the billed figure in place). Shows `✨ ~$x.xxxx · N`,
  `…` while a call is in flight, hidden until first spend. Whole-session figure by design
  (one bill per session — 08/13 decision); enforcement stays per-app in the kernel.
- **A2 — the activity meter no longer filters out `llm.*`.** AI calls get their own lane
  (`A<count>`, violet) instead of the old `return` that made the most consequential bridge
  call the one invisible thing. Other non-file ops stay off the meter.
- **A4 — the ledger is reachable from App Mode:** clicking the pill dispatches
  `app-hud:llm-ledger`; the app page opens the `vault-llm-requests` pane via LlmPanels.

## Defects (B)

- **B1+B6 — one spend authority.** The host chat now gates and renders from
  `VaultLlmLog.totals(null)` (`_hostTotals()`); the instance counters remain only as a
  fallback for pages without the ledger. Session caps can no longer be reset by closing and
  reopening the pane, and the host figure excludes app spend (per-spender scoping intact).
- **B2 — images leave the history after their turn.** The stored history message is swapped
  to text (`question + [N images (names) — attached to this message when it was sent]`) in
  the send's `finally`, so base64 parts are never re-sent on later turns. The transcript
  keeps its thumbnails (DOM), and the chip note — "sent with your next message only" — is
  now true in billing terms.
- **B3 — the 🔧 bar can scope, not just enable.** Path-scoped groups get an allowed-paths
  input (comma-separated globs, saved with the grant, revert-on-failed-save like the
  checkbox), plus an inline "every call will be refused until a scope is set" warning when
  enabled without one. `SGLlmTools.isPathScoped(name)` exported so the UI doesn't duplicate
  the group list.
- **B4 — the context budget drops files instead of overshooting.** Beyond
  `floor(24000/1500)=16` text files, the extras are excluded, the model gets an explicit
  NOTE naming them (with instructions to say it cannot see them), and the chip row warns
  "N files won't fit — remove some".
- **B5 — the cap is re-checked inside `_chatOnce`**, so a multi-round tool turn stops at the
  threshold (+1 call at most, matching the bridge path's semantics) instead of running up to
  9 rounds past it, with an explained "budget reached mid-turn" stop.

## Test impact

**New:** `test__llm_p4.js` (32 assertions), wired into `run-all.sh` — one suite per item,
incl. "a fresh panel still sees the session spend and refuses" (B1) and "the next request
cannot re-bill the image" (B2).

**Intentional contract change in an existing test:** `test__vault_llm_chat.js`'s multimodal
suite captured the live request object and inspected it after the turn; since B2 mutates the
shared history message post-send, the fake client now **snapshots** the request
(`JSON.parse(JSON.stringify(req))`) — which is what the wire actually saw. No assertion
weakened.

**Should NOT break:** everything else — full loader suite green (0 failures), bundle
freshness passes after regeneration.
