# Changelog — voice transcription sent audio to a model that cannot hear

**Date:** 2026-08-03 · **Area:** Vault UI — `sg-voice.js`, `vault-llm-chat.js`
**Reported by:** Dinis — *"Voice failed: OpenRouter 404: No endpoints found that support input audio … I think for now we can hard-code the model to Gemini 3.5 Flash"*
**Follows:** `v0.33.48` (recording could not start at all — that fix is what let this one surface)

## What was broken

With recording fixed, every transcription failed:

```
Voice failed: OpenRouter 404: {"error":{"message":"No endpoints found that support input audio","code":404}}
```

The network payload shows why: `model: "anthropic/claude-3-haiku"` with an `input_audio`
content part. **A model that answers questions is not a model that hears them.**

## Root cause — two places both reached for the chat model

```js
var model = opts.model || session.model || null;          // sg-voice.js — the vault CHAT model
…transcribeWith(this._session, audio, { model: this._model });   // chat panel's own picker
```

The composer's model picker chooses the model that **answers**. Handing that same id to a
transcription call is a category error, and neither layer questioned it.

## The fix

Transcription now picks from audio-capable models only — `session.model` is no longer
consulted at all:

| | |
|---|---|
| Default | `google/gemini-3.5-flash` |
| Accepted | `google/gemini-3.5-flash`, `google/gemini-3.1-flash-lite`, `google/gemini-3-flash-preview`, `google/gemini-3.1-flash-lite-preview`, `openai/gpt-audio`, `openai/gpt-audio-mini`, `mistralai/voxtral-small-24b-2507` |
| Explicit non-audio `model` | Refused **here** with `EMODEL`, naming the model and suggesting one that works — OpenRouter's 404 names no model and leaves the user nothing to act on |
| Vault `models.allow` | Still applies on top. It is a security control, so our default does not bypass it; if it excludes the model the error says which setting to change |

The chat panel now passes no model for transcription. The **answer** still comes from the
picker's model — only the ear changed.

### Where the list came from

Mirrored from SG/Tools' curated list — `tools/…/en-gb/audio-transcribe/api/audio-models.js`,
whose ids were verified against OpenRouter's live catalogue on 2026-06-14 — rather than
imported: it must be usable before any dynamic `import()` resolves, and it is a policy list,
not a library. Their two dedicated-STT ids (`openai/whisper-large-v3`,
`openai/gpt-4o-transcribe`) are **excluded**: those go through `/audio/transcriptions`, which
we do not call.

## Known limit — deliberately not built

The model is a constant, not a vault setting. `.vault/llm/config.json` has `models.allow` and
`models.default`; an `models.audio` field would need `SGLlmConfig.parse`/`serialize` plus the
Settings → AI editor, and Dinis asked for the hard-code "for now". Follow-up if a vault ever
needs a different ear.

## Test impact

**SHOULD break (good failures) if reverted:**
- `test__sg_voice.js` (67 → **86**) — a new suite driving the real `transcribeWith`:
  `anthropic/claude-3-haiku` on the session is **not** what gets called; the audio default is;
  the `input_audio` part is actually attached; an explicit audio model is honoured; an explicit
  non-audio model is refused with `EMODEL` naming both it and a working alternative; and a
  vault allow-list that excludes the default still wins.

**Should NOT break (bad failures — investigate if they do):**
- Full vault unit suite green at commit time.
- Chat (non-voice) model selection is untouched — the picker still drives the answer.
- Budget, consent, permission and ledger behaviour unchanged.

## Unrelated, resolved in the same session: `[boot] assembling 2 parts` → `missing ) after argument list`

Not a repo bug — the boot loader lives in app code inside a vault. Dinis' console output
settled it: `new Function(a + b)` **succeeded**, and the split lands mid-identifier
(`part0` ends `…m.files.filter(func`, `part1` starts `tion(f){`). Raw concatenation restores
`function`; a `parts.join('\n')` produces `filter(func` ⏎ `tion(f){`, which is exactly what
"missing ) after argument list" reports. It reproduced in one vault only because only that
vault's split happened to land inside a token.

App-side fix: `parts.join('')`. Better: the >8 KB write ceiling that forced the split was fixed
at v0.33.47 (base64 chunk 8192 → 8190), so the app can be a single file again and drop the
boot loader entirely.
