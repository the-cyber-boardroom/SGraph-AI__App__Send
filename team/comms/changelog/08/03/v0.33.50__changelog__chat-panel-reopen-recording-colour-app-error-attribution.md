# Changelog — reopenable chat panel, recording in teal, app errors attributed to the app

**Date:** 2026-08-03 · **Area:** Vault UI — `vault-shell.js`, `vault-llm-chat.js`, `app-hud.js`, `app-shell.js`
**Source:** Dinis, after confirming voice works end to end ("those first 3 messages were recorded from audio")

Three unrelated items from one session.

---

## 1. BUG — closing the AI Chat panel killed the button that reopens it

Close the chat (either ✕) and `✨ AI Chat` did nothing, for the rest of the session.

**Cause, from sg-layout's source rather than from guessing.** `_closeTab` detaches before it
announces:

```js
if (tab.el && tab.el.parentNode === this) this.removeChild(tab.el);   // detach FIRST
…
this._events.emit(SGL_EVENTS.PANEL_CLOSED, { id: tab.id });          // announce AFTER
```

Our `panel:closed` handler therefore ran with the element already out of the document.
`_llmEl()` re-queried the DOM (`this.querySelector('vault-llm-chat')`), got `null`, and
`_parkLlmEl` silently no-opped — the element was orphaned with no path back. Every later
lookup returned `null`, so `_showLlmPanel` bailed before mounting anything.

**Fix:** `_llmEl()` holds a hard reference. A live element in the shell's own subtree still
wins, so a shell re-render that builds a fresh `<vault-llm-chat>` replaces the reference
rather than resurrecting a stale one.

The transcript and attached files survive the round trip — it is the same element going back
in, which is the whole reason panels are parked rather than rebuilt.

## 2. Recording is teal, not red

> *"can you make the colours of when the recording less red since that looks that something bad
> is happening, when what is going on is good"*

Correct diagnosis. Both surfaces already spend red on failure — `.vlc-msg--err`,
`.vlc-status--warn`, `.hud-msg--error`, `.hud-act-e`, `.hud-consent-deny` — so a red bar for a
working microphone was competing with the one meaning the palette already had.

| | Before | After |
|---|---|---|
| Chat status line | `#ff9b9b` | `#4ecdc4` (panel accent) |
| Chat mic button | solid `#ff6b6b`, white text | teal-tinted fill, teal border/text — *tinted, not solid*, because the Send button beside it is solid teal and two solid teal blocks stop reading as two things |
| HUD recording bar | red wash + red border | teal wash + teal border |
| HUD dot / Stop button | `#ff6b6b` | `#4ecdc4` |
| Pulse | 1.1 s → 0.25 opacity | 1.6 s → 0.35 opacity (slower, calmer) |

A live microphone still must not be missable — that is carried by the full-width bar, the
pulsing dot, the filled chip and the words *"Recording — your microphone is on"*. None of that
needed an alarm colour.

## 3. App errors now say they came from the app

> *"it would be great if we had a way to show in the console that that error is from the JS code
> inside the Vault App, and not from the Vault code itself"*

An uncaught error in a vault app surfaced on SG/App chrome as a bare
`Uncaught SyntaxError: Failed to execute 'appendChild' on 'Node': missing ) after argument list`
— indistinguishable from a fault in the vault. It cost a real debugging session pointed at the
wrong codebase (see below).

Now, on both sides of the boundary:

- **In the frame** — the injected bridge logs before it posts:
  `[vault-app] index.html — this error is from the APP's own JavaScript, not the vault platform: <message>`
- **On the host** — the report carries `appPath`; the handler logs the same `[vault-app]` line
  and the HUD toast reads `App code (index.html): <message>`.
- **Fallback** — a report without a path is attributed to whatever file the shell is currently
  running, so nothing is left unlabelled.

`unhandledrejection` goes through the same labelling.

### The debugging session this closes

The `[boot] assembling 2 parts (7953 chars)` → `missing ) after argument list` failure chased
across three rounds was **app code inside a vault**, not this repo. Dinis' console output
settled it: `new Function(a + b)` **succeeded**, and the split lands mid-identifier —
`part0` ends `…m.files.filter(func`, `part1` starts `tion(f){`. Raw concatenation restores
`function`; a `parts.join('\n')` yields `filter(func` ⏎ `tion(f){`, which is exactly what
"missing ) after argument list" reports. One vault only, because only that vault's split
happened to land inside a token.

App-side remedy: `parts.join('')` — or, better, drop the boot loader entirely, since the >8 KB
write ceiling that forced the split was fixed at v0.33.47.

## Test impact

**SHOULD break (good failures) if reverted:**
- `test__vault_shell_llm_panels.js` (**new**, 28) — drives the real `_showLlmPanel` /
  `_closeLlmPanel` / `_watchPanelClose` against a fake sg-layout that **reproduces the
  detach-then-emit order**. Verified to fail against the pre-fix `_llmEl`. Covers both ✕
  paths, five open/close cycles, focus-don't-remount, and chat/requests independence.
- `test__app_shell_bridge_build.js` (+16, now 35) — the `[vault-app]` prefix and `appPath` in
  the injected bridge, the host-side attribution and console line, the path-less fallback, and
  a `new Function` parse of the whole injected bridge (a typo in that `<script>` string
  otherwise fails only in a browser).

**Should NOT break (bad failures — investigate if they do):**
- Full vault unit suite green at commit time.
- Colour changes are CSS-only — no test asserts a hex value, by design.
- Panel drag/resize, parking across a `_mountBrowse` teardown, and the sidebar fallback are
  unchanged.
