## What changed (client transport only — no server change)

The server renamed `inbox` → `append` and deployed it (v0.32.7), but the shipped
vault transport client (`sg-inbox.js`) still posted to the dead `/api/vault/inbox/*`
URLs (→ 404) and sent the retired `folder:'inbox'` purge value (→ 400). This is the
**surgical correctness fix** that re-points the client at the live endpoints. It does
**not** rename the class, file/dir, host-event names, or the `inbox` body field — that
larger, app-contract-affecting rename is tracked separately (D-rename).

1. **URL base** `/api/vault/inbox` → `/api/vault/append` (`_post`).
2. **Write verb path** `/append/{vault_id}` → `/write/{vault_id}` (avoids `/append/append/`).
3. **Purge folder value** `'inbox'` → `'pending'` (validation + error message). `'processed'` unchanged.
4. Doc-comment endpoint table + two status comments updated for accuracy.

**Intentionally NOT changed** (per migration guide §3): the `inbox` body field / method
params (`list({inbox})`, `fetch({inbox})`, `purge({inbox})`) — the server retains this
field name; it identifies the token folder. Headers, gate model, batch caps, error
mapping: all unchanged.
