## What changed (client transport only — no server change)

The server renamed `inbox` → `append` and deployed it (v0.32.7), but the shipped
vault transport client (`sg-inbox.js`) still posted to the dead `/api/vault/inbox/*`
URLs (→ 404) and sent the retired `folder:'inbox'` purge value (→ 400). This change
lands in two parts: **(1)** the surgical transport correctness fix that re-points the
client at the live endpoints, and **(2)** the full identifier/terminology rename
across the vault UI (see "Full identifier rename" below). The `inbox` **body field**
and the `'sg-inbox-enum:'` crypto prefix are intentionally preserved.

1. **URL base** `/api/vault/inbox` → `/api/vault/append` (`_post`).
2. **Write verb path** `/append/{vault_id}` → `/write/{vault_id}` (avoids `/append/append/`).
3. **Purge folder value** `'inbox'` → `'pending'` (validation + error message). `'processed'` unchanged.
4. Doc-comment endpoint table + two status comments updated for accuracy.

**Intentionally NOT changed** (per migration guide §3): the `inbox` body field / method
params (`list({inbox})`, `fetch({inbox})`, `purge({inbox})`) — the server retains this
field name; it identifies the token folder. Headers, gate model, batch caps, error
mapping: all unchanged.

## Follow-up — DONE in this change (full identifier rename, approved by Dinis 2026-06-15)

The terminology rename was carried through end-to-end (clean break — no `app.json`
in the repo consumes the old contracts):

| Renamed | From → To |
|---|---|
| Transport global / class | `SGInbox` → `SGAppend` |
| Checker class | `SGInboxChecker` → `SGAppendChecker` |
| Lib dir + files | `sg-inbox/sg-inbox.js`, `sg-inbox-checker.js` → `sg-append/sg-append.js`, `sg-append-checker.js` |
| Outbound verb (client method + bridge) | `append()` → `write()` (matches `POST /write/`) |
| Bridge namespace | `sg.inbox.*` → `sg.append.*` |
| Bridge command type | `_sgCmd("inbox")` / `__sgCmdType==='inbox'` → `"append"` |
| Host events (app-facing) | `inbox.new-messages` / `inbox.error` → `append.new-messages` / `append.error` |
| Permission group + verb | `permissions.inbox.{…,append}` → `permissions.append.{…,write}` |
| Capability strings | `inbox.append`/`inbox.read`/… → `append.write`/`append.read`/… |
| Internal shell fields/methods | `_inbox`/`_inboxChecker`/`_getInbox`/`_scheduleInboxCheck`/… → `_append*`/`_getAppendClient`/`_scheduleAppendCheck`/… |
| Tests | `test__sg_inbox_*`, `test__app_permissions__inbox` → `…append…` (+ `run-all.sh`) |

**PRESERVED (wire/crypto/server contracts — deliberately NOT renamed):**
- `'sg-inbox-enum:'` enum_key derivation prefix (changing it breaks the server gate).
- The `inbox` **body field** in list/fetch/mark/purge requests and the `e.inbox`
  entry field (server retains this name; identifies the token folder — migration §3).
- Unrelated `"root inbox"` deep-link comments in `app-shell.js`.
