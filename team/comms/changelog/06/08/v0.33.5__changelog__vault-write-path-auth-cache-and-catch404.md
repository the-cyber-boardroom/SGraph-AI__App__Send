## What changed (backend only — no API contract change)

Two behaviour-preserving S3/auth reductions on the vault write/read path, motivated by a comms-agent message send fanning out into ~20 requests and a comparable number of S3 calls + Admin-Lambda round-trips.

1. **Access-token validation cache (lever #1 / "V-8").** New `Service__Access_Token` centralises the access-token check (previously copy-pasted in `Routes__Vault__Pointer` and `Routes__Vault__Inbox`) and adds a Lambda-lifetime TTL cache (default 60s, env `SGRAPH_SEND__TOKEN_CACHE_TTL`) in front of `admin_service_client.token_lookup`. Positive validations are cached; negatives never are. Warm repeated writes/batches now skip the per-request Admin-Lambda round-trip.

2. **Catch-404 reads (lever #2 / V-1 + V-2).** `Storage_FS__S3.file__bytes`/`file__str` now do a single `GetObject` and catch the missing-key `ClientError` (return `None`) instead of pre-`HeadObject`-ing. `file__json` inherits it. Redundant `file__exists` prechecks removed from `Service__Vault__Pointer.read`/`_batch_read`/`_cas_write`/`write_if_match`. Every read/batch-read drops ~1 HeadObject.

**Not in scope (deliberately):**
- `file__delete` is unchanged — S3 `delete_object` is idempotent (never raises on a missing key), so its existence check carries a real not-found semantic, not a redundant Head.
- Client-side commit batching (lever #3) is a vault-team change in the `sg-vault` browser library; the backend `batch` endpoint already supports it.

## Test impact

**SHOULD pass unchanged (good — semantics identical):**
- All existing token-auth tests: `401` on bad/missing token, `200` on valid (`test_Routes__Transfers__with_tokens.py`, vault route token tests).
- All read/write/delete behaviour tests, incl. `test__read__not_found`, `_batch_read` not-found, CAS conflict (`test_Service__Vault__Pointer.py`).

**NEW tests:**
- `test_Service__Access_Token.py` (6) — positive cached, negative not cached, missing→401, cache-hit skips lookup, expired→revalidate, env-var fallback.
- `test_Storage_FS__S3.py` (+2) — `_is_not_found` classifies `NoSuchKey`/`NoSuchBucket` as miss but propagates `AccessDenied`; regression guard that reads no longer pre-`file__exists`.

**Would be a BAD failure (investigate, do not just update):**
- Any read returning the wrong bytes, or a real S3 error (`AccessDenied`/throttle) being silently swallowed as `None` — `_is_not_found` must only match absent-key codes.
- A revoked token still accepted **after** TTL expiry.

**Would be a GOOD failure (expected — update the test):**
- Any test asserting `token_lookup` runs on *every* request, or asserting a specific HeadObject call count on reads — those counts are what this change removes.
