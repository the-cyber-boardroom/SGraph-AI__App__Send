## What changed (UI/API surface)

A vault app (`/en-gb/app/`) can now create and manage other vaults, gated by `app.json`:

- `sg.vault.create(opts)` — **signature changed** from `create(path, label)` to `create({ label, link, returnKey, custody, seedFrom })`. Returns `{ vault_id, ref_id, key? }`; `key` is the **composed openable** `passphrase:vault_id` (only when `returnKey:true` + the stronger grant).
- New verbs: `sg.vault.getKey(ref)`, `sg.vault.openApp(ref, opts)`, `sg.vault.list()`.
- `sg.vault.delete(ref)` — **enabled** (was `ENOTIMPL`); key custody solved, server teardown pending `SGVault.destroy()` (reports `server_teardown:false`).
- New `app.json` grants: `vault.createKey` (path), `vault.standalone` (bool), `vault.seedFrom` (path), `vault.openApp` (bool). Default-deny; `createKey` is strictly stronger than `create`.
- New owner-tier credential store: child write-keys sealed under a `write_key`-derived key at `.vault/owner/secrets/` (RO sessions cannot decrypt).
- Key-returning create / `getKey` **always re-confirm** on the HUD (no silent consent cache).

**SHOULD break (good) — migration required:**
- Any in-tree consumer of the **old** `sg.vault.create(path, label)` positional signature must migrate to `create({ link:{path}, label })`. (Intentional breaking change — no backward-compat shim, per direction.)

**Should NOT break (bad if it does):**
- The other `sg.vault.*` verbs (`unlink`, `mount`, `unmount`, `mounts`) — untouched.
- The `vault.create` read-through path with a `create` grant — preserved (omit `returnKey`).
