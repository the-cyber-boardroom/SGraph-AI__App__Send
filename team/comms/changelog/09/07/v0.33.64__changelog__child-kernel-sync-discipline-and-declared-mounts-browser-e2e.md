# Changelog — child-kernel sync discipline + declared-mounts browser e2e (2026-09-07)

**Scope:** vault UI (`sgraph_ai_app_send__ui__vault/v0/v0.2/v0.2.3`), tests, guides.
**Follows:** `v0.33.64__changelog__declared-mounts-transparent-cross-vault-io.md` (same day).
**Brief answered:** "how are pulls and merges handled for child vaults (workflow + UI)?" → implement
"reconcile before write" + a full browser end-to-end with screenshots and a how-to guide.

## Summary

A headless child kernel (a declared mount) has nobody watching a "behind" chip, so it now keeps
itself honest against the server on every op: **reconcile-before-write**, **compare-and-swap
push** (`write-if-match`, the server op that already existed) with merge-and-retry,
**throttled refresh-before-read**, and two new verbs **`vfs.status` / `vfs.sync`** that the parent
(`KernelParent.status/sync/syncAll`) and the HUD Mounts tab consume. Runtime `sg.vault.mount`
behaviour and the shells' `push()` are unchanged (synthetic vaults keep the plain-push path).

Building the first real-browser test of a declared mount (real API server, real vaults, real
null-origin app + child kernel iframes) found **six shipped defects** in the child-kernel path that
the synthetic harnesses could not see — all fixed here (see "Fixes").

## Changes

### Sync (new behaviour)
- `lib/sg-vault/sg-vault-ref-manager.js` — `readRef` caches the exact ciphertext per ref id
  (`lastRawRef`); new `writeRefIfMatch(refFileId, commitId)` → `POST /batch` `write-if-match`;
  throws `ECAS` (cache updated to the server's current bytes) or `ENOMATCH` (never read).
- `lib/sg-send/sg-send.js` — `SGSend._b64ToBytes` (inverse of `_abToB64`).
- `lib/sg-vault/sg-vault--sync.js` — `pushIfMatch()`; `merge(their, { publish: false })` lets the
  caller publish with CAS instead of the blind post-merge `push()`.
- `components/app-shell/kernel-app-handlers.js` — `_reconcile`, `_maybeRefresh`
  (`registerKernelVfsHandlers.REFRESH_MS`, default 5000), `_casPush`/`_safePush` (ECAS → reconcile
  → retry → `EDIVERGED`), `_status`; handlers `vfs.status`, `vfs.sync`; `onUpdated('/')` after a
  refresh/sync replaced the tree. Only vaults with a ref manager take part (`_syncable`).
- `components/app-shell/kernel-parent.js` — `status(mountId)`, `sync(mountId)`, `syncAll()`;
  `list()` rows carry `sync`.
- `components/app-shell/viv-mounts-view.js`, `app-debug-mounts.js` — sync column (`syncTag`).
- `components/app-shell/app-shell.js` — `_checkBehind` (tab focus) calls `syncAll()`; declared
  mounts set the broker policy to `auto` for the fs verbs (owner declared it; the app grant, the
  app-level consent flow and the child's policy still gate).

### Fixes (found by the browser e2e)
- `app-shell._spawnChildChannel` — wait for the srcdoc iframe's `load` before bootstrapping the
  channel (the init port was posted to the initial about:blank window and lost → relay `pending`
  forever); bounded by 10 s. `SecureChannel.create(…, { timeoutMs })` — handshake timeout →
  `EUNREACH`, port closed.
- `kernel-bootstrap.js` — resolve `SGSend` / `SGVault` / `VaultDataSource` as global **lexical**
  bindings when `globalThis.*` is absent ("SGSend is not a constructor" in the real shell);
  read the child's app.json through the **data source** (a real `SGVault` has no `getFileBytes`
  → policy was null → every write `EPERM`); `loadAllSubTrees()` at boot; `secrets` failures are
  logged and sent to the parent as `boot-error` (parent fails fast with the real cause instead of
  a 10 s timeout).
- `kernel-app-handlers.js` — `vfs.list` works on a real `VaultDataSource` (`getFileList` fallback,
  `.vault/**` filtered); the child's `.vault-settings.json` is hidden from listings and refused
  (`EPROTECTED`) through a mount.
- `adapters/vault-data-source.js` — `saveFile` / `renameFile` / `deleteFile` load a lazy target
  folder first (writing into an unloaded folder committed a tree holding only the new file).
- `kernel-shell-bundle.js` regenerated (`scripts/build-kernel-shell-bundle.py`).

## Risks / notes
- The CAS relies on the server's `write-if-match` comparing raw bytes; refs are AES-GCM with a
  fresh IV, hence the ciphertext cache. A ref the manager never read cannot be CAS-written
  (`ENOMATCH`) — `_safePush` reads it first.
- Refresh-before-read is throttled (5 s) and never fails a read; writes always reconcile.
- Declared mounts' broker policy is `auto`; runtime `sg.vault.mount` keeps the default `ask`.
