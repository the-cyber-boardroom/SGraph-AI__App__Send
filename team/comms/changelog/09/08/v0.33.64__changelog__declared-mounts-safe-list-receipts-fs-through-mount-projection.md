# Changelog — declared mounts safe list: write receipts, `fs.*` through the mount, app projection, relay timeout (2026-09-08)

**Scope:** vault UI (`sgraph_ai_app_send__ui__vault/v0/v0.2/v0.2.3`), tests, guides.
**Decision record:** `team/roles/appsec/reviews/09/08/v0.33.64__appsec-decision__declared-mounts-findings-safe-changes-and-security-refusals.md` (items S1–S7, S10 shipped; S8 documented; S9, D1, D2 not shipped — see "Not in this change").
**Debrief to the reporting agent:** `team/comms/briefs/09/08/v0.33.64__debrief-for-agent__declared-mounts-safe-list-shipped-and-how-to-verify.md`.

## Changes

### Kernel (child side) — `components/app-shell/kernel-app-handlers.js`
- `_receipt(vault, extra)`: every mutation returns `{ ok, commit_id, published, … }`. `published` is true only when a push actually ran and returned (CAS for real vaults); `commit_id` is the kernel head at that instant. Applied to `vfs.write` (`size, path`), `vfs.delete` (`path`), `vfs.mkdir` (`path`, now also fires `onUpdated`).
- New `vfs.move` handler: both gates on `path` and `to`, `EREADONLY`, reconcile-before-write, rename in place or `moveFile` + rename across folders, CAS push, receipt `{ from, to }`. `ENOSYS` when the data source lacks `renameFile`/`moveFile` (synthetic harnesses) — never a silent drop.

### Channel / parent — `secure-channel.js`, `kernel-parent.js`
- `SecureChannel.request(type, payload, { timeoutMs })`: bounded wait; on timeout the pending entry is removed and `EUNREACH` thrown. Default unchanged (no timeout) for existing callers.
- `KernelParent`: `relayTimeoutMs` (default 30 s) applied to every relay; `relay()` forwards `to` for move; **`listForApps()`** projection `{ prefix, access, declared, state: idle|unknown|clean|ahead|behind|diverged, at }`.

### Bridge — `components/app-shell/app-shell.js`
- Write stub keeps `commit_id` / `published` (one shape for local + mounted; no `mounted` flag exposed). Mounted branch forwards the child's receipt; local branch returns the clone-branch commit id with `published:false`.
- `_autoPushNow` → host event **`vfs.published`** `{ commit_id, count }` (gated by `app.json.host_events` like every host event).
- `fs` block is mount-aware, in the same order as `vfs.write` (floor → mount → grant): `mkdir` relayed; `move` relayed when `from` and `to` resolve to the **same** mount, `EXDEV` otherwise; `delete` on a mounted path → `EUNDERPRIVILEGED` with an explanatory message (tier model; was the composite's `EMOUNT_RO`). Local `fs.*` unchanged, now sends `EREADONLY` as a code.
- `sg.vault.mounts()` → `_listMountsForApps()` (projection). HUD provider keeps the raw `list()`.
- `_mountDeclaredVaults`: pre-flight event `declared-mount-shadows-folder` when the prefix is a real folder.
- `_spawnChildChannel` sends `parentVaultId`.

### Kernel boot — `kernel-bootstrap.js`
- Trailer `Via-Mount: <label> (declared|runtime) parent=<id>`; `parentVaultId` sanitised to `[a-z0-9]{≤24}`.
- `kernel-shell-bundle.js` regenerated.

## Test impact
**SHOULD break if reverted:** the new assertions above; `test__bundle_freshness.js` (bundle regenerated).
**Should NOT break:** `test__kernel_app_handlers.js` (synthetic vault → `published:false`, extra receipt keys are additive); `test__kernel_relay.js`, `test__kernel_parent.js`, `test__kernel_declared_mounts.js` (`list()` untouched); `test__app_shell_bridge_build.js` (stub still returns `path`/`size`); `test__viv_browser_e2e.spec.js` (passes); all `sg.vault.mount` runtime behaviour.

## Not in this change (and why)
- **`sg.fs.delete` across a mount** — needs per-request elevation (tier model; N2). Interim: `EUNDERPRIVILEGED`.
- **`sg.history` across a mount** — never existed (parent-only); a new verb + policy (D2).
- **Enum-key auto-derivation** — already what the bridge does; documented. **Public-read guard** — no platform flag to key on; documented rule.
- **Validate-before-fetch on append verbs (S9)** — append-lanes owner.
- **404-for-unknown on the append gate** — refused (existence oracle, N1).

## Risks
- Receipt `published:true` is a witness of the CAS publish, not of durability against other writers' blind pushes — stated in every doc that shows it.
- `fs.delete` behaviour on mounted paths changes from `EMOUNT_RO` to `EUNDERPRIVILEGED` — callers matching on the old code must update; the message explains.
