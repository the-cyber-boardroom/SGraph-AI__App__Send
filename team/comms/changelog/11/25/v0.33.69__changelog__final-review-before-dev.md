## Why a second review

The branch sat unmerged for a month while sgit-ai moved from 0.21.0 to 0.27.0, and the earlier work had been verified with the unit suites, Playwright e2e and the CLI round trip, not with every job a push to `dev` runs. This pass ran the whole CI matrix locally and checked the CLI's six new releases for byte-level changes.

## Found and fixed

| # | Finding | Severity | Fix |
|---|---|---|---|
| 1 | Server `batch_read` fanned out to 16 threads with the S3 client still unbuilt; the boto3 client is created lazily behind an unlocked cache, and boto3 client creation is not thread-safe, so the first batch on a cold Lambda could fail sporadically | high (dev Lambda) | the first object is read on the request thread, which builds the client, then the rest fan out; test `test__batch_read__first_read_on_calling_thread` |
| 2 | sgit 0.24+ pack-mode vaults (`packs`, `blob-deflate`) have no loose objects and a deflate blob envelope; the web opened them and would have failed oddly, or written loose objects pack clients never read | medium | `SGVaultBranchIndex.checkFormat` refuses them by name with the way out (`sgit pack export`), as the CLI's pack spec asks of the web |
| 3 | Web commit messages (they carry file names) could exceed 740 bytes, which sgit before 0.26.4 cannot read | low | `SGVaultCommit.capMessage` cuts at 740 UTF-8 bytes on a code-point boundary with an ellipsis |
| 4 | Two tabs opening a vault for the first time both generated a signing key; the last IndexedDB `put` won and the other tab's clone ref was never reopened | low | insert-if-absent (`add`) and adopt the winner; proven with two real Chromium tabs |
| 5 | `batchLoad` looked up the block cache one object at a time before every batch request (Cache API is async per object in a browser) | low (perf) | lookups in parallel |
| 6 | The live child-kernel sync test still asserted the pre-parity CAS contract (a freshly created vault's `pushIfMatch` → `ENOMATCH`); since the parity work a ref the session wrote is a valid CAS baseline | test only | test updated to the new contract; `ENOMATCH` still asserted for a ref neither read nor written |

## Checked and fine

- **sgit 0.27.0 `user_signature`** (Git-style SSH/OpenPGP signature on commits): outside both signing forms in the CLI, so the web's verification is unaffected. Full round trip against sgit 0.27.0 passes (every web commit `verified`, fsck OK, gate / tags / CLI entries preserved).
- **0.24.0 TM-F36** (the CLI refuses every index write when the server's index holds an entry it cannot parse): every field the web writes is a `Schema__Branch_Meta` / `Schema__Branch_Index` field; the clone entry's `name` is `web-ui`.
- **0.26.4 `long-messages`**, **`pack-indexes`**: vaults with them open normally.

## Known limits, not fixed here

- `content_type_enc` follows CPython's built-in `mimetypes` table; a CLI on another Python version, or one that reads `/etc/mime.types`, can guess a different type for rare extensions. Effect: the same folder gets a different tree id in the two clients (lost dedupe), never a wrong read.
- The web reads `min_client` but does not compare it (it names sgit versions). A future CLI feature that changes object formats would need the same by-name refusal added here.
- Clearing site data loses the device's signing key and therefore its clone ref; unpushed commits on that ref stay on the server but are no longer opened. Both shells push automatically, so the window is short.

An independent review then found real bugs, fixed here before the next push. ## Why CI failed on `da276b6` (environment, not this branch)

GitHub's `ubuntu-latest` moved to Ubuntu 26.04:
- the pytest action uses the system Python, now **3.14**; 140 admin-Lambda tests fail under it (`Type_Safe` with 3.14's deferred annotations). Reproduced locally: the same tests fail 12/17 on 3.14 and pass 17/17 on 3.12;
- the locked Playwright cannot install Chromium there ("Playwright does not support chromium on ubuntu26.04-x64").

Fix in a separate commit: those three jobs pinned to `ubuntu-24.04` (system Python 3.12). The Lambda deploy action already pins Python 3.12 itself. Unpin when the project moves to 3.14 and upgrades Playwright.
