# Changelog — click-interceptor fixes (proposals 1–3) + `sg.vfs.download`

**Date:** 2026-07-31 · **Area:** App Mode (`/en-gb/app/`) — `app-shell.js`, `app-hud.js`,
`app-permissions.js` (kernel bundle regenerated)
**Driven by:** architect review `team/roles/architect/reviews/07/30/v0.33.43__review__in-app-nav-click-interceptor-proposals.md`
and the 31 Jul issue report "user-initiated file downloads from inside a vault app"
(vault `eu-ai-act-canonical`).

## What changed

1. **Interceptor opt-out** — the injected click interceptor now returns early on
   `e.defaultPrevented` or `data-sg-native` anchors (before every branch, external included).
2. **Bare-`#` anchors claimed** — `<a href="#id">` is `preventDefault`-ed and scrolled
   in-frame; miss = no-op; no `stopPropagation`. (Browser default in a null-origin srcdoc
   frame was a cross-document navigation to the vault-key screen.)
3. **`location.hash` miss-fallback removed** from the `__sgVfsScrollToHash` listener (was a
   live re-navigation bug for `page.html#id` links whose target renders async).
4. **`sg.vfs.download(path, {filename?})`** — new host-fulfilled download verb. Guarded like
   `vfs.read` (floor → mounts → `fs.read` grant); save happens in the host document (no
   `allow-downloads` sandbox token needed); one-click HUD confirm per file
   (`app-hud.promptDownload`) unless `app.json` `permissions.downloads: true` (new
   default-deny grant); dismiss rejects `'Download not approved'`.

## Test impact

**SHOULD break (good failures) if reverted:**
- `tests/unit/vault_ui/loader/test__app_shell_bridge_build.js` — new pins: opt-out guard
  present; bare-# claim present; `location.hash="#"` fallback ABSENT; `download:_download`
  exposed; `permissions.downloads` parse (true / default-deny / non-boolean).
- `tests/unit/vault_ui/loader/test__bundle_freshness.js` — fails if `app-permissions.js`
  changes without regenerating `kernel-shell-bundle.js` (bundle regenerated in this change).

**Should NOT break (bad failures — investigate if they do):**
- All existing loader tests (`run-all.sh` green at time of commit — 49 files).
- Browser suite `tests/integration/vault_ui/browser/` — `test__app_mode_deep_link` exercises
  `page.html#fragment` navigation, which still works (fragment forwarded + scrolled; only the
  miss-fallback is gone). `test__embed_handshake`, `test__sgit_round_trip` untouched paths.
- Apps relying on bare-# clicks reaching their own **bubble-phase** listeners: the event
  still propagates (no `stopPropagation`), but its default is now prevented by the host. Any
  app that *wanted* the (broken) browser default was already broken.

## App-facing surface

- New: `sg.vfs.download`, `app.json` `permissions.downloads`, `data-sg-native`,
  `defaultPrevented` honoured, bare-# in-frame scroll.
- Removed: `location.hash` fallback after nav (behavioural fix; no API removed).
- Docs: AUTHORING.md ("Downloading files", same-vault-navigation rewrite),
  create-vault-apps SKILL.md (downloads + anchors rows), reality/ui (new dated section).
