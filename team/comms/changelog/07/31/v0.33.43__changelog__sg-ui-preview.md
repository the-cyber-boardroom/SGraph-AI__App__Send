# Changelog — `sg.ui.preview(path)`: host-rendered quick-look overlay

**Date:** 2026-07-31 (follow-on to the interceptor/download batch) · **Area:** App Mode —
`app-shell.js` only (not in kernel bundle; no regen needed)
**Driven by:** the PDF-in-app finding (blob-iframe PDFs are blocked by Chromium inside the
app sandbox — verified empirically) and Dinis's call that the existing read-permission chain
is the only gate preview needs.

## What changed

- New bridge verb **`sg.ui.preview(path)`** → `{ok, path, type, bytes}`. Host reads the
  bytes through the exact `vfs.read` guard chain (floor → mounts → `fs.read` grant) and
  mounts a modal quick-look overlay in the **host document** (real origin — Chrome's native
  PDF viewer works there; it is blocked in the sandboxed frame).
- **No grant, no confirm** — design decision: consent gates effects that outlive the page
  (writes, downloads, popups, vault lifecycle), not ephemeral display of content the app can
  already read. Sovereignty holds passively: the overlay is host DOM (app can't fake or
  suppress it), user closes via ✕ / Escape / backdrop.
- Kinds: `pdf` (blob iframe), `image`, `video`, `audio`, `text` (`<pre>`), `binary`
  (points at `sg.vfs.download`). One overlay at a time; blob URL revoked on close.
- Errors mirror `vfs.read`: `ENOENT` / `EPERM` / `EPROTECTED`.

## Test impact

**SHOULD break (good failures) if reverted:** `test__app_shell_bridge_build.js` — new suite
"sg.ui.preview" (7 assertions: bridge exposure + jsdom overlay behaviour: text renders,
pdf→iframe, one-at-a-time, close removes).

**Should NOT break:** everything else — additive verb on the existing `ui` cmd handler; no
sandbox, permission-parse, or bundle changes (`app-permissions.js` untouched; bundle
freshness unaffected). Full loader suite green at commit time.

## App-facing surface

- New: `sg.ui.preview(path)`. Docs: AUTHORING.md "Displaying PDFs inline" (now option 0) +
  `sg.ui` API block; create-vault-apps SKILL row; reality/ui section extended.
