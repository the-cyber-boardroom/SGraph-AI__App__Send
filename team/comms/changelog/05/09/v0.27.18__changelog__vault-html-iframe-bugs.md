## Summary

Four user-visible bugs in the vault HTML viewer and the split-view HTML editor.
All four are addressed in this commit; the underlying architectural change is
that the **edit-mode preview now reuses the same iframe element that the main
viewer renders into** — there is exactly one `.sb-file__html-frame` per file
view, regardless of whether the user is in view mode or edit mode.

---

## Bugs Fixed

| ID | Severity | Fix | Files |
|---|---|---|---|
| Bug 1 | P1 | Inlined `<script src>` / `<link href>` rewritten to **`data:` URIs (base64)** instead of inlined into the HTML body. Eliminates the entire class of `</script>` / `</style>` HTML-parser early-termination bugs (the bytes now live in an attribute value, never in the body). | `send-browse--v0.3.2.js` |
| Bug 2 | P1 | Edit-mode preview iframe was a second, independently-built iframe and would render blank or differently from the main viewer. Refactored: edit mode now keeps the existing `.sb-file__html-frame` in place, prepends a textarea pane as its left sibling, and live-reloads it on input — so preview is bit-identical to the main render. | `vault-browse-edit.js` |
| Bug 3 | P1 | Iframe document body was transparent for unstyled HTML, letting the dark vault chrome bleed through and rendering black text on dark blue. Set `background:#fff; color-scheme:light` on `.sb-file__html-frame` and remove the now-unused `pvFrame` (which had the same gap). | `send-browse--v0.3.2.js`, `vault-browse-edit.js` |
| Bug 4 | P2 | Duplicate `App Mode` button in the action bar for writable vaults — one universal copy was added near the top of `_renderFileContent`, then re-added in the writable-only block at the bottom. Dropped the second copy. | `vault-browse-edit.js` |
| Bug 5 | P2 | App-Mode auto re-lift on HTML file switch never fired: the `_ext0 === 'html'` check ran *before* `_ext0` was declared (hoisted-undefined `var`). Moved the `_ext0` declaration to the top of the patched function so the re-lift check sees the real extension. | `vault-browse-edit.js` |

## Test Impact

### Tests that SHOULD continue to pass (no behaviour change for them)

- All non-HTML file viewers (markdown, image, PDF, code, csv, eml, json) — untouched.
- Read-only vault HTML viewing — App Mode + Full Screen + Locate + Save still present.
- HTML files with no relative `<script src>` / `<link href>` — inlining is a no-op.

### Tests that SHOULD now pass (previously broken)

- Multi-file HTML apps in writable vaults whose JS source contains `</script>` (e.g. comments mentioning the close tag, template literals containing it) now render fully. Before: the `<script>` block terminated early and the rest of the file leaked as visible page text.
- Edit-mode preview for HTML files in writable vaults now shows the rendered output identical to the main viewer. Before: blank, or visibly different.
- Unstyled HTML files (no `<body>` background) render on a white iframe background instead of showing the dark vault chrome through.

### Tests that SHOULD break and are EXPECTED breaks

- Any test that asserts on a *second* iframe being created in edit mode — the second iframe no longer exists.
- Any test that counts "App Mode" buttons in a writable HTML file action bar and expects 2 — the count is now 1.

### Tests that should NOT break (would be a regression)

- Cancel handler still discards in-flight edits and reloads the iframe with original bytes.
- Save handler still re-renders the file from the persisted bytes.
- App Mode lift behaviour for HTML files (frame-lift via `position:fixed` wrapper).
- The VFS bridge (parent ↔ iframe `postMessage`) is unchanged for runtime `fetch()` and `<img src=>` interception.

## Notes for QA

- The `data:` URI rewrite means the blob HTML is slightly larger (base64 inflates by 33%); for a typical app of 5×JS files at 10–50 KB each this is negligible (~10–20 KB extra).
- Sandbox is unchanged: iframe still has `sandbox="allow-scripts"` only — no `allow-same-origin`.
- The `</script` / `</style` JS-string escapes were removed because they're no longer needed (data URIs sidestep the parser interaction). If a future change re-introduces body inlining, those escapes will need to come back.
- The `_pvBridges` / `pvFrame` symbols are gone from `vault-browse-edit.js`. The edit preview now shares the main viewer's `self._vfsBridges` / `self._objectUrls` arrays via a small `_cleanupBridges` helper invoked before each preview reload.

## Open / Deferred

- **Color/sizing differences** between the main HTML viewer and the App-Mode lifted view (different flex constraints) — *not addressed*; this fix only equalises view-mode and edit-mode-preview because they now share one iframe.
- **CSS `url(...)` in inlined stylesheets** still resolves against the blob origin and fails silently. Listed as a known gap in the technical brief §8.
- **`<audio> / <video> / <source>` native loading** still bypasses the VFS bridge. Listed as known gap.
- **`Full Screen` button possibly duplicated** in some screenshots — only one source in code (`vault-browse-edit.js:354`); if duplication recurs after this commit, look for `_renderFileContent` being invoked twice on the same container.
