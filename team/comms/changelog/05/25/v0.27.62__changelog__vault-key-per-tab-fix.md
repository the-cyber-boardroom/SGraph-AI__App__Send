# Changelog — Fix: vault key is per-tab (access token stays shared)

**Version:** v0.27.62
**Date:** 2026-05-25
**Author:** Dev (Claude Code session, branch `claude/exciting-brown-G2P9Z`)
**Trigger:** Dinis — *"persist vault key in localStorage across tabs" is a bug; we want the
  ACCESS TOKEN persisted across tabs, not the vault key.*

---

## Summary

A recent dev change persisted the **vault key** (`sg-vault-key`) in `localStorage`, sharing it
across all tabs. That breaks multi-window use: opening a second vault in a new tab changed the
first tab's vault on reload. This fixes the storage tiers so they match intent:

- **Vault key → per-tab.** `sessionStorage` is each tab's source of truth; `localStorage` keeps
  only the **last-opened** key as a convenience fallback for a brand-new tab. So: reload tab A → A,
  reload tab B → B, close a tab = no-op for the others, and a fresh tab still restores the most
  recent vault.
- **Access token → shared across tabs (unchanged, intended).** It already persists via its
  `localStorage` `sg-vault-access-key-saved` copy — that is correct (it's the server write gate,
  not the encryption key), and is left as-is.

This completes proposal **P-174** (per-tab vault identity) and unblocks "Open in new window" for
sub-vaults.

## Note

The dev-side surfaces that still read `sg-vault-key` from `localStorage` directly are
**inspector/debug tools** (peek page, token/sgit harnesses) — they intentionally read the durable
last-opened copy and were left unchanged. All **runtime** read/write paths are now per-tab.
