## Summary

- **`<sg-link-card>`** (NEW) — a self-contained modal shown when a locked sub-vault is opened.
  Surfaces the child's **public info before asking for a key** (via the shipped
  `PublicPreviewRead.fetchPreview` when the link carries a `public_id`), then takes the key with a
  save choice (*this device* / *ask each time*), a `👁 Read-only` badge, and three actions:
  **Open here (read-only)**, **Open in new window ↗**, **Cancel**. Self-contained (inline shadow
  styles), like `sg-public-preview-card`.
- **`vault-shell`** — the composite `keyProvider` now shows `<sg-link-card>` instead of a bare
  `window.prompt` (prompt kept as a fallback when the component isn't loaded). On "Open in new
  window" it `window.open('/#'+key)`; on "Save on this device" it stores via
  `VaultLinks.setStoredChildKey`.
- **`index.html`** — `<script>` include for `sg-link-card.js` (after `public-preview-read.js`).
- **User guide** (NEW): `library/guides/content/v0.27.62__guide__vault-in-vaults.md` — how to author
  a `*.link.json`, how sub-vaults open read-only inline, where the key lives, public-info-before-key,
  and an honest limitations table (status-flagged in-development).
