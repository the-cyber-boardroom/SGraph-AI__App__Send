## Summary

First slice of the inline sub-vaults feature. Two pieces, both additive and backward-compatible:

1. **`vault-links.js`** (NEW) — the `*.link.json` convention reader: suffix recognition,
   minimal-link-file parse (returns `null`, never throws, on malformed / missing `ref_id`),
   mount path/label, and a localStorage child-key store ("save on this device"). No DOM, no secrets.
2. **`send-browse--v0.3.2.js`** (user v0.3.3 — the vault-authoritative copy) gains a **generic,
   backward-compatible lazy-on-expand hook**: a tree node carrying `_lazy === true` + `_folderPath`
   renders empty and, on first expand, calls `await this.dataSource.loadFolder(_folderPath)` then
   `_populateTree()` to re-render. `_subvault === true` (+ `_access`) renders a `🗄` glyph + `·ro` chip.

This does NOT yet wire up the end-to-end sub-vault open (the `CompositeDataSource` + `vault-shell`
integration is the next Phase 0 step). On its own it adds a reusable convention reader and a
lazy-expand capability to the shared tree component.

## Test impact

- **SHOULD pass / unaffected (no regression expected):**
  - All existing vault-UI loader unit tests + the pvp crypto KAT — **verified: pvp KAT 9/9, vault-links 26/26**.
  - Share/Open UIs that use `send-browse`: their data sources never set `_lazy`/`_subvault`, so the
    new branches are inert and the rendered tree is byte-identical for them. (Only the v0.3.3 copy was
    patched; user v0.3.2 and open v0.4.0 copies are unchanged and should get the same patch when those
    products need sub-vaults.)
- **Verification gaps (cannot run here):**
  - **No browser/Playwright run** — the send-browse lazy-expand path and the `🗄`/chip rendering are
    syntax-checked and logic-reviewed, not exercised in a real browser. Needs a browser pass.
  - `_populateTree()` re-renders the whole tree on lazy expand, collapsing other open folders — a known
    Phase-0 limitation; Phase 2 should preserve/restore expansion.

## Notes

- Approach (B) chosen by Dinis ("now is the time to make these changes"). The enhancement is generic
  (any `_lazy` node), not sub-vault-specific, so it can serve other lazy-tree needs too.
- No secrets in `*.link.json` by design; child keys (Phase 0) live only in localStorage or a prompt.
