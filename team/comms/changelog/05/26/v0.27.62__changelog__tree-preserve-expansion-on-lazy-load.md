# Changelog — Tree: keep parent folders open when a sub-vault lazy-loads

**Version:** v0.27.62
**Date:** 2026-05-26
**Author:** Dev (Claude Code session, branch `claude/exciting-brown-G2P9Z`)
**Trigger:** Dinis — second test drive. Expanding a sub-vault collapsed its parent folder.

---

## Summary

Observed flow: expand `subvaults` → its children show; expand a child sub-vault (`patient-alex`)
→ a brief "loaded" flash, then the tree appears to **collapse back** to just `subvaults` (closed);
expanding `subvaults` again reveals `patient-alex` already open.

**Root cause.** Expanding a lazy sub-vault calls `_populateTree()`, which **rebuilds the whole tree
from scratch** (`treeEl.innerHTML = ''`) with every folder defaulting to collapsed. The handler then
auto-expanded only the just-loaded node (`patient-alex`) — but left its **ancestor `subvaults`
folder collapsed**. So the child was open yet hidden inside a closed parent, which read as "the tree
collapsed". Re-opening `subvaults` then revealed the already-expanded child.

**Fix.** `_populateTree()` now snapshots which folders are open **before** the rebuild (by
`data-path`) and **restores** them after re-binding listeners. Combined with the existing
auto-expand of the just-loaded node, the parent stays open and the child opens on the first click —
the tree no longer appears to collapse. General fix: any re-render now preserves open folders.
