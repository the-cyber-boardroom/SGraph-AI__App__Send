## Summary

Three fixes from the first real browser test (the feature otherwise worked end-to-end: add a vault,
browse its contents, see a file added to the child *after* linking, embed a YouTube video).

1. **Sub-vault needed two clicks to expand.** The first expand lazy-loaded the child and re-rendered
   the tree (which collapsed the node), so a second click was needed. Fixed: after the lazy
   `loadFolder` + `_populateTree`, the just-loaded node is **auto-expanded**, so it opens on the
   first click. (`send-browse--v0.3.2.js` lazy handler.)
2. **Crash dragging a resource/sub-vault node into a folder** — `Cannot read properties of undefined
   (reading 'split')` in `_executeDrop`. The resource leaf had no `data-path`, so the drag payload
   was `{type:'file', path:undefined}`. Fixed two ways: (a) `_executeDrop` now **guards** `!drag.path`
   (no-op, no crash); (b) link nodes now carry their `*.link.json` path, so **dragging a sub-vault /
   resource into a folder moves the underlying link file** (the intended "move = move the link
   file"). Sub-vault folders drag as a file-move of their `.link.json` (not a virtual-folder move).
3. **No way to view/edit the `*.link.json`.** Sub-vault folders and resource leaves now show a small
   **✎ edit** affordance that opens the raw link file in an editor tab (the composite serves its
   bytes from the root vault), so the owner can view/change the label, URL, pin, etc. The tree stays
   otherwise seamless.
