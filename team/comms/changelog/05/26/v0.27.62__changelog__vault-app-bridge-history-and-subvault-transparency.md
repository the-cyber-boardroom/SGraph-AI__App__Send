## 1. AUTHORING.md corrected (verified against the live bridge)

`library/guides/vault-html/AUTHORING.md` had stale claims. Fixed:
- **`fetch('cities.json')` does NOT work** — `window.fetch` is **not** patched in the iframe. The
  doc previously said it was. Authors must use `sg.vfs.read`/`readText`. Updated the TL;DR, both
  tables, §3, the checklist, and the "why" section (loaders use the postMessage bridge, not fetch).
- **Declarative `<img src="vault-relative">` does NOT work** — there is **no MutationObserver**; only
  an `el.src = …` assignment **from JS** is intercepted (`HTMLImageElement.prototype.src`). Corrected
  §6 + the tables.
- **Ready log line** corrected to `[sg-vfs] ready | writable=… | vaultName=… | page: /en-gb/app`.
- **Documented the previously-undocumented APIs:** `sg.sync.*`, `sg.auth.*`, `sg.ui.*`, the extra
  `sg.app` fields (`vaultName`/`vaultId`/`fileCount`), and noted `sg.git.*` is deprecated.

## 2. New: `sg.history.*` — read past commits / trees / blobs

The iframe can now show previous versions of files/folders. New `SGVault` history methods
(`sg-vault--history.js`, read-only, reuse the read key + `_flattenCommitTree`):
- `logCommits({limit, from})` → `[{id, parents, tree_id, timestamp_ms, message}]`
- `listTreeAt(commitId, path)` → one level under `path` at that commit
- `readFileAt(commitId, path)` → file bytes at that commit
- `readBlob(blobId)` → a content-addressed object by id

Exposed to apps as `window.sg.history.{log,list,read,readText,readBlob}` via a new `history`
command type in the VFS bridge (iframe side + parent handler in `app-shell._setupVfsBridgeHandlers`,
calling the SGVault methods on the current vault). Documented in AUTHORING.md ("Reading history").
History covers the current vault; sub-vault history is a noted follow-on.

## 3. Sub-vault transparency for apps

Goal: an app should `sg.vfs.read('subvaults/alice/x.json')` and just get the inner-vault data
(inner vaults are read-only). Findings + fixes:
- **Was NOT transparent:** the `/en-gb/app` host built a plain `VaultDataSource` (not the composite),
  so apps couldn't see sub-vaults at all.
- **Fix:** `app-shell._setupVfsBridgeHandlers` now wraps the bridge's data source in a
  `CompositeDataSource` (guarded; identical behaviour when there are no sub-vaults). Added
  `vault-links.js` + `composite-data-source.js` (+ `sg-vault--history.js`) to `en-gb/app/index.html`.
- **Auto-open on read:** `CompositeDataSource.getFileBytes` now auto-opens a collapsed mount on
  access (read-only, via a stored `ro-links` record / device key — **no prompt**). So an app reads an
  inner-vault file by path without the user expanding it; if no key is available the read falls
  through to the root (→ ENOENT), preserving zero-knowledge.
- **Known limit:** `sg.vfs.list('subvaults/alice')` shows inner entries only after that vault is
  opened (read a file in it first, or the user expanded it). Inner-vault **writes** are not
  supported (read-only). Documented in AUTHORING.md ("Reading other vaults").
