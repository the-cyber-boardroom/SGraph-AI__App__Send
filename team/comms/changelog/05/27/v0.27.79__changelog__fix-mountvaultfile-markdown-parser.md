# Changelog — Fix: markdown files render in App Mode (MarkdownParser is not a constructor)

**Version:** v0.27.79 · **Date:** 2026-05-27 · **Author:** Dev (branch `claude/exciting-brown-G2P9Z`)
**Trigger:** Dinis — opening a `.md` deep-link in App Mode (`/#<key>|app:README.md` or
`/en-gb/app#README.md`) threw `Uncaught TypeError: MarkdownParser is not a constructor` and showed a
blank app.

## Root cause

`MarkdownParser` (`_common/lib/markdown/markdown-parser.js:28`) is an **object literal** with a
`parse()` method — `MarkdownParser.parse(text) → HTML` — not a class. Every other caller uses it
correctly (e.g. `vault-browse-edit.js:224`), but `_mountVaultFile`'s markdown branch
(`app-shell.js:1135`) called `new MarkdownParser().parse(md)` → "not a constructor".

This path was effectively unreachable before — App Mode ignored deep-links when a vault had an
`app.json`. The "Open as App honours the requested file" fix now routes `.md` deep-links to
`_mountVaultFile`, exposing the latent bug.

## Fix

`new MarkdownParser().parse(md)` → `MarkdownParser.parse(md)` (one line, `app-shell.js`).

## Files
```
EDIT _common/js/components/app-shell/app-shell.js   — _mountVaultFile markdown branch
```

## Test impact
- Syntax-clean; no other `new MarkdownParser` in the tree. Browser check: opening a `.md` file as an
  app (`/#<key>|app:<file>.md` or `/en-gb/app#<file>.md`) renders the markdown instead of a blank/black
  pane with the console error.

## Note (not bugs)
- The **redirect to `/en-gb/app`** from `/#<key>|app:<path>` is by design: the root hash inbox always
  saves the key + deep-link and redirects there (`vault-loader-routing.js`).
- `|<key>|app:<path>` is parsed **only by the root inbox** (`/#…`). On `/en-gb/app#<hash>` the hash is a
  literal file path, so `/en-gb/app#key|app:README.md` is (correctly) treated as a bogus filename and
  "not found". Use the root form for self-contained links (the "Open as App" links already do).
