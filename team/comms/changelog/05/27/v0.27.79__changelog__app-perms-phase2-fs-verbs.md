# Changelog — App-iframe capabilities Phase 2: grants + FS verbs (move/delete/mkdir)

**Version:** v0.27.79 · **Date:** 2026-05-27 · **Author:** Dev (branch `claude/exciting-brown-G2P9Z`)

## Summary

Builds on Phase 1 (floor). The iframe can now **move/rename, delete, and mkdir — when granted** by
`app.json`. Reads/writes are now also grant-aware.

- **`app-shell` parses `permissions`** at open (`this._perm = AppPermissions.parsePermissions(appJson)`)
  and gains `_can(verb, path)` = floor-deny THEN grant lookup (fails safe).
- **Existing verbs are grant-gated:** `vfs.write` → `_can('fs.write')`; `vfs.read` → `_can('fs.read')`;
  `vfs.list` filters to readable, non-`.vault` entries. (Reads still default-allow per the recorded
  decision, so apps with no `read` grant are unaffected; a scoped `read` array now restricts them.)
- **New `__sgCmdType:'fs'` bridge verbs** — `move` / `delete` / `mkdir`. Each requires the access token
  (`writable`) **and** the matching grant. Cross-folder move uses the existing `dataSource.moveFile`
  (lib `moveFile`, `sg-vault--file-ops.js:129`); same-dir → `renameFile`; move+rename composes both.
  Denials reply `{ ok:false, code:'EPERM' }` and emit a bridge-debug event.
- **In-iframe API:** `sg.fs.move(from,to)` / `sg.fs.delete(path)` / `sg.fs.mkdir(path)`.

No new data-source code was needed — `moveFile`/`renameFile`/`deleteFile`/`createFolder` already exist
and the composite forwards them to the root vault.
