# Changelog — App Mode: keep the opened file in the URL (#path) for reloads & shareable links

**Version:** v0.27.79 · **Date:** 2026-05-27 · **Author:** Dev (branch `claude/exciting-brown-G2P9Z`)
**Trigger:** Dinis — after opening a file in App Mode the hash was stripped (URL = `/en-gb/app/`), so a
reload fell back to the default app and the link couldn't be shared to that file.

## Change

`_mountVaultFile` now reflects the resolved file in the URL hash **after** mounting:
`history.replaceState(... '#' + entry.path)`. Because the key-hygiene strips in `_init`/`_initWithKey`
run *before* the mount, the vault key never lingers in the address bar — only the (non-sensitive) file
path does.

Result:
- **Reload re-opens the file** — `_init` re-reads `#path` → `_continue` → `_mountVaultFile` re-mounts
  and re-sets the hash.
- **Links are copy-shareable** — `/en-gb/app#NARRATIVE.md` (relies on the key already in localStorage),
  or the self-contained `/#<key>|app:NARRATIVE.md` which redirects and lands on `/en-gb/app#NARRATIVE.md`.
- The **default app** (no deep-link) keeps a clean hashless `/en-gb/app` URL.

Works for both entry points without touching the router: the root inbox still redirects to
`/en-gb/app`, and `_mountVaultFile` sets the hash once the file resolves.

## Files
```
EDIT _common/js/components/app-shell/app-shell.js   — _mountVaultFile: replaceState '#'+entry.path after resolve
```

## Test impact
- Syntax-clean. Browser check: open a `.md`/`.html` file as an app → URL shows `#<path>`; reload →
  same file re-opens; copy URL into a new tab (same browser) → same file. Opening the vault's default
  app shows no hash. A deep-link equal to the app.json entry mounts the default app (no hash) — expected.

## Note
- Exotic filenames containing spaces/`#` aren't round-tripped (the hash is set raw, `_init` reads it raw).
  Normal vault paths (`NARRATIVE.md`, `photos/web/x.jpg`) work. Encode/decode hardening can follow if needed.
