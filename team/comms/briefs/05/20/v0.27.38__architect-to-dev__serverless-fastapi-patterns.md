## TL;DR

You get a batteries-included FastAPI app by subclassing **`Serverless__Fast_API`**
(from `osbot-fast-api-serverless`) and one or more **`Fast_API__Routes`**
subclasses (from `osbot-fast-api`). The base class gives you the Mangum adapter,
OpenAPI/docs wiring, CORS, MCP mounting, lifecycle (`setup()` → `app()` →
`handler()`), and a Type_Safe-driven service-injection pattern. Routes are
**convention over configuration**: the method name becomes the URL path, the
parameter types drive validation, and `add_route_*` registers the verb.

## 1. The app class — subclass `Serverless__Fast_API`

Reference: `lambda__user/fast_api/Fast_API__SGraph__App__Send__User.py`.

```python
from osbot_fast_api_serverless.fast_api.Serverless__Fast_API import Serverless__Fast_API

class Fast_API__SGraph__App__Send__User(Serverless__Fast_API):
    # Type_Safe attributes — auto-instantiated, hold your shared services
    transfer_service : Transfer__Service       = None
    vault_service    : Service__Vault__Pointer = None
    # … more services …

    def app_kwargs(self, **kwargs):            # OPTIONAL — customise FastAPI() kwargs
        kwargs = super().app_kwargs(**kwargs)
        kwargs['docs_url'   ] = '/api/docs'    # move docs under /api/ for CloudFront routing
        kwargs['redoc_url'  ] = '/api/redoc'
        kwargs['openapi_url'] = '/api/openapi.json'
        return kwargs

    def setup(self):                           # OPTIONAL — build services, then call super()
        with self.config as _:
            _.name           = APP__..._TITLE
            _.version        = version__sgraph_ai_app_send
            _.description     = APP__..._DESCRIPTION
            _.enable_api_key = False           # per-route auth instead of global middleware
        # … construct services (storage backend, clients, etc.) …
        return super().setup()                 # MUST call super().setup()

    def setup_middleware__cors(self):          # OPTIONAL — override to add custom allowed headers
        ...

    def setup_routes(self):                    # REQUIRED — register your route classes
        self.add_routes(Routes__Info)
        self.add_routes(Routes__Transfers, transfer_service=self.transfer_service,
                                           admin_service_client=self.admin_service_client)
        ...
        self.setup_mcp()                        # OPTIONAL — mount MCP after routes
```

### What the base class hands you for free

- **Mangum adapter** — `handler()` returns the AWS-Lambda-compatible callable; you
  do not write any API Gateway / Lambda URL glue.
- **Lifecycle** — `setup()` builds the app; `app()` returns the FastAPI instance;
  `handler()` returns the Lambda entry callable. The handler module uses it as
  `with Fast_API__...() as _: _.setup(); handler = _.handler(); app = _.app()`.
- **`config`** — a Type_Safe config object (`name`, `version`, `description`,
  `enable_api_key`, `enable_cors`, …).
- **OpenAPI/docs** at `/docs`, `/redoc`, `/openapi.json` (relocatable via
  `app_kwargs`).
- **CORS middleware** — on by default; override `setup_middleware__cors()` to add
  custom allowed headers (the User Lambda adds `x-sgraph-access-token` etc.).
- **`add_routes(RouteClass, **service_kwargs)`** — instantiates the route class,
  injecting the keyword args as Type_Safe attributes, and registers its routes.

### Service-injection pattern

Declare services as Type_Safe attributes on the app class, build them in
`setup()`, then pass them to `add_routes(...)` as kwargs. The route class declares
matching attributes and receives them. Services are **constructed once at cold
start and shared across requests** — keep them stateless w.r.t. request data.

> **Memory-FS everywhere.** Services receive a `storage_fs` backend
> (`self.send_config.create_storage_backend()`), which is memory in tests and S3
> in prod. Never reach for S3/boto3 in a route or service directly — go through
> the injected `storage_fs`.

## 2. The route class — subclass `Fast_API__Routes`

Reference: `lambda__user/fast_api/routes/Routes__Transfers.py`,
`Routes__Vault__Pointer.py`.

```python
from osbot_fast_api.api.routes.Fast_API__Routes import Fast_API__Routes

TAG__ROUTES_TRANSFERS   = 'api/transfers'                     # URL prefix + OpenAPI tag
ROUTES_PATHS__TRANSFERS = [f'/{TAG__ROUTES_TRANSFERS}/create',  # document every path (used by tests)
                           f'/{TAG__ROUTES_TRANSFERS}/upload/{{transfer_id}}',
                           ...]

class Routes__Transfers(Fast_API__Routes):
    tag                  : str = TAG__ROUTES_TRANSFERS         # → all paths prefixed with /api/transfers
    transfer_service     : Transfer__Service                  # injected via add_routes(...)
    admin_service_client : object = None                      # 'object' avoids a circular import

    def create(self, request: Schema__Transfer__Create,        # POST /api/transfers/create
                     raw_request: Request,
                     access_token: str = '') -> dict:
        self.check_access_token(raw_request, access_token)
        ...
        return dict(transfer_id=..., upload_url=...)

    async def upload__transfer_id(self, transfer_id: Safe_Str__Id,   # POST /api/transfers/upload/{transfer_id}
                                        request: Request) -> dict:
        ...

    def setup_routes(self):                                    # REQUIRED — register every method
        self.add_route_post  (self.create)
        self.add_route_post  (self.upload__transfer_id)
        self.add_route_get   (self.info__transfer_id)
        self.add_route_delete(self.delete__transfer_id)
        ...
```

### The two ways to define a route's path

When you register a method via `add_route_*`, osbot-fast-api resolves its path with
this exact rule (`Type_Safe__Route__Registration.register_route`):

```
if the method has a __route_path__ attribute (set by @route_path('...')):
        use that path verbatim
else:
        derive the path from the method name (the naming convention)
```

In **both** cases the class `tag` (→ `prefix`) is prepended. So with
`tag = 'api/vault'`, a resolved path of `/destroy/{vault_id}` becomes the public
URL `/api/vault/destroy/{vault_id}`. The HTTP **verb is never inferred** — it comes
solely from which `add_route_*` helper you call in `setup_routes()`.

---

#### Way 1 — naming convention (no decorator)

The method name is parsed by `Fast_API__Route__Parser.parse_route_path`:

1. **Split the method name on `__` (double underscore)** into ordered parts.
2. **The first part is always a literal segment**, with single `_` converted to
   `-` (`convert_to_literal_segment`: `text.replace('_','-')`).
3. **Each later part becomes:**
   - `{part}` if `part` exactly matches one of the method's parameter names;
   - otherwise a literal segment (with `_`→`-` when it contains an underscore).
4. Empty segments are dropped (so a trailing `__` won't create `//`).

| Method signature | Resolved path (before prefix) | Register with |
|---|---|---|
| `create()` | `/create` | `add_route_post` |
| `list_items()` | `/list-items` | `add_route_get` |
| `info__transfer_id(self, transfer_id)` | `/info/{transfer_id}` | `add_route_get` |
| `delete__transfer_id(self, transfer_id)` | `/delete/{transfer_id}` | `add_route_delete` |
| `get_item__by_id__item_id(self, item_id)` | `/get-item/by-id/{item_id}` | `add_route_get` |

Mnemonics: `_` → `-` within a segment; `__` → new segment; a trailing segment that
**names a parameter** becomes `{param}`. The match is by **parameter name**, so the
method parameter must be called exactly `transfer_id` for `…__transfer_id` to bind.

**Limits of the convention** (when you must use Way 2):
- You cannot express a **path converter** like `{file_id:path}` (the catch-all that
  matches slashes) — method names can't encode the `:path` suffix.
- You cannot have a literal segment that needs characters illegal in a Python
  identifier, or a path shape that doesn't map cleanly to `name__param__name`.
- You cannot decouple the URL from the method name (e.g. keep a short method name
  but expose a long path).

---

#### Way 2 — explicit `@route_path` decorator

`from osbot_fast_api.api.decorators.route_path import route_path`

The decorator simply records the path on the function
(`func.__route_path__ = path`); registration then uses it verbatim. This is the
SG-Send vault routes' approach because they need `{file_id:path}` catch-alls:

```python
from osbot_fast_api.api.decorators.route_path import route_path

class Routes__Vault__Pointer(Fast_API__Routes):
    tag : str = 'api/vault'

    @route_path('/write/{vault_id}/{file_id:path}')          # → PUT  /api/vault/write/{vault_id}/{file_id:path}
    async def write__vault_id__file_id(self, vault_id, file_id, request: Request):
        ...

    @route_path('/read-base64/{vault_id}/{file_id:path}')    # → GET  /api/vault/read-base64/{vault_id}/{file_id:path}
    def read_base64__vault_id__file_id(self, vault_id, file_id):
        ...

    @route_path('/destroy/{vault_id}')                       # → DELETE /api/vault/destroy/{vault_id}
    async def destroy__vault_id(self, vault_id, request: Request):
        ...

    def setup_routes(self):
        self.add_route_put   (self.write__vault_id__file_id)        # verb still chosen here
        self.add_route_get   (self.read_base64__vault_id__file_id)
        self.add_route_delete(self.destroy__vault_id)
        return self
```

Use `@route_path` when you need: `{param:path}` catch-alls, full control over the
URL string, multiple/odd path parameters, or a URL that differs from the method
name. The decorated path is still **relative to the class prefix** — write it
without the `tag`/prefix.

> **Tip — keep `ROUTES_PATHS__*` accurate either way.** Whichever style you use,
> list the final relative paths in the `ROUTES_PATHS__<DOMAIN>` constant. SG-Send's
> route test (`test__config_fast_api_routes`) asserts the registered set equals the
> documented set; the two styles can be freely mixed in one class, but every
> registered method must appear in that constant.

---

#### A note on catch routes (missing trailing param)

Because a route like `/read/{vault_id}/{file_id:path}` will **not** match
`/read/{vault_id}` (no file_id), the SG-Send vault class historically registered
extra `@route_path('/read/{vault_id}')`-style stubs that returned a clean 400.
These pollute the OpenAPI surface and were removed for the `delete` case in this
version cycle — prefer letting FastAPI return its natural 404/405 for a wrong URL
rather than adding stub routes, unless you have a concrete reason to intercept.

### Other verb helpers

`add_route_get / add_route_post / add_route_put / add_route_delete /
add_route_patch` map to the obvious verbs; `add_route_any(fn, path=None)`
registers all of GET/POST/PUT/DELETE/PATCH/HEAD/OPTIONS. Batch helpers
(`add_routes_get(*fns)` etc.) register several at once. All return `self`, so
registrations can be chained.

### Request/response: Type_Safe, never Pydantic

```python
from osbot_utils.type_safe.Type_Safe import Type_Safe

class Schema__Transfer__Create(Type_Safe):
    file_size_bytes   : int
    content_type_hint : str = 'application/octet-stream'
    max_downloads     : int = 0
    delete_auth_hash  : str = ''
```

- A Type_Safe class as a parameter ⇒ JSON body, validated.
- A primitive/`Safe_Str__Id` parameter that matches a `{param}` ⇒ path param.
- A primitive parameter that does **not** match a path segment ⇒ query param
  (e.g. `access_token: str = ''`).
- Inject the raw Starlette `Request` by typing a parameter `request: Request`
  (or `raw_request: Request`) — needed for headers, raw body, query params.
- Errors: raise `fastapi.HTTPException(status_code=…, detail=…)`. Returning a dict
  with `error` keys and translating to `HTTPException` (as `create()` does) is the
  house style.

## 3. Per-route authentication (no global middleware)

The app sets `config.enable_api_key = False`; there is **no global auth
middleware**. Each protected route calls a `check_access_token(request, …)` helper
**at the top of the method**. The User Lambda's implementation (in
`Routes__Transfers`) resolves the token from, in order:

1. an explicit `access_token` parameter (MCP tool calls),
2. the `x-sgraph-access-token` header (browser / CLI),
3. an `access_token` query param,

then validates it against the Admin Lambda (`admin_service_client.token_lookup`),
falling back to an env-var check when no admin client is configured (local dev).
Failures raise `HTTPException(401/503)`.

Patterns to copy:
- **Sanitise** path/identifier inputs with `Safe_Str__Id(...)` before use.
- **Public/zero-auth routes are explicit** — e.g. vault reads take no token
  because the payload is opaque ciphertext. Auth is a per-route decision, not a
  blanket rule.
- There are currently **two near-duplicate `check_access_token` implementations**
  (transfers + vault). If you add a third route class needing auth, consider
  factoring a shared helper rather than copy-pasting a third time.

## 4. MCP exposure (optional but cheap)

The app mounts an MCP server in `setup_mcp()` after routes are registered:

```python
mcp_setup = MCP__Setup(name            = 'sgraph-send-user',
                       include_tags    = ['api/transfers', 'api/vault', ...],   # which route tags become MCP tools
                       forward_headers = ['authorization', HEADER__SGRAPH_SEND__ACCESS_TOKEN],
                       stateless       = True)                                  # Lambda-safe: no session state
self.mcp = mcp_setup.mount_mcp(self.app())
```

- Tag a route class (`tag = 'api/...'`) and add that tag to `include_tags` to
  expose its endpoints as MCP tools automatically.
- `stateless=True` is required for Lambda (no server-side session).
- Adding/removing a route changes the MCP tool surface — keep `include_tags` in
  sync.

## 5. SnapStart-friendly init

The User Lambda is deployed with SnapStart. The patterns that keep it correct:

- **Construct boto3/AWS clients lazily** — build a fresh `S3()` inside `setup()`
  (after restore), never pin a client into the snapshot.
- **Avoid STS / `account_id()` at init** — `Deploy__Service.deploy_lambda()`
  injects `SEND__STORAGE_MODE=s3` and explicit bucket-name env vars precisely so
  the app does not need an STS call during snapshot creation (when there are no
  credentials).
- The dependency loader (see brief 1) is already SnapStart-safe (gated on
  `AWS_REGION`, runs during init, single STS only on the real cold path).

If your function doesn't use SnapStart, these are still good hygiene but not
load-bearing.

## 6. Testing (no mocks)

Per project rules, tests start the full stack **in-memory** (~100 ms) with no
mocks/patches. See `library/guides/patterns/v0.13.34__user-lambda-test-server__guide.md`.

- Build the app with the in-memory storage backend; hit it with FastAPI's
  `TestClient` (or the real-HTTP-server mode the guide describes).
- The `ROUTES_PATHS__*` lists exist partly so a test can assert the registered
  route set matches expectations — see
  `tests/unit/lambda__user/fast_api/test_Fast_API__SGraph__App__Send__User.py`
  (`test__config_fast_api_routes`). **If you add/remove a route, update both the
  `setup_routes()` registration and the `ROUTES_PATHS__*` constant**, or that test
  fails. (This exact mismatch broke CI earlier in this version cycle.)

## 7. Checklist for a new route class

- [ ] `class Routes__X(Fast_API__Routes)` with `tag : str = 'api/x'`.
- [ ] Declare injected services as Type_Safe attributes.
- [ ] One method per endpoint. Path is either derived from the method name
      (`__` ⇒ new segment, trailing param-name segment ⇒ `{param}`, `_` ⇒ `-`) or
      set explicitly with `@route_path('/...')` (needed for `{param:path}`
      catch-alls and arbitrary URLs). Both are relative to the class prefix.
- [ ] Type_Safe schema for any JSON body; `Request` param for headers/raw body.
- [ ] `check_access_token(...)` at the top of every protected method.
- [ ] `setup_routes()` registers every method with the correct `add_route_*`.
- [ ] `ROUTES_PATHS__X` constant lists every path (kept in sync for the route test).
- [ ] `add_routes(Routes__X, x_service=self.x_service)` in the app's
      `setup_routes()`.
- [ ] If MCP-exposed: add the tag to `MCP__Setup.include_tags`.
