**From:** Explorer / Vault UI Dev
**To:** SG/App author teams (KneeScore, future apps)
**Date:** 2026-05-12
**Version:** v0.27.19
**Scope:** Vault UI v0.2.3 — IFD overlay
**Touches:**

## TL;DR

The `window.sg` bridge inside every vault-hosted iframe now exposes commit/sync awareness, write-only access-token management, vault metadata, and a HUD-routing message channel. Combined with the new auto-push-on-write behaviour, an SG/App can now deliver the **full vault experience without the user ever leaving App Mode** — including onboarding new users who arrive with just a vault link.

---

## What Changed

### 1. Auto-push on every `sg.vfs.write()`

Previously, a write committed locally but the user had to leave App Mode and click "Push" in the header to publish. We have **yet to find a workflow where unpushed state actually helps the user**, so writes now auto-push after the commit succeeds.

- Push happens on the parent side, after `saveFile()` resolves
- Failures are caught and logged as warnings — they do **not** fail the write reply to the iframe
- Read-only writes are still rejected as before

No iframe code changes needed. Existing `sg.vfs.write()` callers just work — the named ref now stays in sync.

### 2. Sync section in the header + auto "Check for updates"

The Refresh button is now in a visually distinct sync section alongside Push/Pull and a new lightweight ↻ Check button. The shell auto-checks for upstream changes on:

- **`visibilitychange`** (tab regains focus, debounced 30s)
- **Vault open** (1.5s after open)
- **Explicit ↻ click** (always, shows feedback)

No background polling. Relevant to authors because the check updates the same state that `sg.git.status()` exposes.

### 3. New `sg.app.*` static metadata

Injected at iframe boot, no round-trip needed:

```js
sg.app.selfPath     // existing
sg.app.writable     // existing
sg.app.vaultName    // string — vault's display name
sg.app.vaultId      // string — public vault ID (zero-knowledge safe)
sg.app.fileCount    // int    — number of files (excludes folders)
sg.app.totalSize    // bytes  — total decrypted size
```

### 4. New `sg.git.*` — commit / sync (async)

```js
sg.git.status()    // → { ahead, behind, diverged, headCommitId, namedHeadId, writable }
sg.git.check()     // triggers parent's cheap behind-check, returns refreshed counts
sg.git.push()      // manual push (rarely needed since auto-push exists)
sg.git.pull()      // pull from named branch
sg.git.refresh()   // full vault reload (equivalent to header Refresh)
```

`status()` reads cached state — no network call. `check()` does one cheap ref-pointer GET. The rest do the corresponding vault operation and update the header automatically.

### 5. New `sg.auth.*` — write-only access-token management

The **key design constraint**: the iframe can **set** an access token and **check validity**, but can **never read** the key back.

```js
sg.auth.hasKey          // bool — is a key currently set?
sg.auth.setKey(key)     // → { valid, remaining } — sets AND validates server-side
sg.auth.check(key)      // → { valid, remaining, status } — validates without setting
sg.auth.clear()         // → { cleared: true }
```

`setKey()` propagates through the existing `vault-settings-access-key` event, so:
- The header "Read-only" badge disappears
- `sg.app.writable` flips to `true` on subsequent iframe loads
- `dataSource.writable` activates immediately (writes start working)
- The key is persisted to `sessionStorage` (same as the inline unlock panel)

Validation uses `GET /api/transfers/check_token/{name}` — public endpoint, doesn't consume a use.

### 6. New `sg.ui.message(text, type)` — HUD + toast routing

```js
sg.ui.message('Settings saved', 'success')
sg.ui.message('Sync conflict', 'warn')
sg.ui.message('Could not reach server', 'error')
sg.ui.message('Computing scores…', 'info')
```

| Type | App Mode (HUD) | Non-App Mode (toast) |
|---|---|---|
| `info` | `banner.showStatus('•', text)` | `sgraphVault.messages.info(text)` |
| `success` | `banner.showStatus('✓', text, 3000)` (auto-dismiss) | `messages.success(text)` |
| `warn` | `banner.showStatus('⚠', text)` | `messages.warn(text)` |
| `error` | `banner.showStatusError(text, '')` | `messages.error(text)` |

The fallback to `sgraphVault.messages` happens automatically when the banner isn't active — write one line, get the right surface either way.

## Onboarding Flow Example

Here's the full first-time-user path your SG/App can now deliver entirely in-iframe:

```js
// 1. Detect read-only state at boot
if (!sg.app.writable) {
    showOnboardingScreen()
}

// 2. User enters the access key they were given
async function onApplyKey(key) {
    const result = await sg.auth.setKey(key.trim())
    if (!result.valid) {
        sg.ui.message('Invalid access key', 'error')
        return
    }
    sg.ui.message(`Welcome — ${result.remaining} uses remaining`, 'success')
    // sg.app.writable is now true (will reflect on next iframe load)
    renderFullExperience()
}

// 3. From here, sg.vfs.write() auto-pushes — no extra steps needed
await sg.vfs.write('/user-data.json', JSON.stringify(state))
sg.ui.message('Saved', 'success')

// 4. Optional: surface sync state in your UI
const { behind, diverged } = await sg.git.status()
if (behind > 0) {
    sg.ui.message(`${behind} new updates available`, 'info')
}
```

The user never has to:
- Click "Read-only" → unlock panel → type key (the iframe owns that flow)
- Leave App Mode to push
- Refresh the page after entering the key

## Security Guarantees

1. **Access key is never echoed back to the iframe.** `sg.auth.setKey()` returns `{ valid, remaining }`, never the key string. `sg.auth.check()` and `sg.auth.clear()` follow the same rule.
2. **Vault key (clone key) is never exposed.** Only `vaultId` — the public server-side identifier — is in `sg.app.vaultId`.
3. **All `sg.git.*` and `sg.auth.*` calls go through postMessage round-trips.** The parent enforces every contract; the iframe cannot bypass.
4. **`sg.auth.setKey` reuses the existing event flow** (`vault-settings-access-key`), so all the existing UI sync (header badge, `dataSource.writable`, `sessionStorage`, token propagation to `sgSend`) is wired automatically. No new code paths to audit.
5. **Validation endpoint is public** (`/api/transfers/check_token/{name}`) and **does not consume a use** — safe to call repeatedly.

## Promise & Error Semantics

All async methods return promises. On success they resolve with the documented payload. On failure they **reject with an Error**:

```js
try {
    const r = await sg.git.push()
} catch (err) {
    sg.ui.message(err.message, 'error')   // e.g. "Read-only vault"
}
```

Common error messages:

- `'Read-only vault'` — calling `push()`, `pull()` without an access key
- `'Shell not available'` — bridge was set up before vault-shell finished loading (shouldn't happen in normal use)
- `'Unknown git action: <name>'` — typo / version mismatch

`sg.ui.message()` is fire-and-forget — no promise, no failure path.

## Known Caveats

- **`sg.auth.hasKey` is captured at iframe boot.** It does NOT update live after `sg.auth.setKey()` succeeds in the same iframe instance. Check `(await sg.auth.setKey(key)).valid` directly, or call `sg.git.status()` afterwards and read `writable` from the result. The static field will reflect the new state on next iframe load.
- **`sg.git.refresh()` destroys the calling iframe.** A full refresh remounts the browse component, which tears down and re-creates the iframe. The returned promise will not resolve from the author's perspective because the calling window no longer exists. Use it as a fire-and-forget "go reload everything" call — don't `await` it expecting completion semantics. Prefer `sg.git.pull()` if you want to fetch latest content while keeping iframe state alive.

## What's NOT in This Release

Intentionally deferred / out of scope:

- **Subscribing to push events** (`sg.on('git-changed', cb)`). Currently authors poll `sg.git.status()` on relevant interactions or rely on the visibility-change auto-check. Can add this if a clear use case appears.
- **File-level diff / log API** (`sg.git.log()`). The original brief requested this; we de-scoped because the read-only mirror of UI state covers the workflow we hit. Re-open if your app actually needs commit history.
- **Setting the vault name / settings.json from the iframe.** Already possible via `sg.vfs.write('/.vault-settings.json', ...)`. Not adding a typed wrapper unless needed.

## Testing Notes

To exercise the API from any vault-hosted HTML file, open the iframe's devtools console:

```js
sg.app                          // see all static fields
await sg.git.status()
await sg.auth.check('apple-river-1234')   // try a key without setting it
await sg.auth.setKey('apple-river-1234')  // set it for real
sg.ui.message('Hello from App Mode', 'success')
```

The auto-push can be verified by writing a file from the iframe, then watching the vault header — the "Push" button should never appear (the named ref auto-advances).
