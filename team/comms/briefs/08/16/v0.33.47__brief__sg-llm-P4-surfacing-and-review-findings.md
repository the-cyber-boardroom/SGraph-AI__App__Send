6-second toast, once per session (`app-shell.js:_llmNotify`, `_llmNotified` flag).

## Part B — defects found in this review (fix with P4)

Ranked. B1 and B3 are the ones I would not ship another release without.

### B1 — Host-chat budget counters are panel-local and reset on remount (**moderate**)
`vault-llm-chat._send` gates on `this._cost` / `this._calls` (`:821-828`), which live on the
element instance and reset to zero whenever the panel is closed/reopened or the layout re-mounts
it. The ledger (`VaultLlmLog`, module-global) keeps the true figure. Consequence: the vault
policy's session caps are evadable on the host surface by closing and reopening the chat pane —
while the *bridge* path (P2) now enforces against the ledger correctly. One surface, two
authorities. **Fix:** gate on `VaultLlmLog.totals(null)` (host spend) and keep `this._cost`
only as a render cache — or drop it entirely and render from the ledger.

### B2 — Pasted images are re-sent (and re-billed) on every later turn, while the UI says otherwise (**moderate**)
The chip note reads *"sent with your next message only"*, and the chips do clear — but the
outgoing message object, image parts included, is pushed into `_history` (`:844`) and rides in
`history.slice(-20)` on **every subsequent request** until it scrolls out of the window. Base64
image parts are the most expensive tokens we send, and they are being silently resent up to 19
more times. **Fix:** after the turn completes, replace the stored message's image parts with a
`[image: name, N KB — sent earlier]` text placeholder (conversation coherence survives; the
follow-up cost does not), or — if we decide history must keep the pixels for follow-up quality —
change the copy and surface the recurring cost in the composer. Decide, then make the UI and the
bill agree.

### B3 — The 🔧 tools bar can enable a group but not scope it → post-P3 it grants a group that refuses everything (**important, UX regression introduced by P3**)
P3 made an empty `allow` mean **nothing** (`ENOSCOPE`) — correct security posture. But the chat
panel's tools bar (`_renderTools`) offers only enable/disable checkboxes; there is no UI to set
the allow-list. So the only in-product flow now produces: tick `files.read` → grant committed →
every tool call refused with `ENOSCOPE` → remedy is hand-editing `.vault/llm/tools.json`.
**Fix:** add a scope field to the toolbar (comma-separated globs, saved with the grant, with a
suggested starter like `docs/**` prefilled from the top-level folders), and render the
`ENOSCOPE` reason in the bar itself, not only in the model's refusals. Until this ships, the
user guide documents the hand-edit (see Part C).

### B4 — Context budget arithmetic contradicts its own comment (**minor**)
`_contextMessages` floors each file at `MIN_PER_FILE` (1500) but nothing *drops* files, so at
the 20-file cap the real budget is 20 × 1500 = 30 000 chars against the stated 24 000, and the
chip row's "(trimmed to 24,000 total)" is wrong past 16 text files. Either drop files beyond
the budget (what the comment claims) or fix the label and the constant.

### B5 — No mid-turn budget re-check in the tool loop (**minor, bounded**)
`_send` checks caps once, before the turn; a tool turn then makes up to `MAX_ITERATIONS`+1
(9) LLM calls with no re-check, so a session can overshoot `maxCostPerSession` by up to 9 calls.
Bounded, but the check belongs inside `_chatOnce`. (The bridge path has the same shape —
one check per `chat` call — which is fine because each bridge call *is* one LLM call.)

### B6 — Duplicate spend state (consolidate with B1) (**minor**)
`this._cost`/`_accrue`/`_recost` in the panel duplicate what `VaultLlmLog` + `effectiveCost`
already maintain, and the two can drift (they already disagree after a remount — B1). One
source of truth, panel renders from it.

### Verified sound (so nobody re-litigates them)
- The key never reaches the app frame (pinned: sentinel-key assertions in
  `test__app_shell_llm_bridge.js`); `.vault/**` floor holds at bridge and tools layers,
  traversal spellings included.
- Images are cleared from the composer *before* the await, so a double-send cannot re-attach.
- Abort keeps the partial reply and still records/reconciles its cost, on both surfaces.
- Tool results are fenced as untrusted data; the grants file is unreachable by the tools it
  governs; a failed grant save reverts the checkbox (never claims refused authority).
- Consent floors, CSP coupling, per-app ledger scoping (P0–P2) behave as specified in the
  hardening changelog, per the current test suite (0 failures).
