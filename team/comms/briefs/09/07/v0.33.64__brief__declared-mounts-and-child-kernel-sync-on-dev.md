## 1 · What it is, in one paragraph

A vault app can now read and write a folder that is **another vault** without knowing it. The
owner drops `<name>.link.json` in the parent (the same pointer the sub-vault UI already writes)
and keeps the child's key in the owner-secret store; the top kernel turns that into a mount
**before the app iframe exists**, so `sg.vfs.list('name')` / `sg.vfs.write('name/x.json', …)` are
served by a hidden child kernel that opens the child vault on its own clone branch. The child
kernel keeps itself honest against the server: it **reconciles before every write**, publishes
with **compare-and-swap** (merge + one retry on a lost race, `EDIVERGED` never overwrites), and
**refreshes before reads** (5 s throttle). `sg.vault.mount` (runtime mounts) is unchanged.

Proof: a real-browser end-to-end with screenshots —
`library/guides/vault-html/DECLARED-MOUNTS-E2E.md`.

## 2 · How to use it from a vault app (nothing new to call)

| You want | You write |
|---|---|
| a folder `data/` that lives in another vault | in the parent: `data.link.json` → `{ "vault_id": "<child>", "ref_id": "lk-…", "label": "…" }`. Easiest: `sg.vault.create({ …, link: { path: '' } })` from the app, or the sub-vault panel in the vault UI — both write the link **and** the owner records. |
| the mount to be **read-write** for the owner | the child's full key sealed in `.vault/owner/secrets/<ref_id>.json` (`sg.vault.create` with custody does this) **and** in the child: `.vault/app.json` granting `fs.write` (the child's own policy is the second gate) + `.vault/access-token.json` (the child kernel's account token) |
| a **read-only** parent session to still see the folder | `.vault/owner/ro-links.json[<ref_id>]` with the child's `read_key` (written by the same flows) → the child mounts read-only |
| your app to be allowed to write there | your own `.vault/app.json`: `permissions.fs.write: ["data/"]` (plus `delete` / `mkdir` if needed) — checked by the top kernel before any relay |

Then just use `sg.vfs.*` on `data/…`. Do **not** call `sg.vault.mount` for a declared folder.

**What you will see / get back**

- The HUD → Debug panel → **🔗 Mounts** tab lists the mount with `declared`, its access tier
  (`rw` / `ro`) and a sync tag (`clean` / `behind` / `ahead` / `diverged`) once the child has
  been touched. `KernelParent.syncAll()` (also run on tab focus) refreshes the column.
- Errors through a mount: `EPERM` (a grant is missing on **either** side), `EPROTECTED`
  (`.vault/**` or the child's `.vault-settings.json`), `EREADONLY` (child not writable),
  `EUNREACH` (child boot / push failed — the message now carries the real cause),
  `EDIVERGED` (the published ref kept moving; your commit is kept locally, not published).
- Commits the child kernel makes carry a `Via-Mount: <label> (declared)` trailer — visible in
  `sgit log` on the child.
- One mount per child per parent: a second `*.link.json` pointing at the same child is reported
  (`declared-mount-skipped`, `EEXIST`) and not mounted.

## 3 · How to confirm the deployment is live (three levels, cheapest first)

**Level 0 — the deploy itself.** Merging to `dev` runs `deploy-ui-vault.yml` (test gate → S3 →
CloudFront invalidation). `https://dev.vault.sgraph.ai/version` is the plain-text version
uploaded with that deploy (short cache, ~5 min).

**Level 1 — capability probe (read-only, no token, ~2 s).**

```bash
npm run probe:vault-ui -- https://dev.vault.sgraph.ai https://dev.send.sgraph.ai
```

`scripts/probe_vault_ui_capabilities.mjs` fetches the deployed JS and checks 17 markers that
exist only in this change (`vfs.status` / `vfs.sync` handlers, `_reconcile`, `writeRefIfMatch`,
`pushIfMatch`, `boot-error`, the rebuilt kernel-shell bundle, …) plus API health / versions.
Exit 0 with "all markers present" = the code is served. CloudFront can lag a few minutes after
the workflow finishes.

**Level 2 — functional, against the deployed server (Node only, ~20 s, needs a token).**

```bash
SG_API_URL=https://dev.send.sgraph.ai SG_ACCESS_TOKEN=<your token> npm run test:vault-live
```

Creates throw-away vaults on dev and drives the shipped child-kernel handlers through the real
CAS / reconcile / race / read-only paths (45 checks). Proves the **server** side of the contract
(`write-if-match` batch op, refs, tokens) with the browser libraries from your checkout.

**Level 3 — the real thing: the deployed UI in a real browser (~15 s, needs a token).**

```bash
SG_UI_BASE=https://dev.vault.sgraph.ai SG_API_URL=https://dev.send.sgraph.ai \
SG_ACCESS_TOKEN=<your token> SG_REQUIRE_API=1 npm run test:vault-e2e-declared-mounts
```

Seeds a child + parent on dev, opens **dev.vault.sgraph.ai/en-gb/app** with the parent key,
and asserts the four scenarios of the guide (owner write lands in the child; another writer's
publish is fast-forwarded, not lost; the Mounts tab shows `declared · rw · clean`; a read-only
parent gets `EREADONLY`). Screenshots land in `test-results/declared-mounts-e2e/` — attach them
to your debrief. Green here **is** the confirmation that "this code with these capabilities is
live". (Test vaults are left on dev; they are tiny and unreachable without their keys.)

Token: the same account token you use for `x-sgraph-access-token` (`SGRAPH_SEND__ACCESS_TOKEN`
is honoured too). Never commit it.

## 4 · What changed under you (if you maintain kernel / channel code)

Six defects in the child-kernel path were found by the e2e and fixed — read the changelog
before touching `kernel-bootstrap.js`, `kernel-app-handlers.js`, `secure-channel.js` or
`_spawnChildChannel`:
`team/comms/changelog/09/07/v0.33.64__changelog__child-kernel-sync-discipline-and-declared-mounts-browser-e2e.md`.
Rebuild the bundle (`python3 scripts/build-kernel-shell-bundle.py`) after editing any bundled
source; `test__bundle_freshness.js` fails otherwise.

CI: the new job **"Declared mounts e2e + live sync (Python API + Playwright)"** in
`_test-ui-vault.yml` runs both tests with the real API server. In the Node-only e2e job the
spec skips itself visibly (no Python deps there).

## 5 · Not in this change (PROPOSED — does not exist yet)

- A per-mount behind/diverged indicator on the HUD chip (today: the Mounts tab column).
- `EDIVERGED` surfaced to the app with the conflicting paths.
- The `sgit` binary as the e2e's "other writer" (today: a plain `SGVault` on its own clone
  branch — same bytes on the wire).
- Writable **composite** links (the `.link.json` adapter without a kernel) — still read-only by
  design (`EMOUNT_RO`).
