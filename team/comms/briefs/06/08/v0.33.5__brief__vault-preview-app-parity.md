## What landed this session

Three shipped changes (commit on `claude/zealous-thompson-yDjFX`):

### 1. ⭐ Root-cause fix: empty `sg.app.vaultId` in preview

`send-browse--v0.3.2.js` reads `self.dataSource._vault.vaultId` (L886). When the editor wraps the data source in `CompositeDataSource` (the `*.link.json` / sub-vault path — which is the default in v0.2.3), `_vault` was **undefined** on the composite (it stored the underlying source at `_root` instead). `vaultId` therefore fell to `''` and the header showed `my vault: ?`.

**Fix:** added a `_vault` getter on `CompositeDataSource` delegating to `this._root._vault`. The composite is now transparent for the identity delegate, so every consumer that historically read `dataSource._vault` (send-browse, vault-shell, vault-browse-edit, app-shell) gets the right answer.

**File:** `composite-data-source.js` L49.

### 2. `sg.app.context` — make the surface discoverable

Both mount paths now stamp the context so apps can feature-detect deliberately instead of probing namespace presence:

```js
window.sg.app.context = 'app'      // /en-gb/app/ — full surface (app-shell.js)
window.sg.app.context = 'preview'  // SG/Vault editor — reduced surface (send-browse--v0.3.2.js)
```

Apps:
```js
if (sg?.app?.context === 'preview' && !sg.vault) {
  // We're in the editor preview — the reduced API.
}
```

**Files:**
- `app-shell.js` (the in-iframe stub) — `context:"app"`.
- `send-browse--v0.3.2.js` (v0.3.3 copy, the deployed one) — `context:"preview"`.

### 3. HUD consent — testability hooks

`role="alertdialog"`, `aria-label`, and `data-testid` hooks on the consent prompt so Playwright can target `[data-testid="hud-consent-allow"]` reliably. The brief's "blocks the triggering click" claim doesn't actually match the code (the consent is an inline HUD element, not a modal overlay with a click-capturing backdrop) — so no overlay fix is needed; the testability hooks are the real ask.

**File:** `app-hud.js` L42–46 + `_consentLabel` map extended to cover `vault.createKey`.

## What's still PROPOSED (follow-up — not in this commit)

### 4. Extract a single `buildSgGlobal` shared module

The structural fix the source brief asks for. Today both `_buildVfsBridgeScript` (in app-shell.js, ~230 lines) and the equivalent block in send-browse--v0.3.2.js (~70 lines, missing many namespaces) build the same shape from scratch. **Every new `sg.*` capability has to be added in two places or it silently doesn't exist in preview.**

Extract a single helper:

```js
// _common/js/components/app-shell/sg-global-builder.js (new, pure)
globalThis.SgGlobalBuilder = {
  build({ context, currentPath, writable, vaultName, vaultId, fileCount, totalSize }) {
    // returns the script text to be injected as srcdoc into the app frame.
    // Single source of truth for the structure of window.sg.
  }
};
```

Then:
- `app-shell.js._buildVfsBridgeScript` calls `SgGlobalBuilder.build({ context: 'app', ... })`.
- `send-browse--v0.3.2.js` calls `SgGlobalBuilder.build({ context: 'preview', ... })`.
- New capabilities land in ONE place.

### 5. `sg.vault.*` dispatch in the editor preview path

If the preview should be the app (the brief's recommended option A), `__sgCmdType:'vault'` messages from the iframe must be handled host-side in the editor too. Today only the `git`/`auth`/`ui` cmd types are dispatched in send-browse's host loop (`send-browse--v0.3.2.js` L1158+). Three options, in increasing scope:

- **A1 — Stub-with-error.** Reply `EPREVIEW: vault.* unavailable in preview` for now. Apps already feature-detect; this just makes the failure mode loud.
- **A2 — Route to the same helpers.** Move `_createChildVault` + `_ownerSecret*` + `_consent` + permission gating off `app-shell` and onto a kernel-agnostic mixin both mount paths can use. Requires AppPermissions to be loaded in the editor preview path (it's already in the bundle).
- **A3 — Full unification.** Same dispatch loop in both paths. Most code share, biggest change.

Recommend A2 — it's the right factoring and it cleanly separates the dispatch (kernel) from the surface builder (iframe stub).

### 6. Trusted-context pre-grant for tests

A flag that auto-satisfies consent in non-production. Powerful, security-sensitive — deserves its own AppSec brief before implementation. The data-testid hooks above are enough to unblock most automation in the meantime.
