# Implementation Plan: Inbox → Append Rename

**version** v0.32.7
**date** 8 June 2026
**author** Developer (Explorer team)
**type** Technical implementation plan
**status** Awaiting approval

---

## Summary

Rename the vault inbox feature from "inbox" to "append" across all API
endpoints, filesystem paths, service classes, route classes, constants, tests,
reality documents, and cross-team briefs. This is a mechanical rename with one
structural change: move the storage paths from outside `bare/` to inside `bare/`,
and introduce `pending/` and `processed/` sub-folders under each token.

**No behavioural changes.** The six operations, the four-tier gate model, the
Safe_Str validations, the batch caps, and the blind-write contract are all
unchanged. Only names and paths change.

---

## Motivation

The server provides a generic append-only, gate-controlled storage primitive.
"Inbox" bakes in one use case (messaging) when the same infrastructure supports
logs, signals, control messages, state flows, and email workflows. Renaming to
"append" makes the API honest about what it does — the client decides the
semantics.

Moving into `bare/` makes append data a first-class sgit namespace, so the CLI
can manage it during clone/push/pull alongside `data/`, `refs/`, `keys/`, and
`indexes/`.

## Endpoint Changes

| Current | New |
|---------|-----|
| `POST /api/vault/inbox/configure/{vault_id}` | `POST /api/vault/append/configure/{vault_id}` |
| `POST /api/vault/inbox/append/{vault_id}` | `POST /api/vault/append/write/{vault_id}` |
| `POST /api/vault/inbox/list/{vault_id}` | `POST /api/vault/append/list/{vault_id}` |
| `POST /api/vault/inbox/fetch/{vault_id}` | `POST /api/vault/append/fetch/{vault_id}` |
| `POST /api/vault/inbox/mark-processed/{vault_id}` | `POST /api/vault/append/mark-processed/{vault_id}` |
| `POST /api/vault/inbox/purge/{vault_id}` | `POST /api/vault/append/purge/{vault_id}` |

Note: the write operation changes from `append` (verb) to `write` to avoid
`/append/append/` redundancy.

---

## Filesystem Path Changes

| Current | New |
|---------|-----|
| `transfers/vault/{vid}/inbox/{token}/{file}` | `transfers/vault/{vid}/bare/append/{token}/pending/{file}` |
| `transfers/vault/{vid}/processed/{token}/{file}` | `transfers/vault/{vid}/bare/append/{token}/processed/{file}` |

The new structure:

```
transfers/vault/{vault_id}/
├── manifest.json
└── bare/
    ├── data/                          # existing — CAS objects
    ├── refs/                          # existing — branch refs
    ├── keys/                          # existing — PKI keys
    ├── indexes/                       # existing — branch index
    └── append/                        # NEW — append-only lanes
        └── {token}/
            ├── pending/               # files land here on write
            │   ├── {epoch}_{hex}.enc
            │   └── ...
            └── processed/             # mark-processed moves files here
                └── {epoch}_{hex}.enc
```

## Execution Order

The rename is mechanical. To minimize breakage during the process:

```
Phase 1: Storage layer (no tests break yet — nothing imports new names)
  1.1  Update Storage__Paths.py — add new functions, keep old as aliases
  1.2  Run tests — all 957 should pass (old names still work)

Phase 2: Service layer
  2.1  Create Service__Vault__Append.py (copy + rename from Inbox)
  2.2  Update all path function calls to new names
  2.3  Rename methods: append→write, inbox_list→list_entries, inbox_fetch→fetch
  2.4  Rename constants: INBOX_* → APPEND_*
  2.5  Delete Service__Vault__Inbox.py

Phase 3: Route layer
  3.1  Create Routes__Vault__Append.py (copy + rename from Inbox)
  3.2  Update tag, paths constant, method names, service field
  3.3  Delete Routes__Vault__Inbox.py

Phase 4: App registration
  4.1  Update Fast_API__SGraph__App__Send__User.py imports and fields

Phase 5: Tests (this is where we verify everything)
  5.1  Create test_Service__Vault__Append.py (copy + rename)
  5.2  Create test_Routes__Vault__Append.py (copy + rename)
  5.3  Update test_Fast_API__SGraph__App__Send__User.py
  5.4  Delete old test files
  5.5  Run full test suite — must be 957 passing

Phase 6: Storage paths cleanup
  6.1  Remove old alias functions from Storage__Paths.py
  6.2  Run tests again — confirm nothing references old names

Phase 7: Documentation
  7.1  Update reality documents (send-api, vault, index)
  7.2  Update cross-team brief
  7.3  Add rename note to code review document

Phase 8: Commit and push
  8.1  Single commit: "Rename vault inbox → vault append"
```
