## The fix (your two-line ask)

`SGVaultRefManager.writeBranchIndex` now emits:

```js
{
  schema: 'branch_index_v1',
  branches: [{
    branch_id:   'branch-named-' + <12 hex chars from branchIndexFileId>,
    branch_type: 'named',
    head_ref_id: refFileId,           // the deterministic named ref (ref-pid-muw-…)
    name:        'current'             // CLI hardcode
  }]
}
```

**`branch_id` derivation.** I derive the opaque hex suffix from the index file id's own hex tail (`idx-pid-muw-{12 hex}` → 12 hex chars). That's:
- **Deterministic per vault** — same index across re-pushes (stable plaintext, the AES-GCM IV still rotates per write so the ciphertext does not).
- **Opaque** (matches your "not a human label" point) — `[0-9a-f]{12}`, comfortably inside `[8,64]`.
- **Per-vault unique** — collisions would require an HMAC collision on the read_key + vault_id derivation, same property your ref file ids already rely on.

I considered "any random hex" but rejected it — re-rolling a fresh id on every push would churn the index plaintext for no semantic gain (and was one of the things you specifically tested as stable). Deterministic from the index file id keeps the wire format clean and reproducible.

**Why "current" and not a per-vault label here.** Agreed — `"current"` is the literal hardcoded in 10+ CLI workflow steps and matches every CLI-created vault in the wild. The web's display label (which is what *we* really want to call it, e.g. `"main"`) belongs in a separate `display_name` field per the interop contract — happy to add that field there.

### Wire format pinned in tests

Added 6 assertions to `tests/unit/vault_ui/loader/test__branch_index.js` (now 15 total) that **encode your contract directly** so this can't drift again:

- `branch_id` matches `^branch-(named|clone)-[0-9a-f]{8,64}$` (your exact `Safe_Str__Branch_Id` regex).
- `branch_id !== 'branch-named-main'` — regression guard against the exact bug A wire.
- `name === 'current'`.
- `name !== 'main'` — regression guard against bug B.
- Same `branchIndexFileId` → same `branch_id` (deterministic).
- Different `branchIndexFileId` → different `branch_id` (per-vault).

The first two failing in CI would block the merge. That's the durable form of the wire contract on our side, alongside whatever lives in the architect doc.
