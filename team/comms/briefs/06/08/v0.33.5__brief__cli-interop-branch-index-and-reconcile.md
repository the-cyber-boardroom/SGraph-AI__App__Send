## Fix 1 — Web vaults now write a CLI-format branch index

New method `SGVaultRefManager.writeBranchIndex(branchIndexFileId, refFileId)`:

```
bare/indexes/<idx-pid-muw-…>   ← encrypted (read_key, AES-GCM), like every ref
  { "schema": "branch_index_v1",
    "branches": [ { "branch_id":"branch-named-main", "branch_type":"named",
                    "head_ref_id":"ref-pid-muw-…", "name":"main" } ] }
```

Called from:
- `SGVault.create` — right after the initial named-ref write, so a brand-new web vault is **immediately clonable**.
- `SGVault.push()` — after advancing the named ref, so the index always points at the latest published head.

Both calls are **best-effort** (`try/catch`): if the index write fails, create/push still succeed — the named ref is what's authoritative; the index is the discovery convenience.

**`head_ref_id` points at the NAMED ref only — never the clone ref.** This is deliberate and respects your "deliberate non-goal": the CLI keeps cloning the canonical published branch. We never advertise `ref-pid-snw-web-ui` in the index.

**Path:** `bare/indexes/` — the same path your clone pipeline reads. (We checked: the web has no `bare/idx/` anywhere. The 04/16 path-mismatch finding doesn't apply to this build.)

### What this means for `test-vault-1` (and any web vault)
- Created/edited in the web **after this ships** → has an index from creation → `sgit clone` works without your fallback.
- Existing web vaults created before this ships → get an index on their **next Publish/push**. (Until then, your shipped CLI fallback handles them — belt and suspenders.)

## Fix 2 — `SGVault.open` reconcile-on-open (named head is canonical)

The bug you traced:

```js
// before
vault._headCommitId = cloneCommitId || namedCommitId   // pinned to clone once any web commit existed
```

Now:

```js
// after — clean-behind → adopt the canonical named head
let head = cloneCommitId || namedCommitId;
if (cloneCommitId && namedCommitId && cloneCommitId !== namedCommitId) {
    if (await vault._isAncestor(cloneCommitId, namedCommitId)) head = namedCommitId;  // clone strictly behind
}
vault._headCommitId = head;
await vault._loadTreeFromCommit(vault._headCommitId);
```

Semantics, matching your `Step__Pull__RO__Load_Named_Head` reference:
- **Clone strictly behind named** (clone is an ancestor of named — e.g. you pushed from the CLI while the web clone sat still) → load the **named** head. Your pushes are no longer shadowed.
- **Clone ahead / diverged** (unpushed web commits) → keep the clone head. Web work is never lost; the shell surfaces the divergence (auto-sync HUD warning).

**We fast-forward the VIEW only — we do NOT rewrite the clone ref at open** (no access token is applied that early in open; and the next web commit naturally advances the clone ref from the named head). So this is a pure, side-effect-free read correction — exactly the property you wanted.

This lands in the library (`SGVault.open`), so **every** caller — `/app`, `/vault`, and any agent using `SGVault.open` directly — gets the correct behaviour, not just one shell.
