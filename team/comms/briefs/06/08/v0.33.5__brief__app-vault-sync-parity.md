## The problem (two symptoms, one root cause)

Reported from the doctor/patient MVP:
1. Actions inside `/app` left **"↑4 to push"** when returning to `/vault`.
2. Refreshing `/app` showed **stale code** (old `index.html`), while `/vault` refresh showed fresh.

**Root cause (the same for both):** `/vault` (`vault-shell.js`) has an auto-sync engine — `_checkAndAutoSync` auto-**pushes** local commits and auto-**pulls** upstream, gated by `localStorage['sg-vault-autosync']`. **`/app` (`app-shell.js`) had neither.**

So app writes (`sg.fs.write`) committed to this browser's **working clone ref** (`ref-pid-snw-*`) but never pushed to the **named ref** (`ref-pid-muw-*`). When the editor (or another session) then pushed new code to the named ref, the clone and named **diverged**. Consequences:
- `/vault`'s auto-push surfaced the unpushed commits as "↑N to push".
- `/app` refresh: `SGVault.open` loads the tree from `_headCommitId = cloneCommitId || namedCommitId` (the clone), and `_syncViewToPublishedHead` deliberately refuses to fast-forward a **diverged** clone (would lose the local commits) → you see the clone's stale tree.

The fix is to give `/app` the same auto-sync behaviour `/vault` has.

---

## What shipped

All in `app-shell.js`, reading the **same** `sg-vault-autosync` flag as `/vault`:

| Piece | Behaviour |
|---|---|
| **Debounced auto-push** | After a successful `sg.fs.write` / `fs.move` / `fs.delete` / `fs.mkdir`, schedule a push ~2.5s after the last write (coalesces a burst into one push — the "Commit Queue" shape, Option B granularity). Skips when read-only, auto-sync off, nothing ahead, or diverged. |
| **Auto-pull on focus + mount** | `visibilitychange` → `_scheduleBehindCheck(500)`; also 1.5s after mount. Reads the live named ref; if the clone is **cleanly behind**, fast-forwards the view (`_syncViewToPublishedHead`) and remounts the app so new code renders. 30s debounce. |
| **Shared flag** | `_isAutoSyncEnabled()` reads `localStorage['sg-vault-autosync']` — the **same** key the `/vault` settings checkbox writes. One switch governs both surfaces. |
| **Visible "unpushed" warning** | When ahead and can't auto-push (auto-sync off / diverged / push failed), a **persistent** HUD warning (`_surfaceUnpushed`, `ttl=null`) — not just the easy-to-miss pill. Cleared on a successful push. |
| **seedFrom push fix** | `_seedVaultTree` now pushes the child vault after seeding, so seeded content lands on the child's **named** ref (visible to other openers), not just its clone. |

## Answers to the questions that drove this

- **"This shouldn't happen often, right?"** Correct — *after* this fix. Before it, the unpushed state happened on **every** app write (because `/app` never pushed). Now app writes auto-push (debounced); the unpushed state is rare: only when auto-sync is off, offline, or diverged.
- **"Can I replicate the manual-push behaviour by un-checking the sync box?"** Yes. The Settings checkbox writes `sg-vault-autosync`, and `/app` now reads the **same** flag. Uncheck it → both `/app` and `/vault` stop auto-syncing → you get the manual `↑N to push` / `Sync now` buttons + the persistent HUD warning to test against.
- **Refresh-stale, Option B (cache-bust ref reads):** Investigated — `sg-send.js vaultRead` **already** uses `cache: 'no-store'` (refs are never HTTP-cached). So the refresh-stale wasn't a caching problem; it was the **divergence** above. The unified fix (auto-push + auto-pull) resolves it at the root, which is why we went past Option B to the full engine.

## Design notes

- **Auto-push granularity = debounced batch (Option B).** A chatty app (e.g. the comms agent writing `conversation.json` per message) coalesces into one push instead of one-push-per-write. This is the right foundation for the inbox/comms apps and aligns with the Commit-Queue proposal (P-265).
- **Divergence is handled, not clobbered.** Auto-push backs off when the named ref advanced under us (another writer); the user is told to open `/vault` to merge. Auto-pull only fast-forwards a clean-behind clone. Neither operation can lose committed work.
- **Remount on auto-pull.** When `/app` fast-forwards, it re-runs `_continue(appJson)` so the iframe rebuilds from the new tree — this is what makes refreshed/updated app code actually render.

## Acceptance criteria

1. App write in `/app` → auto-pushed within ~3s → opening `/vault` shows "Synced", not "↑N to push". ✓ (browser-unverified)
2. New code pushed from `/vault`/CLI while `/app` is open → `/app` picks it up on tab focus (clean-behind). ✓ (browser-unverified)
3. Un-checking the Settings sync box disables auto-sync in **both** surfaces; the manual push button + persistent HUD warning appear. ✓ (browser-unverified)
4. Diverged state never auto-pushes (no data loss); surfaced prominently. ✓
5. `seedFrom` content is visible when the new vault is opened fresh elsewhere. ✓ (fix)
