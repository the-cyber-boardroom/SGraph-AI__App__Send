## Key Decisions Needing Your Review

### 1. SEC-VIV-002 fix timing (AppSec / Dev)
The popup capability over-grant is a **medium severity OPEN finding**. The agreed fix (gate popups to root vault only) is straightforward but is easier to implement cleanly after P-279 (kernel path unification makes inner-vault detection trivial). Options:
- **Quick patch now**: detect `CompositeDataSource` mounts at the four render sites, strip popup flags for inner-vault paths. Implementable today. Slightly awkward (CompositeDataSource is the render path being retired).
- **Defer to P-279**: cleaner implementation, no awkward detector, but leaves the finding open for longer.

### 2. Kernel path unification start (P-279) — Architect / Dev
The scoping doc is done and well-specified. This refactor removes a parallel code path that today is a security and maintenance liability. It also enables rw sub-vault writes (P-279) and makes P-280 trivial. The question is sequencing: does it displace Vault Chat (P-263), connectors (P-270), or the Akinator proving ground (P-275)?

### 3. CI gate verification (DevOps / Dev)
`_test-ui-vault.yml` is a reusable workflow. Verify that `deploy-ui-vault.yml` actually calls it as a pre-deploy gate (OQ-browser-int-tests-ci-1). If it doesn't yet, the 5 new browser tests run but don't block deploys.
