# Technical Debrief — `/app` now syncs like `/vault` (auto-push + auto-pull)

**Version:** v0.33.5
**Date:** 2026-06-08
**Branch:** `claude/zealous-thompson-yDjFX` (not yet merged)
**Audience:** The vault-manager / comms-agent app team
**Status:** **Implemented + loader-suite green. Browser-unverified — please run the checklist in §5.**

This closes the two things you flagged: "↑4 to push" after working in `/app`, and `/app` showing stale code after refresh. They had the same root cause and one fix.

---

## 1. What was wrong

`/vault` has always auto-pushed your commits and auto-pulled upstream changes. **`/app` did neither.** So when your patient app wrote `conversation.json` / `identity.json` via `sg.fs.write`, those commits landed on this browser's *working clone* and **never pushed**. The clone then *diverged* from the published (named) branch, which is why:

- Going to `/vault` showed **"↑4 to push"** (4 unpushed app writes).
- Refreshing `/app` showed **stale code** — a diverged clone can't safely fast-forward to the new published code, so `/app` kept showing the old tree.

(Worth noting: I checked, and the ref reads already use `cache: 'no-store'` — so this was never an HTTP-cache problem. It was the missing auto-sync.)

---

## 2. What you'll see now

- **Your app writes auto-push.** ~2.5s after your app's last write, the kernel pushes (debounced, so a burst of writes = one push). Going back to `/vault` should show **"Synced"**, not "↑N to push".
- **`/app` picks up new code.** When you push new app code from the editor (or CLI) while `/app` is open, `/app` fast-forwards on the next tab focus and remounts — and a normal refresh now shows fresh code.
- **One switch controls both.** The Settings "auto-sync" checkbox now governs `/app` too (same `sg-vault-autosync` flag).
- **The "unpushed" state is now loud.** If your changes *can't* auto-push (auto-sync off, offline, or diverged), you get a **persistent HUD warning** in `/app` — not just the easy-to-miss pill.

## 4. Behaviour details you should rely on (and not be surprised by)

- **Debounce window ≈ 2.5s.** If your app writes and the user immediately navigates away within that window, the push fires on the timer regardless (it's not tied to the iframe staying mounted within the kernel's lifetime). But a hard tab-close mid-debounce *can* drop the not-yet-fired push — the next time you open the vault anywhere with auto-sync on, it pushes. So: don't treat the write as "durable on the server" the instant `sg.fs.write` resolves; treat it as "durable locally, syncing shortly."
- **Divergence is never clobbered.** If another session pushed while you have local commits, the kernel does **not** auto-push (that would lose their work) — it shows the persistent warning and asks you to open `/vault` to merge. Auto-pull likewise only fast-forwards a clean-behind clone.
- **Auto-pull remounts your app.** When `/app` fast-forwards, it rebuilds the iframe from the new tree. If your app holds in-memory state that isn't persisted to the vault, expect it to reset on an auto-pull. Persist anything you care about (to the vault, or `sg.state.*`).
- **`seedFrom` is now durable.** Bonus fix: vaults created with `seedFrom` now push the seeded content to the child's published ref, so the new vault shows its template when opened fresh elsewhere (previously the seed sat only on the creator's clone).

## 5. Verification checklist (please run on dev)

These are timing/DOM behaviours the Node tests can't cover:

1. **Auto-push:** in `/app`, make your app write a file → wait ~3s → open the same vault in `/vault` → expect **"Synced"** (no "↑N to push").
2. **Auto-pull on focus:** open the vault in `/app`; from the `/vault` editor, edit `index.html` + push; switch back to the `/app` tab → within a moment it should fast-forward and show the new code.
3. **Refresh:** after #2, a normal refresh of `/app` shows the new code (not stale).
4. **Settings switch:** uncheck auto-sync → make an app write → expect it **stays** local + the persistent HUD warning appears + `/vault` shows "↑N to push" until you push manually.
5. **Divergence:** with auto-sync on, create a divergence (push from `/vault` while `/app` has an unpushed write) → `/app` should show the "open in vault to merge" warning and **not** clobber either side.

If #1–#3 behave, the two bugs you reported are fixed.
