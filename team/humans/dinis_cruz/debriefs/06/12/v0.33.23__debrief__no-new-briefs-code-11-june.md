## What Changed in Code

### `fix(vfs)` — commit `2892b4be` (11 Jun 2026)

**Files:** `app-shell.js`, `app-hud.js` (both in `v0.2.3/_common/js/components/app-shell/`)

**Fix 1 — `sg.vfs.write` 8KB cap (now RESOLVED):**
Vault apps could not write files larger than ~8KB. The bridge chunked bytes at 8192 per
`btoa()` slice; since 8192 mod 3 = 2 the non-final slices carried embedded `=` padding that
`atob()` rejected. Fix: chunk size 8192 → 8190 (= 3×2730) — clean multiples, no embedded
padding. Writes now succeed at any practical size (verified through 128KB). Added `EBADENC`
diagnostic for future debugging.

**Fix 2 — Privileges chip colour:**
The standing-grants chip was red when destructive grants were held, which users read as an
error state. Revised: default = slate (informational), destructive grants = amber. Active-
consent-bar red and activity-meter error-pulse red are unchanged.
