## Key Code Changes Since 06/04 Session

### 1. Dev Code-Review of Vault Inbox (`57edba8`)

A code review produced on 04 June found five issues in the vault inbox P0 implementation:

- **B-1 (Blocking):** `Storage_FS__S3.folder__folders` returned `[]` on Lambda/S3 — inbox `list` would silently appear empty on deployed stacks.
- **B-2 (Blocking):** Path traversal via unvalidated `file_id`/inbox strings on local-disk backend.
- **I-1 (Important):** Metadata listing read full payload bytes on every call — O(n·size) reads.
- **I-2 (Important):** Per-append byte-sum required a full-folder download on every write.
- **I-3 (Important):** fetch/mark-processed/purge accepted unbounded `file_ids` batches.

Review document: `team/roles/dev/reviews/06/04/v0.32.1__code-review__vault-inbox-implementation.md`

### 2. Vault Inbox Hardening (`e365c60`)

All five findings resolved. Two new Type_Safe primitives now exist:

- `Safe_Str__Vault__Append_Token` — validates and sanitises append tokens; rejects traversal sequences
- `Safe_Str__Vault__Inbox__File_Id` — validates and sanitises inbox file IDs; rejects traversal sequences

S3 `folder__folders` implemented with regression test. Metadata listing now reads zero bytes. Byte-sum removed. Batch cap 100 file_ids enforced.

**9 files changed, 435 insertions, 92 deletions. 957 unit tests green.**

### 3. Skill Description Fix (`2539220`)

Minor: `library/skills/create-vault-apps/SKILL.md` description field size corrected. No code impact.
