# Debrief — declared mounts: the safe list shipped, the refusals recorded, the agent briefed (2026-09-08)

## Executive summary

From the telemetry agent's findings you asked us to (a) separate what is safe from what we refuse on security grounds and (b) build the safe part. Both are done and code-verified.

**Built (S1–S7, S10):** every mutation now resolves with a receipt `{ commit_id, published }` (the per-write signal that was being discarded); `sg.fs.mkdir` and same-mount `sg.fs.move` go through the mount with a new child `vfs.move` handler; `sg.vault.mounts()` hands apps a flat projection instead of the raw kernel row; relays have a 30 s timeout so an unhandled verb can no longer hang an app; a shadow pre-flight event; the `Via-Mount` trailer carries the parent vault id; and the docs that cost the agent days (manifests replace, `network`, kernel-internal verbs, the narrow child grant, the 3 MB cap).

**Refused, with reasons on record:** `fs.delete` across a mount as a standing request (tier model), cross-boundary `move` (`EXDEV`), the raw mount row as a contract, `vault_id` in the row, any 404 on the append gate (existence oracle), silent enum-key derivation on a public-read vault.

**Corrected in the agent's brief:** their "one working witness" (the mount `state`) is refreshed only by the tab-focus behind-check and never by a write; `sg.history` is parent-only, never a snapshot; the child's vault id lives in the link file, not the row.

## Decisions to be aware of

- `sg.fs.delete` on a mounted path now returns `EUNDERPRIVILEGED` (was `EMOUNT_RO`). Same refusal, honest code.
- The receipt's `published:true` is a witness of the CAS publish, not of durability against blind pushes by other clones. The CAS-push ask to the CLI team is the real fix; until then the agent's recoverable/irreversible split stays.
- S9 (validate-before-fetch on append) is handed to the append-lanes owner; the enum-key public-read guard is a documented rule because the platform has no public-read flag to enforce it on.
