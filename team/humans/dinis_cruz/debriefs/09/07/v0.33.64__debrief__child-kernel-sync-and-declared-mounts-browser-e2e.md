# Debrief — child-kernel sync discipline + declared mounts proven in a real browser (2026-09-07)

## Executive summary

Your two asks from today's follow-up are delivered and code-verified:

1. **"Reconcile before write" is implemented.** A declared-mount child kernel now re-reads the
   published ref before every write (fast-forward or three-way merge), publishes with a
   compare-and-swap (`write-if-match`) and, on a lost race, merges and retries once — it never
   overwrites another writer's publish. Reads refresh on a 5-second throttle. Two new kernel verbs
   (`vfs.status`, `vfs.sync`) feed `KernelParent.status/sync/syncAll`, the HUD Mounts tab (new
   sync column) and the tab-focus behind-check.
2. **A full browser end-to-end exists, with screenshots and a how-to guide.** Real API server,
   real vaults, the shipped App UI, a real null-origin app iframe and child kernel iframe, plus a
   second writer racing the app. It runs offline in ~10 s.

The e2e paid for itself immediately: it found **six shipped defects** in the child-kernel path that
no Node harness could see (the very first real child boot in a browser died with
"SGSend is not a constructor"; the bootstrap port was posted before the iframe loaded; the child's
own policy was never read so every write was EPERM; …). All are fixed in the same change.

## Key decisions

- **CAS, not blind push, for headless kernels.** The shells keep `push()`; child kernels use
  `pushIfMatch()` because nobody is there to notice a lost update. Second CAS failure →
  `EDIVERGED`, local commit kept.
- **Declared mounts skip the broker's per-mount "ask".** The owner declared the mount, the app's
  grant is still checked, the app-level consent flow still runs, the child's policy still gates. A
  second prompt naming a mount id would reveal what the design hides.
- **The child's `.vault-settings.json` is hidden through a mount** (with `.vault/**`): it names the
  child.
- **The CDN layout manager is stood in for by test infra only** (`sg-layout-offline.js`), never by
  anything under test. The sandbox this session runs in cannot reach dev.tools.sgraph.ai.
