## ⚡ New capabilities for vault-app authors (hand this section to app agents)

All shipped and live. Full contracts in
[`AUTHORING.md`](../../../../../../library/guides/vault-html/AUTHORING.md) — the canonical
`window.sg.*` reference; the
[`create-vault-apps` skill](../../../../../../library/skills/create-vault-apps/SKILL.md) is
updated to match.

| New | One-liner | Notes |
|---|---|---|
| **`sg.vfs.download(path, {filename?})`** | `await sg.vfs.download('exports/report.pdf')` | Saves a vault file to the user's device, host-fulfilled — your sandbox needs no `allow-downloads` (in-frame blob-anchor downloads are silently dropped by Chromium; don't build them). One-click HUD confirm per file, or `"permissions": {"downloads": true}` for frictionless. |
| **`sg.ui.preview(path)`** | `await sg.ui.preview('docs/report.pdf')` | Host-rendered quick-look overlay for pdf/image/video/audio/text. **PDFs only work this way** — Chromium blocks its PDF viewer inside the app sandbox (empirically verified), so blob-iframe previews in-frame show a sad-document placeholder. No grant, no confirm (same permission chain as `vfs.read`). |
| **Bare-`#` anchors fixed** | `<a href="#section">` just works | The host interceptor scrolls in-frame. `location.hash` assignment from JS remains **banned** (srcdoc re-navigation). |
| **Interceptor opt-out** | `data-sg-native` attr, or `preventDefault` in window-capture | Sanctioned way for an app to handle its own anchor clicks — no more workarounds. |
| **`location.hash` fallback bug removed** | `page.html#id` deep links are safe | A missing target id is now a no-op (previously it re-navigated the frame to the vault-key screen). |
| **`sg.state.*` / `sg.append.*` documented** | device-local prefs / append-only inbox | Existing bridge features that were undocumented or stale-named; AUTHORING.md now covers both (note: it's `sg.append.*` with verb `write` — `sg.inbox.*` is gone). |

Still true and worth repeating to app agents: vault-relative `fetch()` does NOT work (use
`sg.vfs.readText`/`read` — read returns a raw `ArrayBuffer`, no size cap); direct vault-file
URLs in markup (`<a href="/exports/x.pdf">`, `<iframe src=...>`) can never work; `sgit share
send`/`publish` are disabled in the current CLI — hand off via vault keys or `--read-key`
read-only clones.

## Executive summary

1. **Documentation audit** of every `window.sg.*` guide/skill in the repo, cross-checked
   against the shipped bridge, the live sgraph.ai library vault, the Dev Docs vault, and the
   shipped sgit CLI. Headline: the live library carries **no** vault-app API content; the
   agent-facing skills had three factually wrong claims; `sgit share/publish` are disabled in
   the shipped CLI but taught everywhere. All repo-side fixes executed.
2. **Architect review** verified the cross-vault in-app-navigation issue report against
   source (all claims confirmed; three findings stronger than the report), and its adopt-now
   proposals were **implemented**: interceptor opt-out (`data-sg-native` +
   `defaultPrevented`), bare-`#` clicks claimed in-frame, `location.hash` miss-fallback
   removed.
3. **`sg.vfs.download` shipped** — the sanctioned, host-fulfilled download API requested by
   the eu-ai-act downloads report, with a new default-deny `permissions.downloads` grant and
   HUD confirm. The app sandbox needs no `allow-downloads` token.
4. **PDF-in-app question settled empirically, then solved:** blob-URL `<iframe>` PDFs are
   **blocked** by Chromium inside the App Mode sandbox (verified by screenshot matrix) —
   and **`sg.ui.preview(path)` shipped the same day** as the one-call answer: a
   host-rendered quick-look overlay at the real origin, where the native PDF viewer works.
   No grant, no confirm — gated by the existing read-permission chain only (Dinis's call:
   consent gates effects that outlive the page, not display of readable content).

## Key decisions

1. **Downloads are host-fulfilled, not sandbox-widened.** No `allow-downloads` token for app
   frames; the save runs in the host document behind a HUD confirm (or the `downloads` grant).
   Less privilege in the frame, consent the app can't suppress.
2. **Bare-`#` anchors are now a host responsibility** (in-frame scroll); `location.hash`
   assignment stays banned (srcdoc spec, not fixable host-side).
3. **`data-sg-native` / `defaultPrevented`** is the sanctioned interceptor opt-out — apps
   stop needing window-capture workarounds.
4. **PDF inline rendering:** blob-iframe is a dead end in the sandbox (empirically verified,
   contrary to my own earlier reply); PDF.js-to-canvas is the sanctioned in-frame approach.
   `sg.ui.preview(path)` — host-side overlay reusing `vault-file-preview` — is **PROPOSED,
   does not exist yet**.
