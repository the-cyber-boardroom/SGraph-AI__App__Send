## What Changed in Code

### Feature: app.json Resource Injection into Vault HTML Preview
**Commit:** `09288b20` | **Version:** v0.27.60 → v0.27.61

Apps hosted in SG/App vaults (`app.json` + `present:true`) have no `<link>`/`<script>` tags — all CSS/JS is declared in `app.json`'s `resources` block. On `/en-gb/app`, `<app-shell>` injects these automatically. The vault _file browser_ did not have this injection logic, so previewing an app entry HTML in the vault file browser produced a blank div.

**Fix:** When `_applyAppJson` encounters a `resources` block with CSS/JS arrays and `autoOpen` is set, it now:
1. Pre-fetches each resource file from the vault
2. Patches `dataSource.getFileBytes` for the entry HTML to prepend `<style>`/`<script>` blocks
3. send-browse's BRW-020 inlining creates the blob URL with resources already embedded

Result: vault file browser preview rendering now matches `/en-gb/app` exactly.

### E2E Test Alignment (Not a New Feature)
**Commits:** included in `e2f05030` merge

`test__routing.spec.js` and `test__regression__root_hash_inbox_saves.spec.js` updated to expect `/en-gb/app` instead of `/en-gb/vault` in routing assertions. The routing change was shipped 22 May (already documented in the 05/23 master index). These tests were catching up.
