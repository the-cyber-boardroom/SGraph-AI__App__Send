## The key insight

**This is mostly wiring, not new invention.** Almost every primitive already exists and is
code-verified:
- `.vault/owner/*` double-encryption (HKDF owner-secret over the read-key layer) — reused verbatim for the pointer file.
- `SGVault.openReadOnly(...)` and `VaultLoader.openROToken(...)` already resolve a `{vault_id, read_key, ref_file_id}` reference and open a vault read-only. **A sub-vault "pointer" is structurally a stored read-only-token payload**, so opening one is the code path we already ship.
- Lazy folder loading is the model for "pre-initialise on access."
- `app.json`/`_page.json` is the convention-file template we stay uniform with.

## The main decisions (for your sign-off)

- **One convention file, `type`-discriminated:** `.vault/owner/pointers.json` holds an array of
  `{type: vault|link|video|app, …}`. This answers the briefs' open question ("shared format + type field?") and settles naming simply (no stacked extensions).
- **Owner-only by default:** the pointer file is double-encrypted, so only the parent vault's
  full-key holder can read/traverse it (correct for the doctor use case). A reader-visible tier is an additive option later.
- **External embeds are default-deny and a *different* code path from apps:** cross-origin
  iframe, locked-down sandbox, **no VFS bridge, no message listener**. This is the security crux — see pack §6.
- **Scope:** Vault Web UI first (read + traverse + owner add). CLI clone-within-clone and the
  selective app-grant channel are deferred to a Phase 4 (their own brief).

## What the Designer changed (and we adopted)

Granting data access is now behind an "Advanced" disclosure with a type-to-confirm that names
the site, folder, and file count (no more one-click leak); the live "granted" embed state is
drawn (amber, names the folder, attributes the choice to you, inline Revoke); the embed
guarantee banner lost its ✕ and is sticky; and read-only viewers see none of the owner-only
pointers (the labels themselves are sensitive). A "BEYOND THIS VAULT" divider + consistent
trust chips replace the ambiguous emoji.
