## The plan in one screen

- **Sub-vaults are seamless inline folders.** Transparency = invisibility: the user just expands
  a folder. A subtle vault glyph + a `·ro`/`·rw` access chip is the only cue. No separate section.
- **A dumb, movable link file in the tree.** Any filename ending `.link.json`; the prefix is a
  user-chosen label, the suffix is the UI signal. It carries **no key** — only a public `vault_id`,
  a `ref_id`, a submodule-style commit `pin` (default *latest*), and a description. Rename it off
  the suffix and it becomes a plain `.json` file (a tidy "disable" gesture, and the reason no secret
  may live in it). The same vault can appear in many places; moving a sub-vault = moving the file.
- **Keys live in `.vault/owner/`, split by power:** `ro-links.json` (read_key-encrypted, readable
  by anyone with parent read access — read-only child keys) and `rw-links.json` (owner-only,
  double-encrypted — full child keys). Cross-referenced by `ref_id`.
- **Access is governed by the key you hold; v1 opens every sub-vault read-only** regardless of key
  (write/recursive-write deferred until nested commit/push management exists).
- **The link card** shows the vault's **public info before asking for a key** (accounting for your
  upcoming per-vault public-info / IDE brief), with save-to-vault / save-on-device / ask-each-time,
  and "open in new window" that tracks the parent↔sub-vault relationship so you don't lose the parent.
- **External resources stay strictly default-deny:** cross-origin iframe, locked sandbox, no bridge,
  no listener, sticky guarantee banner. The one sanctioned exception — an **opt-in, scoped, read-only
  app→vault grant** — is a first-class v1 capability (because the doctor-never-sees-the-vault workflow
  needs it); per-file monitoring and granularity come later.

## The key engineering insight

This is mostly *wiring existing parts together*: `SGVault.openReadOnly` and `VaultLoader.openROToken`
already resolve a `{vault_id, read_key, ref_file_id}` reference and open a vault read-only; `.vault/owner/*`
double-encryption is the audited store for the keys; lazy sub-tree loading is the model for "open on
access"; `app.json`/`_page.json` is the convention template. No backend change is needed for v1.
