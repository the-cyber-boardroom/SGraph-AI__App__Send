## The Critical Architectural Correction

**IMPORTANT: Read the data broker brief (doc 516, P-271) before any connector implementation.**

The original connector framework (doc 513) assumed the null-origin app iframe could perform OAuth. This is wrong — Phase 3's security gate (already shipped) made all app iframes null-origin, and null-origin frames have no URL for OAuth redirects to land on.

**The fix (data broker model):**
- A separate data broker iframe holds all OAuth tokens and makes all API calls
- The UI app renders and asks the broker; it never touches credentials
- The top-level kernel receives the OAuth redirect and relays it PKI-encrypted to the broker
- Only the broker can decrypt the credentials (PKI-encrypted to its public key)

This is architecturally correct and consistent with the VIV design. It adds modest implementation complexity (a second iframe per connector) but is the only viable approach.
