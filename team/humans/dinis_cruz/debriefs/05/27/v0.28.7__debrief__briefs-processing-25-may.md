## Executive Summary

The 25 May briefs complete the SG/Send product thread begun on 24 May, taking the vault from a storage-and-transfer primitive to a richer product surface. The day's through-line: **a vault can now contain other vaults, embed the outside world, show a public face, and be talked to — all without backend complexity.**

Three of the four capabilities are code-complete on `dev` (though browser-unverified):
- **Sub-vaults** (Phase 0–3): inline vault traversal + external resource embedding + Add link UI + cross-device portable access
- **Public vault previews**: deterministic derivation + transfer-based storage + OG-render service + editor (confirmed shipping in the day-index)
- **App-iframe permission model** (Phases 1–4B): security floor + grant-aware FS + consent surface + vault.create/unlink

The fourth — **talk to the vault (vault chat)** — is proposed (P-248) with a comprehensive 12-document code-grounded architecture dev pack (v0.27.80) ready for an implementation session.
