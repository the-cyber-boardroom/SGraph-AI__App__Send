## Feature 1 — Share a Secret

A new **Secret tab** in the upload wizard lets senders create ephemeral
zero-knowledge encrypted text secrets. The flow:

1. Sender switches to the Secret tab, types their text, sets max views (1/5/10) and
   expiry (1 h / 24 h / 7 d / never).
2. Text is wrapped in the standard SGMETA envelope, encrypted AES-256-GCM in-browser,
   and uploaded via `createTransfer` with a new `secretConfig` payload.
3. After upload, the Done panel shows a share link (`/en-gb/s/{id}#{keyHex}`) and a
   kill link (`/en-gb/s/kill/{id}#{deleteAuth}`).
4. The recipient visits the share link. The new `/en-gb/s/index.html` receive page
   downloads the ciphertext, decrypts it, strips the SGMETA envelope, and renders the
   plain text — all in-browser. The key never reaches the server.
5. The kill path on the same page renders a "Delete Now" confirmation that calls
   `DELETE /api/transfers/delete/{id}` with the raw `deleteAuth` token.

**Delete auth** is a random 32-byte token generated client-side. The server stores
`sha256(deleteAuth)`; the raw token travels only in the `#fragment` of the kill URL
and is never sent in HTTP requests.

## Backend Work Needed

### REQUIRED for Feature 1: `expires_at` type fix

**Problem:** The frontend sends `expires_at` as **int milliseconds** (`Date.now() + delta`,
e.g. `1746652800000`). The backend `Schema__Transfer.expires_at` is declared as `str`
(ISO-8601 string), and `Transfer__Service._is_expired()` parses it as a string.

**Impact:** Secret expiry will not function correctly until this is fixed. Secrets
without expiry (`expires_at=0`) and max-download enforcement will still work.

**Required backend changes:**

1. **`Schema__Transfer`** — change `expires_at: str` to `expires_at: int` (milliseconds
   since epoch, 0 = never expires). Default should be `0`.

2. **`Transfer__Service._is_expired()`** — update to compare int ms:
   ```python
   def _is_expired(self, transfer):
       expires_at = transfer.expires_at
       if not expires_at:          # 0 or None = never expires
           return False
       return int(time.time() * 1000) > expires_at
   ```

3. **`Transfer__Service` or handler** — when creating a transfer with `secretConfig`,
   store `secretConfig.expires_at` (int ms from frontend) into `transfer.expires_at`.

4. **`GET /api/transfers/{id}/info`** — response should include `expires_at` (int ms)
   so the receive page can display "expires in X hours". Currently `send-secret-view.js`
   reads `transferInfo.expires_at` directly.

Until these backend changes land, the expires_at field will be stored as-is (Python may
coerce int→str with `Type_Safe`) and the expiry check will always return False (no
expiry enforced). Everything else — encryption, download, SGMETA stripping, kill flow,
max_downloads enforcement — works independently of this fix.
