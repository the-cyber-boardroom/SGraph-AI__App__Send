## What This Debrief Covers

This session resolved a chain of bugs introduced by the IFD layered-merge
approach for the vault UI (v0.2.0 → v0.2.1 → v0.2.2), and concluded with the
creation of **v0.2.3 as a full self-contained snapshot** to prevent the same
class of bug recurring.

---

## Part 1 — What Went Wrong With the Previous Layered Approach

### The IFD Layer Structure Before v0.2.3

The vault UI is built using IFD (Incremental File Delta). Each version only
commits the files that changed. The three previous versions had disjoint
concerns:

| Version | What it contained | URL it served |
|---|---|---|
| `v0.2.0` | Full base: all `_common/` JS/CSS/fonts, original `en-gb/index.html` | `/` and `/en-gb/` |
| `v0.2.1` | Design 02 landing page (`en-gb/index.html`), `en-gb/browse/index.html`, sg-site-header, vault-settings update | `/en-gb/` (new look) |
| `v0.2.2` | App Mode root shell (`index.html`), sg-app-banner, vault-browse-edit update | `/` (new shell) |

Note: **v0.2.2 has no `en-gb/` directory at all.** It only changed the root
shell. The Design 02 landing page lives in v0.2.1.

### The Merge Logic Required by This Structure

**CI workflow** (`deploy-ui-vault.yml`) had to:
1. Set `SOURCE_DIR = v0.2.2` (latest, only has `index.html` + `_common/` delta)
2. Set `BASE_SOURCE_DIR = v0.2.1` (has `en-gb/index.html`)
3. Seed `en-gb/` by copying `v0.2.1/en-gb/` into `v0.2.2/en-gb/` before the i18n script ran

**Local dev script** (`vault__run-locally.sh`) had to:
```bash
VAULT_BASE_VERSION="v0.2.0"
VAULT_IFD_OVERLAYS=("v0.2.1" "v0.2.2")
```
Then loop over base + overlays, merging each layer's `_common/` and locale dirs
into `.local-server-vault/`.

### Why This Caused Bugs

The layered merge was brittle. Two specific failures happened:

**Bug A — Wrong file at `/en-gb/`**
The CI "Populate en-gb/" step used `cp -r $BASE_ENGB $CURR_ENGB`. If that step
failed silently, or ran after the vault shell was already written, `en-gb/index.html`
would be the vault shell (`v0.2.2/index.html`) instead of the Design 02 landing
page (`v0.2.1/en-gb/index.html`). The two files are completely different:

- Vault shell: complex JS routing, requires `_common/` assets, serves at `/`
- Design 02 landing: standalone HTML, inline CSS/JS, no `_common/` deps, serves at `/en-gb/`

When the wrong file was served at `/en-gb/`, the vault shell loaded `_common/`
assets using relative paths (`href="_common/..."`) — but at two directory levels
deep, those paths resolved to `/en-gb/_common/...` which did not exist on S3.
The result: **403 errors on every asset** and then an **infinite redirect loop**
as the shell script tried to navigate to `/en-gb/` when it was already there.

**Bug B — Python IndentationError in CI**
An earlier fix used `python3 -c "..."` inside a YAML `run:` block. YAML
indentation adds leading whitespace to every line of the heredoc, and Python
rejects leading whitespace with `IndentationError`. This silently broke the
path-rewriting step that generates `en-gb/vault/index.html`.

Both were fixed with `sed` replacements (`sed -e 's|href="_common/|...|g'`) but
the root cause — a fragile multi-layer merge — remained.

## Part 2 — How v0.2.3 Was Built

### The Decision

Rather than maintain the layer-merge machinery indefinitely, **v0.2.3 was created
as a complete isolated snapshot** — one directory that contains every file needed
to serve the full vault UI with no external dependencies on earlier versions.

The IFD guide explicitly permits "consolidation snapshots" at version boundaries.
This is the right moment: three previous deltas, a complex merge, and a
deployment bug triggered by the fragility of that merge.

### Files Copied and From Where

The v0.2.3 tree was built by applying the three previous versions in order
(oldest → newest), so later versions override earlier ones:

```
Step 1: cp -r v0.2.0  v0.2.3        # Start from full base
Step 2: cp -r v0.2.1/. v0.2.3/      # Apply v0.2.1 deltas on top
Step 3: cp -r v0.2.2/. v0.2.3/      # Apply v0.2.2 deltas on top
```

This is exactly what the merge scripts were doing at runtime, but done once at
commit time.

**What came from each source version:**

| Source | Files brought into v0.2.3 | Notes |
|---|---|---|
| `v0.2.0` | All of `_common/` (55+ files): fonts, CSS, all JS components and libraries | Full base layer — everything |
| `v0.2.0` | `en-gb/index.html` | Old landing page — **immediately overwritten by v0.2.1** |
| `v0.2.1` | `en-gb/index.html` | **Design 02 landing page** — "Open a vault." hero, recent vaults grid, standalone |
| `v0.2.1` | `en-gb/browse/index.html` | Browse redirect page |
| `v0.2.1` | `_common/js/components/sg-site-header/v1/v1.0/v1.0.6/sg-site-header.{js,css,html}` | Site header component |
| `v0.2.1` | `_common/js/components/vault-settings/vault-settings.js` | Updated vault settings |
| `v0.2.1` | `index.html` | v0.2.1 vault shell — **immediately overwritten by v0.2.2** |
| `v0.2.2` | `index.html` | **App Mode vault shell** — sg-app-banner, vault-browse-edit, localStorage routing |
| `v0.2.2` | `_common/js/components/sg-app-banner/sg-app-banner.js` | App banner component |
| `v0.2.2` | `_common/js/components/vault-browse-edit/vault-browse-edit.js` | Updated browse/edit |

## Part 3 — How the Deployment Scripts Changed

### CI Workflow (`deploy-ui-vault.yml`)

**Before (layered):**
```yaml
env:
  UI_VERSION      : v0.2.2
  SOURCE_DIR      : sgraph_ai_app_send__ui__vault/v0/v0.2/v0.2.2
  BASE_SOURCE_DIR : sgraph_ai_app_send__ui__vault/v0/v0.2/v0.2.1

steps:
  - name: Populate en-gb/ for i18n (IFD delta merge)
    run: |
      BASE_ENGB="${{ env.BASE_SOURCE_DIR }}/en-gb"
      CURR_ENGB="${{ env.SOURCE_DIR }}/en-gb"
      if [ -d "$BASE_ENGB" ]; then
        cp -r "$BASE_ENGB" "$CURR_ENGB"
      fi

  - name: Generate i18n locale pages
    run: python scripts/generate_vault_i18n_pages.py --version ${{ env.UI_VERSION }}

  - name: Generate en-gb/vault/index.html
    run: |
      mkdir -p ${{ env.SOURCE_DIR }}/en-gb/vault
      sed -e 's|href="_common/|href="/_common/|g' \
          -e 's|src="_common/|src="/_common/|g' \
          "${{ env.SOURCE_DIR }}/index.html" > "${{ env.SOURCE_DIR }}/en-gb/vault/index.html"
```

**After (snapshot):**
```yaml
env:
  UI_VERSION : v0.2.3
  SOURCE_DIR : sgraph_ai_app_send__ui__vault/v0/v0.2/v0.2.3

steps:
  # No "Populate en-gb/" step — en-gb/ is already in v0.2.3

  - name: Generate i18n locale pages
    run: python scripts/generate_vault_i18n_pages.py --version ${{ env.UI_VERSION }}

  - name: Generate en-gb/vault/index.html
    run: |
      mkdir -p ${{ env.SOURCE_DIR }}/en-gb/vault
      sed -e 's|href="_common/|href="/_common/|g' \
          -e 's|src="_common/|src="/_common/|g' \
          "${{ env.SOURCE_DIR }}/index.html" > "${{ env.SOURCE_DIR }}/en-gb/vault/index.html"
```

Key changes:
- `BASE_SOURCE_DIR` env var removed entirely
- "Populate en-gb/" step removed — `en-gb/` already exists in v0.2.3
- `en-gb/vault/index.html` generation step retained (it's a CI-generated file, not committed)

### Local Dev Script (`vault__run-locally.sh`)

**Before (layered merge):**
```bash
UI_VERSION="v0.2.2"
IFD_PATH="v0/v0.2/$UI_VERSION"
VAULT_BASE_VERSION="v0.2.0"
VAULT_IFD_OVERLAYS=(
    "v0.2.1"
    "v0.2.2"
)
```

The script then ran three merge loops:
1. Locale dirs (en-gb/, etc.) from all vault IFD layers base→latest
2. `_common/` from base, then overlaid each version's `_common/` delta
3. User UI IFD layers on top of `_common/`

**After (snapshot):**
```bash
UI_VERSION="v0.2.3"
IFD_PATH="v0/v0.2/$UI_VERSION"
VAULT_BASE_VERSION="v0.2.3"
VAULT_IFD_OVERLAYS=()
```

Now the vault merge loops have only one iteration (the base v0.2.3 itself) and
no overlay loop at all. The user UI layer merge (`USER_UI_LAYERS`) is unchanged —
it still applies `v0.3.0` → `v0.3.1` → `v0.3.2` → `v0.3.3` on top of
`_common/` for local CDN override.

## Part 4 — Context: Other Changes Made This Session

This consolidation was the final step in a longer session that fixed several
routing and deployment bugs. For completeness:

1. **Infinite redirect loop** — `v0.2.2/index.html` had a script clause
   `else if (noHash && !onVaultPath) { window.location.replace('/en-gb/') }`
   that fired when already at `/en-gb/`, looping forever. Removed.

2. **localStorage as vault-key source of truth** — hash-based routing
   (`window.location.hash`) replaced with `localStorage('sg-vault-key')`. The
   only place a hash is accepted is root `/` (saves to localStorage, then
   redirects to `/en-gb/` and strips the hash). All other URLs strip any hash
   they receive without acting on it.

3. **`vault-entry.js` history.replaceState calls removed** — two calls that
   put the vault key back into the URL hash were removed. The key now lives
   only in localStorage and never appears in the URL.

4. **Python IndentationError in CI** — both path-rewriting steps that used
   `python3 -c "..."` inside YAML were replaced with `sed`.

## Part 5 — Resuming the Delta Pattern After v0.2.3

When the next change is needed (e.g. a UI tweak, a new component), create
`v0.2.4/` containing **only the changed files**. Then in the scripts:

```bash
# vault__run-locally.sh
VAULT_BASE_VERSION="v0.2.3"
VAULT_IFD_OVERLAYS=("v0.2.4")
```

```yaml
# deploy-ui-vault.yml
UI_VERSION      : v0.2.4
SOURCE_DIR      : .../v0.2.4
BASE_SOURCE_DIR : .../v0.2.3   # re-introduce to seed en-gb/ if v0.2.4 lacks it
```

The next "full snapshot" consolidation is warranted when overlays accumulate
complexity again or a major structural change makes the tree unreadable from
the delta history.
