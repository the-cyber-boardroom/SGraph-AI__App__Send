(dev.vault.sgraph.ai), the SGit protocol, the two Lambdas, the Type_Safe/OSBot house style,

Headline: the briefs are sound and land on patterns the codebase has already shipped in
miniature — Vault Append **is** the append-and-settle rail, `sg.llm.*` **is** the budget

access-token system **is** the credential-record seed. Five items need correcting/deciding
first (stale reservation remnants in the gateway brief; the write-without-read mechanism as
described is the PROPOSED PKI layer, not the shipped hash-gated tokens; one-vault read
access is all-or-nothing so the snapshot needs its own store; the streaming gateway cannot
run on the Python/Mangum Lambda house pattern — container plane recommended; and the
OpenRouter-resale invalidation must be recorded in the reality tree).

## Key findings / decisions surfaced

- **Strongest shipped precedents:** `sg.llm.*` chokepoint (permission → consent → budget →
  policy → call, typed errors, shared ledger, key custody), Vault Append four-tier blind
  inbox, `VaultLlmLog` reconciliation invariants, release-channel pinning for immutable
  receipts, owner-secrets credential custody.
- **Platform boundaries a payment design must compensate for:** refs are last-writer-wins
  (use the shipped `write-if-match` CAS), commits are unsigned, timestamps are
  client-asserted, deletion is possible, and sharing a vault key shares spend authority
  (closed by gateway credential records = the vault UI's PROPOSED minted credentials).
- **Convergence insight:** when SG/Send's `sg.llm.*` host swaps its raw OpenRouter key for
  a gateway credential, every vault app gets server-enforced per-agent budgets and
  vault-held provenance with zero app changes.
- **Process note:** the three v0.33.56 briefs were reviewed from uploads; they are not yet
  in `briefs/` (human-only folder) — please add them so the Librarian daily run can index
  them and record the OpenRouter correction.
