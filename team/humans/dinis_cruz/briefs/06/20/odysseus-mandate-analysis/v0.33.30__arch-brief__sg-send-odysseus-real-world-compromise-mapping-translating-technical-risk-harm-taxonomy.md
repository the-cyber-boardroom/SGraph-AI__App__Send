## What This Is

A further mapping of what a real compromise of the user's assets would look like, building on the Odysseus case study: **the risks and capabilities are still stated too technically for a normal user or exec to picture, so they need translating into an accurate, plain representation, for example access to all local files understates the situation, because the same access reaches the credentials, tokens, and keys stored on the machine or reachable through a logged-in session, which is both worse and more accurate; the mapping then sets out, factually, what an over-enthusiastic or a malicious agent could do, access data, delete it, corrupt it, corrupt it irreparably, act on behalf of the user, exfiltrate it, contact others as the user, and affect data belonging to other users, departments, or entities, all under the user's own account and ownership, because the user granted the mandate; the treatment is deliberately factual, objective, and unemotional, and these are potential risks that have not occurred.** It extends the Odysseus case study toward a representation a non-technical audience can act on (cross-ref: the v0.33.30 Odysseus case study, the v0.33.28 assessment-template and side-effects briefs, and the v0.33.40 infrastructure-not-built-for-agents and risk-acceptance briefs). New contributions: **the capability-to-reality translation, the harm taxonomy, and the under-the-user's-mandate framing.**

## The Framing

What was asked: **make the risk legible, factually.**

The risks and capabilities are still very technical and hard for a normal user or exec to visualise. The task is to map them into an accurate real-world representation, to keep it factual, objective, and unemotional, and to be clear that these are potential risks that have not yet happened.

## Translating Capability Into Accurate Reality

The principle: **state a capability as the consequence a person can picture, accurately.**

A technical capability should be expressed as the accurate consequence it produces, which is often both more legible and more serious than the technical phrasing, not because of emphasis but because the technical phrasing understates the reach. The clearest example: access to all local files reads as a bit bad, but the same file and session access reaches stored credentials, tokens, and keys, and anything reachable through a browser session the user is already logged into, which is the accurate representation of the same fact.

| Stated technically | Accurate representation |
|--------------------|-------------------------|
| Access to all local files | Access to stored credentials, tokens, keys, and anything reachable through a logged-in session |
| Shell or run code | The ability to run any command under the user's account |
| Email access | The ability to read the entire mailbox and send messages as the user |
| Persistent memory | A standing, growing record of the user's data and context |
| Web or deep research | Reading external content that an outsider can control |

Each right-hand cell is the same capability, stated as what it actually reaches.

## What An Over-Enthusiastic Or Malicious Agent Could Do

The taxonomy, stated factually: **the same actions follow whether the agent is over-eager or hostile.** The distinction does not change the capability; an over-enthusiastic agent and a malicious or hijacked one can take the same actions, because the mandate is the same.

| Action | Factual consequence | Note |
|--------|---------------------|------|
| Access data | Read anything the account can reach | The starting point for the rest |
| Delete data | Remove data | Recoverable only if a separate backup exists |
| Corrupt data | Alter data | A small, unknown amount of corruption forces the whole dataset to be treated as untrusted, because there is no way to tell what was changed |
| Corrupt irreparably | Alter data with no recovery | When the system overwrites in place without effective version control, the change cannot be undone, and many databases and systems work this way |
| Act on behalf of the user | Sign, decide, approve, share | Carries the user's authority |
| Exfiltrate data | Move data into other systems | Out of the user's control |
| Contact others as the user | Send messages or requests to others | Can create obligations or conflict in the user's name |
| Affect other parties | Change or expose others' data | Other users, departments, or entities |

The corruption rows are worth stating plainly: corrupting data is more damaging than deleting it, because deletion is known and bounded, while corruption is unknown in extent, and a small, undetected corruption requires the entire dataset to be assumed corrupted. When the underlying system overwrites changes in place and lacks effective version control, that corruption is also unrecoverable (cross-ref: the infrastructure-not-built-for-agents thesis on overriding versus journaling).

## Under The User's Account And Ownership

The attribution point, stated without blame: **every action carries the user's identity, because the user granted the mandate.**

All of the above would be done under the user's own account, with the user's authority and ownership, because the user is the one who gave the agent the mandate to act. This is a statement of attribution, not fault: the actions are indistinguishable from the user's own, which is what makes the mandate the right unit to examine before it is granted (cross-ref: the risk-acceptance brief).

## Why This Matters For Representation

The product point: **the assessment should present these accurate consequences, not the technical capabilities.**

For a user or an exec to make a good decision, the assessment must show the accurate, plain consequence of each mandate, not the technical capability, so that what they are authorising is visible. This is the recipient-language principle and the not-surprised principle applied to harm: the same facts, stated so a non-technical person can see them (cross-ref: the side-effects recipient-language brief and the first-cohort not-surprised definition).

## Honest Notes

- **These are potential risks.** They are derived from the capabilities the mandate grants; they have not occurred, and the mapping does not claim otherwise.
- **Factual and unemotional by design.** The aim is accuracy a person can picture, not emphasis; the translation is more serious only because the technical phrasing understates the reach.
- **The translation must stay accurate.** It must not inflate; each accurate representation has to be defensible against the actual capability.
- **Not unique to Odysseus.** The same mapping applies to any broadly privileged agent; Odysseus is the worked example.
