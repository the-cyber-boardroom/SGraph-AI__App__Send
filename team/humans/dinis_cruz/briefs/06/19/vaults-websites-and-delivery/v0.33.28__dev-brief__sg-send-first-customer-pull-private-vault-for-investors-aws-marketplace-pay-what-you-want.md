# The First Real Pull: A Private Vault For Investors, On The AWS Marketplace

**version** v0.33.28
**date** 19 June 2026
**from** Human (project lead)
**to** Product, Architect, Go-To-Market, @Dev
**type** Dev brief (first-customer milestone)

---

## What This Is

The first real customer pull, turned into a milestone: **someone asked to run a private vault to share information with investors, and telling them to grab the Docker image and run it as a Lambda function or on ECS felt too complex, so the move is to publish the Docker container we already have on the AWS Marketplace with multiple deployment options and multiple permission options, at a very small or zero markup, possibly pay-what-you-want initially to learn how it goes; it is a nice first major milestone and a real use case, with several people already asking to run vaults in their own environment, so make it super easy.** It is the first concrete instance of the run-everywhere principle and the run-not-maintain distinction (cross-ref: the v0.33.28 run-everywhere and need-to-focus briefs, the v0.33.40 commercial-model brief, and the v0.33.2 aws-deployment-lambda and shipping-vault-product briefs). New contributions: **the first-pull validation, the too-complex realisation, and the AWS Marketplace launch.**

## The Framing

What happened: **the first request, unprompted, from a real person.**

The project lead: **"today I had the first request from someone I know, who said, I want to run your vault and share some information with investors. Can I run a private vault? That is really cool."** So this is genuine demand pull, exactly the kind of real use the Explorer phase is meant to discover (cross-ref: the need-to-focus brief).

## Too Complex As It Stands

The friction that surfaced: **the deployment options were too much.**

The project lead: **"it is funny, because I said, you can grab this, you can use Docker Hub, you can run it as a Lambda function, you can run it on ECS, and they felt, that is already too complex."** So the current path asks too much of a willing customer, and the lesson is that willingness is not enough without an effortless route.

## The Move: AWS Marketplace

The fix: **publish the container we already have.**

The project lead: **"what we need to do is put the Docker container we already have on the AWS Marketplace, and figure out the multiple deployment options and the multiple permissions you can give it. That way it should just work. It would be interesting to also do it as a Lambda deployment, but let's start with the AWS Marketplace to run an instance."** So the deliverable is a Marketplace listing of the existing container, with the deployment and permission options exposed as choices, starting with a running instance and a Lambda variant to follow (cross-ref: the run-everywhere marketplace point).

## Pricing: Small Or No Markup, Pay-What-You-Want

How to price the first launch: **learn, do not extract.**

The project lead: **"start with a very small markup, or even no markup, and maybe a pay-what-you-want mode initially, to understand how it goes."** So the first launch is priced to learn, not to extract: near-zero markup and, if it can be arranged, a pay-what-you-want approach, so the goal is adoption and signal rather than revenue (cross-ref: the need-to-focus and commercial-model briefs).

## A First Major Milestone With Real Demand

Why it matters: **it is real, and it is not the only one.**

The project lead: **"that is a nice first major milestone, because it is a real use case. And it is not the only one, I have already had several people ask the same thing. Several people want to run the vaults in their environment, so let's make it super easy for them."** So this is both a milestone and evidence of a repeatable need, which is the run-not-maintain demand made concrete (cross-ref: the run-everywhere brief).

## The Validation

What this proves: **the principle has a customer.**

This is the first concrete proof of the run-everywhere and run-it-yourself-maintained-by-us model: a real person wants to run a private vault in their own environment for a real purpose, sharing with investors, and the job is to remove the friction, not to add features. It validates the Explorer focus on discovering real use and the architecture choice that made the container portable in the first place.

## What This Asks For

1. **Publish the existing Docker container on the AWS Marketplace.**
2. **Expose multiple deployment options** (instance first, Lambda to follow).
3. **Expose multiple permission options** (the choices a buyer gives it).
4. **Price to learn** (very small or zero markup; pay-what-you-want if feasible).
5. **Make it effortless** (one purchase, deployed, no maintenance worry).
6. **Treat it as a milestone** (the first real pull, with several more waiting).

Estimated effort: low to moderate; the container exists; the work is the Marketplace listing, the options, and the pricing setup.

## What This Does Not Try To Be

- **Not a new build.** It is the existing container, listed.
- **Not a revenue play yet.** It is priced to learn.
- **Not maintenance dumped on the buyer.** We maintain it; they run it.
- **Not AWS-only forever.** Start with AWS; other clouds follow.

## Honest Tensions

**Tension 1: pay-what-you-want may not map to Marketplace pricing.** AWS Marketplace supports specific models, free, bring-your-own-licence, usage-based, and contract pricing, and a literal pay-what-you-want may need to be approximated by a free or low fixed-price listing. Mitigation: confirm the supported model and pick the closest to the intent.

**Tension 2: the permission options need defining.** Multiple permissions is vague. Mitigation: define the concrete deployment and permission choices a buyer makes.

**Tension 3: near-zero markup versus the commercial model.** This undercuts the billable-units model. Mitigation: this is a deliberate learning launch, not the pricing strategy.

**Tension 4: support load from self-run instances.** Buyers will need help. Mitigation: keep it effortless and maintained-by-us, and learn the support pattern from the first few.
