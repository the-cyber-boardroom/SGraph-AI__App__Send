## What This Is

An expansion of the skills idea (cross-ref: the v0.31.7 semantic-knowledge-graphs-for-agentic-skills brief) from the point of view of the **creator**: a human, company, or agent that needs a way to create, visualise, and distribute skills, and to be rewarded for doing so. The proposal has two parts. First, the **base vault**: a rich, curated skill vault that holds far more than a SKILL.md, everything that helps with explainability, provenance, and execution. Second, the **commercial model**: the creator sells and licenses a customised, supported version of that base vault to a specific customer and use case. Together these make SG/Vault the substrate for a **creator economy for skills**, where a creator is paid and rewarded for their experience, skills, brand, and reputation.

This reframes the earlier skills work. The skills-graph brief looked at skills from the consuming agent's side (discover, sequence, reason). This brief looks at them from the producing creator's side (build, curate, visualise, license, sell), and SG/Vault is well-suited to both.

## The Shift In Point Of View: The Creator

The earlier work treated skills as things an agent uses. This brief treats them as things a creator produces: **a human, a company, or an agent that has expertise worth packaging, and needs a way to create, visualise, and distribute it.** The creator's needs are different from the consumer's:

| The Consumer (Earlier Brief) | The Creator (This Brief) |
|------------------------------|--------------------------|
| Discover and select skills | Create and curate a skill |
| Reason over and sequence skills | Visualise and explain a skill |
| Execute skills | Distribute, license, and sell a skill |
| Trust a skill (provenance) | Build provenance, reputation, and a brand |

SG/Vault helps the creator specifically, because creating, visualising, and distributing a rich skill is exactly what a vault is for: a self-contained, curated, version-controlled, shareable, encryptable, sellable package. The skill is no longer just a SKILL.md folder; it is a curated body of work, and the vault is how a creator builds, holds, and sells that body of work.

## The Base Vault: Far More Than A SKILL.md

The central idea: **a skill, done properly by a creator, is a "base vault" holding far more than a SKILL.md, all the materials that make the skill explainable, trustworthy, and executable.** The creator takes the time to create, collect, and curate this base vault; it is the canonical, complete expression of their skill.

What a base vault holds:

| Contents | What It Is |
|----------|------------|
| **SKILL.md** | The skill definition itself (the Agent Skills standard) |
| **Documentation (in Markdown)** | From usage guides, to agentic guidance, to architecture diagrams |
| **Code (in multiple languages)** | The implementation, if the skill needs code, across languages |
| **Supporting materials** | Images and PDFs of referenced material about the skill |
| **Images and infographics** | Created about the skill (cross-ref: the infographic tool and visualisation work) |
| **Semantic graph** | For the skill and all its materials: multiple linked ontologies and taxonomies (cross-ref: the skills-graph and vault-per-standard briefs) |
| **Control flows, CI pipelines, integrations** | How the skill runs, deploys, and integrates (cross-ref: the agent-controlled-websites CI pipeline) |
| **Security materials** | For example, threat models (cross-ref: the security-report and SG/Sentinel work) |
| **Tests and evals** | How the skill is verified and evaluated |
| **Licenses and commercial model** | Ideally mostly open source and CC-licensed, but the model supports anything |
| **Anything else relevant** | Any doc or material that helps with explainability, provenance, and execution |

The unifying principle, in the project lead's words: **basically any doc or material that is relevant and will help with explainability, provenance, and execution.** So the base vault is not a thin artefact; it is the whole curated workshop around a skill, the definition, the docs, the code, the references, the visuals, the semantic graph, the pipelines, the security analysis, the tests, and the licensing. This is the vault-as-workshop model (cross-ref: the vault-per-standard brief, where the vault held raw, transformations, model responses with provenance, visualisation, and mini tools) applied to a skill: everything about the skill, curated in one self-contained, version-controlled vault.

Three of these deserve emphasis because they are where SG/Vault adds the most:

- **The semantic graph** (multiple linked ontologies and taxonomies for the skill and all its materials) is what makes the base vault navigable and reasoned-over, not just a pile of files. It connects the docs to the code to the references to the tests, so the whole skill is one coherent, explainable graph (cross-ref: the skills-graph brief).
- **The security materials** (threat models, and the security analysis from the store) make the skill trustworthy before anyone runs it, which matters because skills carry execution risk (cross-ref: the skills-graph brief's safety-surface point).
- **The provenance** (which the vault provides by being version-controlled with stored transformations and model responses) is what underpins the creator's reputation: every claim about the skill traces to its evidence, so a buyer can trust it, and the creator's brand is built on verifiable work.

## The Creator Curates The Base Vault

A key point: **the base vault is something the author takes the time to create, collect, and curate.** It is not auto-generated; it is the creator's craft. The creator assembles the definition, writes the documentation, provides the code, gathers the reference materials, creates the visuals, builds the semantic graph, designs the control flows and CI, writes the threat model, provides the tests and evals, and sets the licensing. SG/Vault gives them the tools to do this (the document-to-graph pipeline for the semantic graph, the infographic generation for the visuals, the version control for provenance, the vault chat to help author), but the curation is the creator's expertise made tangible. The base vault is, in effect, the creator's portfolio piece for that skill: the complete, curated, trustworthy expression of their expertise.

This connects to the evidence-CV thesis (cross-ref: the v0.31.5 evidence-CV brief): just as a person's CV becomes an evidence-anchored, curated vault, a creator's skill becomes an evidence-anchored, curated base vault. The base vault is how a creator demonstrates, provably and richly, that they have this skill.

## The Commercial Model: Base Vault To Customised, Supported Versions

The commercial model: **the creator sells and licenses a customised, supported version of the base vault to a specific customer and use case.** The base vault is the canonical work; the product is a tailored, supported instance of it.

| Layer | What It Is |
|-------|------------|
| **The base vault** | The creator's canonical, curated, complete skill (built once) |
| **The customised version** | Tailored to a specific customer and their use case |
| **Supported** | The creator provides support for the customised version |
| **Sold and licensed** | The customer pays for, and licenses, the customised supported version |

This is the same base-then-customise pattern as the consulting assessments (cross-ref: the v0.31.5 consulting-assessments brief, where per-standard vaults were the foundation and an intersection vault customised per company) and the create-once-render-many pattern (cross-ref: the evidence-CV and security-report briefs): the creator builds the base vault once, then produces customised, supported versions per customer. The customisation and the support are where much of the value (and the price) sits: a customer is not just buying a skill, they are buying a version of it adapted to their use case, backed by the creator's support.

The licensing flexibility matters: **ideally most is open source and CC-licensed, but the model supports anything.** So the base vault might be largely open (CC-licensed, like these briefs), with the commercial value in the customisation, the support, and the creator's expertise, while the model also supports proprietary licensing where a creator chooses it. This mirrors the platform's own open stance (cross-ref: the open-evaluation brief) while leaving room for any commercial arrangement.

This also extends the Vault App Store (cross-ref: the v0.31.5 Vault App Store brief): the store distributes and bills for vaults, optionally bundling OpenRouter credits, with security analysis and agent mapping. A base vault is exactly the kind of rich, sellable vault the store is for, and the base-to-customised model is how a creator sells through it: the store lists the base vault (perhaps with an open, previewable portion via the public-read-only rendering, cross-ref: the public-preview-with-read-only-key brief), and the creator sells customised, supported versions to customers.

## The Ecosystem: Creators Rewarded For Experience, Skills, Brand, And Reputation

The thesis the whole brief builds to: **SG/Vault creates a commercial model and ecosystem where the creator is paid and rewarded for their experience, skills, brand, and reputation.**

This is a creator economy for skills. The base vault makes a creator's expertise tangible, curated, explainable, and provable; the commercial model lets them sell customised, supported versions of it; and the result is that creators are rewarded for what they actually bring:

| Rewarded For | How The Base Vault Surfaces It |
|--------------|--------------------------------|
| **Experience** | The depth and quality of the curated base vault |
| **Skills** | The skill itself, fully expressed and executable |
| **Brand** | The base vault as a portfolio piece; the creator's name on quality work |
| **Reputation** | The provenance, the validation, the track record of customised versions delivered |

The provenance and explainability (which the vault provides) are what make reputation real and portable: a creator's work is verifiable, their track record is recorded, and their brand is built on demonstrable quality rather than claims. This is the same anti-BS, evidence-makes-quality-visible principle as the evidence-CV brief (cross-ref): just as evidence-anchoring lets a genuinely talented person be seen, the base vault lets a genuinely skilled creator be seen and rewarded, because the quality of their curated, provable work speaks for itself.

The ecosystem is mutually reinforcing: creators are drawn to a platform where their expertise is rewarded and their reputation is portable; customers get rich, trustworthy, supported skills; and SG/Vault is the substrate that makes the whole exchange possible (the curation tools, the provenance, the visualisation, the distribution, the billing, the licensing). It positions SG/Vault not just as a vault tool but as the home of a skills creator economy.

## Why SG/Vault Is The Right Substrate

The brief's claim is that SG/Vault is uniquely suited to this, and each creator need maps to a vault capability:

| Creator Need | SG/Vault Capability |
|--------------|---------------------|
| **Create** | The vault as a self-contained workspace; the vault chat to help author (cross-ref: the vault-chat brief) |
| **Curate** | Version control and provenance (cross-ref: the commit-queue brief) |
| **Visualise** | The semantic graph and infographic generation (cross-ref: the skills-graph and visualisation briefs) |
| **Explain** | The auditable semantic graph plus provenance |
| **Distribute** | The Vault App Store and public read-only previews (cross-ref: the store and public-preview briefs) |
| **Customise** | The base-to-customised pattern (cross-ref: the consulting brief) |
| **License and sell** | The store's billing and the flexible licensing |
| **Protect** | Zero-knowledge encryption; sell read-only or customised instances |
| **Build reputation** | Provenance, validation, and a portable, verifiable track record |

None of these is a stretch; all reuse capabilities the platform has or is building. The base vault and the creator economy are the synthesis of the skills, store, consulting, evidence-CV, and visualisation threads into one creator-facing proposition.

## What This Asks For

1. **Support the base vault** as a first-class concept: a rich, curated skill vault holding far more than a SKILL.md (docs, code, supporting materials, visuals, semantic graph, control flows/CI, security materials, tests/evals, licensing, anything aiding explainability/provenance/execution).
2. **Give creators the curation tools** (the document-to-graph pipeline for the semantic graph, infographic generation, version control for provenance, the vault chat to help author).
3. **Build the semantic graph for the whole base vault** (multiple linked ontologies and taxonomies across all the materials).
4. **Support the base-to-customised commercial model** (the creator sells and licenses customised, supported versions per customer and use case).
5. **Support flexible licensing** (mostly open/CC by default; any model supported).
6. **Distribute through the Vault App Store** (list base vaults; sell customised versions; bill; bundle credits; previewable open portions).
7. **Make provenance and reputation portable** (the creator's verifiable track record; brand built on provable work).
8. **Frame SG/Vault as a skills creator economy** (creators rewarded for experience, skills, brand, and reputation).
9. **Produce the library page and example base vault** (the page explains the creator economy; an example base vault is the worked MVP).

Estimated effort: substantial as a proposition, but built almost entirely on existing threads (the skills graph, the document-to-graph pipeline, the vault-as-workshop, provenance and version control, the visualisation primitives, the Vault App Store, the base-to-customised pattern, the public previews, the vault chat). The new work is establishing the base vault as a first-class concept with a defined structure, the creator-facing curation tooling, and the base-to-customised commercial flow. The example base vault is the MVP.

## What This Does Not Try To Be

- **Not a thin SKILL.md.** A base vault is the whole curated workshop around a skill.
- **Not auto-generated.** The creator curates it; SG/Vault provides the tools, the creator provides the expertise.
- **Not closed by default.** Mostly open/CC, with the model supporting any licensing.
- **Not just distribution.** It is creation, curation, visualisation, explanation, customisation, licensing, and reputation, the whole creator economy.
- **Not the consumer's view.** This is the creator's side; the skills-graph brief is the consumer's side.

## Honest Risks

**Risk 1: Curating a rich base vault is real work.** A base vault is a lot to assemble. Mitigation: the curation tooling (the pipeline, infographics, the vault chat) lowers the effort; the base vault is built once and sold many times (customised); the effort is the creator's craft and is what they are rewarded for.

**Risk 2: Quality and trust in a creator marketplace.** A marketplace can fill with low-quality or untrustworthy skills. Mitigation: provenance, the security materials (threat models), the store's security analysis and agent mapping (cross-ref: the store brief), and reputation (verifiable track record) as trust signals; curation as the ecosystem matures.

**Risk 3: Licensing and revenue complexity.** Flexible licensing and base-to-customised sales are non-trivial commercially. Mitigation: default to open/CC with value in customisation and support; the store's billing; start simple; the model supports more as it matures.

**Risk 4: Skill safety (execution risk).** A base vault may include executable code. Mitigation: the security materials (threat models) and the store's security analysis; the skills-graph safety surface (cross-ref); the vault sandboxing (cross-ref: the VIV no-origin/broker model); install/buy from trusted, reputed creators.

**Risk 5: Reputation systems can be gamed.** A creator-economy reputation could be manipulated. Mitigation: reputation grounded in verifiable provenance and delivered customised versions (real track record), not just ratings; the evidence-anchoring principle (cross-ref: the evidence-CV brief).
