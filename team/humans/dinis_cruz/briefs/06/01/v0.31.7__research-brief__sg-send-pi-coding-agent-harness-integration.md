## What This Is

A research brief on Pi (pi.dev): what it is, how SG/Send could use and integrate with it, and how it could help businesses be created around it. It is one of a set of partner-integration briefs aimed at producing library pages and example vaults.

The short version: **Pi is a minimal, self-extensible, open-source terminal coding-agent harness that extends through Skills, Prompt Templates, Extensions, and shareable "Pi Packages," and ships a unified multi-provider LLM API and an embeddable agent runtime.** It is a strong fit for SG/Vault on several axes at once: it speaks the same Skills standard the platform is building on, its package-sharing model parallels the base-vault/marketplace idea, its unified LLM API parallels the platform's OpenRouter/multi-provider stance, and its embeddable runtime could be the agent engine inside or alongside a vault.

## What Pi Is

The research picture, current as of this brief:

- Pi is an open-source AI agent toolkit by Mario Zechner. Its pi-coding-agent is a minimal terminal coding-agent CLI built on a small four-tool core (Read, Write, Edit, Bash), MIT-licensed and bring-your-own-key.
- Its defining design is self-extensibility: the core stays small, and Pi self-extends at runtime through TypeScript Extensions, Skills, Prompt Templates, and Themes, with the philosophy "adapt Pi to your workflows, not the other way around," without forking internals. It deliberately skips features like sub-agents and plan mode, on the basis that you can ask Pi to build what you want or install a third-party package.
- Extensions, skills, prompt templates, and themes are packaged as Pi Packages and shared via npm or git.
- It includes pi-ai, a unified multi-provider LLM API (Anthropic, OpenAI, Google, xAI, Groq, Cerebras, OpenRouter, and any OpenAI-compatible endpoint), with streaming, tool calling, thinking/reasoning support, cross-provider context handoffs, and token/cost tracking; and pi-agent-core, an embeddable agent runtime with tool calling and state management.
- It is notable in the ecosystem as the foundation on which OpenClaw is built, and its creator is associated with a careful, human-judgment-first view of agentic coding.

So Pi is a small, sharp, extensible agent harness plus a unified model API plus an embeddable runtime, with a package-sharing ecosystem.

## Why This Matters To SG/Send (Four Alignments)

Pi aligns with SG/Vault on four axes simultaneously, which is unusual and makes it a strong technical partner:

| Pi Capability | SG/Vault Parallel |
|---------------|-------------------|
| **Skills** (self-extension via Skills) | The platform's skills and base-vault work (cross-ref: the skills-graph and base-vault briefs) |
| **Pi Packages** (shared via npm/git) | The base-vault/marketplace distribution model (cross-ref: the base-vault and marketplace briefs) |
| **pi-ai** (unified multi-provider LLM API) | The platform's OpenRouter/multi-provider, cost-tracked model access (cross-ref: the authentication and GDPR briefs) |
| **pi-agent-core** (embeddable agent runtime) | The vault-chat agent and agent-controlled workflows (cross-ref: the vault-chat and agent-controlled-websites briefs) |

Each of these is a place SG/Vault and Pi could meet, and together they make Pi less a single integration than a like-minded toolkit the platform could build with.

## How SG/Send Could Use And Integrate With Pi

| Use | How |
|-----|-----|
| **Pi as an agent harness over vaults** | Pi (or pi-agent-core) drives work over vault content, using the vault as the curated source and store |
| **Vaults as Pi Packages, and vice versa** | A skill/base vault could be expressed as a Pi Package (shared via npm/git); a Pi Package could be packaged as a base vault |
| **pi-ai as the model layer** | Use pi-ai's unified multi-provider API (with cost tracking) for vault workflows, complementing/alongside OpenRouter |
| **pi-agent-core as an embeddable engine** | Embed pi-agent-core as the agent runtime for vault chat or agent-controlled workflows |
| **Skills interoperability** | Skills authored for the platform's marketplace run in Pi, and Pi skills appear in the marketplace (the open standard) |
| **Pi sessions into vaults** | Pi's emphasis on sharing sessions (for improving agents) maps onto storing sessions in vaults with provenance |

The strongest near-term fit is **Skills and package interoperability**. Pi self-extends via Skills (the open standard the platform is building its marketplace on, cross-ref: the skills-graph and marketplace briefs) and shares them as Pi Packages. So a base vault (cross-ref: the base-vault brief) and a Pi Package are two expressions of the same thing, a shareable, installable unit of capability. The platform could let a base vault be installed into Pi as a package, and a Pi Package be curated into a base vault (gaining the vault's provenance, semantic graph, security materials, and marketplace scoring; cross-ref: the marketplace brief). This makes SG/Vault and Pi complementary: Pi is a place skills run and are authored; SG/Vault is where they are curated, made provable, scored, and sold.

A second strong fit is **pi-agent-core as an embeddable runtime**. The platform has a vault-chat agent and agent-controlled workflows (cross-ref: the vault-chat and agent-controlled-websites briefs); pi-agent-core is an embeddable agent loop with tool calling and state management that could serve as (or inform) that engine, and pi-ai's unified multi-provider API with cost tracking aligns with the platform's multi-provider, budgeted stance (cross-ref: the GDPR and visualisation briefs' cost discipline).

## How It Helps Businesses Be Created Around It

The combination supports businesses building on a **shared, open, skills-and-packages ecosystem.** Because Pi and SG/Vault both speak Skills and both have a package/vault sharing model, a creator's work is portable across them: a creator authors a skill, curates it as a base vault (provenance, graph, security, scoring), sells customised versions through the marketplace (cross-ref: the base-vault and marketplace briefs), and that same skill runs in Pi as a package. The creator economy (cross-ref: the base-vault brief) is not locked to one harness; it spans Pi and SG/Vault via the open standard. This is the multi-marketplace, open-standard reality (cross-ref: the marketplace brief): SG/Vault's differentiator is curation, provenance, and trustworthy scoring; Pi's is the minimal, self-extensible harness; a creator benefits from both.

It also supports developers and teams building agent setups: Pi's "adapt the agent to your workflow" philosophy plus SG/Vault's curated, provable, shareable vaults means a team can build their agent workflow in Pi and store, version, share, and sell the resulting skills/packages as vaults, with provenance and trust. Pi is the workbench; SG/Vault is the curated, provable, sellable output.

## What This Asks For (The MVP)

1. **Establish Skills interoperability with Pi** (skills run in both; the open standard).
2. **Map base vaults to Pi Packages and back** (a base vault installable into Pi; a Pi Package curatable into a base vault).
3. **Consider pi-ai as a model layer** (unified multi-provider, cost-tracked; alongside OpenRouter).
4. **Consider pi-agent-core as an embeddable runtime** (for vault chat or agent-controlled workflows).
5. **Store Pi sessions in vaults** (with provenance; the share-sessions ethos meets the vault's record).
6. **Position SG/Vault as the curation/provenance/marketplace layer for Pi-authored skills** (Pi authors and runs; SG/Vault curates, proves, scores, sells).
7. **Produce the library page and example vault** (the page explains the SG/Vault-plus-Pi model; an example base vault that round-trips with a Pi Package is the MVP).

Estimated effort: low to moderate, because both speak the open Skills standard and both are package/zip-based and open-source. The new work is the base-vault-to-Pi-Package mapping and the interoperability; pi-ai and pi-agent-core are optional deeper integrations. The MVP is a base vault that installs into Pi as a package and a Pi Package curated into a scored base vault.

## What This Does Not Try To Be

- **Not a competitor to Pi.** SG/Vault is the curation/provenance/marketplace layer; Pi is the harness; they are complementary.
- **Not lock-in.** The open Skills standard means a creator's work spans both.
- **Not replacing the vault's model.** The vault stays the curated, provable, encrypted store; Pi is where skills run and are authored.
- **Not a single integration.** Pi aligns on Skills, packages, the model API, and the runtime.

## Honest Risks

**Risk 1: Skill safety applies across harnesses.** A skill that runs in Pi has the same execution risk as anywhere (cross-ref: the marketplace brief's security findings). Mitigation: the vault's provenance, security materials, and marketplace scoring travel with the skill; sandboxed execution (cross-ref: the Daytona brief).

**Risk 2: Standards and tools are young and moving.** Pi and the Skills standard are evolving. Mitigation: build on the open standard (interoperable, not Pi-specific); the mapping is additive; re-verify as both evolve.

**Risk 3: Overlap with the platform's own runtime.** pi-agent-core overlaps with the vault-chat agent. Mitigation: use Pi where it adds value (a proven, minimal runtime); the platform's agent and Pi can coexist; choose per use case.

**Risk 4: Dependence on a third-party toolkit.** Relying on Pi components. Mitigation: Pi is MIT and open-source (portable, not locked-in); the integration is via the open standard; pi-ai/pi-agent-core are optional.
