# Node Type Formulas: Classification as an Explicit, Testable Path-Pattern

## What This Is

The mechanism beneath meaning-through-connectivity: **what a node is gets decided not by a human or an agent out of their knowledge, experience, and bias, but by an explicit Node Type Formula, a required pattern of typed, directed, upward and downward paths that a node either matches or does not, so classification is computed against the graph rather than held in the classifier's head, and is therefore explicit, pragmatic, testable, explainable, and repeatable by construction; the formula still carries judgment, in which paths it requires and where its thresholds sit, but that judgment moves out of the classifier's head and into the formula, where it is visible, versioned, inspectable, and arguable; the ontology definition of a node type is thus its path-pattern, not a sentence about its content; classification becomes a path query that is dynamic and path-relative; and the per-edge tests are kept objective and binary so that an agent can run them and a human can audit them.** This is the single-formula mechanism; the companion brief covers how multiple formulas coexist and connect (cross-ref: the v0.33.35 directed-edges, path-properties, and the v0.33.36 grounding-ladder briefs). New contributions: **the Node Type Formula, classification-as-query, and bias-made-visible.**

## From Judgment to Formula

Today the question "is this a vulnerability?" is answered by a person or an agent drawing on knowledge, experience, and bias. That answer is unauditable, unrepeatable, and likely to differ between two classifiers or between the same classifier on two days. The shift here is to stop having the classification held by the classifier and start having it computed. A Node Type Formula is an explicit pattern of required typed paths; a node either matches it or it does not. Because the answer is a computation against the graph, the five properties that matter stop being aspirations and become structural: a formula is explicit, pragmatic, testable, explainable, and repeatable because that is simply what a formula is.

## The Definition Mechanism: Meaning Paths

What we are really defining is that the ontology definition of a node type is its upward and downward path-pattern, not a sentence about what it contains. Written as formulas:

- `Fact := a node with a downward grounding path (to Evidence, and on toward a measure and a twin).`
- `Vulnerability := a Fact (grounded below) that also has an upward path to a Risk.`
- `Risk := a node with a downward path to a Vulnerability and an upward path toward a top risk on the register.`
- `Hypothesis := a node with an upward implication path but no downward grounding yet.`

The content of the node does not decide its type; its paths do. Two nodes with identical text can be different types because their edges differ.

## Two Directions, Two Jobs

Legitimacy is bidirectional, but the two directions do different work, and naming that resolves the earlier overstatement that legitimacy was only downward.

- **Downward is grounding.** Is it real? Does it reach evidence, a measure, and ultimately a representation of reality?
- **Upward is classification and implication.** What is it, and why does it matter? A Fact becomes a Vulnerability purely because of its upward link to a Risk.

This maps directly onto the facts, hypotheses, and opinions vocabulary:

| Paths present | The node is | Why |
|---|---|---|
| Upward only, implication without grounding | Hypothesis | It means something but is not yet shown to be real |
| Downward only, grounded without implication | Fact on the shelf | It is real but has no established why-it-matters |
| Both directions present | Vulnerability, or a grounded Risk | Real and consequential |

Upward links confer classificatory legitimacy; downward links confer grounding legitimacy; a node is fully legitimate when the paths its formula requires are present.

## Classification Is a Path Query

Because a type is a path-pattern, classification is a query, not a stored label. This is why it is dynamic and path-relative: a node is a candidate until the required edges exist, is promoted when they are drawn, and is demoted if they are later struck off. The same node can satisfy one formula and fail another, so its type is not an intrinsic property but a result computed in a context. Storing a fixed label would force a single answer; running a query lets the answer follow the graph.

## Bias Becomes Visible

A Node Type Formula is not objective truth, and the model does not pretend otherwise. The choice of which paths are required versus optional, where a threshold sits, where the floor is, and where a fact tips into a risk all carry judgment, and often agenda. The gain is not that the bias disappears; it is that the bias moves out of the classifier's head and into the formula, where it is written down, versioned, inspectable, and open to challenge. Two parties who disagree are no longer trading intuitions; they are diffing two formulas. That is the same discipline as the rest of the project, not removing human judgment but making the moment and the shape of it explicit and out of band.

## Keep the Per-Edge Tests Objective and Binary

For the formula to be runnable by an agent and auditable by a human, each test it is built from has to be objective and binary: does this node have an edge of type X to a node of type Y? Compose enough of those binary checks and you get a classification that is deterministic and explainable, the same facts-only discipline applied to the ontology itself. The two places where subjectivity tends to leak back in are the floor test, how deep grounding must go, and the fact-to-risk boundary, when a node stops being a fact and becomes a judgment. Those two are where checkable criteria matter most, because they are where a formula can quietly smuggle a value judgment back into what looks like a computation.

## What This Does Not Try To Be

- **Not a claim of objectivity.** The formula carries judgment; the point is to make it visible.
- **Not the removal of human judgment.** It relocates judgment into the formula, out of band.
- **Not a single universal formula.** Many formulas coexist; see the companion brief.
- **Not a change to the grounding-ladder doc.** That review is the next, separate pass.

## Honest Tensions

| Tension | Note |
|---------|------|
| Objectivity versus residual bias | The formula is repeatable, but its required paths and thresholds still encode judgment |
| Determinism versus the soft boundaries | The floor test and the fact-to-risk tip are where subjectivity re-enters |
| Dynamic typing versus stability | Path-relative classification is powerful but means a node's type can move |
| Runnable by agents versus expressive enough | Binary edge tests must stay simple while capturing real definitions |
