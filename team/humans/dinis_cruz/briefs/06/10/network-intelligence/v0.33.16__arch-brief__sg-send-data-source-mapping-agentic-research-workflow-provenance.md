## Two Parts: The Targets, And The Agentic Workflow

The brief has two halves: **the data-source targets, and the agentic workflow that gathers them, which is itself a strong case study of daily agentic research.**

The project lead: **"this has two parts, the target part and the agentic workflow part, because this is a great case study of proper agentic workflows that can run every day. Part of what we are doing is finding a much more optimised way of doing research."** So the contribution is both what to gather (the sources) and how (a repeatable daily agentic engine), and the workflow itself demonstrates optimised, automated research.

## The Agentic Research Workflow

The engine, and a pragmatic cost model: **a daily agentic research workflow that maxes out the available tokens and credits, or runs to a set budget like five pounds a day.**

The project lead: **"I try to max out my Codex, Perplexity, and other tokens I have access to, but it can also work on a budget. I could say I am happy to spend five pounds a day on research. Use Bedrock credits, or Google Vertex credits that we have."** So the research runs daily as an agentic workflow with two modes: max out the credits and tokens available (Codex, Perplexity, Bedrock, Vertex), or cap it to a budget (for example, five pounds a day). This makes research a continuous, cost-controlled background process (cross-ref: the central-key-management and ephemeral-compute briefs) rather than a manual effort.

## The Data Sources

The targets, as a taxonomy: **LinkedIn, companies in an industry, LLMs as a source, the companies' own websites, feeds, investors, and a country landscape.**

| Source | Use |
|--------|-----|
| LinkedIn | The network (already covered; cross-ref: the LinkedIn briefs) |
| Companies in an industry | The competitive and partner landscape |
| LLMs (Perplexity, internet-capable models) | Query the models' knowledge, then cross-reference for truth |
| The companies' own websites | A semantic graph per site (below) |
| Feeds (Hacker News, RSS) | Current signals the intelligence connects to |
| Investors | Investments, portfolios, areas, relationships, signals |
| A country | A landscape, for example Portugal (below) |

On LLMs as a source, the project lead: **"Perplexity, and the latest OpenAI model has internet access. The models already have a lot of knowledge, so we query them and cross-reference to see if it is true. The LLMs are a good source of material, but the other one is the actual website."** So LLMs are one source among several, treated as material to verify by cross-reference, not as ground truth.

## A Semantic Graph Per Website

A key method, and it is the delta economics applied to the web: **for every website, build a semantic knowledge graph, which reverse-engineers the site and means you pay the heavy cost only on the first hit and stay light after.**

The project lead: **"for every website we interact with, we create a semantic knowledge graph, because it is a great way to show how graphs work, it lets us reverse-engineer a site, and it means we only pay a heavy cost the first time we hit the website, after that it should be very light. Take BBC News for the latest, or companies with RSS feeds."** So each site becomes a semantic graph (cross-ref: the semantic-graph-visualisation brief): the first crawl is expensive, but the graph is saved and version-controlled, so subsequent updates are cheap deltas (cross-ref: the artefact-driven-security-assessments brief's delta scanning). This both demonstrates how graphs work and makes ongoing monitoring light.

And it prepares for a coming shift. The project lead: **"prepare for the future, when companies start to provide LLM, Markdown, or JSON files of their content, and we can track that to see it happening."** So the design anticipates structured content (sites publishing machine-readable content files), and can track the emergence of that practice as a signal in itself.

## Feeds, Investors, And A Country

Three more source types worth calling out:

On feeds, the project lead: **"we should get a feed from Hacker News and specific RSS feeds, all sorts, so the trade intelligence connects to it."** So feeds (Hacker News, RSS) provide current signals that plug into the company intelligence.

On investors, the project lead: **"another good one is investors. Map out the investments, the companies they invest in, the areas of operation, the context, and pick the big signals, the relationships, how everything fits together."** So investors are a source whose portfolios and patterns reveal relationships and signals (cross-ref: the company-intelligence-vault follow-the-line narratives, which trace a company to its VCs).

On a country, the project lead: **"the final one is a country. I want to do one for Portugal. I have done memos in the past about mapping the Portuguese landscape, we should reference those."** So a country landscape (Portugal first) is a source type, and earlier memos on the Portuguese landscape should be referenced (note: those prior memos are not in this session; they can be located and cross-referenced when available).

## The Public And Legality Posture

A deliberate stance on what to gather and publish: **use only sources that can be queried, searched, or hit directly, lean on public data, publish what is public and take it down on complaint, and respect the legality throughout.**

The project lead: **"map out how much of this can be public, because a lot can, especially from public sources, we can just publish it, and if anybody complains we take it off, but in principle it is all public data, just connecting the dots. We should respect the legality, only using sources we can query, especially stuff we publish publicly, stuff we can search, stuff we can hit directly. If it is public, fine, if it is private, we can just hit the website."** So the posture is public-first and lawful: gather from queryable, searchable, directly-accessible sources; publish public data as connected dots, with a take-down-on-complaint policy; and respect the legality of each source (consistent with the no-scraping, replicable stance; cross-ref: the company-intelligence-vault and partner-briefing briefs).

## Provenance Is Mandatory

The non-negotiable that makes it trustworthy: **every piece of information in the vault is linked to where it came from, its location, its timing, and a screenshot of the source.**

The project lead: **"provenance is so important. Every single piece of information we have, in a website, in our vaults, needs to be connected to where we got it, the location, the timing, all the information, including even screenshots of the website we used."** So provenance is mandatory and complete (cross-ref: the semantic-graph-visualisation and company-intelligence-vault provenance, and the PKI-registry brief): each datum records source, location, time, and a captured screenshot, making the whole intelligence base evidential and auditable.

## The Schedule And The Vault

How it runs and where it lives: **on a regular schedule, learning over time, with the vault making it all possible and usable.**

The project lead: **"all this goes in vaults, the vault is what makes a lot of this possible and usable. This can happen at a regular interval, a regular schedule, something we can learn from, a great use of vault technology."** So the research engine runs on a schedule, accumulating and learning, with the vault as the version-controlled, provenance-bearing store that makes the whole thing durable and usable (cross-ref: the append-capability and artefact-driven briefs).

## What This Does Not Try To Be

- **Not a one-off research effort.** A daily, scheduled, budget-bounded engine.
- **Not LLM-as-truth.** LLMs are material to cross-reference and verify.
- **Not heavy on every hit.** Heavy on the first crawl, light deltas after.
- **Not unsourced.** Mandatory provenance: source, location, time, screenshot.
- **Not legally careless.** Queryable, public sources; respect the legality; take down on complaint.

## Honest Risks

**Risk 1: Legality and terms vary by source.** Different sites have different rules. Mitigation: queryable, public, directly-accessible sources only; respect the legality; take-down-on-complaint; no scraping where disallowed (cross-ref: the company-intelligence-vault no-scraping stance).

**Risk 2: Publishing aggregated data can draw objections.** Even public data, connected, can prompt complaints. Mitigation: public sources, connected dots, take-down-on-complaint; provenance shows the source.

**Risk 3: Cost can run away.** Daily research across many sources. Mitigation: the budget mode (a set spend per day); the heavy-first-light-after deltas; max-credits as the alternative.

**Risk 4: LLM sources can be wrong.** Model knowledge can be stale or confabulated. Mitigation: cross-reference against the website and other sources; provenance; do not treat the model as truth.

**Risk 5: Provenance overhead.** Capturing source, time, and screenshots on everything is work. Mitigation: it is what makes the base evidential; the vault stores it; it is captured as part of the pass.
