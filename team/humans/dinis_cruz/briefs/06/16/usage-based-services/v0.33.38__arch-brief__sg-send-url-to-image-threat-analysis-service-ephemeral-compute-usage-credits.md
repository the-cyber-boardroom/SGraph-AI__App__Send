# URL To Image, And Beyond: A Safe URL Threat-Analysis Service

**version** v0.33.38
**date** 16 June 2026
**from** Human (project lead), with a colleague
**to** Architect, Developer (lead), Security, Product, @Dev
**type** Arch brief (service map)

## What This Is

A service that turns a URL into images and then into a full threat-analysis report, built almost entirely on the existing stack and the usage-credits model: **it starts as URL-to-PNG using SG Playwright, stores results in vaults, and escalates through an LLM-powered feature ladder (describe the page, generate an infographic, navigate and screenshot each page with an LLM deciding where to click, registrar and domain-age signals, phishing detection, threat-intel signatures and attack-technique mappings, and export to security tools), packaged in a vault as a downloadable body of evidence, charged at pennies per feature on bought credits, with bring-your-own-key or a dedicated ephemeral sidecar LLM for privacy, and run on fresh ephemeral compute that is destroyed after each analysis so a possibly-malicious URL can be inspected without anyone visiting it.** It applies the usage model and the compute work to a security use case (cross-ref: the v0.33.26 selling-llm-usage and v0.33.38 image-generation-opportunity briefs, the v0.32.4 ephemeral-compute brief, the v0.33.16 artefact-driven-security-assessments brief, and the v0.33.38 tools-execution-control-flow brief for agentic navigation). It maps a working conversation and is kept public-safe at the project lead's instruction. New contributions: **the feature ladder, the safe-inspection security model, the pennies-per-feature economics, and the immediacy tiers.**

## The Core: URL To Image, On The Existing Stack

The starting point: **turn a URL into a screenshot, using what already exists.**

The project lead: **"this is a service that transforms URLs to PNGs, and it leverages a lot of the tech stack we already have, because we already have SG Playwright, the vaults to put the data, and a way to deploy and create customised versions. We charge per usage, pennies on demand, and the customer just buys credits, five or ten pounds, and tops it up."** So the base service is URL-to-PNG on SG Playwright, stored in vaults, on the usage-credits model (cross-ref: the selling-llm-usage and openrouter-key-acquisition briefs).

## The Security Purpose: Inspect Without Visiting

Why an engineer wants this, in a colleague's framing: **see a suspicious URL safely, without navigating to it yourself.**

A colleague in the conversation made the core case: the aim is that an engineer does not have to navigate to a website that might be malicious or carry a payload; instead they get a screenshot, and can navigate and click the links safely to see, for example, whether it presents a fake Microsoft login form, and whether the URL looks like a phishing page. So the service is a safe-inspection tool: the analysis happens in disposable compute, and the engineer never touches the malicious site directly.

## The Feature Ladder

The escalation, from a screenshot to a full report: **each step is a small, LLM-powered addition.**

| Step | Feature |
|------|---------|
| 1 | URL to PNG (the screenshot) |
| 2 | Describe what is on the page (LLM analysis) |
| 3 | Generate an infographic from the page |
| 4 | Navigate and screenshot each linked page (the LLM decides where to click) |
| 5 | Registrar and domain-age signal (newly registered, or years old) |
| 6 | Phishing detection (fake login forms, suspicious URLs) |
| 7 | Threat-intel signatures and attack-technique mappings |
| 8 | Export to security tools, and import and export of the results |

The project lead: **"it goes from a very simple URL-to-PNG to, can you describe the page, add LLM analysis, create an infographic, and you can take the registrar and see whether it was newly registered five days ago or three years ago. It is more than URL-to-PNG, it is almost triage-time analysis."** Each rung is, in the project lead's words, a simple LLM query away, which is what makes the ladder cheap to extend (cross-ref: the artefact-driven-security-assessments brief for the security signals, and the image-generation and infographic work for step 3).

## Agentic Navigation

A neat capability: **let an LLM work out where to click.**

The project lead: **"you can use an LLM to figure out where to click. You say, go to this website and navigate these pages, and you do not even need to specify the pages manually, you can see if the LLM can figure out how to get there."** So multi-page inspection does not need a hand-written page list: the LLM navigates the site, and each page it reaches is screenshotted and summarised (cross-ref: the tools-execution-control-flow brief, where the model chooses tools and actions).

## The Business Model: Pennies Per Feature, On Credits

The economics, and why they work: **charge a penny or a few pennies per feature, and still profit.**

The project lead: **"the interesting thing is to make all those extra bits a minimal charge. Because of the economics, we could charge one, two, or five pence for each of these and still be profitable, and from a customer point of view it feels like a lot of value for money. You can keep adding all these powerful little features that are simple to implement, the real-world features that make a difference, and each is a simple LLM query away."**

| Element | Detail |
|---------|--------|
| Credits | The customer buys credits (five or ten pounds) and tops up |
| Per-feature pricing | A penny to a few pence per feature, still profitable |
| Perceived value | A pound or two feels like a lot of analysis |
| Feature velocity | Many small high-value features, each a simple LLM query |
| Build accelerant | An LLM helps create the UI, so features ship fast |

## The Packaging: A Vault As A Body Of Evidence

What the customer takes away: **the results packaged in a vault, or a PDF, or disposable.**

The project lead: **"in our world I can package it all up in a vault, and you can download that as your body of evidence, or it can be disposable, or you can get a PDF, or whatever information you want."** So the output is a vault (the auditable body of evidence), with a PDF or disposable option, which is the artefact-driven approach applied to URL analysis (cross-ref: the artefact-driven-security-assessments and archiver-cataloguer briefs).

## The Privacy Options For LLM Usage

The concern a colleague raised, and the answers: **a mature customer asks what is being used and where their data goes.**

The project lead's two options: **"they can bring their own key. Or I can spin up an ephemeral GPU instance running the latest open-source models in that environment, network-protected, that never goes anywhere, a sidecar LLM used only for that specific page."**

| Option | Detail |
|--------|--------|
| Bring your own key | The customer supplies their own LLM key (cross-ref: the openrouter-key-acquisition brief) |
| Dedicated ephemeral sidecar LLM | An open-source model on a network-protected GPU instance, used only for that analysis, then destroyed; a cost of roughly one to two dollars an hour |

The dedicated sidecar answers the where-is-my-data question directly: the model runs in isolated, disposable infrastructure and the data never leaves it.

## The Ephemeral Security Architecture

The security model, for the malicious-URL case: **fresh infrastructure per analysis, destroyed after.**

The project lead: **"especially for the malware stuff, I would spin up completely fresh infrastructure, because in case they get popped or something happens. I would spin up ephemeral compute, an ephemeral LLM, and probably even an ephemeral control plane to keep an eye on it, then destroy everything."** So each analysis runs in a clean, isolated, short-lived environment that is torn down afterwards, which contains any compromise from a malicious site (the blast-radius principle; cross-ref: the ephemeral-compute and vault-in-vault-kernel-model briefs). A colleague noted the timing: the first signals arrive within the first thirty seconds to a minute, and the full enrichment runs to about seven minutes, so the first-tier result must land inside a minute.

## The Immediacy Tiers

How to price for speed: **always-on first signal, on-demand spin-up, or always-running.**

| Tier | Behaviour | Cost Model |
|------|-----------|------------|
| Immediate, always-on | Gives the first signal at once, then optional further analysis | A standing cost for the first tier |
| On-demand spin-up | Spins up the full environment when needed | Pay per use, with a short setup time |
| Always-running | The environment is kept up | Pay the standing cost (for example, an LLM eight hours a day at roughly eight to ten dollars) |

The project lead: **"you would have different levels: one that is immediate and always-on and gives the first field, and depending on that you can do further analysis, or one running all the time that just becomes a cost. We are not talking about crazy amounts of money."** So customers trade off immediacy against standing cost.

## What This Does Not Try To Be

- **Not just URL-to-PNG.** It is triage-time threat analysis.
- **Not a site you visit.** The point is to inspect without visiting.
- **Not persistent infrastructure.** Fresh, ephemeral, destroyed after.
- **Not opaque on data.** Bring your own key, or an isolated sidecar LLM.

## Honest Risks

**Risk 1: the LLM-usage and data question.** Mature customers ask what is used and where data goes. Mitigation: bring your own key, or the dedicated isolated sidecar LLM.

**Risk 2: the first-signal speed requirement.** The first tier must land inside a minute. Mitigation: the always-on tier for the immediate signal, deeper analysis on demand.

**Risk 3: safely handling malicious sites.** A malicious URL could compromise the analysis environment. Mitigation: fresh ephemeral infrastructure per analysis, network-protected, destroyed after, with a control plane watching.

**Risk 4: public-brief constraint.** This is a public document. Mitigation: nothing confidential is included, per the project lead.
