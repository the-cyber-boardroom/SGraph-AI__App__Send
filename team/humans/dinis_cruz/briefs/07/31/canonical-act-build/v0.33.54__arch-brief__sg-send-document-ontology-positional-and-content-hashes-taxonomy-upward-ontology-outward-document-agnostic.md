# The Document Ontology: Two Hashes, Taxonomy Upward And Ontology Outward, And A Schema That Should Not Know It Is A Regulation

**from** Human (project lead)
**to** Engineering, Architecture, the implementing agent

**type** Architecture brief

*Seventh of 31 July, and the document the memo explicitly parks as separate. Its companion covers what happens to a paragraph once the structure exists. External identifier standards are grounded and cited. Offered to be built on and challenged.*

---

## What This Is

The ontology describing the document itself, separated deliberately from the ontology describing what the document means: **the combined text now exists and is published, which settles a boundary that matters more than it appears, because the work of deciding what the current text is has moved upstream and out of the analysis vault, so the analysis no longer begins by resolving amendments and instead begins from a resolved text and concentrates on paragraphs, connections and semantic graphs; the structure that carries that text should be document-agnostic, describing a title, a description, items, sections and bullet points rather than anything specific to a regulation, so that the same schema serves the next standard without modification, which is the pipeline the corpus has been building toward since May; the fidelity bar is that the ontology must be rich enough to recreate the original rendering, the portable document and the word processor version, because a structure that cannot reproduce its source has lost information it will later be asked for; the pivotal design decision is that a provision needs two hashes rather than one, a positional hash derived from its address in the hierarchy and a content hash derived from its text, and the reason this matters is that they change at different times, since an amendment substitutes the wording while leaving the address intact, so the content hash moves and the positional hash does not, which resolves the identifier problem raised yesterday and makes deep links, citations and contributed comments survive amendment automatically; the vertical relationship is a taxonomy, being merely the structure of the thing, while the outward relationships to meaning are an ontology, and separating them cleanly prevents the common failure where the two are modelled as one and neither works; and cross-references are deliberately a second pass, since a first pass that models structure without resolving the citation graph is completable and useful, whereas one that attempts both at once is neither.** It is the seventh document of 31 July (cross-ref: the companion bow-tie brief, the v0.33.54 paragraph-is-a-folder brief, the v0.33.54 canonical-Act implementation brief, the v0.31.9 vault-per-standard brief, and the v0.33.53 every-paragraph-is-a-graph brief). New contributions: **the boundary that consolidation is upstream and analysis begins from resolved text, the positional and content hash pair with the observation that they change at different times, the resolution of the identifier-survives-amendment problem from that pair, the separation of upward taxonomy from outward ontology, the fidelity bar of recreating the original rendering, and cross-references deferred to a second pass by design.**

## The Boundary That Just Got Drawn

The status matters as much as the design. The project lead: **"we have now created a workflow that fundamentally takes the materials that we created in the vault, that then puts it to a static website, which is now published."** With a careful self-correction worth preserving. The project lead: **"the logic here is that we have created a canonical version, well, not canonical version, the combined version."**

That correction is the same one recorded this morning, and it is right. There is no canonical version; there is a combined one, derived and marked as such.

The architectural consequence is the important part. The project lead: **"the complexity of figuring out which one is the combined version is now not that responsibility; what we're going to focus on is the paragraph analysis and the connection and the semantic graphs."**

So a boundary now exists. Upstream, one system resolves the original text plus its amendments into a combined text and publishes it. Downstream, another system takes that combined text as its input and does the semantic work. Each side has one job.

```
   ORIGINAL + AMENDING INSTRUMENT
        |
        v   consolidation vault: resolve, publish, mark as derived
   COMBINED TEXT  (the boundary)
        |
        v   analysis vault: structure, concepts, connections, graphs
   SEMANTIC GRAPH
```

Two properties follow. The analysis is insulated from amendment mechanics, so a new amendment is an upstream event that changes its input rather than a redesign. And the boundary is a published artefact rather than an internal interface, which means the analysis could in principle run against somebody else's combined text, or somebody else's analysis could run against ours.

## The Schema Should Not Know It Is A Regulation

The memo is explicit that the structure is general. The project lead: **"this should almost be document agnostic, because fundamentally you have a title and then you have a description and you have these items and each item can have a section and then have bullet points."**

That is the right instinct and it is the corpus's established direction, since the May work specified a universal document-to-graph pipeline with several standards named as the first batch. A schema that encodes articles, recitals and annexes as first-class types will need rewriting for the next instrument. A schema that describes a titled, nested, itemised document will not, and the regulation-specific vocabulary lives above it in a profile rather than inside it.

The practical test is whether the same structure holds an ISO standard, a compliance framework and an internal policy without special cases. If it does, the pipeline is real. If it does not, what exists is an AI Act reader.

## The Fidelity Bar

A requirement that sounds like a nicety and is not. The project lead: **"it has to be rich enough to capture all the data, and has to be rich enough to be able to recreate at least the PDF and the Word document in that structure."**

Being able to regenerate the original rendering is a completeness proof. If the structure can reproduce the source document, no information was dropped during extraction. If it cannot, something was discarded, and the discarded material is invariably what somebody needs later: the numbering scheme, the indentation that signals subordination, the emphasis that marks a defined term, the footnote that qualifies an obligation.

It also has a direct product use, since yesterday's publishing plan lists downloadable formats among the site's existing capabilities. Those downloads are the fidelity test running continuously in public.

## Two Hashes, And Why They Are Different

This is the most consequential idea in the memo, and the memo states it almost in passing. The project lead: **"we probably need to have a hash of the actual position, Article 10, paragraph 9, subitem A, and then a hash of the actual content itself."**

They answer different questions and, crucially, they change at different times.

| | Positional hash | Content hash |
|---|---|---|
| Derived from | The address in the hierarchy | The text |
| Answers | Which provision is this? | What does it currently say? |
| Changes when | The provision is renumbered or moved | The wording is amended |
| Used for | Deep links, citations, comment anchors, cross-references | Change detection, cache keys, verification |
| Under amendment | **Stable** | **Moves** |

That last row is the whole point, and it resolves the open question left in yesterday's implementation brief about identifiers that survive amendment.

When Article 10(5) is substituted by an amending regulation, the address is unchanged and the text is different. The positional hash therefore keeps pointing at the same provision, so every deep link, every citation from a risk register, and every contributed comment stays attached. The content hash changes, so the change detection, the analysis cache and the verification record all fire correctly. **One identity for the slot, one identity for what is in it.**

The corollary is that structural renumbering, where a provision genuinely moves, is a different and rarer event that the positional hash correctly treats as such, and it should be handled with an explicit relationship recording that a provision was renumbered rather than by silently reusing an address.

There is precedent for exactly this pattern in the Union's own vocabulary infrastructure. The Publications Office maintains authority tables in which a body's identifier stays constant while its labels change over time, with historical concepts carrying validity dates linked to the current concept through replacement relationships. Stable identity for the thing, versioned content attached to it, is how the institution publishing the instrument already handles the same problem.

## The Address Should Not Be Invented

The positional hash needs an addressing scheme underneath it, and one exists. The European Legislation Identifier defines URI templates for legislation, a metadata specification expressed as a formal ontology, and a serialisation used by the Union's own legal portal. Building the address on that rather than on an internal convention has three benefits: a citation from the corpus resolves in the same terms everybody else uses, external crosswalks can attach without translation, and the scheme already contemplates the versioning of legal acts.

The internal positional hash then becomes a compact derivation of a public address rather than a private naming scheme, which is the same argument the corpus made on 28 July about using the existing legal identifier work rather than inventing one.

## Taxonomy Upward, Ontology Outward

The memo works out a distinction while recording it, and the conclusion is right. The project lead: **"upwards is almost a taxonomy, because the taxonomy fundamentally is just the structure of the thing."** And therefore. The project lead: **"what we have is a core ontology, which probably we should define, which is the ontology that defines the actual document."**

Separating them is what keeps both usable.

```
                    OUTWARD: ontology
                    concepts, definitions, entities,
                    obligations, risks, external terms
                              ^
                              |
   UPWARD: taxonomy    [ PARAGRAPH ]    the structural spine
   bullet -> paragraph -> article -> chapter -> instrument
```

The taxonomy is finite, mechanical and derivable from the document itself. It answers where a provision sits. The ontology is open-ended, requires judgement, and grows with every concept anyone connects. It answers what a provision means.

The failure this avoids is the common one of modelling both as a single graph, where structural containment and semantic relationship become the same kind of edge. Then a query for what this article contains returns concepts, and a query for what this concept relates to returns paragraph numbers, and neither answer is useful.

## Cross-References Are A Second Pass

The memo hesitates and then decides correctly. The project lead: **"I think also here we should initially see if we already include external references or not, and internal relationships within the article; I feel like that's second pass."**

That is the right call. Structure is derivable mechanically from the document. Cross-references require resolution, because a phrase referring to a provision of another regulation has to be matched to a target that may not be in the graph at all, and getting that wrong produces confidently broken edges.

Sequencing them separately also means the first pass is completable. A structural model with two hashes per provision, positional addressing and full fidelity is independently useful: it powers the site, the downloads, the deep links and the delta-based publishing. Cross-references then arrive as an enrichment, and the memo is right that whether they form a distinct ontology or extend this one is an implementation detail rather than a decision needed now.

## What This Does Not Try To Be

- **Not a consolidation system.** That is upstream, and this begins from its output.
- **Not regulation-specific.** The schema describes documents; the AI Act vocabulary sits above it as a profile.
- **Not the meaning model.** Concepts, definitions and entity links are the companion brief.
- **Not a single identity per provision.** Two hashes, because address and content change at different times.
- **Not a first pass that includes cross-references.** Those are deliberately deferred.

## Honest Tensions

| Tension | Note |
|---------|------|
| Document-agnostic versus useful | A schema general enough for any document risks describing every document badly, and the profile layer is where the specificity has to live without leaking down |
| Fidelity to the original rendering versus effort | Reproducing a legal document exactly is real work that serves a completeness proof rather than a user need, and it will be tempting to skip |
| Two hashes versus complexity | It is the correct model and it means every provision carries two identities, which contributors and integrators will confuse unless the naming is unambiguous |
| Positional stability versus renumbering | The scheme is stable under substitution and not under structural renumbering, which is rarer and needs an explicit relationship rather than a silent reuse of an address |
| Deferring cross-references versus what a reader wants | Navigation between provisions is among the most valuable features and is being postponed to the second pass |
| Upstream boundary versus coupling | A published combined text is a clean interface and also a dependency, so the analysis is only ever as current as the consolidation feeding it |

## Open Questions

| Question | Notes |
|----------|-------|
| What is the positional hash derived from? | An identifier built on the public legislation identifier scheme rather than an internal convention |
| How is renumbering represented? | The explicit relationship recording that a provision moved, distinct from substitution |
| What is the profile layer? | Where regulation-specific vocabulary attaches without contaminating the document-agnostic core |
| How is fidelity tested? | Whether regenerating the original rendering is an automated check or a manual comparison |
| Do the language versions share positional hashes? | They should, since the address is language-independent while the content is not, and that has consequences for the translation work |
| When does the second pass start? | The trigger for beginning cross-reference resolution, and whether it extends this ontology or forms another |
