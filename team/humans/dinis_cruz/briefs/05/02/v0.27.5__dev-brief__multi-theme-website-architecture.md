# Multi-Theme Website Architecture: Radical Design Variations from Shared Content

**version** v0.27.5
**date** 02 May 2026
**from** Human (project lead)
**to** @Dev (lead), Designer (Claude Design)
**type** Dev brief

---

## The Opportunity

The website now has a powerful architectural property: content comes from vaults, structure comes from HTML and JavaScript. These are completely decoupled. The vault does not know about the design. The design does not embed any content. This means we can have multiple radical designs rendering the same content, and switch between them without touching the content at all.

This is not just CSS themes (different colours on the same layout). This is fundamentally different layouts, navigation patterns, typography, and visual identities. Same content, completely different experience.

## Why Now

The current design is good but not fully satisfying. Rather than iterate slowly on one design, create 3-5 radical alternatives in parallel. Test them. See what works. Let visitors choose. Use this as the foundation for multi-tenant theming (every customer gets their own visual identity rendering the same underlying vault content).

## The Architecture

```
Content Vault (unchanged)
    |
    +--> articles, images, navigation JSON, knowledge graphs
    |
    v
Theme Layer (multiple, independent, swappable)
    |
    +--> Theme A: "Minimal" (clean, lots of white space, serif fonts)
    +--> Theme B: "Geeky" (dark mode, monospace, terminal aesthetic)
    +--> Theme C: "Bright" (bold colours, large type, playful)
    +--> Theme D: "Corporate" (subdued, structured, formal)
    +--> Theme E: "Documentation" (sidebar nav, code-focused, Stripe-style)
```

Each theme is a set of:
- CSS (layout, colours, fonts, spacing, responsive breakpoints)
- HTML templates (page structure, navigation pattern, header/footer)
- JavaScript (theme-specific interactions, animations, transitions)
- Web Component wrappers (if the theme needs custom rendering of vault content)

Each theme reads from the same vault content, the same navigation JSON, and the same knowledge graphs. Switching themes is a URL parameter, a toggle in settings, or a subdomain.

## What "Radical" Means

Not just colour variations. Fundamentally different approaches:

| Theme | Layout | Navigation | Typography | Feel |
|-------|--------|-----------|------------|------|
| Minimal | Single column, wide margins | Top bar, breadcrumbs | Serif body, sans headers | Magazine, calm |
| Geeky | Two columns, dense | Terminal-style, keyboard shortcuts | Monospace throughout | Hacker News, technical |
| Bright | Full-bleed sections, cards | Bottom tabs (mobile-first) | Large sans-serif, bold weights | Product hunt, energetic |
| Corporate | Three columns, structured | Left sidebar tree | Standard professional fonts | AWS docs, formal |
| Documentation | Two columns (sidebar + content) | Sidebar with search | System fonts, clean | Stripe docs, polished |

## How to Create Themes

### Using Claude Design

Claude Design can generate complete theme designs given:
- The content structure (navigation JSON from the vault)
- Sample content (a few rendered pages)
- The read keys (so it can see real data)
- A mood/direction brief ("dark mode, terminal aesthetic, monospace fonts")

Claude Design produces: mockup screenshots + the actual HTML/CSS/JS code. The @dev agent receives both and implements.

### Using Other Design Tools

Explore whether OpenDesign or other AI design tools can also generate themes from the same inputs. If multiple design tools can produce themes independently, we have a rapid iteration engine: brief 5 tools, get 5 themes, test all of them.

## Implementation: Theme as a Folder

Each theme is a folder with a standard structure:

```
themes/
    |
    +--> minimal/
    |       +--> theme.json       (metadata: name, description, preview image)
    |       +--> styles.css       (all styles)
    |       +--> layout.html      (page template)
    |       +--> components.js    (theme-specific JS, if any)
    |       +--> preview.png      (screenshot for theme selector)
    |
    +--> geeky/
    |       +--> theme.json
    |       +--> styles.css
    |       +--> layout.html
    |       +--> components.js
    |       +--> preview.png
    |
    +--> ...
```

The main app loads the active theme's CSS and layout template at startup. Switching themes reloads these files. Content is fetched from vaults independently of the theme.

## Theme Selector

A UI element (available in settings or as a floating toggle) that lets the visitor choose their theme:

```
[Theme: Minimal ▾]
    Minimal (clean, serif)        [preview thumbnail]
    Geeky (dark, monospace)       [preview thumbnail]
    Bright (bold, colourful)      [preview thumbnail]
    Corporate (formal, structured) [preview thumbnail]
```

Selected theme saved in localStorage. Persists across visits.

## Multi-Language Connection

The same architecture that supports multiple themes also supports multiple languages. The vault content can have language variants (`article.en.md`, `article.pt.md`). The theme renders whichever language is selected. Theme + language = full localisation without touching the code.

## Multi-Tenant Theming (Future)

For enterprise customers, a custom theme renders their vault content with their visual identity. Same platform, same vault technology, completely different look. The theme is just a folder with CSS, HTML, and JS. Customer provides their brand guidelines, we (or Claude Design) produce a theme.

## Acceptance Criteria

| # | Criterion | Verification |
|---|-----------|-------------|
| 1 | At least 3 visually distinct themes created | Three themes render the same library content with completely different designs |
| 2 | Themes are swappable without content changes | Switch theme, same articles appear, different layout/fonts/colours |
| 3 | Theme selector available in UI | Floating toggle or settings option to switch themes |
| 4 | Selected theme persists across visits (localStorage) | Choose a theme, close browser, reopen, same theme active |
| 5 | Each theme is a self-contained folder (CSS + HTML + JS + preview) | Theme folder contains all files, no external dependencies |
| 6 | Claude Design can produce a theme from a mood brief + content data | Brief Claude Design, receive working theme code |
| 7 | Same content renders in all themes without modification | One article, three themes, three different renderings, same markdown source |
| 8 | Multi-language works alongside multi-theme | Switch language, theme stays. Switch theme, language stays. |
