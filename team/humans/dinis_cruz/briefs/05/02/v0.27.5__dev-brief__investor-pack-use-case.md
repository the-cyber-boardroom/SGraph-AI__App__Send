## What We Are Building

A website use case section that demonstrates the investor pack creation workflow: how an investor or consulting firm uses vaults to evaluate a startup, produce a structured deliverable, and share it with the client. This is both a product demo and a functional tool.

The definition of done: someone visits the website, sees the use case, and can immediately start a new engagement. They get the evaluation standard, the prompts, the vault templates, and the workflow to produce a structured investment review of any company.

## The Three-Layer Architecture

### Layer 1: The Standard

The evaluation criteria used to assess a startup. This already exists (created previously as part of the startup security review work). It defines:

- What dimensions to evaluate (team, technology, market, financials, security, compliance)
- What questions to ask per dimension
- How to score
- What evidence to require
- What the output format should be

The standard is a document (or set of documents) in a vault. It is reusable across every engagement. It does not change per client. It evolves slowly as the methodology improves.

### Layer 2: The Master Vault (Consulting Setup)

The "room" where the consulting team (agentic or human) operates. Contains:

```
master-vault/
    |
    +--> standard/
    |       +--> evaluation-criteria.md       (the standard from Layer 1)
    |       +--> scoring-rubric.md            (how to score each dimension)
    |       +--> evidence-requirements.md     (what evidence is needed per dimension)
    |
    +--> templates/
    |       +--> engagement-vault-template/   (folder structure for new engagements)
    |       +--> report-template.md           (the deliverable template)
    |       +--> prompts/
    |               +--> team-analysis.md     (prompt for analysing the team)
    |               +--> tech-analysis.md     (prompt for analysing the technology)
    |               +--> market-analysis.md   (prompt for analysing the market)
    |               +--> security-review.md   (prompt for security assessment)
    |
    +--> workflows/
    |       +--> engagement-kickstart.md      (step-by-step: how to start a new review)
    |       +--> agentic-team-setup.md        (which agents to assign, what roles)
    |       +--> quality-checklist.md         (review checklist before delivery)
    |
    +--> _page.json                           (navigation layout for browsing this vault)
```

This vault is the consulting firm's intellectual property. It contains the methodology, not the client data. It is version-controlled (the methodology improves over time) and encrypted (the prompts and workflows are proprietary).

### Layer 3: The Engagement Vault (Client Deliverable)

Created fresh for each startup being evaluated. Contains:

```
engagement-vault-{company-name}/
    |
    +--> company/
    |       +--> overview.md                  (company description, founding date, team, etc.)
    |       +--> website-analysis.md          (analysis of their public website)
    |       +--> technology-stack.md          (what they build, how they build it)
    |
    +--> analysis/
    |       +--> team-assessment.md           (team evaluation per the standard)
    |       +--> tech-assessment.md           (technology evaluation)
    |       +--> market-assessment.md         (market evaluation)
    |       +--> security-assessment.md       (security evaluation)
    |       +--> financial-assessment.md      (financial evaluation)
    |
    +--> evidence/
    |       +--> sources/                     (archived source materials)
    |       +--> screenshots/                 (website screenshots, product screenshots)
    |       +--> data/                        (financial data, market data)
    |
    +--> scoring/
    |       +--> scores.json                  (dimension scores per the rubric)
    |       +--> summary.md                   (overall assessment)
    |       +--> recommendation.md            (invest / pass / watch, with reasoning)
    |
    +--> report/
    |       +--> executive-summary.md         (1-page summary for decision makers)
    |       +--> full-report.md               (detailed report)
    |       +--> infographic.svg              (visual summary)
    |
    +--> _page.json                           (navigation layout for the client to browse)
```

This vault is the deliverable. It is shared with the client (investor or startup being evaluated) via a read-only share token. The client browses the vault: reads the report, checks the evidence, reviews the scores, and navigates the analysis.

## The Workflow

```
Investor says: "I want to evaluate Company X"
    |
    v
Clone the engagement vault template from the master vault
    |
    v
Populate company overview (from public sources, Perplexity research)
    |
    v
For each dimension in the standard:
    |
    +--> Use the dimension-specific prompt from the master vault
    +--> Research and analyse (using LLM + Perplexity for sources)
    +--> Score per the rubric
    +--> Save evidence (archived sources, screenshots)
    |
    v
Generate scoring summary and recommendation
    |
    v
Generate executive summary and full report
    |
    v
Generate infographic (visual summary via PlaybookLM pipeline)
    |
    v
Create _page.json (navigation layout for browsing)
    |
    v
Share engagement vault with the client (read-only token)
```

## Self-Evaluation: SG/Send as the Test Case

The first engagement vault should evaluate SG/Send itself. This is meta (we use the tool to evaluate the company that builds the tool) but practical:

- We know the company deeply (easy to produce accurate content)
- It demonstrates the tool to visitors ("here is what the output looks like")
- It stress-tests the workflow end-to-end
- The resulting evaluation is a real deliverable we can share with investors

## What Goes on the Website

### Use Case Page (Library Section)

A page explaining the investor pack workflow with:

- Diagram showing the three-layer architecture (standard, master vault, engagement vault)
- Step-by-step walkthrough of how an engagement works
- Screenshots of a real engagement vault being browsed
- Live demo: "Browse the SG/Send evaluation" (read-only vault token)
- Call to action: "Start your own evaluation" (link to the master vault template)

### Live Vault Demos

Two vaults exposed on the website:

1. **Master vault** (read-only): visitors can browse the methodology, the prompts, the templates. This is the "how we do it" transparency.
2. **SG/Send engagement vault** (read-only): visitors can browse the actual evaluation. This is the "what you get" demonstration.

Both rendered via the vault-rendered content system (read key + object ID, client-side decryption).
