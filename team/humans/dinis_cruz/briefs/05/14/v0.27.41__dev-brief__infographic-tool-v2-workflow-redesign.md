# Infographic Tool v2: First-Principles Workflow Redesign

**version** v0.27.41
**date** 14 May 2026
**from** Human (project lead)
**to** Developer (lead), @Dev, @Content
**type** Dev brief

---

## What This Is

The infographic generator is working and has real users. They are happy with the output. The capability is proven. Now the work is to **take a step back and redesign the workflow** with the user's actual journey as the starting point, not the capability we started with.

This brief is the v2 specification. It assumes the underlying generation works (it does), and focuses on:

- The end-to-end user workflow as a coherent experience
- A clear, prominent system prompt the user can shape
- A small, curated model picker
- Asset management within a session (multiple images created; choose, iterate)
- Native integration of the pre-auth + micropayments model from the companion brief
- A grounded path from "I want an infographic" to "I have what I needed and paid for what I used"

## What V1 Got Right (Keep These)

Before redesigning, name what is working so we do not break it:

- **Single-shot prompt model** is fast and produces good results.
- **Re-uploading the source attachment when iterating** works correctly (when one user thought instructions were being ignored, re-attaching the source fixed it).
- **User-provided OpenRouter keys** unblocked early adoption without our infrastructure needing to scale first.
- **Visible cost per generation** is essential and users like it.

These properties stay. The redesign is additive, not corrective.

## What V1 Is Missing (Address These)

| Gap | Why It Matters |
|-----|---------------|
| **The workflow is one-shot; iteration is awkward** | Users generate, find a tweak, lose context, start over |
| **Created assets are not browsable** | Users cannot easily see "what did I generate this session?" |
| **Asset management is missing** | No way to flag favourites, return to a previous variant, branch from one |
| **Payment is bring-your-own-key** | Users without an OpenRouter key cannot use it; users with one resent the setup friction |
| **System prompt is invisible** | The most influential lever (the system prompt) is not surfaced; users cannot shape it |
| **Model choice is unstructured** | Too many models, no curation, hard to pick |

## The Target Workflow

Going back to first principles. A user wants to make an infographic. What does that journey actually look like?

```
1. Arrive. Understand what this tool is and how much it costs.
   ↓
2. Optionally upload a source document or paste a brief.
   ↓
3. See the system prompt clearly. Tweak if desired.
   ↓
4. Pick a model (from 2-3 curated options).
   ↓
5. Submit. See cost estimate before commit (e.g. "This will cost about 0.12.")
   ↓
6. Receive a generated infographic. Possibly 2-3 variants.
   ↓
7. View the variants together. Pick favourites.
   ↓
8. Decide: keep iterating on this image, or start a new one?
   ↓
9. If iterating: refine prompt, generate variant, repeat step 6.
   If new: clear context, return to step 2.
   ↓
10. End session. See total cost. Optionally download or save.
```

Each step is a place where v2 can be intentionally better than v1.

## The UI Surfaces

### The System Prompt (Made Visible)

The system prompt is the most influential lever in the generation. It encodes the design philosophy, the visual constraints, the style. In v1 it is hidden; users cannot tune it. In v2 it should be:

- **Visible** by default, in a collapsible panel
- **Editable** with sensible defaults
- **Saveable** as user-level presets
- **Resettable** to the platform default with one click

A user who never opens the system prompt panel gets a great default. A user who wants to push the output in a specific direction can shape the prompt. Power lives behind a single click, not behind support tickets.

### The Model Picker (Curated)

v1 likely exposes the full OpenRouter catalogue or close to it. Too many choices, no guidance.

v2 should pre-select 2-3 models with clear positioning:

| Model | Position |
|-------|----------|
| **Fast & cheap** | First choice for quick iteration; low cost |
| **Balanced** | Default; quality-cost balance |
| **High quality** | When the final version matters; higher cost |

Each model shows its per-generation cost estimate next to its name. The user picks based on what they need.

Power users can expand to the full model list. Most users never need to.

### The Cost-Visible Submit

Before submitting, the user sees a concrete cost estimate based on the model picked and the size of the input:

> "Generate 3 variants with [Model Name] → ~0.12 total"

The number is the actual estimated cost (using the upstream model's pricing). After generation, the actual cost is shown alongside the variants:

> "Generated. Cost: 0.11. Remaining hold: 4.89."

This makes the cost feel real and trustworthy. The user sees what each action costs before and after it happens.

### The Variant Grid

When 2-3 variants generate, they appear together in a grid:

- Side by side, equal size
- Each clickable to view full size
- Each with a "use this one" button
- Each with a "regenerate with tweak" option

The user picks one or none. They are not forced into a single result.

### The Session Asset Tray

A persistent tray at the side (or below) shows everything generated this session:

- Thumbnails of all generated images
- Grouped by "round" (first generation, second iteration, etc.)
- Hover or click to see the prompt that produced each
- Click to bring it back as the working image for iteration

This solves the "I made something good earlier, where is it?" problem. The session memory is visible and traversable.

### The Iterate-Or-New Decision

After a generation, the user faces a single clear choice:

- **Keep iterating on this image** (preserves context, refines the same direction)
- **Start a new image** (clears the working context, fresh start)

A clean binary choice keeps the user out of "wait, am I editing the right one?" confusion.

## The Pre-Auth Payment Integration

From the companion strategy brief, the model is pre-authorisation + micropayments. The infographic tool is the first concrete integration. The flow:

### First-time user

1. Lands on the tool
2. Sees the value proposition and pricing transparency ("0.05-0.15 per infographic; you pay for what you use")
3. Adds a card
4. We place a £5 pre-authorisation hold
5. They start generating

### Returning user

1. Lands on the tool
2. Their existing hold is still valid → no action needed; just start generating
3. Or their hold has been released (idle) → re-place hold with one click
4. Or their hold is near drainage → renew hold with one click

### Free credits consideration

Worth exploring (and flagged in the voice memo): some free credits to lower friction further. Possible models:

| Model | Notes |
|-------|-------|
| **N free generations per day** | Caps abuse; lets non-paying users try the tool |
| **Free generations only on the fast/cheap model** | Reserves the high-quality models for paying users |
| **First N generations free for any new account** | One-time onboarding incentive |
| **No free tier; clear and small initial cost** | Simplest; tests willingness to pay immediately |

This is worth user testing. The voice memo flagged the question without picking; we should A/B test or just pick one and iterate.

### Cost visibility throughout

The user always sees:

- Current hold remaining
- Cost of the next action before they commit
- Cost of the last action after it completes
- Session total cost

This is the trust-building UI from the payments brief, applied to this tool specifically.

## What "Manage The Assets" Means

The voice memo flagged this: "make it easier to manage the assets that are created." Concretely, in this tool:

| Capability | What It Looks Like |
|-----------|-------------------|
| **See all generated assets this session** | The asset tray |
| **Download any one** | One-click download from the tray or full view |
| **Compare two** | Click two thumbnails → see them side by side |
| **Tag favourites** | Star or flag for easy retrieval |
| **Iterate from a previous one** | Click a thumbnail → it becomes the current working image |
| **Export the session** | Download all assets + prompts as a zip |

Vault integration is deferred per the voice memo's note ("for now, let's not complicate that"). But the asset structure should be vault-shaped from day one, so the future migration is trivial. Each session is effectively a vault-in-waiting.

## The First-Time Experience

A few things matter disproportionately for first-time users:

| Thing | Why It Matters |
|-------|---------------|
| Time to first generated infographic | Should be under 2 minutes from arrival |
| Cost clarity before committing | Removes anxiety about runaway charges |
| The system prompt being visible but not scary | New users see it exists, do not feel obligated to touch it |
| One curated model default | Removes the "which model?" paralysis |
| Quick success | First infographic should be good enough to be impressive |

A user who has a great first experience tells two people. A user who has a confusing first experience leaves and does not return.

## What This Does Not Try To Be

Deliberate omissions in v2:

- **Not a full design tool**: no manual editing, no layer manipulation. The prompt is the lever.
- **Not a template library**: the system prompt encodes the style; no template gallery to maintain.
- **Not multi-format export**: PNG is enough for v2; PDF, SVG, vector exports are later.
- **Not collaboration**: single-user sessions for v2; vault-backed collaboration later.
- **Not version history beyond the session**: in-session asset tray, but no persistent versioning until vault integration.

Each of these is a possible v3 feature. None of them are needed for v2 to be meaningfully better than v1.

## Phasing

The redesign ships in pieces:

| Phase | What Ships | Why First |
|-------|-----------|----------|
| Phase 1 | Pre-auth payment integration, replacing bring-your-own-key | Largest user-experience improvement; unblocks revenue |
| Phase 2 | Visible system prompt + curated model picker | Better creative control with less complexity |
| Phase 3 | Session asset tray + iterate/new flow | Better workflow |
| Phase 4 | Variant grid (2-3 generations per submit) | Better hit-rate per spend |
| Phase 5 | Free credits experiment | Lower onboarding friction |

Phase 1 alone makes the tool meaningfully more usable. Each phase compounds.

## Validation Plan

This is a redesign of a live product with real users. Take care:

- The user who flagged "ignoring my instructions" is a useful validator; ask them to try v2 early
- The other current users (with bring-your-own-key setups) should be migrated thoughtfully (keep their key option as a power-user fallback if useful)
- Run the new flow with 3-5 fresh users to test the first-time experience
- Measure time-to-first-generation, cost transparency comprehension, return rate
