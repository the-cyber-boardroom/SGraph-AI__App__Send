# Milestone: Local Claude on EC2 with Working SGit Tools

**version** v0.27.32
**date** 11 May 2026
**from** Human (project lead)
**to** All Teams
**type** Dev brief (milestone)

---

## What Was Achieved

A fully isolated EC2 instance running an open source LLM model that is powerful enough to execute real workflows, with the SG/Send tool chain working effectively. This is "Local Claude": a self-contained, ephemeral AI environment with vault integration.

### The Key Components Working Together

| Component | Status | What It Does |
|-----------|--------|-------------|
| EC2 instance (GPU-capable) | Running | Hosts the model and tools |
| Open source LLM model | Running | Powerful enough for real instruction-following and tool use |
| Tool use / function calling | **Working** | The model can use tools effectively (this was the hard part) |
| SGit integration | **Working** | The model can clone vaults, pull, push, commit, manage vault content |
| Isolated environment | Confirmed | Everything runs inside the EC2 instance, no external dependencies beyond the model weights |

### What This Enables

The model was given instructions on how to use SGit and was able to:

- Clone a vault using a vault key
- Navigate the vault contents
- Make changes and commit
- Push changes back
- Pull updates from remote

This means we now have an AI agent that can operate on encrypted vaults without any human-hosted infrastructure. The model, the tools, and the vault client all run inside one ephemeral instance. Start the instance, give it a task and a vault key, it works on the vault, you destroy the instance. The model never had access to anything beyond what you gave it.

### Why Tool Use Working Is the Milestone

Many open source models can generate text. Far fewer can reliably use tools (function calling, structured output, following tool-use protocols). Getting an open source model to correctly invoke SGit commands, parse the output, and make decisions based on it is the capability that transforms "a model on a GPU" into "an agent that can work on vaults."

This is the Ephemeral Compute vision from 28-30 Apr realised: a spec that combines compute + model + tools into a self-contained, ephemeral, billable agent session.

## What Comes Next

This milestone is the foundation. The immediate next steps:

1. **Optimise the build/load process** (see companion brief on AMI/EBS refactoring)
2. **Create a proper spec** (`sg-compute_spec_local-claude`) following the spec standard
3. **Add to the stack ecosystem** (Local Claude + S3 Storage + Vault Server = self-contained agent environment)
4. **Benchmark different models** (which open source models handle tool use best for our workloads?)
5. **Cost optimisation** (GPU instance types, spot instances, auto-shutdown)
