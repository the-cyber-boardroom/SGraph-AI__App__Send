## The Case Study, Measured: The Branch Is Hope And The Push Is Enforced

The memo offers the right example and states it too weakly. The project lead: **"the agents, when Claude starts, the agents basically will say, oh, I have my own branch. I'm only going to push to that branch, but that's again that is a soft limitation, and that is hope."**

**Correct, and the same environment enforces three other things in the same domain mechanically.** Read from the environment running this brief:

| Constraint | Where it lives | Enforced? |
|---|---|---|
| **Which branch you may push to** | A sentence in the prompt | **No. Nothing checks it** |
| That there are no uncommitted changes | A hook at session end | **Yes, it refuses to let the session end** |
| That there are no untracked files | The same hook | **Yes** |
| That commits carry a specified signing identity and address | The same hook | **Yes, and it prints the remedy** |
| That nothing is left unpushed | The same hook | **Yes** |

The hook reads the current branch and works with whatever it finds. **It never asks which branch that is.**

So the memo's example is not a case of a constraint being weakly enforced. It is a case of **enforcement machinery being present, working, blocking, and pointed at a different question.** Every enforced item above is about completeness, meaning do not leave work behind. The unenforced one is the only containment constraint in the set.

That is worth stating plainly because it generalises: **where an agent environment has enforcement at all, it tends to be aimed at the operator's convenience rather than at the operator's exposure.**

## Which Means The Mechanism To Fix It Already Exists

The useful consequence, and it turns the memo's illustration into a task.

A hook already runs at the end of every session, already inspects the repository, already knows the current branch, and already refuses by returning a non-zero exit. **Adding a branch constraint is a few lines in a file that is already there**, not new architecture, not a platform request, and not something anybody has to be persuaded to build.

That gives the whole programme its first shipped artefact, and it is small:

```
   MANDATE (declared)          "this session may push only to branches
                                matching agent/*"
        |
        | compiled to
        v
   HOOK (enforced)             the existing session-end check, with one
                                added test that refuses on any other branch
        |
        v
   EFFECT                      the constraint moves from tier three to
                                tier two, and it took an afternoon
```

**And it demonstrates the whole thesis in a single case**, which is worth more than a diagram: here is a mandate, here is the grant it does not cover, here is the delta, and here is the delta closed by an enforcement point that already existed.

## Four Layers Are Already Present, At Three Tiers

The three-tier test from last week, which is that a control bounds a grant only when enforced by something the grant does not include, turns out to be directly observable in this environment. Four layers, at three tiers:

| Layer | What it holds | Tier | Can the agent change it? |
|---|---|---|---|
| An account policy file | Restrictions, compliance markers, defaults | **Boundary**, set above the session | No |
| A settings file | A declarative permissions block, and switches turning individual capabilities off | **Setting**, enforced by the tool | Only if it can write the file |
| Lifecycle hooks | Shell commands at named events, able to refuse by exit code | **Setting, and the strongest one**, because it runs outside the reasoning loop | Only if it can write the file |
| The prompt and project instructions | Everything else | **Expectation** | It is text |

Two observations that matter for the schema work.

**The grant side is already partly declarable**, because the settings file carries a permissions block and a published JSON schema for its own format. So the memo's ask for a schema is half-answered by tooling that already exists, and the honest move is to extend rather than replace.

**And hooks are the interesting tier.** They are configured like a setting and they behave like a boundary while they run, because the command executes outside the agent's turn and its exit code is not something the agent argues with. **That is the closest thing to real enforcement available to somebody who does not control the platform**, and it is the natural compilation target for a declared mandate.

## What The Industry Already Has, And The One Piece It Does Not

The memo asks explicitly. The project lead: **"see if there's something in the industry that we can already use or link or reference or basically reuse, there's no need to reinvent the wheel."**

The answer is specific rather than a list, and it splits into three parts.

| Concern | Adopt or build |
|---|---|
| **Expressing a policy** | **Adopt.** A mature open policy language already expresses principal, action, resource and context, with default-deny, delegation depth limits, and evaluation in a separate process outside the agent's reasoning loop. A major cloud vendor has built its agent authorization service on it. **Do not invent a policy language** |
| **Establishing identity** | The same language's documentation states plainly that it evaluates authorization and does not establish identity, so this is the registry's job and the two compose rather than compete |
| **Declaring the mandate** | **Build. Nothing found does this** |

That third row is the finding. Published agent cards declare scope of authority and spend caps, which is the closest thing, and they are self-published, so they carry no issuer other than the subject and no interval, which is the pair that makes a mandate accountable rather than descriptive. A permissions file says what is allowed. **Nothing anywhere says what was expected, by whom, and until when.**

So the gap to fill is one document rather than a stack, and the surrounding pieces are somebody else's problem already solved.

One property of the adopted language is worth carrying into the design rather than discovering later. **It evaluates in a separate process outside the agent's loop**, which is precisely the test this corpus set for whether a control is a boundary or a setting. Any mandate format that compiles to it inherits that property. Any mandate format that compiles to a prompt does not.

## Implicit Authority Rather Than Implicit Authorisation

A refinement rather than a correction, offered at that strength because the memo's formulation is close and the word matters in a document whose whole subject is the difference between what was decided and what exists.

The project lead: **"the mandate is the explicit authorisation, and the grant is the implicit authorisation."**

**Authorisation implies that somebody authorised.** The argument this vocabulary exists to make is that nobody did: the excess arrived bundled with a credential, and there is no meeting, no owner, no date. Calling it implicit authorisation quietly concedes the point.

> **The mandate is authorisation. The grant is authority.** One was decided; the other merely exists.

**And there is a real sense in which the memo's word is right**, which is worth keeping rather than discarding. The finding recorded on 20 August is that under the doctrine of apparent authority a principal is bound by acts a third party would reasonably take as authorised, and that issuing a visibly broad credential is what creates that appearance. So the grant is not authorisation to the holder and it is treated as authority by the outside world.

The precise form, which the site can use:

| | Who decided it | How the world treats it |
|---|---|---|
| Mandate | Somebody, on a date, for an interval | Actual authority |
| Grant | Nobody | **Apparent authority, and binding anyway** |

## A Grant Is Discovered, Not Authored

The load-bearing design rule, and the memo states the reason without drawing the conclusion. The project lead: **"this is not about what we wish it happens. This is about what happens."**

**A hand-written grant file is a wish.** It records what somebody believed the environment could do on the day they wrote it, which is exactly the thing the memo says the grant is not.

So:

> **The grant document is generated by measurement, carries provenance per node, and is dated. It is never hand-authored, and a node with no evidence is marked unevidenced rather than omitted.**

That is the 2 August discipline applied to a new subject, where every fact is evidenced or explicitly marked as not, and it has three consequences for the format.

**Every node needs a source.** Read from a settings file, observed by running a command, stated in documentation, or inferred. The four are not equally trustworthy and the file should say which.

**Every node needs the tier.** Boundary, setting, or expectation, from the test above, because a list of what is reachable without saying what stands in the way is the part people already have.

**And the file needs a measurement date rather than a version.** The memo's own drift question depends on it.

## The Two Documents

What the memo asks for, specified. **Two files, not one, because they have different authors, different lifecycles and different trust properties.**

| | `grant` | `mandate` |
|---|---|---|
| Produced by | **Measurement**, generated | **A person**, authored |
| Authority | The environment as it is | The issuer |
| Signed by | Whoever ran the measurement | **The issuer, and this is what makes it a mandate** |
| Carries an interval | No. It carries a measurement date | **Yes. Without one it is a grant under another name** |
| Changes when | The environment changes | Somebody decides |
| Stored as | An identifier, a hash, and the measurer's signature | The same, plus the issuer's signature |
| Keyed | **No.** Both are artefacts, not principals | **No** |

Shape, in outline rather than in full, since the field names are the next memo's subject:

```
   grant
     measured_at, measured_by, environment
     nodes[]
        capability          what it can do
        reachable           what that reaches
        tier                boundary | setting | expectation
        control             what stands in the way, or nothing
        evidence            read | observed | documented | inferred | none
     
   mandate
     issuer, subject, issued_at, expires_at, revocation
     allow[]                the enforceable form
     prohibitions[]         the presented form, generated from allow[]
     
   delta                    COMPUTED, never stored
     excess[]               in grant, not in allow
     shortfall[]            in allow, not in grant
```

**The delta is computed and never stored**, for the same reason the register entry carries no history array: a stored delta is stale the moment either side moves, and the interesting property of this system is that it can be recomputed at any time.

Two things carried from last week rather than re-decided. The allow-list is the enforceable form and the prohibitions are a generated rendering with their own date, because a deny-list widens silently whenever a provider ships a capability. And the shortfall row matters as much as the excess, because a mandate the grant cannot satisfy is what produces the next over-broad credential.

## The Skill, And What It Must Not Be

The memo wants a skill. The project lead: **"eventually a skill that we can give an agent so that we can be very explicit to the agent of what we expect it to do."**

It should do three things and refuse a fourth.

| Does | |
|---|---|
| **Discover** | Runs the measurement, produces the grant document with provenance and tiers |
| **Declare** | Walks the person through authoring a mandate, in prohibitions, storing the allow-list |
| **Diff** | Computes the delta, and re-runs the discovery to answer the drift question |

| Must not | Why |
|---|---|
| **Enforce** | A skill runs inside the agent's own loop, so a skill that polices the mandate is the agent marking its own homework, which is the tier-three failure this whole exercise exists to expose |

**The skill compiles; the hook enforces.** That division is the entire architecture in four words, and getting it wrong would produce something that looks like a control and is an expectation, which is worse than nothing because it would be believed.

One honest note on the discovery step. **An agent measuring its own grant reports what it can see**, and a capability it does not know it has will not appear. So the generated document is a floor rather than a census, and it should say so on its face.

## Drift Has A Cheap Answer

The memo asks the recurring question. The project lead: **"is our grant understanding still correct, or has it changed, and should we adjust that?"**

Because the grant is generated rather than authored, the answer is mechanical: **re-run the measurement and diff it against the last one.** Three outcomes, each meaning something different:

| Diff shows | Meaning |
|---|---|
| A new capability appeared | The environment changed under you, and the mandate now covers less of it than it did |
| A node moved from setting to expectation | **A control was removed, and this is the alarming one** |
| A node moved from expectation to boundary | Somebody improved something, and it should be recorded |

**The second row is the one to alert on**, because it is the silent case: nothing broke, nothing failed, and the containment stopped existing.

And the cadence is the same discipline used everywhere in this corpus for things that age: dated, re-runnable, and with the method published so somebody else can run it and get the same answer.

## Build Order

1. **The branch constraint in the existing hook.** One afternoon, it demonstrates the thesis end to end, and it produces the first case where a declared mandate became mechanical.
2. **The grant measurement**, for one environment, generated with provenance and tiers, dated.
3. **The two schemas**, written down, with the delta computed rather than stored.
4. **The mandate for that same environment**, authored, in prohibitions, with the allow-list stored.
5. **The skill**, doing discover, declare and diff, and refusing to enforce.
6. **The compilation target**, taking the allow-list to the adopted policy language, at which point the mandate becomes evaluable outside the agent's loop.

The acceptance test, in the discipline this corpus uses:

> Run the skill in a fresh environment. It produces a dated grant document nobody wrote. Author a mandate that is deliberately narrower. The delta is non-empty and specific. Compile one line of it into the existing hook. **Then attempt the prohibited action and be refused by something that is not the agent.**

The last sentence is the whole thing, and until it passes, everything above is instrumentation.

## What This Does Not Try To Be

- **Not a new policy language.** One exists, is open, is default-deny, and evaluates outside the agent's loop.
- **Not an identity design.** The adopted language says explicitly that it does not do identity, which is the registry's job.
- **Not a hand-written grant.** A grant that somebody typed is a wish, and the memo says so itself.
- **Not an enforcement skill.** A skill runs inside the loop; the hook runs outside it.
- **Not a census.** An agent measuring its own grant reports what it can see, so the document is a floor.

## Honest Tensions

| Tension | Note |
|---------|------|
| Compiling mandates to hooks | It is real enforcement available today and it works only where somebody controls the environment, which is the population that needed it least |
| Adopting an external policy language | It saves inventing one and it binds the format to somebody else's roadmap and to a cloud vendor's implementation |
| Grant by measurement | It is honest and it is a floor, since an agent cannot enumerate what it does not know it has |
| Two documents | It separates the measured from the decided and it means two things to keep current instead of one |
| The skill that refuses to enforce | It is architecturally correct and it will be the first thing somebody asks it to do |
| Implicit authority | The distinction is precise and it is one word apart from the memo's, which is exactly the kind of correction that does not survive being repeated |
