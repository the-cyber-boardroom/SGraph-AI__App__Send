## Do This First: Inventory What The Two Sites Already Publish

The instruction that comes before everything, and it is the same one given on 14 August for a different pack: **the pack cannot be written honestly until somebody establishes what already exists**, or it will duplicate what is there and assume what is not.

Fetched today:

| Site | Already publishes | Does not have |
|---|---|---|
| **pki.sgit.ai** | The 2019 keyserver failure as grounding, four rules, identity and mandate as two independently revocable statements, a roadmap, a documents section, a participant disclosure, its own machine-readable index | **Any entries.** It is a design specification, not an operating registry |
| **graphs.sgit.ai** | A scoped lexicon, a methods register of more than thirty techniques, an artefact catalogue, formally defined edge sets, provenance chains tracking source and authority, nodes at document, section, sentence and word scale, byte-for-byte source preservation with hashes, and gated releases that fail if frozen content drifts | Nothing about grants or mandates |

**So the first deliverable of the pack is that inventory and the second is the architecture**, and the pack should say which of its own contents are new, which surface something that exists, and which replace something. That three-way marking was asked for on 14 August for the same reason and is worth repeating here.

## The Separation Of Concerns Is The Architecture

The memo states it and it should be stated harder, because it is the decision everything else hangs from. The project lead: **"the risk mandate does not have this information, does not need to leverage the data and the JSON files and the information and the graphs that we create on the other one."**

| | **pki.sgit.ai** | **riskmandate.ai** |
|---|---|---|
| Holds | **The library**: a grant tree per environment, generated by measurement, dated | **The instance**: this user's selections, mandates, deltas and risks |
| Nature | A public dataset | A private instance over it |
| Personal data | **None. Ever** | All of it |
| Produced by | Re-running a measurement | A person answering questions |
| Stored in | A repository now, a vault later | The browser first, the user's own vault later |
| Shared how | Published, fetchable in one request | **Never published** |

**And the rule that follows is the one settled on 20 August for a different product: the instance stores references into the library and never copies.** Two consequences, and the second is the one nobody states.

**The library stays versionable.** A building block corrected next month improves every instance that referenced it, and an instance that copied it keeps the old answer silently.

**And a finished pack becomes shareable.** If the instance is a list of library identifiers plus a mandate, then handing somebody your pack discloses which products you use and nothing about your machine. **That is what makes the mandate pack a sendable object at all**, and it is the property the vault transport exists to serve.

## Reality Before The Risk Register

The memo corrects its own approach and this is the most important line in it. The project lead: **"at the moment we're starting with the risks first, and it's the other way around. We have to start with the reality."**

**That is right, and it needs to be an explicit ordering rule in the pack**, because a pack whose first screen is a risk register will reproduce exactly the habit it was written to fix. The chain is the one worked on 2 August, with the subject changed:

```
   REALITY        the agentic environment, as installed and configured
   TWIN           that installation, which everything attaches to
   FACTS          the grant, measured, dated, provenance per node
                  the mandate, authored, signed, with an interval
   FINDING        the delta, computed rather than argued
   RISKS          derived, at each altitude, in that altitude's language
   DECISIONS      separate nodes, named acceptor, interval
```

**You cannot author a risk before you have a fact, and the fact is a measurement.** So the first screen of the MVP is not a risk and not a questionnaire about risk appetite. It is: which environment, and here is what it can do.

The prior work the memo asks to be referenced fits at the end of that chain rather than the start. The plug work of 24 July gives each derived risk its profile across who holds the stop, blast radius, speed, side effects and recoverability, and recoverability is the dimension that matters most here because a grant exercised once cannot be un-exercised.

## The Comparison Has Three Terms, Not Two

The change that makes the library worth building, and the memo has two terms where three are needed.

The memo wants the agent to report on itself. The project lead: **"get an agent to say, hey, here's the grant that you have given me, or here's the grants that I have based on what you gave me."**

**An agent asked to report its own grant is both the instrument and the subject.** It reports what it can see, which this corpus established this morning is a floor rather than a census, and it has no way to report a capability it does not know it has. A self-report is therefore unfalsifiable on its own.

So three terms, and two deltas:

| Term | Source | What it is |
|---|---|---|
| **Library** | Measured once, published, dated | What this environment is **known** to grant |
| **Self-report** | The agent, in this session | What this agent **noticed** it has |
| **Mandate** | The person | What was **asked for** |

```
   LIBRARY  ----minus----> SELF-REPORT     = BLIND SPOTS
                                             what the environment has and
                                             this agent did not report

   SELF-REPORT ---minus--> MANDATE          = EXCESS AUTHORITY
                                             the delta already named
```

**The blind-spot delta is new and it is the argument for the library.** Without it there is no way to tell a thorough self-assessment from a lazy one, and it produces a number the memo would want: how much of its own grant did this agent find. It is also the honest answer to the memo's suggestion of trying the same exercise with different agents, because that comparison is only meaningful against a common reference.

**And it should be rendered rather than buried**, because a screen that says this agent reported eleven of the nineteen capabilities its environment is known to have is the most persuasive thing in the whole flow.

## Memory Gives The Grant A Time Axis

The best example in the memo, and it changes the schema specified this morning. The project lead: **"if in cloud code you have access to the past history and memory, then all of that is now technically exposed to every single chat, right? Or maybe a prompt injection, or you are one prompt away from manipulating that."**

**Correct, and the consequence is structural.** With memory off, a grant is what this session can reach. With memory on, it is that **union with everything any prior session reached**, for as long as the history is retained. This corpus established last week that the session transcript is an ordinary file and is a superset of every file the session read, so memory is not a separate store to be assessed separately: it is the accumulated record, and everything any earlier session touched is inside it.

| | Grant shape |
|---|---|
| Memory off | A tree. A property of the environment |
| **Memory on** | **A union over history. A property of the environment and its past** |

Two things follow.

**Two identical installations have different grants**, if their histories differ, which means a library entry can never be the whole answer for a real user. That is not a defect in the library; it is the split:

> **The library publishes the static term. The instance carries the accumulated term.**

**And this is the clearest case in the whole product**, because it needs no security argument. Anybody understands that a tool which remembers everything you have ever shown it can be asked about any of it, and that the asking need not come from you.

The schema from this morning should gain one field on the grant document recording whether history is retained and over what window, because it changes the meaning of every other node.

## The Graph Conventions Are Already Published On Your Own Site

The memo asks the registry to define the lexicon, the relationships and the semantic flows, and points at the sibling site. The project lead: **"take a look at the great work we've been doing on graphs.sgit.ai, especially on the books, especially on the thinking in graphs document."**

**The conventions exist and should be adopted rather than restated.** That site publishes a scoped lexicon, a methods register, an artefact catalogue, formally defined edge sets, provenance chains that track source and authority, and nodes at several scales on the principle that a node carries no inherent meaning and what a thing is emerges from the edges traceable from it.

Two of those are directly load-bearing here.

**Provenance chains tracking source and authority** are exactly what the grant document needs per node, and this morning's brief specified the same field independently. Adopting the existing edge vocabulary means the grant tree is a graph in the house style rather than a bespoke format.

**And the release gate that fails when frozen content drifts is the drift mechanism this corpus asked for this morning**, already built. A library of dated claims about other people's products needs precisely that: a build that fails when a frozen claim no longer matches.

One more, and it is worth recording as a small correction to a brief written six days ago. That site's second edition is being written **top-down from the central thesis so that a reader finds a complete argument at any depth**. On 20 August this corpus proposed the same rule for the explanation levels, that each level must be a complete answer rather than a step towards one, and presented it as new. **It was already an established convention on a sibling site, and was the stated reason for rewriting a book.** The convention should be cited rather than re-derived.

## Two Metaphors: One Already Tested, One Already Taken

The memo reaches for visual metaphors and is right to be cautious about one of them. The naming check, and it is the sixth in this corpus in a fortnight.

| Metaphor | Prior treatment here | Recommendation |
|---|---|---|
| **Card** | Clean in this domain | **Use it** |
| **Pack** | Clean, and already used for briefing packs and evidence packs in a compatible sense | **Use it** |
| **Passport** | **Already tested and found wanting.** The corpus carries a table headed with passport properties and why they misfit | **Set aside, as the memo already does** |
| **Wallet** | **Taken.** In this corpus a wallet is a payments object: self-custody, accounting abstraction, transaction integration | **Avoid** |

The wallet one is worth a sentence beyond the collision. **If the interface looks like a wallet, readers import the expectation of verifiable credentials**, meaning signed claims held by the subject and presented to a verifier. This corpus decided last week that grants and mandates are artefacts rather than principals and are signed by an issuer rather than held as credentials. So the wallet metaphor would promise a model the design deliberately does not use, and the confusion would land in the interface aimed at people making decisions.

## What The Mockups Must Show

The memo asks for design mockups and there is now a design capability able to produce them. **Six screens, and the fourth is the one that will be got wrong.**

| # | Screen | Must show |
|---|---|---|
| 1 | Choose the environment | From the library, each entry with its measurement date |
| 2 | The grant | The tree, with each node's tier and provenance, and the history field prominent |
| 3 | **The self-report comparison** | Three terms, two deltas, and the count of what the agent missed |
| 4 | **Declare the mandate** | **Prohibitions, because that is what a person can accept.** The allow-list is stored and not shown here |
| 5 | The delta | Excess and shortfall, side by side, as the product |
| 6 | The pack | What is in it, what it discloses, and that it is references rather than a description |

Screen four is the trap. **Showing a person an allow-list and asking them to approve it produces consent without comprehension**, and the corpus settled last week that the prohibition list is the presentation layer generated from the allow-list, with its own date.

## The Agent Is A Primary Consumer, Which Changes The Packaging

The memo is explicit and this is the half most likely to be under-served. The project lead: **"we are as much talking to a user that's going to do this as we're talking to an agent."**

Three requirements follow, and they are not interface requirements.

**One fetch.** The library must be obtainable in a single request, as a concatenated document or an archive, because an agent that cannot follow links can only use what one fetch returns. That was established on 14 August and confirmed on 20 August, where the conclusion was that the constraint is harness-dependent and the mitigation costs nothing.

**A document, not a rendering.** The agent's output is a grant document and a mandate document, and the interface renders them. If the interface is where the data lives, the agent path does not exist.

**And the self-report must be structured before it is compared.** An agent asked to describe its grant in prose produces something incomparable. The skill should hand it the schema first, which is what makes the blind-spot delta computable rather than a judgement.

The acceptance test for the pack, in the discipline used repeatedly:

> Give a fresh agent the machine-readable index and nothing else. It fetches the library in one request, produces a structured self-report of its own grant, computes both deltas against a mandate the user wrote in prohibitions, and hands back a pack containing references rather than descriptions. **No page is read by a human anywhere in that sequence.**

## What This Does Not Try To Be

- **Not the pack.** It specifies what the pack must settle and hands the building to the site's agent.
- **Not a new graph format.** The lexicon, edge sets and provenance conventions exist on the sibling site.
- **Not a risk-first flow.** Reality, then facts, then the delta, then risks, and the ordering is a constraint.
- **Not a wallet.** The word is taken by the payments work and it promises a credential model this design does not use.
- **Not a claim that a self-report is enough.** It is a floor, and the library is what makes it checkable.

## Honest Tensions

| Tension | Note |
|---------|------|
| The library as a public dataset | It is what makes self-reports falsifiable and it is a dated public assessment of other people's products, maintained indefinitely |
| References rather than copies | It keeps instances small and shareable and it means an instance silently changes meaning when a library entry is corrected |
| The blind-spot delta | It is the most persuasive number in the flow and it measures the agent as much as the environment, which will be read as a vendor comparison |
| Memory as a time axis | It is the clearest example for a lay audience and it makes the library entry incomplete for every real user by construction |
| Adopting the sibling site's conventions | It costs nothing and it binds this format to a book that is still being written |
| Agent as primary consumer | It is where the leverage is and every requirement it adds is invisible in a design review that looks at screens |

## Open Questions

| Question | Notes |
|----------|-------|
| Who measures a library entry, and with what authority? | The candidate is an agent inside that environment, which is the party being measured |
| How often is an entry re-measured? | It is a dated claim about somebody else's product and it ages on their release schedule |
| Does the instance record which library version it used? | Otherwise a user returning next month cannot tell whether their setup changed or the library did |
| What is the history window field? | Retention differs per product and per plan, and the grant's meaning turns on it |
| Where does the pack live once built? | The browser, a vault, or a file, and only the second survives a device |
| Is the blind-spot number published per agent? | It is a comparison between vendors' agents whether or not it is framed as one |
