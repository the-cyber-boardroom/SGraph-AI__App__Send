# The Measurable Primitives, Measured Inside A Running Session Rather Than Assumed

**version** v0.33.62
**date** 26 August 2026
**from** Human (project lead)
**to** The implementing session

**type** Reference

*Everything in this document was measured on 26 August inside a running agent session, and the commands that produced each figure are named so the measurement is reproducible. Where something cannot currently be measured it says so rather than proposing a field for it. The figures are from one session on one date and are illustrative of shape rather than of typical volume.*

---

## The Rule This Document Exists To Serve

> **A policy may only be written in units the system already meters.** If nobody can name the counter, the claim needs a judgement, and a judgement is not settleable in milliseconds.

So this document is the list of counters. Anything not in it cannot be policed yet.

## Tokens: There Are Four Counters And The Obvious One Is Wrong

**The single most important finding in this pack.** The session transcript records a usage object on every assistant turn, carrying these fields:

```
input_tokens                    output_tokens
cache_creation_input_tokens     output_tokens_details
cache_read_input_tokens         server_tool_use
service_tier                    cache_creation
inference_geo                   iterations
speed
```

Totalled across one working session:

| Counter | Value | Share |
|---|---|---|
| `input_tokens` | **562** | Negligible |
| `cache_creation_input_tokens` | **16,988,879** | Large |
| `cache_read_input_tokens` | **91,336,787** | **Dominant** |
| `output_tokens` | **967,984** | Material |

> **A policy written against `input_tokens` would have measured 562 for a session that actually moved a hundred and nine million tokens.** That is wrong by five orders of magnitude, and it is the field anybody would reach for first.

Two consequences for the rate table.

**Four counters need four prices**, because they do not cost the same. Cache reads are cheap per token and enormous in volume; output is expensive per token and small in volume. A single token price applied to a single counter produces a meaningless number whichever counter is chosen.

**And the dominant term is cache reads, which grow with conversation length rather than with work done.** A long session doing nothing accumulates cache reads. So a token policy measures duration at least as much as it measures activity, and the rate table has to decide whether that is intended.

**How to read it:** parse the session transcript, take `message.usage` from records of type `assistant`, and sum per field.

## Tool Calls: Countable By Name

Every tool invocation appears in the transcript as a `tool_use` block with its name and parameters. Counted across the same session:

| Tool | Calls |
|---|---|
| Bash | 67 |
| WebFetch | 35 |
| SendUserFile | 19 |
| WebSearch | 15 |
| Read | 9 |
| TaskCreate | 3 |
| TaskUpdate | 3 |
| ToolSearch | 2 |
| AskUserQuestion | 1 |

**This is the richest primitive available and it is free.** It gives a rate per tool, and because the parameters are recorded it also gives the arguments, which is where the interesting policies live.

## Network Egress: Countable, And The Destinations Are Recorded

Egress happens through named tools, so it is countable as a tool rate, **and the destination is in the parameters**. Fifty requests to a package index and fifty requests to fifty different hosts are the same count and very different facts.

| Policy shape | Measurable? |
|---|---|
| Number of outbound fetches | **Yes**, tool count |
| Which hosts were reached | **Yes**, from the parameters |
| An allow-list of hosts | **Yes**, and it is the most useful network policy available |
| Bytes transferred | **Not directly.** Response sizes are not recorded as a field |

So write network policy against **destinations and counts**, not bandwidth. Bandwidth is the primitive the memo asks for and it is the one not currently exposed.

## Git: Everything, At Hook Time

All of these are available to a shell hook at commit or push time, with no special tooling:

| Primitive | Command |
|---|---|
| Current branch | `git branch --show-current` |
| Commits today, by branch | `git rev-list --since=midnight --count HEAD` |
| Staged diff size in bytes | `git diff --cached --numstat`, or the byte count of `git diff --cached` |
| Files changed | `git diff --cached --name-only \| wc -l` |
| Largest single blob added | `git diff --cached --numstat`, per path |
| Unpushed commits | `git rev-list @{u}..HEAD --count` |

**Git is the best-instrumented surface in the whole system**, which is why the first two policies are written against it.

## Session State Size

The transcript itself is a primitive: **3.2 megabytes across 926 records** for the session measured. It grows continuously and is a proxy for context accumulated. Worth recording because it is free and because it correlates with the cache-read term above.

## What Cannot Currently Be Measured

Stated rather than quietly omitted, because the pack's credibility depends on the boundary being visible.

| Wanted | Status |
|---|---|
| Bytes transferred over the network | **Not exposed.** Counts and destinations only |
| Wall-clock time attributable to a task | Partially, from record timestamps, and it includes waiting |
| CPU or memory consumed | **Not exposed** |
| Cost in money | **Derivable** from token counters and a price list, not measured directly |
| What a subagent consumed, separately | **Unverified.** Needs checking before a policy depends on it |

## The Evidence Tier Of These Measurements

This matters more than the list, and it is the reason self-monitoring is acceptable here despite the obvious objection.

**The transcript is written by the harness, not authored by the agent.** The agent does not compose its own usage records; they are produced by the runtime as a side effect of running. So a usage figure read from the transcript is **observed**, not **self-reported**, which is a materially stronger evidence tier and it is the difference between a meter and a claim.

| Source | Tier |
|---|---|
| The transcript, read by a hook | **Observed.** The agent did not write it |
| Git state, read by a hook | **Observed** |
| An agent's own statement about its usage | **Self-reported.** Use only where nothing else exists |

The memo concedes that self-monitoring is acceptable for now and can move to a proxy later. **The transcript is better than self-monitoring already**, and the honest caveat is the remaining one: an agent running as root in its own container could in principle alter the file. That is a reason to move the reading to a hook rather than to the agent, which is what this pack specifies, and eventually to ship the events off the machine, which is what the append lane does.
