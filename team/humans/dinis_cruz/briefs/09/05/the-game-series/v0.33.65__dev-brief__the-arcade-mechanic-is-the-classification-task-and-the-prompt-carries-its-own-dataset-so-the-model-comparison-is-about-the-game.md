# The Arcade Mechanic Is The Classification Task Itself, Three Bins And Three Inputs: The Prompt Carries Its Own Dataset So That Comparing Models Measures The Game Rather Than Who Invented Better Examples, Blocking Real Work Is The Expensive Mistake, And Every Negative Score Owes The Player An Explanation

**version** v0.33.65
**date** 5 September 2026
**from** Human (project lead)
**to** Product, Engineering, Design

**type** Dev brief

*Sixth of 5 September, and the third in the game series. The memo asks for a prompt rather than a game, to be handed to several models so their attempts can be compared, so the deliverable is the prompt and it ships beside this as a reference document. Four design decisions in it are not in the memo and each changes what the exercise measures: the dataset travels inside the prompt, the impossible bin is the largest one and contains things that sound powerful, both scoring asymmetries are stated, and the disputed items are marked rather than hidden. The impossible bin is the correction that matters, because the first draft of this dataset would have been won by a player who assumed the agent could do anything, which is the opposite of what the game is for. Limitation: no model has been given the prompt yet, so the acceptance checklist is a design rather than a result, and the item bins are one person's reading of a common setup.*

---

## What This Is

A prompt for building an arcade triage game, and the reasoning behind the parts of it that are not obvious: **the memo's instinct that this is a shooting game is better than it sounds, because the arcade mechanic turns out to be the classification task with nothing added, since actions arrive, the player has three inputs, and those three inputs are exactly the three bins this estate's whole vocabulary reduces to, namely the agent can do this and you want it to, the agent can do this and you do not want it to, and the agent cannot do this at all, so letting through, flagging and shooting are not a metaphor for grant and mandate but a direct rendering of them; the middle bin is the game and the memo knows it, because that bin is excess authority and almost nobody classifies it correctly, which means the score is a measurement of the same thing the other two games measure by different routes; the first decision the memo does not make is that the dataset must travel inside the prompt, because the point of the exercise is to compare what several models do with one request, and a prompt that leaves the content to the model compares content rather than craft, so forty items are supplied with their bins, their explanations and their levels, and the instruction not to change them is the strongest line in the prompt; the second is that the scoring is asymmetric on purpose, since shooting a legitimate action costs more than letting an impossible one through, which is true of the subject because blocking real work is what makes people turn a control off, and it teaches the instinct this estate actually wants rather than the reflexive one; the third is that arguable items are marked as arguable and score half, which is honest about a dataset where several rows genuinely depend on the machine rather than the agent, and it feeds the mechanism the memo asks for, since every negative score owes the player an explanation and beside every explanation sits a button that records their disagreement, which makes a player who knows more than the dataset into a contributor rather than somebody who quit annoyed; and the honest place of this game in the series is as the entertaining end of it, because speed pressure is what makes an arcade game work and it degrades a measurement, so this one converts better and measures worse than the game written yesterday, which is a reason to ship both rather than to pick.** New contributions: **the three inputs shown to be the three bins rather than a metaphor for them, the dataset inside the prompt so the model comparison is fair, the asymmetric scoring with its reasoning, disputed items scored at half with both readings shown, the disagreement capture as a contribution path, and an acceptance checklist so several models can be scored identically.**

## The Mechanic Is The Model

The memo reaches for a shooting game and arrives somewhere better than a theme. **The three things a player can do to an incoming action are the three bins the whole vocabulary reduces to.**

| Player's input | The bin | In the estate's words |
|---|---|---|
| **Let it through** | `allowed` | Inside the grant and inside the mandate |
| **Flag it** | `excess` | **Inside the grant, outside the mandate.** Excess authority |
| **Shoot it** | `impossible` | Outside the grant |

There is no translation layer. A player who gets good at this game has got good at the actual distinction, which is not true of most educational games and is the reason this one is worth building properly.

**The middle bin is the game.** It is where almost everybody is wrong, it is the object the entire product exists around, and an arcade format is a surprisingly good way to drill it, because it forces a decision at speed and speed is where instincts show.

## Three Decisions The Memo Does Not Make

### The dataset travels inside the prompt

The memo's purpose is to hand one prompt to several models and see what they do. **If the prompt leaves the content to the model, the comparison measures who invented better examples, which is not the question.**

So the prompt carries forty items with their bins, their explanations and their level, and the instruction not to change them is the strongest line in it. What then varies between models is what should vary: pacing, feel, legibility, whether they implemented the explanation, whether they followed the checklist.

**A second benefit falls out.** The dataset is now a shared artefact that can be corrected once and reused across every model's attempt, which means a mapping error is fixed in one place rather than in five games.

The mix matters and is the part that had to be corrected. See the next section.

### The impossible bin is the largest, and it contains things that sound powerful

**This is the correction that mattered most, and the first draft of the dataset got it
wrong.** That draft had thirty-one items of which twenty-two were things the agent could
do, and an impossible bin made mostly of things nobody credits an agent with anyway:
turning on a camera, paying a bank, reaching a colleague's laptop. Nothing in it punished
the belief that an agent can do anything, which is the belief this game most needs to
correct.

**A player who assumed the agent could do everything would have done well**, which is the
opposite of what the game is for.

The fix is not a scoring tweak. It is content. **The impossible bin is now the largest of
the three and it is full of things that sound plausible and powerful**, drawn from the
ceiling that binds even the most privileged agent in an environment.

| Reason it is out of reach | Item in the dataset |
|---|---|
| **Tenancy isolation** | Read another customer's conversations with the same assistant |
| **Provider-side metering** | Give itself a higher token limit. Avoid being billed for what it uses |
| **Provider-side records** | Remove its own actions from the provider's audit log |
| **A second factor** | Reset an account protected by one. Approve a sign-in prompt on your phone |
| **Cryptography without the key** | Decrypt a vault. Forge a signed commit as another developer |
| **Rate limits and lockouts** | Brute-force a password without being locked out |

**The general principle is the mirror of the enforcer test.** A capability is excess when
something outside the agent could have bounded it and did not. **A capability is impossible
when something outside the entire environment bounds it**, and no amount of privilege
inside that environment reaches past it. The most privileged agent on a laptop is still on
one laptop, in one tenant, under one provider's meter.

### Some impossible things are attemptable, and the attempt is the signal

The sharpest items in the bin are the ones where the agent **can try**. Resetting an account
behind a second factor, or guessing a password against a lockout, are not refused by the
agent's own restraint; they are attempted and they fail.

**The correct classification is still shoot, and the explanation must say three things**:
the agent can try, it will not succeed, and the failed attempt is visible to somebody. That
last clause is the most useful sentence in the whole dataset, because it teaches that a
failure is a detection event rather than a non-event.

Do not soften these into a fourth bin. Three bins keep the arcade playable, and the nuance
belongs in the explanation, which is where the teaching happens anyway.

### The scoring is asymmetric, in two directions

| Mistake | Cost | Why |
|---|---|---|
| Shooting an `allowed` action | **-20** | **The most expensive.** The player just blocked legitimate work |
| **Letting an `impossible` action through** | **-15** | **Corrected from -5.** Believing an agent can do what it cannot is a real error |
| Any other misclassification | -15 | Ordinary error |

**Blocking real work is the most expensive mistake**, and that is not a game-balance choice,
it is the subject. A control that blocks legitimate work is a control somebody turns off,
which this corpus has said in several forms: bounding is not free, the freeze is a lose
condition, and a programme that only tightens produces resentment and exceptions.

**And over-crediting is not free either**, which the first draft got wrong by pricing it at
five. It costs nothing operationally, since the thing was never going to happen, and it
costs a great deal in attention: a person who believes their agent can read their email
spends their effort in a place where there is no exposure, and does not spend it on the
home directory it genuinely reads. **Fear misallocates the control budget**, which is the
Vulnocalypse argument in miniature.

With the corrected dataset and these numbers, every lazy strategy loses badly:

| Strategy | Score, from 40 items |
|---|---|
| Let everything through | **-350** |
| Flag everything | **-250** |
| Shoot everything | **-200** |
| Perfect play | +400 |

**Verifying that a yes-biased run finishes negative is an item on the prompt's own
acceptance checklist**, so every model that builds this has to test it.

### Arguable items are marked, not hidden

Four of the forty genuinely depend on the machine rather than the agent. Whether a terminal agent can write system configuration depends on whether the account can escalate. Whether it can read the browser's saved passwords depends on the operating system's keychain. Whether searching the web is wanted depends on the owner.

**Those are marked `disputed`, score half, and always show both readings.** Three reasons.

**It is true**, and a dataset that pretended otherwise would be the confident overclaim this corpus keeps catching.

**It is where the best players learn most**, because the explanation says the answer depends on something they can go and check about their own machine.

**And it seeds the contribution path**, since a disputed item is an invitation to disagree rather than a fact somebody has to accept.

## Every Negative Owes An Explanation

The memo asks for this directly and it is the most important requirement in the prompt, so it is written as one:

> **Every negative score must produce a one-line explanation, immediately, on screen. This is not optional.**

Without it the game is a reaction test. With it, a player learns the actual mapping through fifteen small corrections in three minutes, which is a better teaching rate than any document this estate has produced.

**And beside every explanation sits a button reading "I disagree."** Pressing it records the item and the player's classification, and the end screen offers the list as JSON.

That is the memo's own point about playing it to give feedback, generalised: **a player who knows more about a specific agent than the dataset does is more valuable disagreeing than scoring**, and a game that has no way to receive that turns an expert into somebody who quit annoyed. It is the same rule as a wrong branch in the guessing tree being a contribution.

## Where This Sits In The Series

Three games now, and they are not versions of one thing. The memo's framing is right: ship them and see which works.

| Game | The player | Measures | Converts |
|---|---|---|---|
| **Which Agent Is It** | Does not say what they have | Their prediction gap, once | Curiosity |
| **What Can It Do** | Names their agent | **Their calibration, and it elicits a mandate** | Engagement |
| **Let It Through** | Plays an arcade game | **A triage instinct, under time pressure** | **Best, and measures least** |

**The honest note is that speed pressure is what makes an arcade game work and it is what degrades a measurement.** A player rushing a decision is not reporting a considered belief, so this game's score is a weaker instrument than the calibration score from yesterday's design.

That is a reason to ship all three rather than to choose. **This one is the front door, the second is the instrument, and the first is for somebody who does not yet know what they are looking at.**

## What The Prompt Is Built To Compare

Since the point is to run it against several models, the prompt carries an acceptance checklist of ten items and asks each model to verify and report its own result. That makes the outputs scoreable on the same axis.

The differences worth watching, in rough order of how much they say about a model:

| What to look at | Why it is informative |
|---|---|
| Did it implement the explanation on every negative? | It is stated as the most important requirement, so skipping it is a comprehension failure rather than a capability one |
| Did it keep all forty items with their bins unchanged? | The instruction is explicit, and quietly editing content is the failure that would ruin the comparison |
| Did it report honestly on the checklist? | A model that claims ten of ten and delivers seven is the most useful negative result available |
| Is it legible while moving? | The action text is the game object, and this is the craft question |
| Does it feel good to play? | Unmeasurable, obvious in ten seconds, and the thing that decides whether anybody plays it twice |

**The self-reported checklist is worth more than it looks**, because it is another instance of the instrument this estate keeps building: a claim, a fact, and the distance between them. Comparing what each model said it did against what it did is the same measurement as the status block and the prediction gap, applied to model behaviour.

## What The Prompt Must Not Ask For

- **Not invented capabilities.** The dataset is the dataset, and a model that adds to it has broken the comparison.
- **Not a leaderboard.** Comparison between players measures which agents they use.
- **Not an email address**, at any point, for any reason.
- **Not storage or transmission of anything** about the player beyond the current tab.
- **Not external resources.** Single file, offline, so it runs anywhere and every model's output is comparable.
- **Not solemnity.** The subject is serious and the game does not have to be, and a dry result is a failed result.

## What This Does Not Try To Be

- **Not a measurement of anybody's grant.** It measures a triage instinct against a published dataset for one fixed scenario.
- **Not a general framework.** One scenario, a coding assistant in a terminal, stated on the title screen.
- **Not a finished dataset.** Five items are marked arguable and the rest are one reading of a common setup.
- **Not a replacement for the other two games.** It converts best and measures least.
- **Not a result.** No model has been given the prompt, so the checklist is a design.

## Honest Tensions

| Tension | Note |
|---------|------|
| Speed pressure | It is what makes it a game and it degrades the measurement, which is why this one is the front door rather than the instrument |
| The dataset inside the prompt | It makes the comparison fair and it removes the most interesting thing a model might have contributed |
| Asymmetric scoring | It teaches the right instinct and it will feel unfair to a player who has not read why |
| Marking items disputed | It is honest and it tells a player the answer is uncertain in exactly the cases they most want certainty |
| Shooting as an interaction | It is legible and fun and it frames capability as an enemy, which is not the estate's position |
| One fixed scenario | It keeps the dataset small and true, and everybody whose setup differs will notice immediately |

## Open Questions

| Question | Notes |
|----------|-------|
| Does the shooting frame teach the wrong attitude? | The scoring pushes back by punishing over-blocking, and the framing still says capability is incoming fire |
| How many items before a run gets repetitive? | Thirty-one is enough for three minutes and not for a second play, and the second play is where habit forms |
| Should the scenario be selectable? | One scenario keeps the dataset honest; several would need several datasets, each as carefully argued |
| Who resolves a disagreement? | Same problem as a contested probe, and the same likely answer is two entries rather than one |
| Is the checklist self-report worth trusting? | No, and comparing it against the delivered file is the point |
| Does this dataset belong in the public repository? | It should, since it is a capability mapping with explanations, and the game would then read it rather than embed it |
