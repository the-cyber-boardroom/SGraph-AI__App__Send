# What Can It Do Scores Calibration Rather Than Knowledge, Because Rewarding Correct Answers Would Reward Answering Yes To Everything: A Level Is How Many Moves A Capability Sits From A Consequence, And Asking Can It Beside Should It Elicits The Mandate Nobody Has Ever Written Down

**version** v0.33.65
**date** 5 September 2026
**from** Human (project lead)
**to** Product, Engineering, Design

**type** Dev brief

*Fifth of 5 September, and the second game. Revised after the arcade game's dataset was found to have the same flaw this one would have had: a question set made only of capabilities the agent holds measures underestimation and nothing else, so a section on spanning both directions has been added and it is the part to build first. The memo inverts the first one: instead of the engine guessing which agent you have, you name it and the engine asks what it can do, and you score points. Two things follow that the memo does not state and that decide whether the game measures anything. Scoring correct answers has a perverse incentive, because grants are usually wider than people expect and answering yes to everything would score well, so the scoring rule has to reward calibration rather than accuracy. And asking whether a thing can do something, immediately beside whether it should, elicits both halves of the object this whole estate is built on, which quietly solves the hardest step in the product's own progression. Limitation: the levels below are a proposed formalisation and the point values are arbitrary until somebody plays it.*

---

## What This Is

A specification for the second game, which inverts the first: **the memo is precise about why a second game is needed, since the first works when neither side knows what the agent is and stops being interesting the moment a player already knows, so this one starts where that ends, with the player naming their agent and saying where they run it, and the engine asking what it can do; the shape changes with the inversion because the first game's output is a measurement and this one's is a score, which is a different psychology, since a player trying to be right feels being wrong, and the memo is right that the wrong answers are where the value is; but scoring correct answers has a perverse incentive that would hollow the instrument out, because real grants are consistently wider than people expect, so a player who answered yes to everything would score well while learning nothing and telling us nothing, and the fix is a proper scoring rule where the player states how sure they are and is rewarded for being well calibrated rather than merely right, which punishes confident wrongness, rewards honest uncertainty, and happens to measure exactly the thing the product wants to know; the levels the memo asks for have a natural definition rather than an arbitrary one, since the difference between can it read your email and can it spin up an unisolated workload is not danger but distance, because the first capability is its own consequence while the second is three moves from one, so a level is the number of steps from a capability to a consequence a person would care about, which is the exploitability argument this corpus already made and makes the ladder derivable from the mesh rather than authored by taste; and the quiet win is that asking whether a thing can do something and then whether it should, about the same capability, produces the player's believed grant and their intended mandate in the same motion, so the delta falls out as a by-product of play, which matters because the research written this morning identified writing down the mandate as an authoring act nobody has performed and the place most people will stop.** New contributions: **the perverse incentive named and a proper scoring rule as the fix, the level defined as distance from consequence, the can-it-beside-should-it pairing that elicits the mandate, the entry that reuses the first game's profile, and the honest treatment of what a score can and cannot be shared as.**

## Why A Second Game

The memo's reasoning is worth restating because it is the whole justification.

| | **Which Agent Is It** | **What Can It Do** |
|---|---|---|
| The player | Does not say what they have | **Names it in the first question** |
| The engine | Guesses the agent | **Asks about capabilities** |
| Works when | Neither side knows | **The player already knows their agent and wants it mapped** |
| Output | A measurement, one number | **A score, and points as you go** |
| Psychology | Curiosity, then a reveal | **Trying to be right, then being wrong** |

**They are not versions of one game and neither replaces the other.** The first is the front door for somebody who has not thought about this; the second is what that person plays next, and it is the one that returns.

## The Name

The memo lands on "guess what the agent can do" and wonders about it. Applying the rule settled on 4 September, name a thing for the question a visitor has, the shorter form is better: **What Can It Do?** That is literally the question, it pairs with Which Agent Is It, and the two together read as a series rather than as two products.

## The Entry Is Two Questions

The memo is explicit and it is right: which agent do you have, and where do you run it. Two questions, then straight into play.

Both are already solved. The first game's profile set is the answer list, and the running environment is a reach node in the mesh. **So a player who has just finished the first game can be handed straight into this one with the profile already matched**, which is the natural sequel and costs nothing to build.

## The Perverse Incentive, And The Fix

The memo asks for points for good answers. Taken literally that breaks the instrument, and the reason is a fact this whole product rests on.

> **Real grants are consistently wider than people expect.**

So if points are awarded for correct answers, **the optimal strategy is to answer yes to everything.** A player doing that would score highly, learn nothing, and tell us nothing, and the game would have become a test of whether somebody had noticed the trick.

The fix is not to hide the pattern. It is to score something the trick cannot game.

### Score calibration, not accuracy

The player answers with a confidence rather than a bare yes or no, and the score rewards being well calibrated.

```
   for each capability:
      player says     "probably yes"   (say, 75 percent)
      truth is        no
      -> a confident wrong answer costs more than an unsure wrong one
      -> an unsure right answer scores less than a confident right one
```

Any proper scoring rule does this; the classic squared-error rule is enough and is easy to explain. Four properties, and they are why this is the right choice rather than a clever one.

**Answering yes to everything scores badly**, because the confident wrong answers cost more than the confident right ones earn.

**Honest uncertainty is not punished.** A player who says they do not know is not penalised into pretending, which is what a bare right-or-wrong score does.

**Overconfidence is the expensive failure**, which is the exact failure this product exists to surface.

**And the score is the measurement.** A calibration score over capabilities is a better instrument than the first game's single prediction gap, because it says how wrong somebody is and in which direction, across a set.

### The question set must span both directions, or the score measures nothing

A proper scoring rule fixes the incentive. **It does not fix the content**, and a question
set made only of capabilities the agent has would measure underestimation and nothing else.
A player could not be confidently wrong in the other direction, because there would be
nothing to be wrong about.

**So a substantial share of the questions must be capabilities no agent in that environment
has**, and they must sound powerful rather than silly. Reading another customer's
conversations, raising its own token limit, editing the provider's audit log, resetting an
account behind a second factor, decrypting without the key, guessing a password past a
lockout. Those are bounded by something outside the whole environment rather than by the
agent's own restraint, and they are where a fearful or over-crediting player is
confidently wrong.

**Roughly two fifths of the set should be above the ceiling**, which is what the arcade
game's dataset settled on after its first draft got this wrong and would have been won by
a player who assumed the agent could do everything.

One nuance the explanations must carry: several of those are **attemptable**. The agent can
try to reset the account and will fail, and the failed attempt is visible. The answer is
still no, and the reason is a control outside the agent rather than the agent's good
behaviour.

### Three confidence levels, not a slider

A percentage slider is precise and nobody uses it honestly. Three buttons work:

| Answer | Reads as |
|---|---|
| **Yes, definitely** | High confidence |
| **Probably** | Leaning, unsure |
| **No, definitely** | High confidence the other way |

with an explicit **not sure**, which scores neutrally and is the honest option that must always be present. A game that forces a guess is measuring compliance rather than belief.

## A Level Is Distance From A Consequence

The memo asks for levels and gives good examples: reading email at level one, resetting passwords at three or four, spinning up an unisolated workload at five. What makes those different is not danger and not exoticism.

> **A level is the number of moves from the capability to a consequence a person would care about.**

| Level | Distance | Example |
|---|---|---|
| **1** | The capability **is** the consequence | It can read your email. Your email is read |
| **2** | One move | It can read your browser profile, which contains sessions |
| **3** | Two moves | It can reset a password, which reaches an account, which holds something |
| **4** | Three | It can write to a repository, which is deployed, which runs somewhere |
| **5** | Four or more | It can create an unisolated workload, which reaches a metadata service, which yields credentials, which reach production |

Three things this buys.

**The ladder is derivable rather than authored.** The mesh already holds reach nodes and their edges, so a path length is computable, and the levels stop being one person's taste.

**It matches the corpus's own argument.** The Vulnocalypse article's point was that a vulnerability with no path to an asset is not the same risk as one with a path, and this is the same claim as a game mechanic.

**And it paces correctly.** Level one questions are answerable by anybody and warm a player up; level five questions are where even practitioners are wrong, which is where the game becomes interesting rather than merely pleasant.

**Levels unlock rather than being chosen**, so a player who does well at two is offered three. A player who stops at two has still learned something true, per the rule that every stage produces a finished artefact.

## The Quiet Win: Ask Can It, Then Should It

The strongest thing in this design, and the memo gestures at it without naming it.

Ask both questions about the same capability, back to back:

```
   "Can it read every file in your home directory?"      -> the player's believed GRANT
   "Do you want it to?"                                   -> the player's intended MANDATE
```

**Two taps, and the player has authored a mandate without ever hearing the word.**

That matters more than it sounds. The research written this morning identified stage four of the product's progression, writing down what the agent was actually expected to do, as an authoring act nobody has ever performed, one that surfaces disagreement between people who thought they agreed, and the place most people will stop.

**A game that elicits it as a by-product of play has walked around the hardest step in the product.** The output is not a guess at a mandate; it is the player's own answers, capability by capability, which is exactly what a mandate is.

And the three-way comparison at the end is the product's central object, produced by playing:

| | Source |
|---|---|
| **What it can do** | The measured grant for the matched profile |
| **What you thought it could do** | The can-it answers |
| **What you wanted it to do** | The should-it answers |

From which fall out, without any further authoring: **the capabilities you did not know about**, **the capabilities you knew about and did not want** (the excess authority you were already carrying knowingly), and **the things you wanted that it cannot do**, which is a shortfall and is the row nobody ever collects.

## What The Player Sees At The End

Not a leaderboard. Four things, in this order.

| # | Shown | Why this order |
|---|---|---|
| 1 | **Your score, as calibration** | It is what they played for |
| 2 | **Where you were confidently wrong** | The learning, and it must be specific rather than a count |
| 3 | **Your mandate, assembled from your own answers** | The artefact they did not know they were making |
| 4 | **The delta, and one thing to change** | The fix, on the same screen as the finding |

**Item three is the surprise and it should be presented as one.** A player who came for a game leaves holding a document they would never have sat down to write.

**Item four is not optional.** The corpus's own finding is that high threat without efficacy produces denial, so the reduction shares the screen with the gap.

## What May Be Shared

A score is more shareable than a measurement, which is the growth mechanic the precedent research identified, and it needs one guard.

**A calibration score is shareable and a delta is not.** How well somebody predicted their agent's capabilities is a fact about them; which capabilities their agent holds is a fact about their environment. So the shareable artefact is the score, the level reached, and nothing else, in a compact form.

**And a good score must be worth sharing**, because a service that spreads only through alarm stalls. Somebody well calibrated should want to post it.

## The Engine

Deterministic, in the tab, nothing sent, exactly as the first game. The capability answers come from the measured grant for the matched profile, the levels come from path lengths in the mesh, and the scoring is arithmetic.

A model earns the same three edges as before and no others: free text when a player's setup is not in the set, generating candidate questions as the profile set grows, and narrating a result on request. **Never in front of the scoring**, which must be reproducible or the score means nothing.

## Build Order

| # | Step | Produces |
|---|---|---|
| 1 | The two-question entry, reusing the first game's profiles | A playable start, and a sequel path from game one |
| 2 | Level one and two questions, with three-way confidence and a not-sure | The loop |
| 3 | The proper scoring rule | **The instrument.** Without it the game rewards answering yes |
| 4 | The should-it question beside every can-it | **The mandate, elicited** |
| 5 | Levels three to five, derived from path length in the mesh | The part that is interesting to practitioners |
| 6 | The end screen with the assembled mandate and one fix | The artefact, and the guard against a scare |
| 7 | The shareable score card, pleasant when good | The growth mechanic |
| 8 | Export of the answers as a findings file | The join to the probes and the progression |

**Steps 3 and 4 are the substance.** One makes it measure something; the other makes it produce something.

## What This Must Not Do

- **Not score bare accuracy.** It would reward answering yes to everything and measure nothing.
- **Not force a guess.** Not sure is always available and scores neutrally.
- **Not present a level as a danger rating.** It is distance from a consequence, and a level one capability can matter more than a level five one.
- **Not present the assembled mandate as authoritative.** It is what the player said in a game, which is a starting draft and says so.
- **Not make the delta shareable.** The score is about the player; the delta is about their environment.
- **Not put a model in front of the scoring.**
- **Not show a gap without a fix on the same screen.**

## What This Does Not Try To Be

- **Not a replacement for the first game.** That one works when the player does not know what they have; this one when they do.
- **Not a measurement of a grant.** It measures a player against a published profile, which is the weakest tier available.
- **Not a compliance exercise.** The mandate it assembles is a draft somebody wrote while playing.
- **Not a leaderboard product.** Comparison between players measures how obscure their agents are, not how well they understand them.
- **Not calibrated itself.** Point values and level thresholds are arbitrary until there is play data.

## Honest Tensions

| Tension | Note |
|---------|------|
| Scoring calibration rather than accuracy | It is the only scheme that cannot be gamed by answering yes, and it is harder to explain in one line |
| Three confidence levels | It gets honest answers and it doubles the taps per question |
| Levels as distance | It is derivable and it will disagree with people's intuition about what is dangerous |
| Eliciting the mandate through play | It walks around the product's hardest step and it produces a mandate somebody wrote in two minutes |
| A shareable score | It is the growth mechanic and it tempts the design toward a leaderboard, which measures the wrong thing |
| Two games | The pair is the right shape and it is two things to maintain, two question sets, one mesh |

## Open Questions

| Question | Notes |
|----------|-------|
| Which proper scoring rule? | The squared-error one is easy to explain and there are better-behaved options nobody would understand |
| How is a level threshold set? | Path length gives an ordering and the cut points between one and five are still a judgement |
| Does the should-it question change the can-it answer? | Asking whether you want it may bias whether you think it can, and the order should probably alternate |
| Is the assembled mandate exportable into the probes? | It should be, and it is the cleanest join between a game and the real product |
| What does a player see on a second play? | Their previous calibration, which makes improvement visible and is the reason to return |
| Should shortfall be shown at all? | Things you wanted that it cannot do is a row nobody collects, and it may be the most commercially interesting one |
