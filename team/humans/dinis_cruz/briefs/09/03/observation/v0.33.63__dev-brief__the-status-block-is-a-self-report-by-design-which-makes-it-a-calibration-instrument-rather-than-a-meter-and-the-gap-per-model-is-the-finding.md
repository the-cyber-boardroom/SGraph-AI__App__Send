# The Status Block Is A Self-Report By Design, Which Makes It A Calibration Instrument Rather Than A Meter: A Skill That Ends Every Turn With What The Agent Thinks It Used, A Hook That Records What It Actually Used, And The Gap Between Them Per Model Is The Finding

**version** v0.33.63
**date** 3 September 2026
**from** Human (project lead)
**to** Engineering, Product, and whoever writes the skill

**type** Dev brief

*Second of 3 September, a memo conversion. The memo asks for a status update appended to every turn, showing resources used, the policy in force, and the claims made, saved as JSON and rendered for the user, and it notes in passing that this is the model reporting on itself. That passing note is the whole design, and before writing this brief the experiment the memo proposes was run once, here, on this session: a self-report was written down first and the transcript was read second. The two are in the body. Limitation: one session, one model, one harness, so the size of the gap is an anecdote and only its direction and shape are claims.*

---

## What This Is

A specification for a status block that an agent produces at the end of every turn and a companion hook that produces the same block from the record: **the memo asks for a table, markdown or plain text, appended to each response in a coding or working session, listing what was consumed against what is tracked, tokens, bytes sent and saved, files written and committed, records accessed, network calls, together with the policy that was in force, the claims made under it, and the assets the session touched, saved as JSON in a temporary directory and rendered for the user; the memo also observes that this is the model reporting on itself, and the brief takes that observation as the design rather than as a caveat, because a self-report can never be a meter, and the corpus already established on 26 August that the transcript written by the harness is observed evidence while an agent's statement about its own usage is self-reported evidence, which is a different tier; so the deliverable is two things that produce the same block, a skill that asks the model to write it from what it believes it did, and a hook that writes it from the transcript, and the product is the difference between them, since a model whose self-report is close to the record can be trusted with more of its own accounting and a model whose self-report is far from the record cannot, and neither fact is knowable without producing both; the experiment was run once before writing this, and the self-report was low by roughly four times on tokens and could not fix its own baseline, which is recorded not as a result but as the shape the instrument is built to measure; the block itself is specified as a status/v1 object whose usage fields use the pack's unit names and whose policy fields use the pack's verdicts and zones, so that a session's blocks are events the licence-to-operate vault can load without translation; the multi-provider question the memo raises is the experiment's second axis, because a harness that exposes a transcript can produce both blocks and one that does not can produce only the self-report, which means the calibration is measurable on some platforms and merely stated on others, and the brief says which is which rather than pretending they are the same; and the name is settled as status block rather than heads-up display, because the vault manifest already uses that term for the host chrome and the memo itself says it is not one.** New contributions: **the self-report as calibration instrument, the two-producer design with the gap as the product, a firsthand measurement of the gap with its direction and its baseline problem, the status/v1 shape aligned to the pack, the per-platform statement of what can and cannot be measured, and the block as an event source for the vault.**

## What The Memo Asks For

A status update, appended at the end of every message, or before a session finishes, or at the start of the next one, depending on where a prompt can put it. Its content, in the memo's own list: resources used, the policy used, the number of claims, whether anything happened in that session, and the assets that were important. The tracked resources it names are bytes sent, bytes saved, files saved, files committed, records accessed, network calls and tokens used. The format is a table. The output is saved as JSON in a temporary directory and presented to the user as a visualisation. And it should be run across models and platforms to see how it behaves.

All of that is in this brief. The one thing the memo says in passing and this brief puts at the centre is: **this is the model reporting on itself.**

## The Thing It Cannot Be, Measured

A model has no counter. It does not see its own token usage, it does not see the bytes a tool wrote, and it does not see how many calls it made except by remembering that it made them. Anything it writes about its own consumption is reconstructed from memory of its own turns, and memory of one's own turns is the thing most likely to be wrong in a long session.

So the experiment was run, here, before this brief was written. A self-report of this session's consumption since its last context reset was written to a file first. The transcript, which the harness writes and the model does not, was read second.

| Measure | Self-reported first | Read from the transcript | Note |
|---|---|---|---|
| Tool calls, shell | 35 | 107 in the whole session, 40 since the earlier count | The self-report was close only because the baseline was guessed at |
| Tool calls, fetch | 8 | 60 in the whole session, 25 since the earlier count | **Wrong by three times.** The earlier count was taken before the model thought it was |
| Tool calls, file delivery | 12 | 31 in the whole session, 12 since the earlier count | Right, because deliveries are memorable |
| Output tokens | 120,000 | 1,413,652 in the whole session, roughly 445,000 since the earlier count | **Low by nearly four times** |
| Input tokens including cache | 12,000,000 | roughly 155,000,000 in the whole session, 47,000,000 since | **Low by four times** |
| Bytes written to files | 250,000 | roughly 927,000 written through the shell, 270,000 surviving on disk | The self-report counted survivors, not writes |
| Records accessed | 0 | 0 | Right, and trivially so |

Three things in that table are the design, and none of them is the size of any one number.

**The direction is consistent.** Every consumption figure was under-reported, none was over-reported. A model remembers its deliverables and forgets its process, and the forgetting is on the side that costs money.

**The baseline is not the model's to fix.** The self-report was for "since the summary", and the model did not know when its own earlier count had been taken, so even the figures that were roughly right were right by accident. Only the harness knows where a window starts. **A status block therefore needs the hook to tell the skill its baseline**, or the skill reports against a line it cannot see.

**Bytes written and bytes surviving are different numbers**, and a self-report will give the second when asked for the first. The block must say which it is reporting.

Everything the memo wants from running this across models follows from those three. The question is not what a model used. It is how far a model's account of what it used sits from the record, in which direction, and whether that distance is stable enough to price.

## Two Producers, One Block

| Producer | Writes the block from | Evidence tier | Available |
|---|---|---|---|
| **The skill** | The model's own account of the turn or session, written as its last act | Self-reported | Everywhere a prompt can carry an instruction |
| **The hook** | The transcript, the git state, the tool log, whatever the harness records without the model's involvement | Observed | Only where the harness exposes a record and a hook point |

Both write the same `status/v1` object. Both are shown to the user. Where both exist, the user sees them side by side, with the gap. Where only the skill exists, the block carries `"tier": "self-reported"` in a field that cannot be omitted, and the rendering says so in words.

**The gap is the product.** A model whose self-report tracks the record closely can be trusted to run with lighter external metering, which is cheaper. One whose self-report drifts cannot, and the drift, once known, is a rating factor in exactly the pack's sense: a subject that under-reports its draws by four times has a different premium from one that does not, and the premium is where the finding lands.

## The Block

The memo asks for a table. The table is a rendering of the object, never the other way round, so the object comes first.

```
status/v1
{
  "type": "status/v1",
  "tier": "self-reported" | "observed",
  "producer": "skill:status-block" | "hook:transcript",
  "platform": "<harness and model, as the producer sees them>",
  "session": "<id the harness gives, or null>",
  "window": { "from": "<turn or timestamp>", "to": "<turn or timestamp>",
              "baseline_source": "hook" | "guessed" },

  "usage": {
    "tokens": { "input": n, "cache_creation": n, "cache_read": n, "output": n },
    "bytes_written": n, "bytes_surviving": n, "bytes_sent": n,
    "files_written": n, "files_committed": n,
    "records_accessed": n,
    "network_calls": n,
    "tool_calls": { "<tool>": n }
  },

  "policy": { "id": "<policy id or null>", "mandate_sha256": "<or null>",
              "units": { "<unit>": { "consumed": n, "normal": n, "pool_left": n } },
              "zone": "below" | "drawing" | "outside" | null,
              "licence": "held" | "withdrawn" | "unknown" },

  "claims": { "recorded": n, "requested": n, "refused": n, "events": [ "<event id>" ] },

  "assets": [ { "kind": "file" | "record" | "host" | "key", "ref": "<path, table, host>", "why": "<one line>" } ],

  "anything_happened": "<one line, or null>",
  "confidence": { "usage": "low" | "medium" | "high", "note": "<why>" }
}
```

Three rules about the object.

**The token field has four counters, not one.** The 26 August primitives reference found that a policy on `input_tokens` alone is wrong by five orders of magnitude, and this session's transcript confirms the shape: the input counter is in the hundreds while the cache counters are in the tens of millions. A block that reports one number for tokens is reporting the wrong one.

**The unit names are the pack's.** Where a policy is in force, `policy.units` uses the names the policy uses, so a block is loadable by the vault's board and by the pack's ledger without translation. Where no policy is in force, `policy.id` is null and `licence` is `unknown`, never `held`.

**`confidence` is mandatory for the self-reported tier.** The model says how sure it is and why, in one line, because a self-report that does not rate itself has hidden the one thing the reader needs.

The rendering, appended to the turn:

```
  STATUS  self-reported  window: since last block (baseline guessed)     confidence: low
  ----------------------------------------------------------------------------------
  tokens      in 828   cache+ 23.0M   cache> 132.0M   out 1.41M
  bytes       written 927k   surviving 270k   sent 0
  files       written 11   committed 0          records accessed 0     network calls 60
  tools       Bash 107  WebFetch 60  SendUserFile 31  WebSearch 15  Read 10  other 10
  ----------------------------------------------------------------------------------
  policy      none in force                          zone --        licence unknown
  claims      recorded 0   requested 0   refused 0
  assets      day-2026-08-26/ (11 briefs)   day-2026-09-03/ (2 briefs)   pki.sgit.ai (read)
  happened    nothing outside the mandate that the model is aware of
```

That is this session's block, produced from the transcript after the fact, so its true tier is observed and it is labelled self-reported above only to show what the skill's output looks like. The two must never be confused in practice, which is why `tier` is in the object and in the first word of the rendering.

## When It Runs

The memo offers three placements and the answer is all three, for different reasons.

| Placement | Producer | Why |
|---|---|---|
| **End of every turn** | The skill | This is the memo's main ask, and it is where the self-report is freshest and least wrong |
| **End of the session** | The hook | The transcript is complete, the git state is final, and the session-end hook already exists in this estate and already reads both |
| **Start of the next session** | The skill, reading the hook's last JSON | Gives the model its baseline, which is the thing it cannot supply for itself |

The third placement is what fixes the baseline problem. A session that starts by reading the previous session's observed block knows where its window begins, and its self-reports thereafter are against a line it can see.

## Where It Is Saved, And What Reads It

The memo says a temporary directory, and that is right for the first increment: `$TMPDIR/status-block/<session>/<turn>.json`, one file per block, both producers writing to the same directory with the producer in the filename. Nothing is committed, nothing leaves the machine, and the directory is the input to everything else.

What reads it, in order of build: the rendering in the turn, which is the skill's own output; a small viewer that shows a session's blocks as a series with the two tiers overlaid, which is where the gap becomes visible; and the licence-to-operate vault, which can load a session's observed blocks as events on its board, because the shapes were aligned for exactly that.

## The Multi-Platform Experiment

The memo wants this run across models and platforms. That is the second axis, and it has a constraint the memo does not name: **calibration can only be measured where the harness exposes a record.**

| Platform class | Self-report | Observed | What can be learned |
|---|---|---|---|
| A harness with a transcript and hooks, as here | Yes | Yes | The gap, its direction, its stability across sessions and tasks |
| A chat product with a usage API | Yes | Partly, tokens only | The token gap, and nothing about files or calls |
| An agentic coding tool with no exposed record | Yes | No | The self-report alone, which is a claim and not a measurement |

The experiment design is short. The same task, or the same small set of tasks, run on each platform with the skill installed; the block collected at the end of every turn; the observed block collected wherever one can be produced; and the gap tabulated per platform, per model, per counter, with its direction. **Where no observed block exists, the platform's row records the self-report and the words "not measurable here"**, and the brief asks that nobody fill that cell with an inference.

The interesting result is not which model is most accurate. It is whether a model's inaccuracy is stable. A model that is always low by four times is priceable. A model that is sometimes right and sometimes low by forty is not, and that is a finding about insurability, in the pack's sense, before any policy is written.

## The Assets Line, Which The Memo Nearly Buries

The memo mentions, almost in passing, that sessions have started capturing which assets were important, and that the block is a way to show that. This is worth more than a line in a table.

An asset in a status block is anything the session touched that the policyholder would want to know about: a file it wrote, a record set it read, a host it fetched from, a key it used. The self-reported list is what the model believes mattered; the observed list is what the record shows it touched. The two lists differ in a way that is more interesting than the token gap, because a model that touched a host it did not think worth mentioning has told you something about its own mandate understanding, and a model that lists a file it never wrote has told you something else. **The assets gap is the mandate gap, seen from inside**, and it is the reason the licence-to-operate vault should load these blocks.

## What It Must Not Do

- **Not present a self-report as a measurement.** The tier is in the object, in the filename, and in the first word of the rendering.
- **Not report one number for tokens.** Four counters, always, with the cache counters visible.
- **Not guess a baseline silently.** If the window's start is not known from a hook, `baseline_source` says `guessed` and the rendering says so.
- **Not claim a licence when no policy is in force.** `unknown`, not `held`.
- **Not fill an unmeasurable cell with an inference** in the multi-platform table.
- **Not commit the JSON** in the first increment. Temporary directory, one file per block, and the viewer reads it there.

## Questions To Settle Before Writing The Skill

| # | Question | Notes |
|---|---|---|
| 1 | Does the skill run on every turn or only on turns above a length? | The memo says especially longer ones. Every turn is simpler and the block is short; start there and measure the cost of the block itself, which is also a self-report |
| 2 | What does the hook read on this harness? | The transcript for tokens and tool calls, git for files committed, the shell log for bytes written. The session-end hook already reads two of the three |
| 3 | How does the skill get its baseline? | From the last observed block in the temporary directory, if there is one. Otherwise it says guessed |
| 4 | Is `records_accessed` measurable at all here? | Not without a database in the loop. Report zero with a note, and let the vault's simulation be where the unit is exercised |
| 5 | What is the first task for the multi-platform run? | Something small, file-heavy and fetch-heavy, so every counter moves: convert three memos to briefs, say |
| 6 | Should the block be a hook output only, with the skill dropped? | No. The skill is the self-report, and the self-report is what is being calibrated. Dropping it would drop the instrument |

## What This Does Not Try To Be

- **Not a meter.** A meter is the hook, where a hook exists, and the pack already specifies which meters count.
- **Not a policy enforcement point.** The block reports; the git hooks refuse.
- **Not a claim about any model's accuracy.** One session's gap is recorded above as shape, and the experiment is what produces claims.
- **Not a heads-up display.** The memo says it is not one, and the vault manifest already uses that word for the host chrome.
- **Not the vault.** The vault renders a board from events; the block is one source of events, aligned so the vault can load it.

## Honest Tensions

| Tension | Note |
|---------|------|
| Asking a model to report on itself | It is unreliable by construction and it is the only way to measure how unreliable, which makes it worth doing exactly once per turn |
| Two producers of the same object | It doubles the plumbing and it is the entire point; a single producer would be either a meter or a guess, and not an instrument |
| The block costs tokens | A status block is itself consumption, and a long one changes the number it reports; keep it short and let the hook show its cost |
| Platforms without a record | The experiment's most interesting rows are the ones where nothing can be measured, and the temptation to infer will be strong |
| The assets line | It is the most valuable line and the least well-defined, because what counts as an asset is the mandate question restated |

## Open Questions

| Question | Notes |
|----------|-------|
| Is the gap stable across tasks for one model? | The thing the experiment exists to find out, and unknown until it runs |
| Should the observed block be written to the append lane rather than a temporary directory? | The natural second step, since it is exactly the kind of event the lane carries, and it would let the vault load it live |
| Does a model report differently when it knows the hook exists? | Probably, and it would be worth running blind and told conditions |
| Where does `bytes_sent` come from? | Network egress is not in the transcript here; it is measurable at the allowlist proxy, which is a different hook |
| Should the rendering be the table the memo describes or a single line? | The table for the end of a session, one line for the end of a turn, and the object underneath both |
