## Test Quality Assessment

### What the tests do well

1. **Storage-leak pinning:** The most important assertion is `sg-vault-key NOT in localStorage OR sessionStorage`. This is not just a behaviour check — it is a security assertion. The test verifies the key isolation property that the feature was built to provide.

2. **Precondition pinning:** The sandboxed test checks that `typeof caches` actually throws in the iframe before asserting vault-open succeeds. Without this, the test would be trivially satisfied by a browser that doesn't sandbox cache access.

3. **Deep-link content assertion:** Checking for specific rendered text (`EMBEDDED_PATIENT` vs `EMBEDDED_OK`) is far stronger than checking URL navigation — it verifies that the deepLink was actually applied, not just accepted without error.

4. **Protocol contract coverage:** 13 invalid-input scenarios for `parseOpenMessage` is thorough. Real-world parent pages will often have subtle message format issues.

### Gaps

| Gap | Severity | Notes |
|-----|----------|-------|
| `sg-app-perm-ok:*` consent write not covered in embed flow | Low | Unreachable from current open path; would catch regression if authed-vault embed test is added |
| Cross-origin parent browser test | Low | Protocol-level covered by unit tests; browser test would add depth |
| null-origin parent driving sandboxed child | Low | Covered by harp-make-6182 live fixture; CI would require two-level iframe setup |
| run-all.sh vs full ViV suite gap | Note | run-all.sh runs 113 assertions; full suite is 335+. Not a gap per se — the extra tests are run via separate harnesses — but worth clarifying in CI docs |
