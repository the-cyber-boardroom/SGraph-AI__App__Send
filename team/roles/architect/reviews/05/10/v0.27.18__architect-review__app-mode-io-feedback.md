# App Mode I/O Feedback — Design

**Status:** PROPOSED — does not exist yet
**Author:** architect
**Date:** 2026-05-10
**Component:** `sg-app-banner` + `vault-browse-edit` (vault UI v0.2.x)
**Related:** Phase 4 vault-loader refactor (branch `claude/vault-ui-architecture-review-6nTQZ`)

> **Decisions locked in (2026-05-10):**
> 1. **100 % vault-side.** All writes flow through the parent-side VFS bridge.
>    The iframe app has no idea this feedback is happening. No postMessage
>    protocol changes — App Mode is entirely a vault concern.
> 2. **HUD lives in `sg-app-banner.js`** — self-contained, unsubscribes
>    cleanly on App Mode exit.
> 3. **Show every read/write/sync** — no debouncing in v1; visibility over
>    calm.
> 4. **Single-app HUD** — multi-app / multi-tab coordination is out of scope
>    for v1.

---

## 1. Problem

When the vault UI is in **App Mode** (the lifted full-screen iframe mode driven by
`sg-app-banner._liftContentFrame()`), the vault chrome is hidden behind the iframe:

- The messages sidebar is collapsed and obscured.
- The status bar message-count badge sits underneath the lifted iframe.
- Save buttons inside the user's app live in the iframe — the vault's own
  "Saving..." button-state feedback is not visible.

So when the user's HTML app inside the iframe writes a file (today via the
parent-side VFS bridge in `vault-browse-edit.js`; in the future via a
postMessage protocol) **there is no visible indication that anything is
happening**. Compare this to non-App-Mode where the user gets:

- Save button transitions: `Save` → `Saving...` (disabled) → `Save`
- Toast message in the messages panel: `✓ "notes.txt" saved` (5 s auto-dismiss)
- Status bar badge increments

In App Mode, all of those signals exist but are visually unreachable.

---

## 2. Goal

Provide a **single non-intrusive feedback surface** in App Mode that confirms:

1. **Vault writes** — file is being saved into the vault store.
2. **Vault reads** — assets / files are being loaded.
3. **Upstream sync** — vault is pushing to the SG/Send API.
4. **Errors** — operation failed, with a path to retry / inspect.

The surface must:

- Stay out of the user's way during normal use.
- Auto-dismiss on success.
- Stay pinned on error until acknowledged.
- Never block the iframe content (no modal overlays).

---

## 3. Solution — App Mode Status HUD

A slim status strip lives in `sg-app-banner`'s DOM (parent document, not inside
the iframe) and sits above the lifted iframe via `z-index`. It is the single
visible feedback surface in App Mode.

### 3.1 Idle / baseline

```
┌─────────────────────────────────────────────────┐
│ ◈ App Mode                       [Exit App Mode]│  ← 28 px strip, always visible
├─────────────────────────────────────────────────┤
│                                                 │
│       iframe content                            │
│                                                 │
└─────────────────────────────────────────────────┘
```

### 3.2 Vault write in progress

```
┌──────────────────────────────────────────────────────┐
│ ◈ App Mode   ⟳ Saving notes.txt…      [Exit App Mode]│
└──────────────────────────────────────────────────────┘
```

- `⟳` is animated (CSS rotation).
- Long filenames are truncated: `⟳ Saving very-long-fil….md…`

### 3.3 Vault write succeeded → upstream sync starts

```
┌──────────────────────────────────────────────────────┐
│ ◈ App Mode   ↑ Syncing to SG/Send…    [Exit App Mode]│
└──────────────────────────────────────────────────────┘
```

- Distinct icon (`↑`) signals network activity vs local write.
- The local-vault write phase and the upstream-sync phase are separate states.

### 3.4 All done — fades out after 3 s

```
┌──────────────────────────────────────────────────────┐
│ ◈ App Mode   ✓ Saved                  [Exit App Mode]│
└──────────────────────────────────────────────────────┘
                                         ↑ fades to nothing after 3 s
```

### 3.5 Read / asset load

```
┌──────────────────────────────────────────────────────┐
│ ◈ App Mode   ↓ Loading assets…        [Exit App Mode]│
└──────────────────────────────────────────────────────┘
```

### 3.6 Error — pinned until dismissed

```
┌──────────────────────────────────────────────────────┐
│ ◈ App Mode   ✗ Save failed  [Details ▾]  [Exit App Mode]│
└──────────────────────────────────────────────────────┘

                ┌──────────────────────────────┐
                │ ✗  Failed to write notes.txt  │  ← expands inline below strip
                │    Network error (503)         │
                │    [Retry]  [Dismiss]          │
                └──────────────────────────────┘
```

### 3.7 Multiple operations queued

```
┌──────────────────────────────────────────────────────┐
│ ◈ App Mode   ⟳ Saving (3 files)…      [Exit App Mode]│
└──────────────────────────────────────────────────────┘
```

## 4. Event Flow

The iframe app is not a participant in the protocol — it triggers writes
through whatever UI it has, and the **parent-side VFS bridge** intercepts
those operations transparently. The HUD subscribes to vault events emitted
by the bridge.

```
iframe app          vault parent (VFS bridge)         SG/Send API
   │                          │                            │
   │  user clicks "Save"      │                            │
   │  in the app              │                            │
   │     ── intercepted ─────▶│                            │
   │                          │ emit vault:write:start     │
   │                          │ → HUD: ⟳ Saving notes.txt… │
   │                          │                            │
   │                          │── sgVault.writeFile() ─────│
   │                          │   (local vault store)      │
   │                          │◀─ resolve ─────────────────│
   │                          │ emit vault:write:ok        │
   │                          │                            │
   │                          │ emit vault:sync:start      │
   │                          │ → HUD: ↑ Syncing…          │
   │                          │── API push ───────────────▶│
   │                          │◀─ 200 OK ──────────────────│
   │                          │ emit vault:sync:ok         │
   │                          │ → HUD: ✓ Saved (3 s fade)  │
```

The iframe needs no awareness of the HUD or the events. Errors emitted by
the bridge surface in the HUD only — the app continues to receive whatever
ack/reject signal the bridge already gives it (unchanged behaviour).

## 5. Implementation

Two pieces, both vault-side, no iframe contract changes.

### 5.1 HUD element in `sg-app-banner.js`

```
sg-app-banner host (position:fixed, z-index above iframe)
 └── .sgab-strip (flex row, 28 px tall)
      ├── .sgab-mode-badge      "◈ App Mode"
      ├── .sgab-status          ← the new bit (empty when idle)
      └── .sgab-exit-btn        "Exit App Mode"
```

Two new public methods on the `sg-app-banner` element:

- `showStatus(icon, text, autoDismissMs)` — sets `.sgab-status` content and
  optionally schedules a fade.
- `clearStatus()` — fades `.sgab-status` to empty immediately.
- Error states pin the status, expose a `[Details ▾]` toggle, and render an
  inline detail panel below the strip.

### 5.2 Route vault events to the HUD when App Mode is active

```js
// In vault-browse-edit.js — single source of truth for write/read events.
sgraphVault.events.on('vault:write:start', ({ file }) => {
    if (sgAppBanner.isActive())
        sgAppBanner.showStatus('⟳', `Saving ${file}…`);
    else
        messagesService.info(`Saving ${file}…`);
});

sgraphVault.events.on('vault:write:ok', ({ file }) => {
    if (sgAppBanner.isActive())
        sgAppBanner.showStatus('✓', 'Saved', 3000);
    else
        messagesService.success(`"${file}" saved`);
});

sgraphVault.events.on('vault:write:error', ({ file, reason }) => {
    if (sgAppBanner.isActive())
        sgAppBanner.showStatusError(`✗ Save failed: ${file}`, reason);
    else
        messagesService.error(`Failed to save ${file}: ${reason}`);
});

// Similar handlers for vault:read:* and vault:sync:* (upstream API).
```

The decision tree (`isActive()` → HUD vs `messagesService`) keeps the existing
non-App-Mode behaviour untouched and adds App Mode handling beside it without
duplication.

## 6. Decisions (resolved 2026-05-10)

| # | Question | Decision |
|---|---|---|
| 1 | postMessage protocol scope | **No protocol changes.** All writes flow through the parent-side VFS bridge already; the iframe app is unaware of the HUD. |
| 2 | HUD location | **`sg-app-banner.js`** — self-contained, unsubscribes cleanly on App Mode exit. |
| 3 | Upstream sync visibility | **Show every action.** No debouncing in v1 — visibility over calm. |
| 4 | Multi-app coordination | **Out of scope for v1.** Single HUD per App Mode session. |

---

## 7. Out of Scope (v1)

- Progress bars for large file uploads.
- Conflict resolution UI when two writers race on the same file.
- Per-app icons / branding in the HUD.
- Sound or haptic feedback.

## 8. Test Plan

Three layers of coverage, mirroring the vault-loader Phase 4 layout.

### 8.1 Unit tests

- `sg-app-banner.showStatus()` updates DOM correctly for each state.
- `sg-app-banner.showStatusError()` pins until dismissed.
- Auto-dismiss timer fires at the configured interval.

### 8.2 Integration tests

- Emitting `vault:write:start` while App Mode is active calls
  `sgAppBanner.showStatus()`, not `messagesService.info()`.
- Emitting `vault:write:ok` after `:start` transitions HUD: `⟳` → `✓`.
- Emitting `vault:write:error` pins the HUD with the error reason.

### 8.3 E2E tests

- Open vault in App Mode, trigger a save from the iframe app, assert the
  `.sgab-status` text matches `Saving …` then `Saved`.
- Force an error path (mock `sgVault.writeFile` to reject) and assert the
  `[Details ▾]` toggle appears.

A regression seed (`test__regression__app_mode_io_feedback.spec.js`) lives
alongside the existing browse-edit regression seeds — initially `test.skip()`
until the HUD lands.

---

## 9. Recommended Sequence

1. Land the HUD element in `sg-app-banner.js` with unit tests (no event wiring
   yet) — `showStatus()`, `showStatusError()`, `clearStatus()`, auto-dismiss.
2. Emit `vault:write:start` / `vault:write:ok` / `vault:write:error` from the
   parent-side VFS bridge in `vault-browse-edit.js`; wire into the HUD; add
   integration tests.
3. Emit and wire `vault:read:*` events.
4. Emit and wire `vault:sync:*` events for the SG/Send upstream push.
5. Enable the regression seed (`test__regression__app_mode_io_feedback.spec.js`).

Each step is independently mergeable behind the existing test gate.
