## Overview

The RO token system lets a vault owner create short-lived, revocable, read-only sharing links.
The server never learns which vault a token belongs to. The encryption key never touches the wire.

Two phases:

| Phase | Status | Where |
|---|---|---|
| Phase 1 | **Shipped** — dev harness only | `/en-gb/vault/token` |
| Phase 2 | **Blocked** on `SGVault.openReadOnly()` | `vault-shell.js` + `_common/` |

## Flow 1 — Owner Creates an RO Token (Phase 1 as-built)

```
OWNER BROWSER
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  /en-gb/vault/token
  ┌──────────────────────────────────────────────────────┐
  │  <vt-vault-loader>                                   │
  │   1. User pastes vault key  word-word-NNNN           │
  │   2. parseCredential()  →  { mode:'full', vaultKey } │
  │   3. resolveCredential() → { vaultId: SHA256[:12] }  │
  │   4. storeCredentials()  → sessionStorage            │
  │   5. SGVault.open(sgSend, vaultKey)  → vault obj     │
  │      ↳ vault._readKey  = AES-256-GCM CryptoKey       │
  │      ↳ vault._writeKey = AES-256-GCM CryptoKey       │
  │      ↳ vault.writable  = true                        │
  └──────────────────────────────────────────────────────┘
              │ credentials + vault obj in memory
              ▼
  ┌──────────────────────────────────────────────────────┐
  │  <vt-token-manager>                                  │
  │   6. User sets label / expiry / use-limit            │
  │   7. generateFriendlyToken()  → roToken = adj-noun-NNNN
  │                                                      │
  │   8. ENCRYPT PAYLOAD                                 │
  │      rawReadKey = exportKey('raw', vault._readKey)   │
  │      readKeyB64 = btoa(rawReadKey)  [44 chars]       │
  │      payload    = { vault_id, read_key: readKeyB64 } │
  │      encPayload = AES-GCM(PBKDF2(roToken), payload)  │
  │        ↳ salt: 'sgraph-ro-token-v1'                  │
  │        ↳ IV:   random 12 bytes, prepended to cipher  │
  └──────────────────────────────────────────────────────┘
              │ three API calls
              ▼
┌─────────────────────────────────────────────────────────┐
│  SG/Send API  (dev.send.sgraph.ai)                      │
│                                                         │
│  POST /api/transfers/create                             │
│    body: { file_size_bytes:0, delete_auth_hash,         │
│            max_downloads, expires_at (ms epoch) }       │
│    resp: { transfer_id, upload_url }                    │
│                                                         │
│  POST {upload_url}                                      │
│    body: <encPayload bytes>   ← ~120 bytes of ciphertext│
│                                                         │
│  POST /api/transfers/complete/{transfer_id}             │
│    → server marks blob as ready for download            │
│                                                         │
│  SERVER KNOWS:                                          │
│    encrypted blob, TTL, use-count, delete_auth_hash     │
│  SERVER DOES NOT KNOW:                                  │
│    which vault, what read_key, what roToken string is   │
└─────────────────────────────────────────────────────────┘
              │ transferId back to browser
              ▼
  ┌──────────────────────────────────────────────────────┐
  │  <vt-token-manager>  (continued)                     │
  │   9. BUILD token entry:                              │
  │      { token: roToken, transfer_id, delete_key,      │
  │        label, created_at, expires_at,                │
  │        uses_max, uses:0, note:'',                    │
  │        revoked:false, revoked_at:null }              │
  │                                                      │
  │  10. SAVE TOKEN LIST  (.vault/owner/readonly-tokens) │
  │      plainBytes = JSON.stringify(entries)            │
  │      innerCipher = ownerEncrypt(vaultKey, vaultId,   │
  │                      plainBytes)                     │
  │        ↳ vault_secret_key = HKDF-SHA256(             │
  │            input=vaultKey, salt=vaultId,             │
  │            info='sgraph-vault-secret-v1', len=32)    │
  │        ↳ AES-256-GCM(vault_secret_key, plainBytes)   │
  │      vault.updateFile('/.vault/owner',               │
  │                       'readonly-tokens.json',        │
  │                       innerBytes)                    │
  │      vault.push()  → server stores double-encrypted  │
  │        outer: vault read-key (standard vault layer)  │
  │        inner: vault_secret_key (HKDF layer)          │
  └──────────────────────────────────────────────────────┘
              │ token created
              ▼
  ┌──────────────────────────────────────────────────────┐
  │  Token Manager UI shows:                             │
  │    ro-adj-noun-NNNN  [active]  [Copy link] [Revoke]  │
  │  Share URL:  /en-gb/vault/#ro-adj-noun-NNNN          │
  └──────────────────────────────────────────────────────┘
```

## Flow 2 — Recipient Opens an RO Link (Phase 2 target — NOT YET WIRED)

```
RECIPIENT BROWSER
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  URL: /en-gb/vault/#ro-adj-noun-NNNN
        ↑ "vault" or "app" (same flow)

  ┌──────────────────────────────────────────────────────┐
  │  vault-shell.js  (PHASE 2 — does not exist yet)      │
  │   1. window.onhashchange / DOMContentLoaded          │
  │   2. hash = location.hash  →  '#ro-adj-noun-NNNN'    │
  │   3. cred = parseCredential(hash)                    │
  │      →  { mode:'readonly', roToken:'adj-noun-NNNN' } │
  └──────────────────────────────────────────────────────┘
              │
              ▼
  ┌──────────────────────────────────────────────────────┐
  │  resolveCredential(cred)  [vault-credentials.js]     │
  │   4. GET /api/transfers/check-token/adj-noun-NNNN    │
  │      → server validates TTL + use-count              │
  │      → resp: { ciphertext: '<base64>' }              │
  │   5. _decryptWithPassphrase(roToken, ciphertext)     │
  │      PBKDF2(roToken, salt='sgraph-ro-token-v1')      │
  │      AES-GCM-decrypt → plaintext bytes               │
  │   6. JSON.parse → { vault_id, read_key: '<b64>' }    │
  │   7. storeCredentials({ mode:'readonly',             │
  │        vaultId, readKey, roToken })                  │
  │      → sessionStorage;  hash cleared from URL        │
  └──────────────────────────────────────────────────────┘
              │
              ▼
  ┌──────────────────────────────────────────────────────┐
  │  SGVault.openReadOnly(sgSend, vaultId, readKeyB64)   │
  │  [_common/sg-vault.js — DOES NOT EXIST YET]          │
  │                                                      │
  │   8. cryptoKey = importKey('raw',                    │
  │        base64decode(readKeyB64),                     │
  │        {name:'AES-GCM'}, false, ['decrypt'])         │
  │   9. vault._readKey  = cryptoKey                     │
  │      vault._writeKey = null   → vault.writable=false │
  │      vault._passphrase = null                        │
  │      vault._vaultId  = vaultId                       │
  │  10. vault._loadTree(vaultId)                        │
  │      → lazy subtree load from server                 │
  │      → .vault/owner/* present but inner-decrypt will │
  │        fail gracefully (no vault_secret_key)         │
  └──────────────────────────────────────────────────────┘
              │
              ▼
  ┌──────────────────────────────────────────────────────┐
  │  vault-shell.js / vault-header.js  render            │
  │  11. vault.writable === false                        │
  │      → header badge: 👁 Read-only — cannot modify    │
  │      → write controls hidden / disabled              │
  │  12. Normal file-browse / app-open flow from here    │
  └──────────────────────────────────────────────────────┘
```

## Flow 3 — Owner Revokes a Token

```
  <vt-token-manager>._revokeToken(idx)
    │
    ├─► DELETE /api/transfers/{transfer_id}
    │     header: x-sgraph-transfer-delete-auth: <delete_key preimage>
    │     → server verifies SHA-256(preimage) == delete_auth_hash
    │     → blob deleted; subsequent GET returns 404
    │
    └─► saveTokenList(vault, tokens)
          entry.revoked    = true
          entry.revoked_at = now
          → vault.push()  [double-encrypted, see Flow 1 step 10]
```

## Encryption Layer Diagram

```
  FILE PATH                   ENCRYPTION LAYERS
  ─────────────────────────────────────────────────────────────────────
  /any/normal/file.txt        [ outer: vault read-key (AES-256-GCM) ]
                              server sees: opaque ciphertext

  /.vault/owner/              [ outer: vault read-key (AES-256-GCM) ]
  readonly-tokens.json        [ inner: vault_secret_key (AES-256-GCM) ]
                              server sees: doubly-opaque ciphertext
                              RO recipient sees: path listed, bytes unreadable
                              Owner sees: decrypted plaintext

  vault_secret_key derivation:
  ┌────────────────────────────────────────────────────────────┐
  │  HKDF-SHA256(                                              │
  │    input_key_material = UTF8(vault_key_passphrase),        │
  │    salt               = UTF8(vault_id),                    │
  │    info               = UTF8("sgraph-vault-secret-v1"),    │
  │    length             = 32 bytes                           │
  │  )                                                         │
  │  → deterministic: same key on every device, no exchange    │
  │  → vault-bound: different vault → different secret-key     │
  └────────────────────────────────────────────────────────────┘
```

## Token Payload Encryption Diagram

```
  ENCRYPT (create token — owner browser):
  ┌──────────────────────────────────────────────────────────────────┐
  │  passphrase_key = PBKDF2-SHA256(                                 │
  │    password   = roToken  (e.g. "amber-brook-4291"),              │
  │    salt       = "sgraph-ro-token-v1",                            │
  │    iterations = 100,000                                          │
  │  )                                                               │
  │  iv = random 12 bytes                                            │
  │  ciphertext = AES-256-GCM-Encrypt(passphrase_key, iv,            │
  │    JSON{ vault_id: "a3f9c1b2d4e6",                               │
  │          read_key: "<44-char base64 of 32-byte AES key>" })      │
  │  upload = iv || ciphertext  (base64-encoded, ~120 bytes)         │
  └──────────────────────────────────────────────────────────────────┘

  DECRYPT (resolve token — recipient browser):
  ┌──────────────────────────────────────────────────────────────────┐
  │  same PBKDF2 derivation from roToken                             │
  │  iv   = upload[0..11]                                            │
  │  data = upload[12..]                                             │
  │  plain = AES-256-GCM-Decrypt(passphrase_key, iv, data)           │
  │  → { vault_id, read_key }                                        │
  └──────────────────────────────────────────────────────────────────┘

  SERVER BOUNDARY:
  ┌──────────────────────────────────────────────────────────────────┐
  │  Server holds: opaque ciphertext blob (~120 bytes)               │
  │  Server holds: expires_at, uses_remaining, delete_auth_hash      │
  │  Server NEVER sees: roToken string (URL fragment never sent)     │
  │  Server NEVER sees: vault_id, read_key                           │
  │  Server CANNOT link: this blob → any vault                       │
  └──────────────────────────────────────────────────────────────────┘
```

## Phase 2 Implementation Order

```
  Step 1  ── Add SGVault.openReadOnly() to _common/sg-vault.js
              (the single _common/ change that unblocks everything)

              static async openReadOnly(sgSend, vaultId, readKeyBase64) {
                const vault      = new SGVault(sgSend)
                vault._vaultId   = vaultId
                vault._passphrase = null
                vault._writeKey  = null          // vault.writable → false
                vault._readKey   = await crypto.subtle.importKey(
                  'raw',
                  Uint8Array.from(atob(readKeyBase64), c => c.charCodeAt(0)),
                  { name: 'AES-GCM' }, false, ['decrypt']
                )
                vault._initManagers()
                await vault._loadTree(vaultId)
                return vault
              }

  Step 2  ── Move vault-credentials.js + vault-hkdf.js to _common/js/lib/
              (or import from harness path in vault-shell.js for minimal Phase 2)

  Step 3  ── Wire vault-shell.js
              a. On load: parse hash → if #ro- → resolveCredential()
                          → openReadOnly() → render vault in RO mode
              b. If sessionStorage already has readonly credentials: skip API call

  Step 4  ── Wire vault-header.js
              Read credentials.mode from sessionStorage
              → 'full'     → existing owner badge / controls
              → 'readonly' → 👁 Read-only badge; hide write controls

  Step 5  ── Visual cues (deferred, can ship separately)
              Per-file access badges
              File-open banners
              Issue-time preview in create-token form
```

## Security Boundary Summary

```
  WHO                  CAN DECRYPT                     CANNOT DECRYPT
  ────────────────────────────────────────────────────────────────────────
  Owner (full key)     All vault files                 (nothing)
                       .vault/owner/* inner layer
                       All issued token payloads

  RO recipient         Normal vault files              .vault/owner/* inner layer
  (ro-token)           (via read-key from token)       Other tokens' payloads
                                                       Owner notes / secrets

  Server               Nothing                         Everything (ciphertexts only)

  Eavesdropper on      Nothing                         Everything
  the wire             (URL fragment never sent to server; TLS on API calls)
```
