## 2. The principles (govern every decision)

1. **Reuse over build.** The chat, tool loop, VFS, LLM provider, iframe shell, bridge, and commit/sync already exist. Track A is four real builds + four tiny bridge extensions (§6).
2. **Two file systems, kept separate.** The LLM works on an in-iframe `sg-vfs` **memory** working set; the **vault** is reached only through `window.sg` and only on a deliberate flush.
3. **The harness holds the purse and the policy, not the model.** Budget and tool-availability are enforced in code; the model is *told* its budget only as advisory steering.
4. **Unavailable = invisible.** A disabled tool is omitted from `tools[]`, not refused at runtime — the model can't be jailbroken into a tool it was never offered.
5. **Commit-free by default.** `ephemeral` is the default; sync/zip are opt-in granularity dials.
6. **Every layer is inspectable.** Vault, VFS, attachments, history, assembled prompt, token count, and ledger are all viewable; mutations are visible and (by default) confirmed.

## 3. The corrections that re-shaped the contract (code reality)

The contract was written without `__Send` code access. The load-bearing corrections (full table: dev pack 00, C1–C7):
- **The execution center is mostly reuse, not a Python port.** `sg-agentic-loop` + `sg-tool-runner` + `sg-tool-definition` already exist in JS; we wrap them with a **policy + budget + CONFIRM** layer.
- **The chat lives in the iframe and can only reach the vault via `window.sg`.** It cannot call `vault.createCommit` directly. So a flush coalesces through a small **`sg.vfs.writeBatch({message})`** bridge extension (one commit, not N).
- **There are two "VFS"es.** `window.sg.vfs` (bridge→vault, write-through, one-commit-per-write) vs `sg-vfs` (pluggable providers + bus). The working set is the latter; the vault is the former.
- **Today the key is in `localStorage`, not the vault; the iframe has no `sandbox=` attribute.** Both are reconciled honestly (§4, dev pack 09).

## 5. Architecture in one screen

- **Chat = a Vault App** in the app-shell blob: iframe (REUSE). It talks to the vault through `window.sg` (REUSE) and runs `sg-vfs` memory as the LLM working set (REUSE).
- **The agentic loop is reused**; the only new code in the tool path is `ExecutionCenter.execute()` (the gate) + tool-list compilation.
- **Vault-awareness** = a cheap `list`-built manifest in the system prompt + on-demand `read_file` pull-through (no vault dump).
- **Persistence** = `VaultFlushController` coalesces memory→vault on a trigger via `sg.vfs.writeBatch` (one commit); `ephemeral`/`snapshot`/`synced`.
- **Keys** = parent reads `/.vault/secrets/**`, injects once; `/.vault/**` invisible to the tool-runner.
- **Cognition (B)** = sidecars + consensus + `/graph/**`, on the same buses + the one budget ledger; no new substrate.

## 10. The override flagged for the lead

Carried from the contract: **commit-free by default** overrides the briefs' literal "every message a file → every file a commit." Every message is still a *file* (in memory); it is not a *commit* until a flush. Confirmed this session (D5); reversible by setting the default mode to `synced`.
