## 3. The kernel→app event channel (the new substrate)

```
  IN-VAULT (kernel side)                  IN-IFRAME (app side, null-origin)
  ───────────────────────                 ────────────────────────────────────

       inbox checker
       fires bus event
            │
            ▼
   ╔═══════════════════════╗
   ║ window.sgraphVault    ║
   ║   .events             ║
   ║ ───────────────────── ║
   ║ emit('inbox.new-      ║
   ║   messages', payload) ║
   ╚═══════════╤═══════════╝
               │
               │  (fan-out: one listener per running app)
               ▼
   ┌───────────────────────┐         postMessage{
   │ app-shell.pushEvent() │ ──────▶   type:'sg-event',
   │                       │           name:'inbox.new-messages',
   │ ─── filter ──────     │           payload:{...}
   │ AppHostEvents.allows( │         }
   │   _hostEvents,        │
   │   eventName )         │              │
   │                       │              ▼
   │ if allowed →          │   ╔══════════════════════════╗
   │   postMessage to      │   ║ sg-app-stub.js           ║
   │   iframe              │   ║ ──────────────────────── ║
   │                       │   ║ window.addEventListener( ║
   │ if not allowed →      │   ║   'message', e =>        ║
   │   silently drop +     │   ║     e.data.type ===      ║
   │   log to debug pane   │   ║       'sg-event'         ║
   │                       │   ║   ? dispatch(e.data.name,║
   └───────────────────────┘   ║     e.data.payload)      ║
                               ║   : ignore               ║
                               ║                          ║
                               ║ const _handlers = Map(); ║
                               ║                          ║
                               ║ sg.on(name, cb)          ║
                               ║   _handlers.get(name)    ║
                               ║     .add(cb)             ║
                               ╚════════════╤═════════════╝
                                            │
                                            ▼
                                   app callback fires
                                   one-liner in app:
                                     sg.on('inbox.new-
                                       messages', cb)
```

**Why this matters:** the same channel that pushes `inbox.new-messages` will push `vault.commits-behind`, `peer.connected`, `task.progress`, and every future kernel→app event. **Build it once.**

## 8. Data — credential and token flow

```
                              ┌──────────────────────────┐
   passphrase ───PBKDF2──────▶│ read_key (vault — exists)│
                              └──────────┬───────────────┘
                                         │
                            ┌────────────┴────────────┐
                            ▼                         ▼
                     ┌──────────────┐         ┌──────────────────┐
                     │ structure_key│         │ enum_key (new)   │
                     │ (existing)   │         │ SHA256(          │
                     └──────────────┘         │  "sg-inbox-enum:"│
                                              │  || read_key_raw)│
                                              └────────┬─────────┘
                                                       │ HEX hashed
                                                       │ → sent to server
                                                       │ in configure body
                                                       │ as enum_key_hash
                                                       │
                                              ┌────────▼─────────┐
                                              │ server stores    │
                                              │ SHA256(enum_key) │
                                              └──────────────────┘

                              ┌──────────────────────────┐
   passphrase ───PBKDF2──────▶│ write_key (vault—exists) │
                              └──────────┬───────────────┘
                                         │
                                         │ hex → header
                                         │ x-sgraph-vault-write-key
                                         │ on configure / purge
                                         ▼
                              ┌──────────────────────────┐
                              │ server compares to       │
                              │   SHA256(write_key) hash │
                              └──────────────────────────┘

   per-accepted-sender (L2 app concern — vault doesn't derive):
   ───────────────────────────────────────────────────────────
   sender_pubkey ──SHA256──▶ append_token ──SHA256──▶ append_anchor
       (L2)                    (sender uses)         (server stores)
```

The vault layer touches `enum_key`, `write_key`, and forwards `append_token`/`anchor` verbatim. **It never sees pubkeys or plaintext.**

## 9. Lifecycle — what runs when

```
   vault closed
       │
       │ user enters key
       ▼
   ┌──────────────────────────────────────────────────────────┐
   │ _onVaultOpened                                           │
   │   • derive enum_key from read_key                        │
   │   • new SGInbox + attach                                 │
   │   • new SGInboxChecker(inbox, bus, getConfig)            │
   │   • load .vault/inbox/config.json (or default)           │
   │   • run initial check('vault-open')                      │
   └──────────────────────────────────────────────────────────┘
       │
       │ vault is open
       ▼
   ┌──────────────────────────────────────────────────────────┐
   │ DORMANT  (no timer, no poll, no background activity)     │
   └──────────────────────────────────────────────────────────┘
       │
       │ one of:
       │   • tab gains focus       (visibilitychange)
       │   • user clicks "Refresh" (vault-header menu)
       │   • user clicks "Check now" (status panel)
       │   • peer kernel sends 'vault-notify' over SecureChannel
       │   • app loads (after _onAppMounted)
       ▼
   ┌──────────────────────────────────────────────────────────┐
   │ check(trigger)                                           │
   │   • debounce floor: ≥1s since last check?                │
   │     NO → coalesce                                        │
   │     YES → list(metadata-only) → diff → emit (+ fetch     │
   │           if auto_fetch=true)                            │
   └──────────────────────────────────────────────────────────┘
       │
       └─▶ back to DORMANT
```

There is **no background thread**, **no `setInterval`**, **no polling timer**. The system is event-driven end-to-end.

## 10. Event taxonomy

```
   Event name                  Emitter         Typical consumer
   ──────────                  ───────         ────────────────
   inbox.new-messages          checker         mail-reader app, badge
   inbox.config-changed        owner UI        any app watching config
   inbox.error                 checker         debug pane, error toast
   vault.commits-behind        ref-checker     (existing, retrofit later)
   peer.connected              ViV kernel      cross-vault apps
   peer.disconnected           ViV kernel      cross-vault apps
   task.progress               eph compute     ephemeral-task UI
```

All travel through the same `app-host-events` channel. All gated by `app.json.host_events`. The taxonomy is a living document — owned by the architect, edited as features land. New names default-off for existing apps (back-compat free).

## 11. What's NOT in these diagrams (and why)

| Absent | Reason |
|---|---|
| Polling loop / `setInterval` | r3 removed it. The system is event-driven. |
| `sg.inbox.subscribe / status / checkNow / setAutoPull` | r3 removed them; `sg.on` and the transport verbs are sufficient. |
| X25519 / AES boxes | App concern (L2). Vault is encryption-blind. |
| "Accepted public keys" UI | App concern (L3). |
| Per-message decrypted body pane | App concern (L3). |
| `sg-inbox-poll.js`, `sg-inbox-crypto.js`, `sg-inbox-pki.js` | r3 deleted them. |
