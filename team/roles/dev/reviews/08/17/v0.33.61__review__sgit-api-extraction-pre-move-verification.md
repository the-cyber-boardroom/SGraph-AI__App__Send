## Problems found that the pack did not cover — and what was done

### 1. Five test files inside `tests/unit/lambda__user/` could not move (fixed by relocation)

The pack calls `tests/unit/lambda__user` "the suite that proves the move", but five of its
files imported packages that are **staying**:

| File | Imported | Relocated to |
|---|---|---|
| `fast_api/static__user/test__App_Send__UI__User__static_pages.py` | `sgraph_ai_app_send__ui__user` | `tests/unit/ui__user/` |
| `fast_api/static__user/test__welcome_page_route.py` | `sgraph_ai_app_send__ui__user` | `tests/unit/ui__user/` |
| `service/test_Service__Access_Token.py` | Admin FastAPI (in-memory) | `tests/unit/lambda__user__with_admin/` |
| `service/test_Admin__Service__Client.py` | Admin FastAPI (in-memory) | `tests/unit/lambda__user__with_admin/` |
| `fast_api/routes/test_Routes__Transfers__with_tokens.py` | Admin FastAPI (in-memory) | `tests/unit/lambda__user__with_admin/` |

All five keep running in CI (`tests/unit` covers both new folders). The three admin-coupled
files are the no-mocks pattern for the user→admin token-validation flow — they belong in the
origin repo where both lambdas exist. `tests/unit/lambda__user` is now import-clean of
everything that stays behind.

The unique `/api/docs` + `/api/openapi.json` assertion that lived in the relocated UI test
was moved into `test_Fast_API__SGraph__App__Send__User.py` (`test__api_docs_served`) so the
moving suite keeps that coverage.

### 2. Hidden test-order dependency that would have broken the extracted repo (fixed)

`test_Routes__Transfers__with_tokens.py` clears `SGRAPH_SEND__ACCESS_TOKEN` as a setup side
effect, and `test_Routes__Vault__Public.py` (7 tests) was silently depending on that clear —
remove the former from the directory and the latter starts failing with 401s. In the
extracted repo (where the admin-coupled test cannot exist) the suite would have failed on
day one, looking like a broken move.

Fixed by making `test_Routes__Vault__Public` self-contained: it now saves, clears, and
restores the env token around its own class. Order-independent in both repos.

### 3. `Deploy__Service.py` UI bundling (fixed — option A)

Applied the pack's recommended option A: the `sgraph_ai_app_send__ui__user` import and
`add_folder` call are now conditional on the package being importable. Zero behaviour change
while the package is present (origin repo); works unmodified when it is absent (extracted
repo). The bundling itself stays a deletion candidate (`05__deletion-candidates.md`).

### 4. Pack manifest gaps (recorded — for the extraction session)

- **`tests/unit/utils/` and `tests/unit/_for_osbot_aws/` must move too** — they test
  `utils/` and `_for_osbot_aws/`, which the pack moves, but the pack's test manifest lists
  only `tests/unit/lambda__user` and `tests/deploy/User__Lambda`. Include
  `tests/unit/utils/test_vault_crypto_interop.js` (companion to `test_Vault__Crypto.py`).
- **`tests/deploy/targets/test_smoke__deployed_target.py` should be copied** to the new repo —
  it is the platform-agnostic smoke suite (parametrised over `SG_BASE_URL`/`SG_ACCESS_TOKEN`,
  "validates Lambda, Fargate, EC2, Cloud Run, Heroku, or a local container"), which is exactly
  the multi-platform/multi-region success criterion. One adaptation needed: `test_3__vault_ui_root`
  asserts `/` returns HTML, which holds for the joint container but not for a bare API Lambda —
  make it conditional or drop it in the API repo's copy.
- **`requirements-test.txt` carries `issues-fs`** (issue tracking) — not needed by the moved
  code; trim during scaffolding adaptation.
- **`utils/` now has 4 source files** including `Vault__Crypto.py` (with its test and a JS
  interop test) — consistent with "take the whole directory".

### 5. Reverse coupling: admin imports from the user tree (recorded)

`Fast_API__SGraph__App__Send__Admin.py` imports `Routes__Info__SGraph` from `lambda__user`.
This does not affect the extraction (the moved copy is self-contained and the origin keeps
its copy through step 5), but it **blocks the eventual step-6 deletion** of `lambda__user/`
from the origin repo. Recorded in `05__deletion-candidates.md` §A.

### 6. Reality doc corrected

`reality/send-api/index.md` claimed 3 live `/join/*` endpoints. Code-verified false — the
section now records the routes as orphaned, resolving the pack's `01` §2 caveat: the
exclusion of `Routes__Join.py` is safe, and there is no admin↔user coupling to escalate.

## For the CI / multi-platform-multi-region goal

What the extraction inherits, verified:

- **Region is already env-driven end to end.** `Deploy__Service` derives bucket names from
  `aws_config.region_name()` (`{account_id}--{infix}--{region}`), and the deploy tests are
  stage-parameterised (`user-dev`/`user-main`/`user-prod`). Multi-region = a CI matrix over
  `AWS_DEFAULT_REGION` values calling the same reusable workflow; no code change needed.
- **The deploy pipeline shape to extract** (ADR-5) is the `run-tests → increment-tag →
  aws-deploy-lambda__user` chain in `ci-pipeline.yml`, dropping the admin/PyPI/DockerHub/UI
  jobs. The composite action `.github/actions/aws__deploy__lambda` is already parameterised
  by `lambda_type`/`target` and can be copied with `lambda_type: 'User'` hard-wired.
- **Multi-platform** beyond Lambda (container targets) is the joint API+vault deployment,
  explicitly deferred by the pack — but the smoke suite above is already written for those
  targets when they arrive.
