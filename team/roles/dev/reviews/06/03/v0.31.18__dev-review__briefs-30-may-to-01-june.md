1. Create vault with public preview + embedded RO token
2. Follow the public link in a fresh browser session (no saved keys)

**Estimate:** 2–3 days (1 day wiring, 1 day tests, 1 day browser verification)

#### P-285 — Agent-Controlled Website + Vault CI Pipeline

**Status:** PROPOSED. **BLOCKED on P-279 (kernel path unification).**

Do not implement P-285 before P-279 is scheduled. The website vault CI pipeline requires writable VIV (per-section-vault write through the VIV parent). Implementing on `CompositeDataSource` (the path being retired in P-279) creates double the migration work.

**Once P-279 is scheduled, Phase 1 scope:**
- One section vault (ambassador section) that an agent can push to
- The main website vault reads/embeds the section vault content via VIV
- No dev/QA/prod pipeline yet — just the single writable section vault proving the pattern

**Phase 2 scope (vault CI pipeline):**
- Environment vaults: dev → QA sign-off → prod promote
- Vault-to-vault promotion script / skill
- QA sign-off: a vault commit with a structured "approved" record
