## 0. The reframing (why this is revision 2)

The SG API is **PKI-blind** — it routes opaque tokens and opaque blobs. The vault's native job is **transport + poll + notify**, mirroring the existing "check for new commits → auto-pull" loop. PKI, sealing, sender identity, and mail UX are **app concerns**, not vault concerns.

What this revision removes from r1:

- The entire `sg-inbox-crypto.js` module (X25519/AES seal+open).
- The `sg-inbox-pki.js` module.
- The `<vault-inbox-view>` mail reader component + `--store` view-model.
- The `<vault-inbox-settings>` accepted-pubkey CRUD component.
- The PKI Modes 1/2/X25519-vs-P-256 decision tree.

What this revision adds over r1:

- `sg-inbox-poll.js` — the poll loop, event emission, auto-pull state machine.
- `<vault-inbox-status>` — small observability panel (count, per-anchor, last-checked, auto-pull toggle).
- `sg.inbox.subscribe / status / checkNow / setAutoPull` bridge methods alongside the six transport methods.
- `.vault/inbox/config.json` — the only persistent state (anchors + flags + cosmetic labels).

The result is ~1100 LOC across A–D versus ~1700 in r1, with all crypto pushed to the app.

## 3. Shared infrastructure: two pure modules

### 3.1 `_common/js/lib/sg-inbox/sg-inbox.js` — transport client

```
class SGInbox {
  constructor(sgSend) { this._sgSend = sgSend; this._vault = null; ... }
  attach(vault) { this._vault = vault; this._enumKey = this._deriveEnumKey(); }

  // Owner-only (writable, x-sgraph-vault-write-key header)
  async configure({ append_anchors })   // vault adds enum_key_hash
  async purge({ folder='processed', inbox, file_ids=null })

  // Owner read/process (x-sgraph-vault-enum-key header)
  async list({ inbox=null, after_file_id=null, limit=50, include_content=false })
  async fetch({ inbox, file_ids })
  async markProcessed({ inbox, file_ids })

  // Outbound (no auth header — token is auth)
  async append({ vault_id, append_token, payload })

  // Internal
  _deriveEnumKey()   // SHA256("sg-inbox-enum:" + readKeyBytes).hex()
  _headers(kind)     // kind in {'write', 'enum', 'none'} → header dict
}
class SGInboxError extends Error { constructor(code, http, message) {...} }
```

Errors: `EBADTOKEN | EFORBIDDEN | EPAYLOAD | ENOSPACE | EREADONLY | ENETWORK`. Pure transport — no DOM, no crypto beyond SHA-256 for the enum_key derivation. Web Crypto only. Node-testable via `runInThisContext`.

### 3.2 `_common/js/lib/sg-inbox/sg-inbox-poll.js` — poll loop + events

```
class SGInboxPoll {
  constructor(inbox, bus, config) { this._inbox = inbox; this._bus = bus; ... }

  start()                     // begin polling per config.poll_interval_ms
  stop()
  scheduleCheck(delayMs=0)    // debounced
  async checkNow()             // returns status
  setAutoPull(enabled)         // updates config (caller persists)
  status()                    // { enabled, auto_pull, total, per_anchor, last_checked_ms }

  // Internal
  async _tick()               // metadata list, diff against seen set, emit inbox-changed; if auto_pull, fetch new and emit inbox-messages
  _diffEntries(newEntries)    // returns entries not in this._seen[anchor]
}
```

Pure (DOM-free). Takes an event bus and an `SGInbox` instance; emits `inbox-changed`, `inbox-messages`, `inbox-error`. Unit-testable with a fake bus and a stubbed `SGInbox`.

### 3.3 What we **don't** build

- **No `sg-inbox-crypto.js`.** No X25519, no seal/open.
- **No `sg-inbox-pki.js`.** No accepted-pubkey logic.
- **No `sg-inbox-batcher.js` as a separate module.** Trivial chunking lives inside `sg-inbox.js`.

## 5. Endpoint → client method (locked)

| Server | Client method | Headers vault adds | Body |
|---|---|---|---|
| `POST /configure/{vault_id}` | `configure({ append_anchors })` | `x-sgraph-vault-write-key`, `x-sgraph-access-token` | `{ append_anchors, enum_key_hash }` (vault adds the hash) |
| `POST /append/{vault_id}` (remote) | `append({ vault_id, append_token, payload })` | none | `{ append_token, payload }` |
| `POST /list/{vault_id}` | `list({ inbox, after_file_id, limit=50, include_content=false })` | `x-sgraph-vault-enum-key` | `{ inbox, after_file_id, limit, include_content }` |
| `POST /fetch/{vault_id}` | `fetch({ inbox, file_ids })` | `x-sgraph-vault-enum-key` | `{ inbox, file_ids }` (≤100) |
| `POST /mark-processed/{vault_id}` | `markProcessed({ inbox, file_ids })` | `x-sgraph-vault-enum-key` | `{ inbox, file_ids }` (≤100) |
| `POST /purge/{vault_id}` | `purge({ folder='processed', inbox, file_ids })` | `x-sgraph-vault-write-key`, `x-sgraph-access-token` | `{ folder, inbox, file_ids }` |

Client-side pre-checks (mirror API guide token-format table):
- `append_token` and `inbox`: `^[0-9a-f]{16,128}$` else `EBADTOKEN`.
- `file_id`: `^\d{13}_[0-9a-f]{24}\.enc$` (round-trip server strings — never construct).
- `file_ids.length <= 100` else `EBADTOKEN`.
- `payload` base64-test + raw ≤ 5 MB else `EPAYLOAD`.

## 6. Key plumbing

```
On vault open (vault-shell._onVaultOpened):
  this._inbox       = new SGInbox(this._vault._sgSend);
  this._inbox.attach(this._vault);           // derives enum_key from readKeyRawBytes
  this._inboxConfig = await this._loadInboxConfig();   // .vault/inbox/config.json
  this._inboxPoll   = new SGInboxPoll(this._inbox, window.sgraphVault.events, this._inboxConfig);
  if (this._inboxConfig.enabled) this._inboxPoll.start();
  window.sgraphVault.inbox     = this._inbox;
  window.sgraphVault.inboxPoll = this._inboxPoll;
```

`enum_key` is derived once per session in `SGInbox.attach`, held in the `SGInbox` instance, **never exposed via the bridge**. Apps that call `sg.inbox.list` go through the vault, which attaches the header transparently.

`.vault/inbox/config.json` is read/written via the existing `vault._objectStore` (same path as `app.json`, `ro-links.json`). Protected by the `.vault/` floor in `AppPermissions`, so apps cannot read or write it directly — they can only mutate it through `sg.inbox.configure` and `sg.inbox.setAutoPull` (which require the corresponding capability).

## 7. Auto-pull loop (the headline feature)

`SGInboxPoll._tick()`:

```
1. const status = await this._inbox.list({ include_content: false });
2. Group entries by `inbox` → per-anchor counts.
3. const diff = this._diffEntries(status.entries);      // entries not in this._seen
4. if (diff.changed) {
       this._bus.emit('inbox-changed', { total, per_anchor });
   }
5. if (this._config.auto_pull && diff.newEntries.length > 0) {
       const groups = groupBy(diff.newEntries, 'inbox');
       for (const [anchor, entries] of groups) {
           const fileIds = entries.map(e => e.file_id);
           // batch ≤100
           const res = await this._inbox.fetch({ inbox: anchor, file_ids: fileIds });
           this._cache.push(...res.files);   // ring buffer cap 200
           this._bus.emit('inbox-messages', { entries: res.files.map(...) });
       }
   }
6. for (id of diff.newEntries) this._seen.add(id);
```

Triggers (in `vault-shell.js`):
- `_visibilityHandler` (`vault-shell.js:37`) — already fires `_scheduleBehindCheck(500)`; add `_scheduleInboxCheck(500)` immediately after.
- "Check inbox" menu action (`vault-header.js`) — fires `_scheduleInboxCheck(0)`.
- `inbox-config-changed` bus event — re-reads config; updates cadence.

Cadence: `_lastInboxCheckTime` + `config.poll_interval_ms` debounce (default 30 s).

## 12. Risks + mitigations

| Risk | Mitigation |
|---|---|
| Auto-pull cache grows unbounded | Ring buffer cap 200; cleared on tab close. |
| Two tabs race on poll | `BroadcastChannel('sg-inbox-' + vaultId)` for soft leader election; fall back to "both poll" (costs an extra metadata call, no correctness impact). |
| `sg.inbox.configure` from one app overwrites another app's anchors | Bridge enforces **merge semantics**: the vault reads current `config.json.anchors`, unions with the app's submission, and only then calls `inbox.configure` server-side. Apps can ADD anchors via the bridge; REMOVAL is owner-only via the status panel. |
| Outbound `sg.inbox.append` becomes a data exfiltration vector | Q5 in spec. No allowlist in v1; debug pane logs every append for auditing; revisit if abuse surfaces. |
| Coarse `inbox.read: true` lets one app read another's anchors | Acceptable for v1; per-anchor scoping is Phase E. |
| Vault clones see empty inbox | Surface explicitly in `<vault-inbox-status>` ("messages live on the server only"). |
| `read_key` raw-bytes exposure for `enum_key` derivation widens key surface | The bytes never leave the vault layer; only the derived `enum_key` hex is used in network headers. AppSec sign-off Q1. |
| Refresh tick + visibility-change double-fires | `_lastInboxCheckTime + poll_interval_ms` debounce in `SGInboxPoll`. |
