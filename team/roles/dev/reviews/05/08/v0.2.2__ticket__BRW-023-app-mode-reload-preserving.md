# Ticket BRW-023 — App Mode: Reload App While Preserving App Mode State

**Date:** 2026-05-08
**Milestone:** v0.3 (deferred)
**Priority:** Low
**Team:** Explorer → Dev

---

## Summary

The App Mode banner's "Reload App" button was removed in v0.2.2 because it could not
reliably reload the current HTML file while keeping App Mode active and without
corrupting the vault layout on subsequent "Open Vault" actions.

The page-level browser reload (F5 / Ctrl+R) works correctly: if `app.json` has
`"present": true`, the vault re-opens and App Mode activates automatically.

---

## Problem Description

The attempted implementation in `sg-app-banner.js` used `vault-header-refresh` to
re-render the active file, then re-lifted the new iframe wrapper via `MutationObserver`.
Two issues surfaced:

### Issue 1 — Flicker during re-render
When `vault-header-refresh` runs, the vault removes the old iframe wrapper from the DOM.
The old wrapper was `position:fixed`, covering all vault chrome. Once removed, vault chrome
briefly flashed before the new wrapper was lifted.

**Attempted fix:** A cover div at `z-index:7998` masked the gap. This worked.

### Issue 2 — Broken vault layout on "Open Vault" after reload
After a Reload App cycle, clicking "Open Vault" left the vault in a broken state:
no file tree panel, no tab bar, full-width content area.

**Root cause analysis:** On initial app.json activation (`present: true`), no iframe
exists yet, so `_activateAll()` takes the fallback path:
1. Injects shadow CSS into `sg-layout.shadowRoot` (hides `.sgl-tab-bar`, `.sgl-resize-handle`)
2. Hides the tree `.sgl-stack` via inline style (`display:none !important`)
3. Starts `MutationObserver` to lift the iframe once it appears

After Reload App (new iframe, new frame-lift), the shadow CSS and `.sgl-stack` hiding
**from step 1 remain in effect** — they are not re-applied by the reload path.

When the user then clicks "Open Vault" (`_deactivate()`), the deactivate logic
removes shadow CSS and calls `_restoreTreeStack()`. However, the vault layout
still appeared broken, suggesting that:
- The `window.resize` event dispatched post-deactivate was not sufficient to
  trigger sg-layout to re-measure panel dimensions, OR
- Some other state in sg-layout was corrupted by the `position:fixed` ↔
  `position:relative` transition cycle on the wrapper div.

---

## Technical Context

### Frame-lift approach
App Mode works by applying `position:fixed; top:2.25rem; left:0; right:0; bottom:0;
z-index:7999` to the `wrapper` div that contains `.sb-file__html-frame`. This div
is a light-DOM child of the content panel in `sg-layout`. The iframe itself does not
move in the DOM (which would trigger a reload).

When the wrapper is `position:fixed`, it is out of normal document flow. The content
panel (`div[slot="s2"]`) has no in-flow children and may collapse to height 0.
sg-layout may cache this collapsed state.

### sg-layout opacity
`sg-layout` is loaded from CDN (`dev.tools.sgraph.ai/core/sg-layout/v0.1.0/sg-layout.js`).
Its internal resize/layout API is not directly accessible. Panel re-layout is
triggered via `window.dispatchEvent(new Event('resize'))`, which may not reach
all internal ResizeObserver instances.

---

## Possible Approaches

1. **iframe blob reload (simplest):** Instead of `vault-header-refresh`, call
   `iframeEl.contentWindow.location.reload()`. This reloads the current blob URL
   (inlined CSS/JS from the vault), restarting the app without re-fetching from the
   vault. Preserves App Mode trivially since the iframe stays in place.
   - Limitation: does not pick up vault edits made since the file was opened.

2. **Decouple activation state:** Track whether shadow CSS / tree hiding was applied
   as part of the initial activation (fallback path). On deactivate, only undo what
   was actually done. On Reload App, re-apply the same activation steps on the new
   iframe without disturbing the sg-layout state.

3. **sg-layout API exploration:** If a future version of sg-layout exposes a
   `refresh()` or `invalidateLayout()` method, use it in `_deactivate()` instead
   of relying on the resize event.

4. **Position-fixed on content panel, not wrapper:** Instead of lifting the wrapper
   div, apply `position:fixed` to the sg-layout content panel element itself
   (`div[slot="s2"]`). The panel stays in the slot assignment (sg-layout knows about
   it) but visually fills the viewport. This avoids the content panel collapsing to
   height 0.

---

## Current State (v0.2.2)

- "Reload App" button removed from App Mode banner.
- Users who need to reload the app can use browser page reload (F5).
- `app.json "present": true` ensures App Mode re-activates automatically on page reload.
- The `_reloadAndLift()` and cover-div code remain in `sg-app-banner.js` in case
  a future version wants to restore the button.
