# Ticket VLT-026 — Vault Broadcast Event Bus

**Date:** 2026-05-08
**Milestone:** v0.2.3
**Priority:** Medium
**Team:** Explorer → Dev

---

## Summary

Vault operations (file saved, file loaded, commit made, sync event) currently produce no observable signal that vault-hosted apps or third-party components can listen to. The `window.sgraphVault.events` bus is internal to vault-shell; iframe apps have no access to it.

This ticket adds a **broadcast event surface** that vault-hosted HTML apps (and co-loaded scripts) can listen to without postMessage polling.

---

## Motivation

The iframe write API (`Change 5`) gives vault apps a way to write files. After `writeFile()` resolves, the app has no way to know:
- Whether the commit triggered an auto-sync
- Whether the file tree changed in ways that affect other open tabs
- When the named-head advances (e.g., after a `Push`)

An event bus fills this gap without requiring polling.

---

## Proposed API

### Parent-side: emit on vault operations

In `VaultDataSource` and vault-shell, after key operations:

```javascript
// After a successful saveFile (write from browse-edit or iframe write API):
window.dispatchEvent(new CustomEvent('vault:file-saved', {
    detail: { path: 'reports/output.json', size: 1234 }
}));

// After vault tree refresh (pull/merge/manual refresh):
window.dispatchEvent(new CustomEvent('vault:tree-changed', {
    detail: { source: 'pull' | 'push' | 'write' | 'refresh' }
}));

// After a file is opened/rendered in send-browse:
window.dispatchEvent(new CustomEvent('vault:file-opened', {
    detail: { path: 'reports/index.html' }
}));

// After commit (any commit):
window.dispatchEvent(new CustomEvent('vault:committed', {
    detail: { message: 'Edit reports/output.json', headId: 'abc123' }
}));
```

### Iframe-side: relay via postMessage

The VFS bridge injects a listener into the iframe that relays these events:

```javascript
// Injected in vfsBridgeScript (parent → iframe relay):
window.addEventListener('vault:file-saved', function(e) {
    // Forward into iframe via new envelope:
    iframeEl.contentWindow.postMessage({ __sgVfsEvent: 'file-saved', detail: e.detail }, '*');
});
```

Inside the iframe, `window.sgVault` exposes:

```javascript
window.sgVault.on = function(eventName, handler) {
    window.addEventListener('message', function(e) {
        if (e.data && e.data.__sgVfsEvent === eventName) handler(e.data.detail);
    });
};
// Usage:
window.sgVault.on('file-saved', function(detail) {
    console.log('Saved:', detail.path);
});
```

## Scope

| File | Change |
|------|--------|
| `vault-data-source.js` | Dispatch `vault:file-saved`, `vault:committed` after `saveFile()` |
| `vault-shell.js` | Dispatch `vault:tree-changed` after pull/merge/refresh |
| `send-browse--v0.3.x.js` | Dispatch `vault:file-opened` in `_openFileTab`; relay events to iframe via postMessage |
| `vfsBridgeScript` (in send-browse) | Add `__sgVfsEvent` relay; add `window.sgVault.on()` |

**Estimated LOC:** ~50 lines.
