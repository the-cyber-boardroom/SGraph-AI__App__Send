## 0. Read-me for the coding session (house rules — do not skip)

1. **Branch:** work on the designated feature branch; branch from `dev`; `git push -u origin <branch>`.
2. **Version file:** never touch `sgraph_ai_app_send/version` — CI owns it. Don't reference it in commit messages.
3. **Testing model:** real stack, no mocks/patches for backend; the **only** mock is the standalone harness's in-memory `window.sg` (it's a test fixture, not a patch). Playwright for the chat E2E.
4. **Changelog:** every UI/API-affecting change gets an entry in `team/comms/changelog/MM/DD/`, classifying which tests SHOULD vs SHOULD-NOT break.
5. **Secrets:** never commit the OpenRouter key, vault keys, or share tokens. The key lives at `/.vault/secrets/openrouter.key` in a vault and is read at runtime only.
6. **Reality doc:** when a phase ships, add the shipped items to `team/roles/librarian/reality/` (ui + ai-agents domains) in the same commit.
7. **Build order:** follow the phases (§6). Do **not** build Track B before Phase 4 substrate exists.
8. **Reuse first:** before writing anything, confirm the `TOOLS/` module + version still resolves (dev pack 08 §B) and the `VAULT/` path still exists (paths verified 26 May).

## 6. Phase task lists & definition-of-done

- **P0 — Standalone shell** ☐ chat app + harness with mock `window.sg` ☐ tool loop vs `sg-vfs` memory ☐ ExecutionCenter skeleton (AUTO only) ☐ bridge-log tool/llm rows. **DoD:** the harness drives a full read→write→read loop with visible tool/llm rows, no vault.
- **P1 — Bridge wiring** ☐ mount as Vault App ☐ real `sg.vfs.list` manifest ☐ `read_file` pull-through ☐ right pane. **DoD:** chat reads a real vault file on demand; manifest in the system prompt.
- **P2 — Execution center** ☐ policies + loadouts + availability ☐ inline CONFIRM/DRY_RUN ☐ budget ledger + preflight + memory sub-cap ☐ injection floor (fencing, no-self-widen). **DoD:** a COSTLY tool over budget is refused; CONFIRM card approve/always/deny works; disabled tool absent from `tools[]`.
- **P3 — Persistence + keys** ☐ `writeBatch` EXTENSION ☐ FlushController + 3 modes ☐ `flush_memory` ☐ `__sgSecrets` + `/.vault/**` exclusion. **DoD:** `synced` turn-end = 1 commit; `snapshot` = 1 zip commit; key never a VFS path (test); chat authenticates.
- **P4 — Memory + inspector** ☐ every-message-as-file ☐ `consolidate_memory` (lossless) ☐ inspector (layers/full-prompt/history-edit). **DoD:** prune drops live detail, originals retrievable; inspector shows assembled prompt + token count + ledger.
- **P5 — Fractal + next-chat** ☐ scope=doc/folder/vault ☐ two-pane next-chat. **DoD:** session B starts from files session A edited.
- **P6 — Track B** ☐ injection→extraction→curation/consolidation sidecars ☐ consensus ☐ `/graph/**`. **DoD:** each sidecar enable/disable + budget-tagged; consensus fan-out preflighted.
- **P7 — Keystone** ☐ first-class surface ☐ chat-created app rendered via app-shell. **DoD:** chat writes an app; "created apps" mounts it.
- **P8 — Hardening** ☐ pin + SRI ☐ vendor `TOOLS/` into `__Send`. **DoD:** key-holding context loads no run-time third-party origin (R-supply exit).

## 7. Test plan (assertion-level; no mocks except the harness fixture)
- **T-U (unit):** `compileTools` omits `OFF`/unavailable; `preflight` refuses when `projected>remaining`; `degradeIfReadOnly` forces WRITE→unavailable; FlushController coalesces N dirty paths → one `writeBatch`.
- **T-S (security):** `read_file`/`list_folder`/`<img>` on `/.vault/**` → ENOENT; no tool can mutate a policy/budget; fenced untrusted content is labelled data; `__sgSecrets` not re-requestable.
- **T-I (integration):** full agentic loop (send→tool-calls→execute→results→resend) against `sg-vfs` memory; CONFIRM deny returns a graceful tool-result, not an error.
- **T-E (E2E, Playwright):** mount chat as Vault App; read a vault file; CONFIRM an infographic; `synced` turn-end produces exactly one commit (assert via `sg.sync.status`); existing Vault App still mounts (regression).

P0–2 are pure reuse + new shell (no vault writes, no key) → low risk, ship-and-try. P3 is the engineering (flush + keys) and is **AppSec-gated** (dev pack 09 §2).
