# BUG — `_navigateToPath` references undefined `iframeEl` in the `.html` branch

**Date:** 2026-05-31
**Severity:** High (suspected live break of in-vault `.html` link navigation)
**Status:** OPEN — static-confirmed, runtime-unconfirmed
**Found at:** `origin/dev` sha `15ff5a2b`
**File:** `sgraph_ai_app_send__ui__vault/v0/v0.2/v0.2.3/_common/js/components/app-shell/app-shell.js`

## What

`_navigateToPath(href, opts)` (line 1420) declares only `var self = this`
(line 1424). Its `.html/.htm` branch then uses a **bare `iframeEl`** six times:

```
1476  iframeEl.removeAttribute('src');
1477  iframeEl.srcdoc = injected;
1482  iframeEl.contentWindow.postMessage({ __sgVfsScrollToHash: fragment }, '*');
1483  iframeEl.removeEventListener('load', onLoad);
1485  iframeEl.addEventListener('load', onLoad);
```

`iframeEl` is **not declared** in this method. File-wide it exists **only** as the
parameter of a different method, `_setupVfsBridgeHandlers(iframeEl, dataSource)`
(line 1944). Under the file's `'use strict'`, the bare reference should throw
**`ReferenceError: iframeEl is not defined`** as soon as the `.html` branch runs.

The sibling branches are correct — they delegate via `self.`/`this.`:
- `_page.json` → `self._mountPageLayoutByPath(...)`
- `.md` → `self._mountMarkdownByPath(...)`
- other → `this._mountVaultFile(...)`

Only the inlined `.html` branch uses the unqualified name. Intended code was
almost certainly `var iframeEl = self._iframeEl;` (the iframe set in `_mountApp`).

## Impact

`_navigateToPath`'s `.html` branch is reached by:
1. **In-vault link clicks** — `__sgVfsNavReq` → `self._navigateToPath(..., {pushHistory:true})` (line 1959). So clicking an in-vault `.html` link likely throws and does nothing.
2. **HUD `app-hud:nav` `'jump'`** (line 59) and **`_navBack/_navForward/_navReload/_navHome`** when the target is `.html` (they call `_navigateToPath`).
3. **External automation** (sg-playwright) calling `_navigateToPath` for `.html`.

This is exactly the behaviour commit `ee6f4995` ("in-vault link nav broken under
null-origin frames") set out to fix — the fix changed `src`→`srcdoc` correctly but
left the variable unqualified.

## Why it likely slipped through

The dev-branch Phase 4/5 review already flagged the matching coverage gap:
*"no e2e drives a real app-shell mount + in-vault link click."* Nothing exercises a
real click→`.html`-nav in a browser, so a runtime ReferenceError on that path is
invisible to the suite.

## Fix

One line in `_navigateToPath`, before the `.html` branch uses it:
```js
var iframeEl = self._iframeEl;
```
(or replace the five `iframeEl` uses with `self._iframeEl`).

## Verify (the test the codebase is missing)

Add an app-shell nav e2e: real decrypt → mount a vault with an in-vault `.html`
link → click it → assert the frame content changed (and no `pageerror`). This both
proves the fix and closes the coverage gap that hid it. A `node` unit test can't
catch it (ReferenceError is runtime, not syntax; `node --check` passes).

## Runtime confirmation (1 line, in an open `/en-gb/app`)
```js
try { document.querySelector('app-shell')._navigateToPath('patient/index.html', { alreadyResolved:true }); console.log('no throw'); }
catch (e) { console.log('THREW:', e.name, e.message); }
```
Expect `ReferenceError: iframeEl is not defined` if the bug is live.
