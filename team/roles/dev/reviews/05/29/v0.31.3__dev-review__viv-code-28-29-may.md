## 1. What Was Delivered

### Phase 1: SecureChannel Foundation — COMPLETE

Two standalone modules, fully unit-tested, no UI change:

**`secure-channel-envelope.js`** — Pure WebCrypto P-256 envelope.
- `pack(payload, sigKey, encKey?)` → `Envelope`; `unpack(envelope, sigKey, encKey?)` → payload
- Payload kinds: `bytes` (Uint8Array), `json` (arbitrary JSON), `mixed` (`{path, data: Uint8Array}` — for `vfs.write`)
- `ReplayGuard` — rejects re-used nonces within the guard's lifetime
- ECDSA P-256 signing always; ECDH-AES-GCM encryption when `sensitiveKey` is set
- 29 assertions covering: round-trip, tamper-detect (T5), replay (T6), PNG-byte round-trip (E7/E8, review B2), padding edges (0/1/1 MiB), 1000-nonce uniqueness, Unicode JSON

**`secure-channel.js`** — Port-anchored authenticated channel.
- `SecureChannel.create(iframe, opts?)` → returns the initiator channel half
- `SecureChannel.accept(port, opts?)` → returns the responder channel half
- K1 one-use bootstrap key: parent generates ephemeral key, child re-derives, parent discards. Secrets delivered encrypted under K1.
- Directional rule (B1 resolved): `request()` is initiator-only; `send()` works both ways for events/replies
- Reply types `__ok` / `__err` carry value directly — binary results round-trip byte-exact without re-encoding
- cid check after unpack (M6 fix): rejects envelopes addressed to a different channel
- Bounded `_preHandshakeBuf` (L4 fix): 8 types × 8 entries max
- 14 assertions covering: round-trip, K1 handshake + sniffer-confidentiality (C2), directional rule (C3a/C3b), PNG bytes live round-trip (C5/T13/B2), concurrent request id-correlation, error propagation, close → EUNREACH

### Phase 2: Spawn + Cross-Vault Write — COMPLETE (browser end-to-end PROPOSED)

**`kernel-mounts.js`** — `KernelMounts`: add/remove/get/list/resolve (13 assertions M1-M12)
- Longest-prefix match with traversal-collapse (uses AppPermissions.normalizePath)
- `resolve('mounts/p')` returns `rest === ''` (N1 resolved)

**`kernel-broker.js`** — `KernelBroker` per-kernel sidecar (22 assertions BR1-BR12)
- `mediate(op, mountId, path, credentialClass)` → `{decision, entryId}` — opaque entry ID (N3)
- `finalize(entryId, result)` — concurrent-safe by entryId lookup
- Default policy: `fs.read=auto`, mutations=`ask`
- Audit: log records metadata only (no file contents)

**`kernel-app-handlers.js`** — `registerKernelVfsHandlers` (24 assertions, new in v0.31.2)
- Policy-enforcing kernel-side VFS handler registration
- Two-sided gate: `AppPermissions.isFloor` + `can()` checked before any relay (H1 fix)
- `_safePush` raises EUNREACH on push errors (M1 fix, silent data-loss closed)
- Covers T7 (no capability → EPERM), T8 (child refuses regardless of parent grant)

**`kernel-bootstrap.js`** — `bootKernelOnPort` (13 assertions, new in v0.31.2)
- Testable bootstrap: handshake → vault.open → registerKernelVfsHandlers
- Reads endpoint from secrets payload (M5 fix, was hardcoded)
- Shares code with the shipped child (M4 fix — relay tests now use real bootstrap)

**`app-permissions.js`** (extended) — `vault.mount` capability key (6 assertions VM1-VM6)

**`app-shell.js`** (extended):
- `_mountChildVault(ref, opts)` — builds null-origin srcdoc iframe with `KERNEL_SHELL_HTML`, runs `SecureChannel.create({sensitiveKey:true})`, delivers `{vaultKey, accessToken}` encrypted, waits for child `ready`
- `_handleVfsViv(op, path, data)` — resolves mounts → broker.mediate → relay over child's SecureChannel
- `vfs.read` + `vfs.write` + `vfs.list` bridge handlers route through `_handleVfsViv` when a mount applies (M2 fix: mount-resolve before grant check; M3 fix: list relay added)
- `__sgCmdType:'vault'` switch extended with `mount/unmount/mounts` actions

**`scripts/build-kernel-shell-bundle.py`** — concatenates kernel + sg-vault* + sg-send* + vault-data-source + vault-links + kernel-mounts + kernel-broker sources, inline child-kernel bootstrap, → one 191 KB self-contained HTML string in `globalThis.KERNEL_SHELL_HTML`. **Must be re-run before any change touching bundled modules.**

**`kernel-shell-bundle.js`** — AUTO-GENERATED output. 1 freshness assertion (`test__bundle_freshness.js`).

**`test__kernel_relay.js`** — 16 integration assertions using real SecureChannel + KernelMounts + KernelBroker + synthetic in-memory data source. Covers T7, T8, T9, T3a/b (directional, B1), T4 (non-transitive), R2/R3 (PNG-byte relay, T13/B2), R5 (mount-root list, N1), BR7 (concurrent finalize, N3).

### Phase 3 Sub-step C Prep — LANDED (not yet wired)
