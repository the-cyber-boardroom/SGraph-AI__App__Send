## Verdict

Most findings are fixed and covered by tests, including the worst one: a diverged Push no longer overwrites the published commits. **One High remains**: a merge can still delete folders that stayed unloaded without being reported as failed (reproduced). Two more findings are only partly fixed: auto-sync on a rewound vault, and `switchBranch` reclassification. The fixes also add three Medium issues: silent merges in `push()`, a commit-by-commit walk cost, and auto-sync retrying a rewound vault endlessly.

## New concerns

**A — High, data loss (reproduced twice).** A merge still deletes folders that stayed lazy without being reported as failed.
- Steps:
  1. A Browse walk is in flight, and "Sync now" joins it (same root).
  2. Meanwhile `loadSubTreeOnDemand('/a')` runs, from a write's `_ensureFolderLoaded`, a UI expand or the embedded-token reader.
  3. When the walk's batch returns, `/a` is already loaded, so it is skipped and `/a/b` is never queued.
  4. The walk returns `failed: []`.
  5. `_flattenInMemoryTree` skips the lazy `/a/b`, the merge treats it as deleted by ours, and publishes.
- Probe output: `merge result: {"merged":true,…,"published":true}`; `published /a: x.txt  /a/b: []` (`deep.txt` gone).
- Fix:
  - In the walk's `run()`, queue a loaded node's lazy children instead of `continue` (`folder-ops.js:195`).
  - In `_loadAllSubTreesInMemory`, re-check the current tree after the walk: if any `_loaded === false` node remains, walk once more, then throw EINCOMPLETE.

**B — Medium. `push()` merges silently.**
- With both sides editing the same file, `push()` returns `undefined` and `doc_conflict.txt` is published.
- `_onPush` shows "Pushed" and does not remount Browse.
- Auto-sync now merges and publishes conflict copies in the background whenever a collaborator has pushed.
- Fix:
  - Return the merge result; the shells remount and warn about conflicts.
  - Give auto-sync a no-merge mode that throws EDIVERGED, so the banner shows instead.

**C — Medium. Auto-sync on a rewound vault.**
- `_checkAndAutoSync` and `_checkBehindOnly` set `_namedHeadId` to the rewound head without classifying it, and `rewound` stays false.
- Every activity then calls `push()`, which throws EREWOUND. The user sees an "Auto-sync push failed" toast each time, and each attempt walks up to 2 × 2,000 commits.
- Fix:
  - Skip auto-push when `remoteHeadStatus === 'rewound'`.
  - Classify whenever the named head changes.
  - Refresh the sync state in the catch.

**D — Medium, cost. The 5,000-commit walks issue one request per commit on a linear history.**
- Measured on 300 commits: a diverged push made 305 POST /batch calls; opening a fresh signed device made 302.
- Fix:
  - Put the legacy-adoption cap back to 500 or less (an incomplete walk already means "do not adopt").
  - Cap the push pre-walk near 500 and let `_findCommonAncestor` decide the rest.

**E — Low-Medium. The 740-byte message cap cuts off the `Via-Mount:` audit trailer.**
- A three-file upload with long names produced a 740-byte message with no trailer.
- Fix: cap the body to 740 minus the trailer's bytes, then append the trailer.
- The cap itself is sound: 740 + 28 bytes of IV and tag = 768 bytes = 1,024 base64 characters, applied before signing, UTF-8 safe.

**F — Low, latent. `push({acceptRewind:true})` re-publishes the commits a rewind removed** when the rewind went back to an ancestor of the local head: the fast-forward check passes, so the merge is skipped. Probe: `secret.txt` published again. No current caller passes this option.

**G — Low. `switchBranch` loads a rewound head silently.** Probe: status `rewound` before the switch, `forward` after. Fix: classify against the recorded accepted head, and refuse or show the banner.

**H — Low.**
- The accept-rewind dialog (`vault-shell.js:869-871`) still says removed commits "stay in your working branch". They no longer do.
- Conflicts from `_acceptRewindTo` are not reported.
- Child kernels relabel EREWOUND as EUNREACH (`kernel-app-handlers.js:222-226`).

**Checked and sound:**
- The pack-mode refusal (`checkFormat` refuses `packs` and `blob-deflate`) runs on open, on read-only open and before every push and pull. Vaults with `long-messages` or `pack-indexes` still open.
- The bundle matches its build script.
- Probe scripts: `scratchpad/devreview/probe1.mjs`, `probe2.mjs` (session scratchpad, not committed).
