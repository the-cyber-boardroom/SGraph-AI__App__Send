## 1. Agent Authorization: New Entities and Graph Logic

### What Needs Building

Three new entity types and one computation:

**`AuthorizationClosure`** — computed subgraph
```python
# Vault file path pattern:
# vaults/{vault_id}/graph/auth-closures/{agent_id}/closure.json
{
    "agent_id": "...",
    "nominal_grant": [...],      # stated permissions
    "closure": [...],            # everything reachable (transitive)
    "delta": [...],              # closure minus nominal_grant
    "computed_at": "...",
    "capability_certificate": "..."  # ref to CapabilityCertificate if scoped
}
```

**`CapabilityCertificate`** — scoped, PKI-signed grant
```python
# vaults/{vault_id}/graph/capability-certificates/{cert_id}.json
{
    "cert_id": "...",
    "agent_id": "...",
    "grant": [...],              # named permission list
    "block_list": [...],         # edges the agent cannot traverse
    "allows_redelegation": false,
    "signed_by": "...",          # PKI public key
    "signature": "...",
    "issued_at": "...",
    "expires_at": "..."
}
```

**`MomentOfAuthorization`** — timestamped consent record
```python
# vaults/{vault_id}/graph/authorization-moments/{moment_id}.json
{
    "moment_id": "...",
    "agent_id": "...",
    "granter": "...",
    "original_delegator": "...",  # who originally held the permission
    "redelegation_consent": false, # did original delegator consent?
    "authorized_at": "...",
    "capability_certificate": "..." # ref if scoped
}
```

### Implementation Estimate

| Item | Effort | Blocker |
|------|--------|---------|
| `AuthorizationClosure` vault schema | 0.5 days | Architect decision on traversal rule |
| `CapabilityCertificate` entity + PKI signing | 1.5 days | Uses existing SG/Send PKI crypto |
| `MomentOfAuthorization` entity | 0.5 days | None |
| Closure computation (graph traversal) | 2–3 days | Traversal rule definition |
| Delta computation (closure - nominal) | 1 day | Depends on traversal |
| Tests | 1 day | Uses existing in-memory stack |

**Total estimate: ~7 days** (blocker: traversal rule definition by Architect)

### Risk

The closure computation is the only technically novel piece. The traversal logic (what makes one node reachable from another in the authorization graph) must be specified before implementation starts. Without that specification, the closure entity and the CapabilityCertificate are implementable, but the computation itself is not.

**Estimate:** 2 days (schema definition; blocked on graph representation decision)

### Stream B — RAMM Level Predicates (graph queries)

Five level predicates need to be written as query functions operating over the vault graph. Each predicate is a function that takes a vault graph and returns `(level, failing_nodes)`.

```python
def ramm_level_3(vault_graph):
    """Returns True if every acceptance node has owner, approver, expiry, review, control."""
    for acceptance in vault_graph.nodes_of_type('RiskAcceptanceDecision'):
        if not (acceptance.has_edge('ownedBy') and
                acceptance.has_edge('approvedBy') and
                acceptance.has_edge('expiresAt') and
                acceptance.has_edge('reviewedAt') and
                acceptance.has_edge('justifiedBy')):
            return False, acceptance
    return True, None
```

**Estimate:** 3 days (5 predicates + test suite)
**Blocker:** vault graph query API — needs to be defined or extracted from existing graph code
