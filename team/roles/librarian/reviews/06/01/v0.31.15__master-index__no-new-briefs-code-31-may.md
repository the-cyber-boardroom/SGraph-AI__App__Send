### New EXISTS: Deep-Link HTML Fix + Extended Nav Tests (v0.31.13 batch)

**Commit `3271fbdf` — fix(app): deep-link HTML in app vault now loads CSS/JS + body-hidden delay**

Root cause: `_continue()` flow for `/en-gb/app/#path/index.html` was calling `_mountVaultFile(deepPath)` when the deep-link path differed from `app.json`'s `entry`. `_mountVaultFile` is a bare single-file view that ignores the `resources` block in `app.json` — CSS/JS was never loaded. Fix: deep-link HTML is now always mounted via `_mountApp(deepPath)` (the full app path), so `app.json` resources are injected exactly as they are for the normal entry path.

**Bonus fix:** body-hidden self-check delay raised from `setTimeout(0)` to `setTimeout(2500)` — the prior zero-delay fired before reveal-on-ready apps (e.g. Private Health Score) had time to unhide their body, triggering a false "App body is hidden" banner. 2500ms is safely above every reasonable app init time while still catching genuinely hidden bodies.

**Coverage extended:** `test__app_shell_nav_helpers.js` extended from 35 assertions (v0.31.12) to 47 assertions. New test coverage spans:
- DM5–DM6: non-HTML deep-links → file strategy
- DM7: HTML deep-link + no app.json → file (no app to mount)
- DM8–DM10: regular and empty cases
- DM11: substring "html" mid-path does NOT trigger the HTML branch

## New PROPOSED Items

| # | Item | Source |
|---|------|--------|
| P-279 | **Kernel Path Unification / CompositeDataSource Retirement:** Retire `CompositeDataSource` (read-only sub-vault adapter) and converge the vault tree view (`/en-gb/vault`) and app view (`/en-gb/app`) onto a single `KernelParent` + relay kernel path. All file ops (root + every mount) go through `VaultAccess` → `relay` → `KernelParent` → `SecureChannel` → child kernel → `_safePush`. The two shells (vault-shell + app-shell) become one shell over one data path. Enables rw sub-vault writes from the tree view; security stack lives on one code path (broker policy, B10 custody gate, floor, audit, Edge-1 push). Scoped in `team/roles/architect/reviews/05/31/v0.31.2__scoping__rw-sub-vaults-kernel-relay-in-tree.md`. | Architect session 05/31 |
| P-280 | **Popup Capability Gate for Inner Vaults:** Fix AppSec finding SEC-VIV-002 — gate `allow-popups-to-escape-sandbox` to the root vault only. Inner/mounted sub-vault content must NOT receive this capability unconditionally. An inner vault wanting popups becomes a future `request + parent-consent` flow (analogous to the capability grant model). Decision confirmed (Dinis, 05/31). Implementation: detect CompositeDataSource-mounted paths at the four mount sites (`_mountApp`, `_mountPageLayout`, `_mountVaultFile` HTML+markdown) and set sandbox without popup flags for inner-vault renders. Blocked on P-279 (kernel path unification makes the detection trivially available via mount context). | AppSec session 05/31 |
