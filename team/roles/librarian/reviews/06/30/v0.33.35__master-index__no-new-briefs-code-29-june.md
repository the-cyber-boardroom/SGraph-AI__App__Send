## Code Changes Since Last Session

### 1. `sg-embed-helpers.js` — New Module (EXISTS)

**Commit:** Merged via `ddff724` (2026-06-29)
**File:** `sgraph_ai_app_send__ui__user/_common/js/components/app-shell/sg-embed-helpers.js`
**What it does:** Pure `SgEmbed` class implementing the `sg.vault.embed(mountEl, key, opts?)` one-call parent helper. Collapses the ~70-line hand-rolled vault-in-vault embed pattern into a single bridge call. Builds the iframe, enforces least-privilege sandbox (`allow-scripts` only; refuses `allow-same-origin` and `allow-popups-to-escape-sandbox`), posts `vault-open` to the right target, resolves on `vault-ready`.
**Tests:** `tests/unit/vault_ui/loader/test__sg_embed_helpers.js` — **17 assertions** (Node/jsdom-free). Covers: iframe build, sandbox enforcement, origin logic for opaque-origin embedding, handshake round-trip (embed-ready → vault-open → vault-ready → resolve).
**Author guide updated:** `library/guides/vault-html/AUTHORING.md` now has an "Embedding another vault" section prescribing the one-liner. The hand-rolled pattern is the anti-pattern.
**Reality domain:** `ui/index.md` (already updated in merge commit — `sg.vault.embed` section in ViV/Vault-Embed).

**Commit:** `66ce528` (2026-06-29)
**What changed:**
- `osbot-fast-api`: 0.38.0 → 0.39.0 (handles `_IncludedRouter` wrapper from FastAPI ≥ 0.137)

**Root cause of the prior failure:** FastAPI ≥ 0.137 stopped flattening `include_router()` child routes into `app.routes` — it inserts an `_IncludedRouter` wrapper (`BaseRoute` with no `.path`). `osbot-fast-api` 0.38.0 iterated `app.routes` and accessed `.path` directly, crashing on the wrapper. osbot-fast-api 0.39.0 handles it via `effective_candidates`.
