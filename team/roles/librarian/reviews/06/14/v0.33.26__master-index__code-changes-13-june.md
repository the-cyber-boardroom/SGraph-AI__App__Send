## Commit 1 — `c32bfed6`: Print margin parity fix (`sg-print.js` v1.0.2 → v1.0.3)

**Date:** 2026-06-13 10:47 UTC
**Files changed:**
- `sgraph_ai_app_send__ui__user/v0/v0.3/v0.3.1/_common/js/sg-print.js`

**Path note:** `sg-print.js` lives in the user-UI v0.3.1 `_common/` overlay. It is the shared
print-to-PDF utility component used by both the SG/Vault file-viewer Print button and
`app-shell._onPrint`. The v0.3.1 merge is the authoritative copy; no other tree carries a newer
version.

### Problem

The print preview card (screen) and the actual printed page (PDF) used **different margins**:

- Screen preview: `.sg-print-page { padding: 0.8cm 1.2cm }`
- Print: `@page { margin: 1cm 1.25cm }` (page element's own padding reset to 0)

The net effect: the on-screen preview did not faithfully represent the printed PDF output.
The `1cm` top margin also read as cramped in the output. The file's own changelog comment
erroneously claimed `@page margin` was `0` — it had drifted out of sync with the actual code.

### Fix

**Single source of truth:** `PAGE_MARGIN = '1.5cm'` — one constant, used in **both** places:
1. `@page { margin: ' + PAGE_MARGIN + '; }` — the actual printed-page margin
2. `.sg-print-page { padding: ' + PAGE_MARGIN + '; }` — the screen preview card padding

The print media block still resets the page element's own `padding`/`margin` to `0` so `@page`
is the sole margin source (no doubling). The comment on the `.sg-print-page` padding rule was
updated to read: `/* matches @page margin so preview == print */`.

**Version bump:** `sg-print.js` exports `{ version: '1.0.3' }`.

### Scope and reach

- **Component is "browser-unverified"** per the commit message: "worth a real Save-as-PDF pass
  to confirm the margins read right and the preview matches." The fix is code-correct but no
  PDF round-trip was captured in CI.
- **Open follow-up (commit note):** If a page still looks scaled/shifted after this fix, the
  cause is likely wide ASCII `<pre>` diagrams overflowing the page width and triggering Chrome's
  shrink-to-fit. Separate fix: wrap/clip/scale wide `pre` in print media. Not done here.
