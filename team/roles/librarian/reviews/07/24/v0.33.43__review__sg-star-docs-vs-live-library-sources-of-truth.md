# Review — `sg.*` documentation & guidance: repo vs live sgraph.ai library

**Role:** Librarian
**Date:** 2026-07-24
**Scope:** All `window.sg.*` / vault-authoring guidance in this repo, cross-checked against
(a) the shipped bridge (`app-shell.js` v0.2.3), (b) the live library vault
(`pmcv9tfe` → https://sgraph.ai/en-gb/library/), (c) the live Dev Docs vault
(`bf31a13c78c9` → https://sgraph.ai/en-gb/dev/), and (d) the shipped `sgit-ai` CLI (v0.14.27).
**Method:** repo-wide doc audit (agent-assisted), read-only sgit clones of both public
vaults (read keys published by design in `/core/public-vaults.json`), CLI verification.

---

## Executive summary

1. **`library/guides/vault-html/AUTHORING.md` is the only current, reliable `window.sg.*`
   reference.** Every other doc correctly defers to it. Its defects are additive omissions
   only (no `sg.append.*`, no `sg.on/off`, missing newer `sg.vault.*` verbs).
2. **The live sgraph.ai library — positioned as the main source of truth — contains *no*
   vault-app API content at all.** No AUTHORING contract, no `sg.*` reference, no permission
   model, no `app.json` docs. Agents building vault apps cannot get this guidance from the
   place we tell them is canonical.
3. **`library/skills/create-vault-apps/SKILL.md` is the most stale agent-facing document**
   and it is exactly the file vault-app agents load. Three of its claims are now wrong.
4. **All sgit guidance (repo skills + live vault + quickstarts) teaches `sgit share` /
   `sgit publish` — both are disabled in the shipped CLI** (v0.14.27: "pending Simple Token
   security rework").
5. **Skill distribution has no versioning.** The sgit skill exists in ≥3 places (repo,
   library vault `library/reference/sgit-skill.md`, per-session installs). They happen to be
   in sync *today* (byte-identical repo↔vault, frontmatter-only drift in session copies),
   but nothing stamps a version or points at a canonical source, and the documented
   distribution flow is a manual download-and-upload (claude-setup.md). Staleness is a
   when, not an if.

**Cross-repo drift #1 — `inbox → append` rename:** shipped bridge says `sg.append.*`; both
reality indexes still say `sg.inbox.*`; AUTHORING.md doesn't document the namespace at all.
Only HOSTING-ON-STATIC-STORAGE.md is correct.

**Cross-repo drift #2 — sgit CLI reality (verified against v0.14.27):**
- `share send` and `share publish` are **disabled** ("pending Simple Token security rework");
  `share receive` still works. Every doc teaching "share a snapshot → token" is now wrong.
- Both token positions work; `create-vault-apps`' claim that the global-flag form
  "does not work" is outdated.
- CLI now also has `create` (init+push one-step), `clone-branch`, `clone-headless`,
  `clone-range`, `write`, `cat`, `ls`, `--read-key` read-only clones — none of the skills
  mention read-key clones, which is exactly how agents should consume public vaults.

## B. Live library vault (`pmcv9tfe` → sgraph.ai/en-gb/library/)

153 files: agentic-teams, email-fs-lite, building-on-sgraph, machine-readable-content,
use-cases, get-started, reference. Quality is good; freshest content ~2026-06-06.

- **No `window.sg.*` / vault-app authoring content whatsoever.** The canonical app-API
  guidance lives only in this repo, which the live library never references.
- `library/reference/sgit-skill.md` is **byte-identical** to this repo's
  `skills/use_sgit-and-vaults/SKILL.md` — in sync today, stale-together (share/publish).
- `library/get-started/claude-setup.md` documents the skill distribution flow: *download
  the skill from the library, upload via Claude Settings → Skills*. Manual copy, no version
  stamp, no update signal — this is the mechanism by which agent copies go stale silently.
- `library/reference/vault-read-keys.md` is a good, current reference (hex vs base64url) —
  the model for what the missing app-API pages should look like.

## C. Live Dev Docs vault (`bf31a13c78c9` → sgraph.ai/en-gb/dev/)

All content authored 2026-05-06. No `sg.*` bridge content. `cli-quickstart.md` pins
`sgit-ai v0.14.1` and demonstrates the now-disabled `sgit share` flow. The embed
quickstart documents `sg-vault-client.js` v1.2.2 + `<sg-vault-content>` components
(dev.tools.sgraph.ai) — a *fourth* documentation surface for vault access, disjoint from
the repo docs. `project/workstreams.json` already tracks a SKILL.md fix task (WS-2-T6),
so a maintenance loop exists but has not run since early May.

## Recommendations (priority order)

1. **Fix `create-vault-apps/SKILL.md` now** — remove the false `fetch()` claim, replace the
   external-links section with the deny-by-default + `externalLinks` model, add `hud.mode
   "none"`, `sg.append.*`, static-host mode, fix the 3 dead links. Highest leverage: this
   is the file vault-app agents actually load.
2. **Propagate the `inbox → append` rename** into `reality/vault/index.md` and
   `reality/ui/index.md`; fix `sg.state.list()` → `keys()`.
3. **Add the missing namespaces to AUTHORING.md** (`sg.append.*`, `sg.on/off`, newer
   `sg.vault.*` verbs, `app.context`/`totalSize`, current `vault.create` signature) so the
   canonical doc is complete, not merely correct.
4. **Update all sgit guidance for v0.14.27** — mark `share send`/`publish` disabled, drop
   the token-position warning, add `--read-key` read-only clones (the pattern agents should
   use for public vaults) and the new clone variants.
5. **Make the live library actually the source of truth for this content.** Either
   (a) publish the four vault-html guides + the skills into the library vault under
   `library/reference/`, with the repo as the authoring source and a CI/publisher step that
   pushes on change; or (b) declare the repo canonical and have every live page link to it.
   (a) matches the stated intent of sgraph.ai/en-gb/library/.
6. **Stamp every SKILL.md** with a header block: `canonical-source` (repo path + vault id),
   `version`, `verified-against` (bridge date / sgit version). Add a
   `library/reference/skills-manifest.json` in the library vault listing each skill +
   version + hash, so any agent can check freshness with one read-key fetch before
   trusting its local copy.
7. **Re-arm the Dev Docs maintenance loop** — the vault's own workstream file shows the
   intent; the quickstarts need a v0.14.27 pass.
