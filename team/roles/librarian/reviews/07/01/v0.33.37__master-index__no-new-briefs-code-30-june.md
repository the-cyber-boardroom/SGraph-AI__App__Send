### 1. `feat(sg-send): static-host mode` — v0.33.36 (EXISTS)

**Commit:** `74d5444` (2026-06-30) | **CI version:** v0.33.36

**What it does:** Lets the SAME vault-app HTML run against either the live FastAPI backend or a
100% static file host (GitHub Pages / S3), transparently. The app only talks to `window.sg`
and never knows the difference. The only layer that changes is the HTTP transport.

**Why it's nearly free:** Opening + browsing a vault is entirely deterministic GET reads
(file IDs are content-hash/HMAC of the key, computed client-side — no list/discovery call),
so a static host that mirrors the GET paths just serves the encrypted bytes.

**`SGSend.staticMode` (default `false` → live behaviour byte-identical; zero impact on current vaults):**

| Behaviour | Detail |
|-----------|--------|
| Flag source | Constructor `{staticMode: true}` or `window.SG_STATIC === true`; default `false` |
| `vaultBatch` in static mode | `op:'read'` ops fan out to parallel `vaultRead` GETs returning the **identical** `[{status, file_id, data:<b64>}]` shape — `SGVaultObjectStore.batchLoad` unchanged. Write op → `EREADONLY` |
| `vaultWrite` / `vaultDelete` in static mode | Throw `EREADONLY` immediately (no opaque 405/404) |
| `vaultReadLarge` in static mode | Skips presigned API call; reads directly via GET |
| Read-only open | No access token → `sg.app.writable===false` → bridge gates writes. Correct app already branches on `sg.app.writable`, so same HTML runs read-only unchanged |

### 2. `fix(app-shell): _buildVfsBridgeScript bare _embedHelperSrc() call` — v0.33.37 (EXISTS)

**Commit:** `97426c2` (2026-06-30) | **CI version:** v0.33.37

**What broke:** The bridge builder called `_embedHelperSrc()` as a bare function instead of
`this._embedHelperSrc()`. Valid syntax, but a runtime `ReferenceError` — and
`_buildVfsBridgeScript` runs on **EVERY** app mount, so it broke all `/en-gb/app/` apps:

```
[app-shell] initWithKey failed: ReferenceError: _embedHelperSrc is not defined
  at AppShell._buildVfsBridgeScript (app-shell.js:2465)
  at AppShell._mountApp ...
```

**Root cause:** Regression from the June 29 `sg-embed-helpers` merge (`ddff724`). The `_embedHelperSrc()` method was added there, but the call site inside the injected-string builder omitted `this.`. Node `--check` and the jsdom embed smoke missed it because the smoke called `el._embedHelperSrc()` with `this` — the bare call is a runtime (not syntax) error.

**Impact:** All 4 Playwright "Browser integration" jobs failed (app-mode deep link, embed handshake ×2, sgit round trip) — all mount an app, all timed out waiting for a bridge that never built.

**Fix:** `_embedHelperSrc()` → `this._embedHelperSrc()` in `app-shell.js`.

**Files changed (3):**

| File | Change |
|------|--------|
| `sgraph_ai_app_send__ui__vault/v0/v0.2/v0.2.3/_common/js/components/app-shell/app-shell.js` | −1/+1 line: bare call → `this._embedHelperSrc()` |
| `tests/unit/vault_ui/loader/test__app_shell_bridge_build.js` | NEW — 9 assertions (regression guard) |
| `tests/unit/vault_ui/loader/run-all.sh` | +1 line (wires new test) |

**Tests:** `test__app_shell_bridge_build.js` — 9 assertions:
- `_buildVfsBridgeScript` does not throw (catches the `_embedHelperSrc is not defined` regression)
- Bridge returns non-trivial string; exposes `window.sg`
- Bridge injects the embed helper (verified `function _embedVault` in output)
- Bridge wires `sg.vault.embed`
- Default external-link path posts `__sgOpenExternal` (no sandbox escape)
- `externalLinks` grant → `window.open` path + `allow-popups-to-escape-sandbox` in sandbox
- No grant → sandbox is `allow-scripts allow-forms` (no escape)

**Verified:** Test FAILS with bug reintroduced ("_embedHelperSrc is not defined"); passes with fix. This class of "method called bare inside an injected-string builder" bug cannot slip past the fast unit run again.

**Reality impact:**
- `qa/index.md` — `test__app_shell_bridge_build.js` (9) added to ViV loader suite; total 364+ → 373+
