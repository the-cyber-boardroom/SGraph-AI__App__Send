## Thematic Groupings

### Theme A: Demo Discipline — Testing, CI, and LLM Validation

**Briefs:** 417 (demo capabilities), 418 (testing framework), 419 (CI pipeline), 420 (Nova POC)

**Signal:** Four briefs land as a coherent cluster. The same JS API surface used by vault apps for production is the right surface for testing — no parallel testing API needed. The four-layer model (unit / integration / QA / browser-automation) is extended to a fifth: LLM-validated qualitative tests via Nova. At $0.0003 per CI review, the cost is operationally free. The CI pipeline's key architectural decision is that it triggers our own ephemeral compute (Fargate/container hosts) for test execution, not just a hosted CI runner. Nova Act SDK (AWS-native browser automation) enters as a specific substrate for browser testing against vault demos, with >90% accuracy on tricky UI patterns (date pickers, dropdowns, popups) per AWS benchmarks.

### Theme B: The Accountant Demo As A Template

**Brief:** 421 (accountant demo)

**Signal:** The structural insight is more important than the accounting use case: same vault + two apps (role-aware SG/App routing: `/accountant` and `/client` routes on the same vault). A 12-step orchestrated workflow with FastAPI behind a four-pane UI. Template for the recruitment, news, risk, and medical demos that follow. Auto-teardown after 15-20 minutes idle guarantees no resource leakage. Two modes: full setup-to-teardown (impressive to partners) and pre-provisioned shared (appropriate for public-facing self-service).

### Theme C: New Product Surfaces — Discovery and AppSec

**Briefs:** 422 (vault discovery + public keys), 423 (AppSec mini-tools)

**Signal:** Two high-impact new directions crystallised. Vault discovery (`/.well-known/vaults`) gives servers a structured way to answer "what vaults exist here?" — enabling offline demo bundles, manager vault catalogues, and air-gapped deployment artefacts. The Ed25519+X25519 key pair per vault makes "send to a vault" possible: anyone can encrypt to a public key; only the vault owner with the private key decrypts. This is the foundation for anonymous tip-lines, cross-org submissions, and inter-vault messaging.

AppSec mini-tools is a meaningful new product direction. The insight: every AppSec tool has a data-sharing problem; vaults solve it once for all of them. StrideGPT (mrwadams/stride-gpt) is the first integration target — actively-developed, LLM-integrated (Claude 4.5, GPT-5.2, Gemini 3), supports STRIDE + OWASP LLM Top 10 + multi-modal input. The pattern (find strong open-source tool, host on our infra, give it our UI + vault integration, contribute back) extends to 8 concrete mini-tools.

### Theme D: The Serverless Synthesis

**Brief:** 424 (SG/Compute serverless synthesis)

**Signal:** The clearest crystallisation in Day 66. The primitives built over three weeks now compose into a serverless environment specifically for agents. The key differentiation from Lambda: **containers handle parallel requests naturally; Lambda cold-starts each parallel slot** — a real problem hit in sgit clone. The resulting product surface ("serverless cost shape + agent-friendly parallelism + vault-grounded state + customer-controlled substrate + optional confidential compute + isolation per use case") is genuinely new. The framing: we compete in the agent-deployment market (where AgentCore Runtime is the comparison), not in the function-as-a-service market.

### Theme E: Email, Multi-Cloud, and Agent Communication

**Briefs:** 425 (SG Mail), 426 (multi-cloud + agent communication)

**Signal:** SG Mail's key framing decision: we are not building email infrastructure. Vault starts the moment an EML file exists. SES/Cloudflare/Gmail handle delivery, IP reputation, DKIM, abuse. We build the vault client on top of email-fs. WorkMail replacement for the project lead (~£8/month) is the forcing function. The cost target is achievable; the connectors are composable.

Multi-cloud forces two decisions: SG/Deploy as a separate codebase (keeps SG/Compute clean), and vault-as-communication-medium as the canonical agent-to-agent pattern. Agents communicate through shared vaults, not library imports or subprocess calls. Properties: decoupled, audit-trail-for-free, idempotent, multi-language, no new infrastructure.

### Theme F: Operational Reality — Backup, Provisioning, Admin

**Briefs:** 427 (backup), 428 (provisioning), 429 (admin interface + DNS registry)

**Signal:** Three operational briefs that make the platform real rather than conceptual. Backup gets the right framing: "backups that are never restored are not backups." The restore drill schedule (daily/weekly/monthly/quarterly) is the discipline that makes backups meaningful. Separate AWS backup account (write-only IAM from account A; SCPs in account B) is the ransomware isolation pattern.

Provisioning crosses a real milestone: **50-second end-to-end vault provisioning is working in production** (one command → EC2 instance up → vault created → cert issued → URL live). The DNS pinning fix (holding-page-detects-readiness Lambda, 302 redirect) is the solution to the transition problem. Randomised ephemeral addresses and "found existing instance, want to join?" UX are the natural next additions.

Admin interface corrects the CNAME-to-wildcard DNS scheme from the voice memo (RFC 4592 prevents wildcard matching when a concrete record exists at that name; A records are the clean solution). Admin vault is the registry of truth; DNS records are a projection of it.
