## Thematic Groupings

### Theme A: The Vault as a Richer Product Surface

**Signal:** All four documents continue the SG/Send product thread from 24 May (docs 464–472), turning the vault from a storage-and-transfer primitive into a richer product:
1. **Sub-vaults (convention):** a vault can now contain and traverse other vaults as conventional reference files (like Git submodules). Phase 0–3 implemented.
2. **External resources (iframes):** a vault can embed the outside world (YouTube, links, external apps) in controlled default-deny iframes. Phase 2 implemented.
3. **Public vault previews:** a vault can expose a deliberately-public preview surface (title, description, thumbnail, social-share meta-tags), opt-in, user-chosen. Code-complete; browser-unverified.
4. **Talk to the vault:** a vault can be talked to — a chat window with tool-calling acts on the vault's files. Architecture spec produced; implementation proposed.

Each is layered on the existing vault primitive without backend complexity, consistent with the project lead's standing no-backend-complexity principle.

### Theme B: Controlled Exposure as a Design Philosophy

**Signal:** The public vault previews brief introduces and names the design principle: **controlled exposure, not vulnerability**. An exposure is chosen, bounded, and opt-in. This framing appears across multiple concurrent workstreams: the public preview (chosen public surface), the controlled iframe (default-deny but selectively grantable), the sub-vaults read-only model (parent read-access is the floor), and the app-iframe permission model (security floor + grants). The through-line: give users and operators control over what is exposed, rather than binary all-or-nothing.

### Theme C: Existing Components Compose Into New Capabilities

**Signal:** Both the public vault previews and talk-to-the-vault briefs emphasise reuse of existing components. The previews reuse the SG/Send transfer flow, encryption, and the `/en-gb/app` route. Talk-to-the-vault reuses the tools website's `sg-agentic-loop`, `sg-tool-runner`, `sg-tool-definition`, and `sg-llm-*` components. The vault-chat dev pack (v0.27.80) explicitly catalogues what is REUSE vs EXTEND vs BUILD-NEW. This is the IFD surgical-composition pattern operating at product-feature scale.
