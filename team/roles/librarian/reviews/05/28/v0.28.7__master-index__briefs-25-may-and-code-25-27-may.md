## Thematic Groupings

### Theme A: The Vault As A Richer Product Surface

**Day 71's through-line:** Where Day 69–70 established the SG/Send product model and SG/Sentinel design, Day 71 deepens the vault primitive itself into a product surface. Four capabilities were added (or designed):

1. **Sub-vaults** — a vault can reference and open other vaults via convention files, making vault-of-vaults operable without backend complexity. Built (Web UI, Phases 1–3).
2. **External resources** — the same convention pattern embeds external resources in controlled iframes. Built (Phase 2 external resources embed).
3. **Public vault previews** — a vault can have a deliberately-public preview for effortless sharing. Built and shipped within the day (multiple pvp commits, confirmed by the talk-to-the-vault brief).
4. **Talk to the vault** — a chat window with tool-calling inside the vault, using existing tools. Designed (arch docs); not yet built.

The framing the project lead used: each is a usability or capability gain layered on the existing vault primitive, without backend complexity.

**App-Mode Permission System (EXISTS — Phases 1–4B, 05/27):**
