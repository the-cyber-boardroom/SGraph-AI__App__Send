## Code Changes — Vault UI v0.2.3 (22 May 2026)

All changes are in `sgraph_ai_app_send__ui__vault/v0/v0.2/v0.2.3/`.

### New Page: SG/App Hosting (`/en-gb/app/`)

**File:** `en-gb/app/index.html`

New dedicated route for running vault-hosted apps. Distinct from `/en-gb/vault/` (browser)
and `/en-gb/` (landing). Mounts `<app-shell>`, `<app-hud>`, `<app-debug-pane>`.
Includes global `window._appDebug` event buffer (vault events, bridge calls, network calls,
capped 300 each) and a fetch proxy recording all outbound HTTP calls.

## Thematic Summary

The vault UI shipped a major developer-experience layer on 22 May:

1. **SG/App as a first-class route** — `/en-gb/app/` is now the canonical entry point for vault-hosted apps, distinct from the vault browser. The `/#key` shortcut now routes there rather than to the vault browser.

2. **Self-contained app shell** — `<app-shell>` (1,154 lines) handles the full lifecycle without depending on `vault-loader` scripts: credential parse, vault open, auth gate, app.json read, resource pre-fetch, iframe mount, VFS bridge. Includes PageLayoutRenderer inlined.

3. **Debugging infrastructure** — 5 focused debug components plus a global event buffer and fetch proxy. The debug pane is collapsible to a thin edge strip so it doesn't obstruct the hosted app.

4. **UX polish** — app opens in same tab (was new tab), vault key survives page reloads via localStorage, entry form has an explicit server endpoint field with a sensible default.
