## Thematic Grouping

### Email-FS Protocol Family — v0.6 Specifications

Both documents originate from `@Email-FS (architect.spec)` and were published on 6 May 2026. Together they form the canonical specification for the two profiles of the Email-FS protocol:

**Email-FS (full v0.6):**
- Programmatic operation, per-message cryptographic signing (RFC 2822 + S/MIME-capable)
- 3-component agent names (`{role}.{location}.{session-id}`)
- ULID-keyed filenames, sidecar metadata folders, 5-state operations
- Four-document set (Specification, Architecture, SKILL, Simulation)

**Email-FS-lite (v0.6):**
- Manual operation in chat-driven multi-agent workflows
- 2-component agent names (`{role}.{team}`) — stable across runtime restarts
- Sequence-numbered filenames, append-only session notes, 3 operations (SEND, DELIVER, DONE)
- Integrated Issues-FS-lite (task tracking in same vault folder structure)
- Commit cadence: one commit per processing cycle
- Sgit as explicit substrate with pull-diff as inbox notification

**Relationship:** Both profiles share the `mail/` namespace, the single-writer rule, the mailroom transit zone, and the outbox archive. They can coexist in the same vault (different agent-name formats) but mixing within a vault adds friction. Lite is the correct default for today's manual SGraph Send agent workflow.
