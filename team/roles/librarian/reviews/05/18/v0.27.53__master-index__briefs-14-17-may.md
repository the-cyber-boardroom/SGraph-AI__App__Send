### Theme A: Vault Hosting Architecture
**Briefs:** 384 (vault collections), 385 (hosting density), 386 (vaults-of-vaults), 389 (EC2 boot optimisation), 391 (vault rendering without iframe)
**Signal:** The vault is evolving from a file-sharing primitive into a deployable, self-contained mini-app. Three density modes, vault collections as zip-portable units, and 10-20s boot times establish the foundation for the compute layer. Vault rendering without iframe simplifies the architecture for published single-app vaults.

### Theme B: Platform Validation Against Kubernetes
**Briefs:** 392 (infographics reference), 393 (security deep-dive), 394 (orchestration comparison), 395 (strategy validation)
**Signal:** Four documents validate the per-tenant VM choice against Kubernetes. Research confirms the architecture is appropriate for bursty, isolation-sensitive, low-duty-cycle workloads. This is strategic positioning material, not new code.

### Theme C: Monetisation Foundation
**Briefs:** 396 (pre-auth micropayments), 390 (infographic tool v2)
**Signal:** The pre-auth + micropayment model is now the monetisation substrate for all chargeable features. Infographic tool v2 is the first concrete instantiation. This is a strategic pivot from bring-your-own-key to platform-managed payments.

### Theme D: Manager Vaults and Credential Management
**Briefs:** 386 (vaults-of-vaults), 387 (credential manager vault), 397 (dynamic credential delivery service)
**Signal:** Three briefs establish a layered credential management architecture: manager vaults as the pattern, credential manager vault as the first instance, and dynamic credential delivery service as the AWS-scoped implementation. This is a coherent cluster ready for Explorer implementation.

### Theme E: Infrastructure CLI Expansion
**Briefs:** 399 (Fargate experiment), 401 (instance sizing), 402 (S3 native CLI), 403 (container hosts), 404 (Bedrock CLI), 405 (substrate strategy)
**Signal:** Massive CLI surface expansion. Every major AWS primitive (Fargate, EC2 sizing, S3, container hosts, Bedrock) gets CLI-native treatment following the same pattern. The substrate strategy brief provides the unifying framework: everything above ad-hoc laptop work moves to a managed substrate, selectable by one flag.

### Theme F: Observability and Security Posture
