## Detailed Analysis

### Feature: app.json Resource Injection into Vault HTML Preview

**Commit:** `09288b20`
**File:** `sgraph_ai_app_send__ui__vault/v0/v0.2/v0.2.3/index.html` — `_applyAppJson()` function

**Problem solved:**
SG/App-style vault applications store their HTML entry point without any `<link>` or `<script>` tags. All CSS/JS dependencies are referenced via `app.json`'s `resources` block. On `/en-gb/app`, the `<app-shell>` component reads `app.json`, pre-fetches resources, and injects them into the entry HTML before mounting it in an iframe. However, the vault _file browser_ (`send-browse`) was not aware of this injection pattern — it would open the entry HTML as-is, producing a blank placeholder div with no styles or scripts.

**Solution:**
In `_applyAppJson`, when `config.resources` is present and `autoOpen` is active (i.e., the file browser is about to auto-open the app entry point), the vault browser now:

1. Reads `config.resources.css` and `config.resources.js` path arrays from app.json
2. Pre-fetches each file from the vault using `dataSource.getFileBytes()`
3. Builds an injection block: CSS files → `<style data-sg-app>…</style>` tags; JS files → `<script data-sg-app>…</script>` tags
4. Patches `dataSource.getFileBytes` to intercept reads of the entry HTML file and prepend the injection block into `<head>` (or prepend to the top if no `<head>` found)
5. The patched data source is then consumed by `send-browse`'s BRW-020 inlining, which creates the blob URL with resources already inline

**Impact:** Vault HTML preview rendering is now at parity with `/en-gb/app`. Apps that rely on CSS/JS from `app.json` resources now render correctly in the vault file browser.

**Security note:** The injection is CSS/JS from inside the same vault — no cross-vault or external resource loading. The `<style data-sg-app>` / `<script data-sg-app>` tagging matches the same convention used by `<app-shell>`, making the injection source identifiable in DevTools.
