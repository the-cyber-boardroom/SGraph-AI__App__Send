# SG/Vault — Markdown Authoring Guide

**Version:** v0.2.3 | **Audience:** Claude sessions, human authors writing content for SG/Vault encrypted vaults

> **See also:** `v0.20.13__guide__sg-send-browse-markdown-authoring.md` — covers links, images, navigation patterns, and the full supported syntax table (all of which also apply inside the vault).
>
> This guide focuses on vault-specific features: front matter, page breaks, print control, and the live edit preview.

---

## 1. Front matter

Front matter is a YAML block at the **very start** of the file, delimited by `---`. It configures how the file is rendered and printed. It never appears in the rendered output — instead the vault shows a compact "⚙ doc-settings" badge above the content (hidden in print).

```markdown
---
page_break_before: [h1, h2]
print_css: |
  h1 { font-size: 1.8em; }
  h2 { color: #2c5282; }
---

# Document title starts here
```

### Supported front matter keys

| Key | Values | Effect |
|-----|--------|--------|
| `page_break_before` | `h1` · `h2` · `[h1, h2]` · `true` | Insert page-break marker before headings of the given level(s). `true` = h1 only. |
| `print_css` | Literal block (`\|` + indented CSS) | Raw CSS injected into the print preview window (`@media print { ... }`). Lets you fine-tune fonts, margins, colours without touching vault UI source. |

### Rules

- The `---` opening must be the **absolute first line** of the file (no blank lines before it).
- Only flat key–value pairs are supported (no nested YAML objects or sequences — use the inline array `[h1, h2]` syntax for lists).
- Unknown keys are shown in the badge but otherwise ignored.

## 2. Page breaks

### Automatic page breaks via front matter

Add `page_break_before` to automatically insert page breaks before every heading at a given level:

```markdown
---
page_break_before: h2
---

# Report Title

## Chapter 1        ← page break inserted before this
...

## Chapter 2        ← page break inserted before this
```

The first heading in the document **never** gets a page break (nothing to break before it).

**Default:** No automatic page breaks. Most documents do not need them.

### Explicit page breaks via inline directive

Insert a manual page break anywhere in the document body with:

```markdown
Some content.

<!-- page-break -->

Content on the next page.
```

This works regardless of front matter — no configuration needed. The directive must be on its own line with no other content.

### What the page-break marker looks like

**On screen** (vault viewer and print preview): a dashed horizontal rule with a "PAGE BREAK" label in the centre. This lets authors see exactly where breaks fall without printing.

**When printing** (Ctrl+P or the Print button): the marker becomes invisible and triggers a real page break. The label does not print.

## 3. Print CSS (`print_css`)

For documents that will be printed or exported as PDF, you can inject custom CSS into the print window using a `print_css` front matter key. The CSS is wrapped in `@media print { ... }` automatically.

```markdown
---
print_css: |
  h1 { font-size: 1.6em; page-break-after: avoid; }
  h2 { font-size: 1.2em; color: #2c5282; }
  .sg-print-header { display: none; }
  @page { margin: 1.5cm 2cm; }
---
```

Use cases:
- Adjust font sizes for your specific document
- Change page margins (`@page` rule)
- Hide the SG/Send print header/footer for private documents
- Set column layout for reference cards

## 4. Image sizing

Use the Discourse pipe convention to resize images without touching the URL. Works in vault and Send/Browse contexts.

| Syntax | Effect |
|--------|--------|
| `![caption](img.png)` | Default — `max-width: 100%` (fills available width) |
| `![caption\|400](img.png)` | Fixed width: 400 px |
| `![caption\|50%](img.png)` | 50% of container width |
| `![caption\|800x600](img.png)` | 800 px wide × 600 px tall (exact crop) |

```markdown
![Architecture overview|600](images/architecture.png)

![Logo|120x120](images/logo.png)

![Full-width banner|100%](images/banner.jpg)
```

## 5. Live edit preview (vault only)

When editing a markdown file in a writable vault, clicking **Edit** opens a **split-view** layout:

- **Left pane:** raw markdown textarea (monospaced font, tab-size 4)
- **Right pane:** live rendered preview, updating ~400 ms after each keystroke

The preview includes:
- Front matter badge (so you can see settings at a glance)
- Page-break markers (so you see where breaks fall)
- Image rendering (vault images resolve from the encrypted store)

Click **Save** to persist the file to the vault. Click **Cancel** to discard changes (the original rendered view is restored from the unmodified bytes).

## 6. Supported markdown syntax (quick reference)

| Feature | Supported | Notes |
|---------|-----------|-------|
| Headings `#` — `######` | ✓ | |
| Bold `**text**` / `__text__` | ✓ | |
| Italic `*text*` / `_text_` | ✓ | |
| Bold+italic `***text***` | ✓ | |
| Strikethrough `~~text~~` | ✓ | |
| Inline code `` `code` `` | ✓ | |
| Fenced code blocks ` ``` ` | ✓ | Language label shown |
| Tables `\| col \| col \|` | ✓ | Column alignment supported |
| Blockquotes `> text` | ✓ | |
| Unordered lists `- item` | ✓ | |
| Ordered lists `1. item` | ✓ | |
| Horizontal rule `---` | ✓ | |
| Images `![alt](url)` | ✓ | Pipe resize syntax supported |
| Internal file links | ✓ | Open as tabs in the vault browser |
| External links | ✓ | Open in new browser tab |
| `<!-- page-break -->` | ✓ | Explicit page break (vault + send-browse) |
| Front matter `---` | ✓ | `page_break_before`, `print_css` |
| HTML tags | ✗ | Stripped/escaped — no passthrough |
| Nested lists | ✗ | Not supported |
| Task lists `- [ ]` | ✗ | Not supported |
| Footnotes | ✗ | Not supported |
| Anchor headings `{#id}` | ✗ | Not supported |
